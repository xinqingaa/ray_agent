# Draw Tech Diagrams

只有图能比文字更清楚地表达关系、变化或执行过程时才画，不规定每份文档的配图数量。一张图只回答一个主要问题，箭头标明语义，当前实现与未来设计分开表达。

## 控制密度，让关系先被看见

控制图中文字密度，让读者先看见关系和流程。节点优先使用简短名称，按需补一条关键说明；详细解释放正文或图注。标题、副标题、节点说明和底部结论不应重复同一判断，也不默认凑齐这些元素。信息拥挤时先精简重复内容或拆图，不靠缩小字号容纳段落。

## 选择术语

采用读者熟悉且简短的术语，例如图中直接写 `Context`、`Memory`，不必逐个翻译或重复中英双标；术语在正文中解释并保持一致。中文与英文按清晰程度选择，不强行统一为英文。精简后仍需保留关键动作、条件、来源线索与箭头含义，避免只剩抽象名词、无法推演过程。渲染检查同时看文字密度与可理解性，不以字数越少越好。

## 落地到工具并校验

遵循目标项目或用户的格式、尺寸、风格与资源路径约定；本 skill 不固定默认值。需要技术架构图且 Fireworks Tech Graph 可用时，读取其 skill 及对应风格参考，按需使用；不要凭技能名称猜测规范，或把模板中的能力当作系统事实；工具不可用时如实说明，不代为编造效果。

作图工具的默认设置不能覆盖目标项目的明确约定。完成后检查图文一致性、结构、文本可读性与裁切，并实际渲染查看。临时预览与正式交付分开；未查看不能声称视觉验证通过。动画只在明确需要时制作，先确认工具支持的结构与依赖。
