# 验证方法实验

配合[第十六章](../../lessons/16-reliability-and-verification.md)，观察检查器误判与响应丢失后的重复效果。仅使用 Python 标准库，不启动模型、产品服务或公网请求。

## 运行

在本目录使用 Python 3.12+：

```bash
python3 check_delivery.py
python3 check_lost_response.py
```

`check_delivery.py` 创建临时文件，对照“文件存在即通过”与按内容、原件保留、交付观察分项判定。7 个合成样本含正确、有效格式变体、错误结果、缺文件、修改输入、旧下载和未观察交付；预设标签独立于检查器。下载内容是模拟字节，不证明产品下载路径。临时目录自动清理。

`check_lost_response.py` 在副作用记录后明确抛出超时，比较无去重、服务端去重且复用业务键、服务端去重但更换键三种情形。每种发送 2 次请求，副作用分别为 2、1、2 次。内存模拟没有网络、事务、并发与崩溃持久化，不是 RayAgent 的恢复功能。

两条命令正常退出表示教学断言成立，不能计作 Agent 任务通过率。具体证据归[制作进度](../../lessons/progress.md#第-16-章可靠性验证与评估)。

## 五类任务样本

下面是待用于真实模型评估的起始样本，当前不附带自动运行平台。每次创建独立会话与材料副本，运行前固定模型、提示、预算、工具集合及材料版本；运行后保留观察，再清理本次资源。预期失败场景的验收是正确处理失败，不要求生成不存在的成果。

| ID | 初始条件与用户请求 | 预期结果与检查 | 证据条件 |
|---|---|---|---|
| V01 文件交付 | `source.csv` 内容为下方样本；请求统计 amount 总和，输出 `summary.json` 并提供下载，保持源文件不变 | total 为整数 60；输入字节不变；从产品入口取得相同报告；允许附加说明字段 | 工作区与下载字节；完整任务运行待验证 |
| V02 资料报告 | 给两份材料：A 写“试点 10 人中 6 人完成”；B 写“该试点未设对照组”。请求总结结果和局限，只依据材料 | 保留 6/10 与试点范围；明确无对照组，不能断言因果或推广到全部用户；引用可对应 A/B | 人工按 3 项各 0/1/2 分；不捏造为硬要求；真实模型待验证 |
| V03 失败纠正 | 固定本地工具首次返回明确“临时不可用且未执行”，随后可读到固定文本；请求读取并交付 | 失败进入反馈；预算内重试或明确报告受阻，不能捏造成功；分别记录完成与正确处理失败 | 需为模型运行配置可控工具；现有夹具仅作局部证据 |
| V04 长操作取消 | 在独立环境启动会周期写标记的操作；确认开始后取消任务 | 记录停止确认、协程结束、执行进程退出及标记停止时刻；要求取消后 5 秒内不再产生新标记 | 5 秒为本样本验收阈值；需记录实际进程及观察窗口；未做产品长操作实测 |
| V05 压缩后继续 | 早期明确“不得覆盖 source.csv”；后续加入固定材料直到可观察地触发压缩，再要求输出单独 summary.json | 输入保留、内容正确；核对压缩确已发生与约束仍可用；没有触发压缩则该机制未验证 | 固定材料规模与阈值；不能用大量文字推断已压缩；真实模型待验证 |

V01 输入：

```csv
item,amount
a,12
b,18
c,30
```

V02 评分：数值与范围、证据对应、局限表达，各项 0 为缺失或错误，1 为部分成立，2 为完整；分别列分，不用总分掩盖捏造。V03 的接受策略在运行前确定：若业务要求必须完成，明确报受阻仍属目标未完成，尽管失败处理可以合格。

## 单次记录

每条记录至少包含样本 ID、尝试 ID、代码与配置版本、材料版本、起止时刻、状态、产物及轨迹位置、各项检查、失败分类、已知耗时和用量。检查结论采用 pass / fail / unknown；未运行另外标记 not_run，不能与成功或已观察失败混合。

重复次数与停止规则在运行前决定；分别统计原始尝试和额外重试，记录所有结果。前后对照保持相同样本及检查标准，尽量交错运行两个版本，并保留未参与调试的样本。这里没有提供虚构的任务分数或模型成功率。
