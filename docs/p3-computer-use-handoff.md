# P3 文件夹工作区：真实窗口走查交接

本文是临时交接材料，交给没有项目背景的模型，用 Computer Use 在真实 Tauri 窗口里走查"文件夹工作区"。自动化检查（后端测试、前端脚本、宿主测试）已经覆盖逻辑，这里只负责它们覆盖不到的部分：原生文件夹选择器、系统授权、Finder 里的真实操作、窗口里的实际观感与跨进程的外部变更。走查结束后，本文可以直接删除。

走查只观察和记录，不修改仓库。发现问题按[问题记录格式](#问题记录格式)写成清单交回，不要自行修复代码。

## 目标与范围

目标：确认用户在桌面窗口里把一个本机文件夹当作工作区使用的完整路径可用，且对用户文件是安全的。

在范围内：创建与打开工作区、移动与复制后的识别、不可用与重新定位、文件夹面板（树、预览、添加文件）、对话读写文件夹、外部修改刷新、写入占用提示、撤销与撤回、归档、改名、删除、独立对话附件、设置里的默认位置与清空数据。

不在范围内（当前没有实现，遇到不要当缺陷报告）：

- 本机命令与浏览器工具：执行端口尚未接入，对话里不会有终端或浏览器工具。
- 外部进程写入者（PROCESS）的写入租约，及其"用户确认后释放"的入口：留给执行端口工作包，当前没有调用方。
- 覆盖发布没有用 macOS 的 `renamex_np` 做条件替换，最后一次核对与替换之间仍有很小的竞争窗口，无法靠走查复现，不报告。
- 非 macOS 的"在文件管理器中显示"分支没有做编译验证；本机是 macOS，只会走 Finder。
- 记忆、Todo、计划页等其他工作包的能力。

## 当前已实现的工作区能力（以源码为准）

- 工作区就是一个绑定的本机文件夹。文件夹里写入 `.rayagent/workspace.json` 作为身份标记，并记录文件系统身份（设备号与 inode）。
- 创建：在"默认位置"（默认 `~/RayAgent`，可在设置里改）下按名称新建同名文件夹；打开：用系统文件夹选择器选已有文件夹，打开后显示一次扫描摘要。
- 移动识别：文件夹被移走后再从新位置打开，认出是原来的工作区并更新位置；复制出的副本带着同一个标记，打开时弹出冲突对话框，可选"作为新工作区"或"改绑到这里"。
- 已经是工作区的文件夹再次打开：不新建，直接进入已有工作区。嵌套（在已有工作区之内或之上）、数据根、系统目录等不能作为工作区。
- 不可用与重新定位：文件夹被删除、改名或所在卷离线时，工作区页显示不可用横幅，可"重新检查"或"重新定位"；重新定位在有写入租约、有活动运行、目标已绑定别的工作区、目标带有另一工作区的标记时被拒绝并说明原因。
- 文件夹面板：目录树、文本、图片与 HTML 预览、中文文件名、"添加文件"（同名时提示另存名称）、"本次成果"、"最近修改"。
- 对话通过文件工具读写文件夹；文件访问经根目录句柄，拒绝越界、符号链接穿越与对凭据、版本控制内部路径的访问。
- 写入保护：每个工作区同一时刻只允许一个写入者持有租约，不排队，被占用时立即提示；写文件前先备份原内容；运行结束后在对话里提示"本次运行修改了文件夹里的 N 个文件"，可撤销。
- 撤销：运行之后文件又被改过则标为冲突，需要逐项选择"仍要覆盖"；撤销本身也有记录，可以撤回。
- 外部变更：文件监视加周期重扫，经事件流刷新目录树；正在预览的文件被改动或删除时提示"重新载入"。
- 归档（对话与文件夹变只读）、取消归档、改名、删除；删除只清理应用里的登记、备份与对话，不删除或改动用户文件夹里的任何文件。
- 独立对话（不属于任何工作区）有自己的会话工作目录；上传的附件放在那里，由文件工具读取。独立侧栏只列独立对话，工作区侧栏只列该工作区的对话。
- 设置里可改默认位置；"清空所有对话与附件"会清掉全部对话与工作区登记，但不删除任何工作区文件夹里的用户文件。

## 前置条件

### 权限

走查者使用的应用（运行 Computer Use 的程序）需要在"系统设置 → 隐私与安全性"里获得"辅助功能"与"屏幕录制"。缺权限时 Computer Use 会拒绝并说明，请把拒绝原文交回，不要绕过。

### 模型连接

核心从 `~/.config/rayagent/config.toml` 读取模型地址与密钥（可用环境变量 `RAYAGENT_CONFIG` 另指路径），格式见[运行指南的模型连接](../ray_agent/README.md#模型连接)与[配置示例](../ray_agent/api/config.example.toml)。走查前确认文件存在、设置页"模型提供商"里至少一个模型显示可用。

- 不要把密钥、令牌抄进问题记录、截图说明或对话内容。
- 缺少可用模型时，只能走查"不需要对话"的用例（见下表标注"需模型"的用例会无法执行），其余照常。

### 启动

以下在仓库的 `ray_agent/desktop/` 目录执行，首次需 `npm ci`、`npm --prefix ../ui ci` 并准备好 `../api/.venv`，见[桌面开发指南](../ray_agent/desktop/README.md#环境准备)。

```bash
cd ray_agent/desktop
RAYAGENT_CORE_DATA_DIR=/tmp/rayagent-p3-walk-data npm run dev
```

`RAYAGENT_CORE_DATA_DIR` 把业务库、备份和会话目录放进独立数据根，不碰真实的应用数据。终端里 `[core]` 前缀是核心日志，`[host]` 前缀是宿主日志，走查全程保留这个终端，发现异常时抄下相关日志行。窗口标题与应用名是 `RayAgent`，用 Computer Use 的应用列表找到它。界面只在这个窗口中工作，浏览器里打开开发服务器地址不能用。

要观察大目录在默认描述符限制下的表现，在启动前先执行 `ulimit -n 256`（macOS 终端默认就是这个值，通常不需要额外设置，但要确认 `ulimit -n` 的输出）。

### 测试夹具

所有测试文件夹放在 `~/rayagent-p3-walk/` 下，走查结束整体删除。下面的脚本在终端里一次执行：

```bash
set -e
B=~/rayagent-p3-walk
mkdir -p "$B"

# 1. 日常文件夹：中文名、中文文件名、文本、CSV、图片、HTML
mkdir -p "$B/季度复盘资料/图表" "$B/季度复盘资料/空目录"
printf '# 季度复盘\n\n这是说明文件。\n' > "$B/季度复盘资料/说明.md"
printf '月份,销售额\n1月,100\n2月,120\n' > "$B/季度复盘资料/数据.csv"
printf '<!doctype html><meta charset="utf-8"><title>页面</title><h1>你好，工作区</h1><script>document.title="脚本已执行"</script>\n' > "$B/季度复盘资料/页面.html"
python3 - <<'PY'
import os, struct, zlib
def png(path, w, h):
    row = b'\x00' + b'\x20\x80\xe0' * w
    raw = row * h
    def chunk(t, d):
        c = struct.pack('>I', len(d)) + t + d
        return c + struct.pack('>I', zlib.crc32(t + d) & 0xffffffff)
    data = b'\x89PNG\r\n\x1a\n' + chunk(b'IHDR', struct.pack('>IIBBBBB', w, h, 8, 2, 0, 0, 0)) + chunk(b'IDAT', zlib.compress(raw)) + chunk(b'IEND', b'')
    open(path, 'wb').write(data)
png(os.path.expanduser('~/rayagent-p3-walk/季度复盘资料/图表/示意图.png'), 160, 90)
PY
head -c 20000 /dev/urandom > "$B/季度复盘资料/二进制.bin"

# 2. 大目录：1500 个目录，每个 2 个文件；另有一条 40 层深的链
mkdir -p "$B/大目录"
for i in $(seq 1 1500); do d="$B/大目录/d$(printf %04d $i)"; mkdir -p "$d"; echo "$i" > "$d/a.txt"; echo "$i" > "$d/b.txt"; done
deep="$B/大目录/深链"; for i in $(seq 1 40); do deep="$deep/n$i"; done; mkdir -p "$deep"; echo deep > "$deep/end.txt"

# 3. 其他用例要用的空文件夹与副本来源
mkdir -p "$B/外层/内层" "$B/第二个资料夹" "$B/空文件夹"
echo "第二个工作区的文件" > "$B/第二个资料夹/b.txt"
ls -la "$B"
```

另外准备两个独立附件：`~/rayagent-p3-walk/附件.txt`（随便写几行中文）和 `~/rayagent-p3-walk/附件图.png`（可复制上面生成的示意图）。

确认三个位置在走查前都不存在，存在就说明上次走查有残留，先按[清理](#清理)处理：`~/RayAgent`、`/tmp/rayagent-p3-walk-data`、`~/rayagent-selftest`。

## 记录方式

每个用例按"步骤 → 预期 → 证据"执行。证据是：窗口截图（Computer Use 截图）与界面上读到的原文（引号内的按钮与提示文字要逐字对照）。终端里的文件系统状态用 `ls`、`cat` 取证并抄录。预期与实际不同，或者界面文字与本文不同，都记为问题。

## 用例

编号用于问题记录引用。用例按依赖顺序排列，建议按顺序走；标"需模型"的用例要有可用模型。

### A. 创建与打开

**A1 原生文件夹选择器与系统授权**

1. 在首页点击"打开文件夹"。
2. 预期：弹出 macOS 原生的文件夹选择器（NSOpenPanel），不是网页里的伪选择器；窗口在选择期间不卡死。
3. 在选择器里点"取消"。预期：回到首页，不出现任何提示或新工作区。
4. 再点"打开文件夹"，用 Cmd+Shift+G 输入 `~/rayagent-p3-walk/季度复盘资料` 选中。预期：进入这个工作区。
5. 可选：在 `~/Documents` 下建一个测试文件夹再打开。若出现系统的"想访问文件夹"授权提示，记录提示的完整文字与它显示的应用名；授权弹窗无法由 Computer Use 点击时，停下并交回，不要反复尝试。

证据：选择器截图、取消后的首页截图、授权提示原文。

**A2 打开已有文件夹与扫描摘要**

1. 接 A1 第 4 步。预期：工作区页顶部出现一次性横幅"已打开文件夹，共 …"，带文件与目录数量、总大小；点"知道了"后消失，刷新窗口后不再出现。
2. 回到首页，再次"打开文件夹"选同一个文件夹。预期：提示"这个文件夹已经是工作区，已为你打开"，进入已有工作区，工作区列表里没有新增条目。
3. 终端检查：`ls -la ~/rayagent-p3-walk/季度复盘资料/.rayagent/` 应有 `workspace.json`；记下内容里的工作区 id（不是凭据）。

**A3 默认位置新建工作区**

1. 首页点"新建工作区"。预期：对话框"新建工作区"里有名称输入框（占位例如"例如：季度复盘"）和默认位置说明。
2. 在设置里先确认默认位置（A11 会改它）；此处先用默认值，名称填"默认位置测试"，创建。
3. 预期：进入新工作区；终端 `ls -la ~/RayAgent/默认位置测试` 存在且含 `.rayagent/workspace.json`。
4. 再创建一个同名工作区。预期：不覆盖已有文件夹，不出现内部错误；记录实际表现（失败提示原文，或另取名称的方式）。

**A4 嵌套被拒绝**

1. "打开文件夹"选 `~/rayagent-p3-walk/季度复盘资料/图表`（已有工作区之内）。预期：被拒绝，提示说明原因，不创建工作区。
2. 先把 `~/rayagent-p3-walk` 本身当作候选：选择它（它包含已有工作区）。预期：同样被拒绝。
3. 选 `~/rayagent-p3-walk/外层/内层` 打开成功（建一个工作区），再选其上一级 `~/rayagent-p3-walk/外层`。预期：被拒绝。完成后把"内层"工作区保留，A 组之后用得上。

### B. 移动、复制、不可用与重新定位

**B1 在 Finder 里移动后重新打开会被认出**

1. 在 Finder 里（用 Computer Use 操作 Finder，或终端 `mv`；至少要有一次用 Finder 拖动）把 `季度复盘资料` 改移到 `~/rayagent-p3-walk/新位置/季度复盘资料`。
2. 回到 RayAgent。预期：该工作区变为不可用，工作区页横幅显示"文件夹暂时不可用："加原因，带"重新检查"与"重新定位"按钮；工作区列表里也有可区分的状态。
3. "打开文件夹"选新位置。预期：toast"已认出这是原来的工作区，位置已更新"，工作区变回可用，原来的对话仍在。不会出现新的重复工作区。

**B2 复制产生冲突对话框**

1. 终端：`cp -R ~/rayagent-p3-walk/新位置/季度复盘资料 ~/rayagent-p3-walk/季度复盘资料-副本`（`cp -R` 会带上 `.rayagent` 标记）。
2. "打开文件夹"选副本。预期：弹出对话框，标题"这个文件夹带有「…」的标记"，说明"…仍绑定在另一个位置，看起来你选择的是它的副本"，列出"原位置"与"所选"两个路径；按钮为"取消""作为新工作区""改绑到这里"，两个选项各有后果说明。
3. 点"取消"：不产生任何变化。再次打开副本，选"作为新工作区"：预期出现第二个工作区，副本里的标记换成新的 id，原工作区不受影响。
4. 另取一个副本（`cp -R` 到 `季度复盘资料-副本2`）打开，选"改绑到这里"。预期：原工作区的位置改为副本2；原来的 `新位置/季度复盘资料` 此后不再是任何工作区的位置（终端可检查它的标记仍在，说明它是个残留标记，记录之后再打开它时的表现）。

**B3 删除与改名后不可用，重新定位恢复**

1. 选一个已有对话的工作区，在终端把它的文件夹改名：`mv X X-改名`。预期：窗口里在数秒内（或点"重新检查"后）显示不可用横幅。
2. 点"重新检查"。预期：状态按钮显示"正在检查"，结果仍不可用时给出"文件夹仍然不可用"。
3. 点"重新定位"，选 `X-改名`。预期：显示"正在重新定位"，成功后恢复可用，文件夹面板重新显示内容。
4. 对另一个工作区在终端直接 `rm -rf` 它的文件夹（只删夹具，不要删别的）：预期同样不可用；"重新定位"选一个全新的空文件夹，应能成功或给出明确说明，记录实际表现。
5. 不可用期间点文件夹面板的"添加文件"，预期被禁用或提示，不能写入。

### C. 文件夹面板与预览

在 `季度复盘资料` 工作区（恢复可用后）进行。

**C1 目录树**

1. 打开文件夹面板（标签为"文件夹"）。预期：显示"图表""空目录"及根下文件；中文文件名显示正常。
2. 展开"图表"、"空目录"。预期："空目录"显示"空文件夹"提示；展开状态可以收起再展开。
3. 点面板的"刷新"。预期：树重新读取，已展开的目录保持展开。
4. 工具提示"在 Finder 中显示文件夹"悬停可见，见 L1。

**C2 预览**

1. 点 `说明.md`、`数据.csv`：预期文本预览，中文无乱码。
2. 点 `示意图.png`：预期显示图片。
3. 点 `页面.html`：按[产品说明的文件预览](product.md#文件预览)，HTML 在系统浏览器中以隔离方式运行，页面应显示"你好，工作区"，且不能访问应用存储；记录打开的是哪个浏览器、地址形式（不要抄任何令牌）、页面是否正常渲染。
4. 点 `二进制.bin`：预期不渲染成乱码，而是说明原因（不支持或无法预览）；工作区里的文件只读、不提供下载入口。记录提示原文。

**C3 添加文件**

1. 点"添加文件"，在系统选择器里选 `附件.txt`，目标目录为"文件夹根目录"。预期：toast"已添加「附件.txt」"，树里出现该文件，终端里文件内容与源文件一致。
2. 再添加一次同一个文件。预期：不覆盖，提示改用另存名称，树里出现两个文件，原文件内容不变。记录新名称的形式。
3. 向"图表"目录添加：打开"添加到"选择，选"图表"。预期文件落在对应目录。

**C4 大目录**

1. 先在终端确认 `ulimit -n` 是 256，并在这个终端环境里启动的应用中走查（若已有应用在跑，退出后重启）。
2. 打开 `~/rayagent-p3-walk/大目录`。预期：打开成功，扫描摘要显示目录与文件数量。
3. 展开根目录。预期：目录树显示条目，条目过多时提示"只显示前一部分条目，目录过大"；展开"深链"逐层进入，直到 `end.txt` 可以预览。
4. 全程观察终端 `[core]` 日志：不应出现"Too many open files"之类的描述符耗尽错误，窗口不卡死。若出现，记录日志原文与触发的步骤。

### D. 对话读写文件夹（需模型）

**D1 对话创建与修改文件**

1. 进入 `季度复盘资料` 工作区，新建对话，发送："在文件夹根目录创建 `总结.md`，写三行中文总结；再把 `说明.md` 末尾追加一行'已复核'。"
2. 预期：对话里出现文件工具调用卡片；完成后文件夹面板里出现 `总结.md`（外部刷新，不需要手动点刷新）；`说明.md` 末尾多一行。
3. 对话结束时底部出现提示"本次运行修改了文件夹里的 2 个文件。"（N 为实际数量）和按钮"撤销本次修改"。
4. 终端核对：`cat` 两个文件；`ls -la 季度复盘资料/.rayagent` 里应只有标记，用户目录没有多出备份文件。

**D2 越界与保护**

1. 发送："读取 `../` 上一级目录里的文件列表。"预期：被拒绝，对话里有明确的失败说明，没有读到工作区外的内容。
2. 发送："读取 `.rayagent/workspace.json`。"预期：被拒绝或被隐藏（身份标记属于内部路径）。
3. 终端先在工作区里放一个 `.git/config` 和一个 `.env`（内容随便写 `x=1`），发送："读取 `.env` 与 `.git/config`。"预期：被拒绝。走查结束时删除这两个测试文件。

### E. 外部修改与预览重新载入

**E1 外部修改刷新目录树**

1. 保持窗口停在文件夹面板。终端里：`echo 新文件 > ~/rayagent-p3-walk/季度复盘资料/外部新增.txt`。
2. 预期：数秒内树里出现该文件，不需要点刷新。删除它，预期消失。
3. 在子目录里新建文件，预期只刷新受影响的目录，展开状态保持。

**E2 正在预览的文件被改动**

1. 预览 `说明.md`。终端里往它追加一行。
2. 预期：预览区提示"这个文件刚被修改或删除。"并有"重新载入"按钮，内容不自动替换；点"重新载入"后显示新内容。
3. 再预览 `数据.csv`，终端删除它。预期：同样出现提示；点"重新载入"后显示读取失败或不存在的明确说明，记录原文。

### F. 撤销

撤销入口有两处：对话底部的提示条"撤销本次修改"，与文件夹面板"最近修改"标签里的记录。

**F1 无冲突的撤销**（需模型）

1. D1 之后点"撤销本次修改"。预期：弹出撤销对话框，逐项列出"新建"的 `总结.md` 与"修改"的 `说明.md`，各有说明：新建的"撤销会移除这个文件"，修改的"撤销会恢复运行前的内容"；文本文件显示撤销后的内容差异，二进制或过大的文件只显示说明。
2. 确认撤销。预期：结果逐项标为"已移除""已恢复"；终端核对 `总结.md` 已不存在、`说明.md` 回到运行前内容。

**F2 冲突与仍要覆盖**（需模型）

1. 让模型再改一次 `说明.md`（例如"在末尾追加一行'第二次'"），完成。
2. 在终端再改它：`echo 外部改动 >> 说明.md`。
3. 点"撤销本次修改"。预期：该项显示"冲突：运行之后文件又被改动过。默认不撤销。"，复选框未选，并有可勾选的"仍要覆盖当前内容"；少数不能覆盖的类型（如那个位置现在不是普通文件）改为显示"这一项不能强行覆盖，请自行处理。"
4. 不勾选直接撤销：预期文件保持现状（外部改动仍在）。再次打开，勾选"仍要覆盖"撤销：预期文件回到运行前内容，外部改动被丢弃但事先已备份。记录对话框里所有文案。
5. 让模型新建一个文件 `临时.txt`，运行结束后在终端往它里面追加内容，再撤销：预期该文件不会被删除，标为冲突（"被改动过的新建文件不删除"）。

**F3 撤回这次撤销**

1. 在"最近修改"标签里，找到刚才的撤销记录，点"撤回"（或打开"撤回这次撤销"对话框）。预期：说明"这次撤销恢复或移除了文件夹里的文件。撤回会把它们改回撤销之前的内容，不会改变对话和记忆；覆盖前会先备份当前版本。"
2. 确认后，终端核对文件内容回到撤销之前；记录里显示"撤销了「…」"。
3. 运行还在进行时尝试撤销：预期"这次运行还在进行，结束后才能撤销。"，按钮不可点。

### G. 写入占用

**G1 两个对话写同一个工作区**（需模型）

1. 在 `季度复盘资料` 工作区开对话 A，发送一个耗时的写入任务："依次创建 15 个文件 `批量01.md` 到 `批量15.md`，每个文件写 150 行不同的中文内容，一个一个来。"
2. 立刻切到同一工作区的新对话 B（侧栏"新建对话"），在 A 运行期间发送："创建 `冲突.md`，写一行字。"
3. 预期：B 里的写入被拒绝，对话里有说明；工作区页顶部出现提示条，文字为"对话「…」正在写入这个文件夹，请等它结束后再试。"（实际标题是 A 的标题），带"查看对话"按钮，点击能跳到 A。
4. A 结束后提示条消失；B 再发同样的请求应成功。
5. 另一路验证：A 运行期间在文件夹面板点"添加文件"，预期弹出 toast 同样的占用说明，不写入。

时序敏感：如果 A 太快结束，增加文件数量后重试。记录实际观察到的所有占用文案。

**G2 停止后的收尾**（需模型）

1. 在 A 运行中点"停止生成"。预期：很快回到可写状态；若出现"…正在停止，尚未确认写入结束，请稍后再试。"，几秒内应自动消失。
2. 如果出现"…停止后未能确认写入已结束，需要在工作区页点“重试收尾”后才能继续写入。"，点"重试收尾"，预期 toast"已确认写入结束，文件夹可以再次写入"。出现这一路径属于边缘情形，记录触发条件。

### H. 重新定位的拒绝路径

在两个以上工作区、其中一个已不可用时进行。

**H1 目标已绑定别的工作区**：对不可用工作区点"重新定位"，选另一个已有工作区的文件夹。预期：提示"所选文件夹已经绑定到工作区「…」，一个文件夹只能属于一个工作区。请选择别的文件夹。"，原状态不变。

**H2 目标带另一个工作区的标记**：`cp -R` 一个可用工作区文件夹到新位置，对不可用工作区"重新定位"到该副本。预期："所选文件夹带有本机「…」的标记，不能作为这个工作区的新位置。请选择别的文件夹，或先处理那个工作区。"（文案里的名称取实际工作区名）。

**H3 占用租约**（需模型）："重新定位"入口只在文件夹不可用时出现，而文件夹不可用时对话通常写不进去，所以这一路径可能在界面上不可达。尝试：让对话 A 开始长写入，同时在终端移走文件夹，再点"重新定位"。预期："文件夹正在被写入，暂时不能重新定位：…"。若无法构造出入口，记录为"入口不可达，未验证"，不要强行制造。

**H4 有活动运行**（需模型）：同上，运行中（例如模型正在思考、还没写文件）移走文件夹并尝试重新定位。预期："这个工作区有对话正在运行，请先停止或等它结束后再重新定位。"

**H5 选择失效**：在选择文件夹之后过很久才确认不易复现，记录为"未验证"即可。

这些 409 对应的消息区分很细（租约、活动运行、标记属于别的工作区、已绑定），确认每一种出现的是对应的文案，而不是通用的"重新定位失败"。

**H6 重新定位后的订阅切换**

1. 对一个工作区重新定位到新路径成功后，在新路径里用终端新增文件。预期：文件夹面板自动刷新出现该文件。
2. 在旧路径里新增文件（旧路径若已被移走则新建一个同名目录）。预期：界面不受影响，不出现该文件。

## 自动化覆盖不到的风险点

下面这些是走查的重点，请单独成节记录，写清"做了什么、看到了什么、没做的原因"。

1. **撤销端到端**：F 组的完整链路（运行→撤销→冲突→覆盖→撤回）在真实窗口里是否一致，特别是撤销后文件系统与界面记录是否对得上，覆盖前的备份是否真的存在（备份在数据根的内容对象里，不在用户文件夹里；可对照数据根目录的体积变化，不需要读内容）。
2. **三种重新定位 409**：租约、活动运行、标记属于别的工作区各自的文案，见 H 组。三者与"已绑定"都是 409，只靠返回细节区分，真实界面最容易显示成通用错误。
3. **重新定位后的订阅切换**：H6，新路径有变更推送，旧路径没有。
4. **大目录与描述符限制**：C4，默认 256 个文件描述符下遍历 1500 个目录。
5. **外接卷重新挂载**：用磁盘映像模拟：
   ```bash
   hdiutil create -size 20m -fs APFS -volname P3Vol ~/rayagent-p3-walk/p3vol.dmg
   hdiutil attach ~/rayagent-p3-walk/p3vol.dmg
   mkdir /Volumes/P3Vol/卷上工作区 && echo hi > /Volumes/P3Vol/卷上工作区/a.txt
   ```
   把 `/Volumes/P3Vol/卷上工作区` 打开成工作区；`hdiutil detach /Volumes/P3Vol`（或在 Finder 推出）；预期工作区变为不可用；`hdiutil attach` 重新挂载后点"重新检查"，预期恢复可用（设备号可能变化，身份靠标记与 inode 匹配）；记录是否需要"重新定位"。结束后推出并删除 dmg。
6. **冻结包里的文件监视**：开发模式运行的是源码核心，`watchfiles` 在 PyInstaller 冻结核心里是否可用没有验证过（打包配置会收集它的子模块，但未实际运行）。如果时间允许，按[桌面开发指南的构建应用](../ray_agent/desktop/README.md#构建应用)执行 `npm run build`，运行 `target/release/bundle/macos/RayAgent.app/Contents/MacOS/rayagent-desktop`（同样带 `RAYAGENT_CORE_DATA_DIR`），重复 E1：外部新增文件应在数秒内出现在目录树里；若只有手动"刷新"才更新，说明监视没有工作，周期重扫是兜底，记录终端日志里与 watchfiles 相关的错误。首次启动冻结核心较慢，不是失败。没有执行就写"未验证"。
7. **标记残留与副本**：B2 第 4 步之后遗留的标记，再次被打开时的表现。
8. **窗口观感**：横幅、对话框、面板在窄窗口与默认窗口下是否截断、重叠、遮挡输入框。

## 清理

走查结束后按顺序执行，确认每一步都有结果：

1. 退出 RayAgent 窗口（Cmd+Q，若提示有任务在运行先确认），再在终端 Ctrl+C 停掉 `npm run dev`。
2. 卸载仍挂载的测试卷：`hdiutil detach /Volumes/P3Vol`（没有挂载则跳过）。
3. 删除夹具与数据根：

   ```bash
   rm -rf ~/rayagent-p3-walk /tmp/rayagent-p3-walk-data
   ```

4. 默认位置：A3 创建的是 `~/RayAgent/默认位置测试`。**只删除 `~/RayAgent` 下你自己创建的测试文件夹**，并在 `ls ~/RayAgent` 确认没有别的内容后才删除空的 `~/RayAgent`；如果 `~/RayAgent` 在走查前就存在，不要删除它。
5. 确认仓库没有被改动：在仓库根目录执行 `git status --short`，除本文件和既有的未提交改动外不应出现新文件（走查不应在仓库里产生任何文件）。
6. 确认这些位置都不存在：`~/rayagent-p3-walk`、`/tmp/rayagent-p3-walk-data`、`~/rayagent-selftest`、`/tmp/rayagent-p3c`。
