# 设计取舍记录

本文保留影响执行机制、资源归属与验证方式的选择。当前机制见[Harness 工程](harness.md)和[架构说明](architecture.md)，证据与局限见[能力与边界](capabilities.md)。

## 自研执行循环

项目的教学与实验目标包含 Harness 本身，因此选择自研循环，把上下文装配、工具分发、退出、失败和控制边界留在可追踪的实现中。成熟框架能减少编排工作，但会把部分研究对象封装成配置与默认策略。

代价是需要自行维护契约和验证：当前只有白名单独立读取的有界并发，没有持久执行检查点。协议接入或局部修复不构成框架迁移理由；原方案与调研依据见[演进背景](background/README.md)。

## 单循环加计划工具

使用一个循环、一份模型记忆，计划由 `update_plan` 记录，不由独立 Planner 驱动步骤。开放任务可以按工具反馈调整路线，减少两份上下文的交接和重复规划。代价是清单不是确定性调度器，勾选完成也不构成成果验收。旧双循环保留在 `baseline-v1`，其教学价值见[演进背景](background/README.md)。

## 原始事件、工作上下文与页面投影分开

数据库事件保存过程事实，模型记忆可以整形与压缩，页面消费面向展示的投影。事件先提交再通知，按序号恢复；临时文本增量不落库。这样可回看过程并重建模型请求，代价是要维护事件与投影契约，刷新会丢失未保存的半截文本，持久记录也不等于可恢复执行的检查点。

## 流式响应组装完整后再执行工具

为了让长响应期间有可见反馈，默认接收流式分片；文本增量送到页面，执行循环仍只消费组装完成的消息。工具参数可能分多片到达，未取得结束原因时视为响应未完成，不能执行半截调用或写入模型历史。推理内容保存到完整消息，不作为页面首字。

这一选择把低延迟展示与动作边界分开。代价是适配层必须处理分片身份、断流和重试；增量不持久化，刷新只能恢复完整记录。非流式路径仍可用，供应商没有 usage 时只能估算部分指标。

## 有限结束反馈与实际产物验证

无工具调用的回复在普通执行模式下经过有限检查：明确的交付需求、交付失败、已修改计划中的未完成项最多触发一次纠正反馈，仍有问题则写入最终说明。反馈使用可观察信号，不引入通用目标判定器。业务质量仍需检查产物；[销售表任务](plan/evidence/s01-sales-2026-10-08.md)用独立脚本核验文件内容，不能推广成所有任务都已可靠。

## 按需资源与有界读取并发

独立对话首次使用文件、Shell、浏览器、网页抓取或同步附件时准备沙箱，纯回答无需启动容器；MCP 所选服务和 A2A 卡片按需发现。整批为允许的独立读取时最多并发三项，其余串行。减少不必要的准备和串行等待，代价是首次使用仍有冷启动，发现状态和资源所有权需要在等待、停止与续接中保持一致，不能据此承诺所有任务更快。

项目运行保留占用、旧写入者收尾、附件发布、文件保护及同步等准备顺序，因为文件保护优先于推迟容器启动。

## 浏览器文本反馈与显式视觉

正文、交互元素和动作后观察共用本次调用结果，界面不另读文件或 Shell 补预览。普通动作不自动截图；显式截图区分分析与交付，支持视觉的模型才读取像素。避免重复读取及无目的图片存储，代价是需要明确的观察范围和截图意图。

元素引用绑定真实页面节点与标签页，导航或页面重建后需重新观察。动作成功而观察失败时只补观察，同批后续写动作停止，避免重复副作用。提取是有限 DOM 文本观察，不能代替完整可访问性树或任意页面目标验证。

## 单次工具执行与动作授权

工具管线负责校验、计划模式限制与 allow/ask/deny；副作用工具执行一次，不自动重试。模型传输错误、空回复和截断另行处理。减少不确定结果下重复写入的风险，代价是工具失败需要模型判断下一步，超时或响应丢失仍可能留下未知副作用。策略只按工具匹配，参数、路径和网络不因此成为安全围栏。

## 终态、进程与环境分别收尾

完成、失败、取消和中断使用不同状态。停止取消协程并尝试结束本次登记的 Shell 进程组；重启标记中断，不自动重放。独立对话复用沙箱，项目终态则停止环境、确认静止后释放占用。文件不回滚，远程取消不保证成功，进程内登记不能提供多实例执行所有权。

## 沙箱复用与项目终态收尾

独立对话按会话复用沙箱，首次需要资源时准备，便于继续处理同一批工作文件并减少重复启动。每个任务使用一次性环境会丢掉这种连续性，也增加冷启动开销。

项目采用平台文件副本，运行结束后停止环境并确认旧写入者静止，再释放占用；跨运行不保证浏览器和终端状态延续。独立对话仍依赖 TTL 或显式销毁回收，这些寿命不能由任务终态代替。沙箱也不提供多租户隔离。

## MCP 与 A2A 接入同一工具层

外部工具和远程 Agent 都通过本地工具契约参与任务，协议差异由适配层处理。这样保留一个执行链，不另建远程任务协调器。

代价是远程 Task 语义被收敛为工具结果：input_required/auth_required 不能接入本地等待续接，远程状态不逐条投影成本地进度，远程产物不自动成为本地附件。按需发现减少未使用服务的准备工作，但不能据此声称完整实现两种协议。

## 等待时退出并重建运行器

等待用户可能持续很久，因此保存等待状态并退出协程，收到答复后从持久记录重建。挂起协程虽然便于沿调用栈继续，却长期依赖进程内资源，重启会丢失这些状态。

代价是续接需要完整的调用配对和运行快照，局部变量不能承担恢复依据。提问答复作为原调用结果续接；审批只执行被批准的那次调用。API 重启保留提问等待，但中断审批并使调用失效；这与执行检查点恢复是不同机制。

## 托管项目文件与透明记忆

平台按项目 id 保存文件副本，通过上传、下载、运行前快照与整项目恢复保护材料；说明、版本化笔记与有来源的摘要在新运行冻结。默认使用不依赖 Git 身份、远端凭据或宿主机目录，文件与旧写入者由平台协调。

代价是用户需下载结果，快照仅保护文件，不能恢复完整历史和记忆；超限允许明确降级，Agent 写入没有硬配额。摘要是有来源的文本压缩，不是无损记忆或语义检索。项目只提供归档与恢复，没有删除入口。
