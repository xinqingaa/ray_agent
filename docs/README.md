# 文档地图

`docs/` 讲清当前 RayAgent Harness 的核心机制与实现事实，`lessons/` 详细展开推导和备选方案，源码是最终依据。当前说明不要求先阅读开发过程；历史按问题组织，专题计划保留优化设计与实施关系，明确授权范围和状态。

## 文档职责与更新条件

| 文档 | 主要内容 | 更新条件 |
|---|---|---|
| 产品说明 | 用户操作、可见结果与流程 | 用户行为或流程改变 |
| Harness 工程 | 核心职责、执行机制及工程代价 | 机制或职责改变 |
| 架构说明 | 模块边界、主要路径、状态及资源所有权、通信 | 系统结构发生变化 |
| 运行参数与限额 | 默认值、超时、容量和资源限额，以及对应源码 | 这些数字或其所在源码改变 |
| 代码地图 | 机制到源码及定向检查的映射 | 路径或主要入口改变 |
| 维护与优化计划 | 重要阶段结论与验证概况；专题目标、设计、责任、依赖、完成条件和实际状态 | 阶段、方案或授权范围改变 |
| 演进背景 | 按问题组织现象、观察、根因、备选方向、选择与重要转折 | 出现新的诊断或方案转折 |
| 服务与实验指南 | 配置、运行、开发与检查方法 | 所属服务或实验入口改变 |
| UI 设计说明 | 设计原则、状态表达和交互契约 | 交互契约或设计规则改变 |

同层详细说明只维护一处，其他位置按需链接；不同文档可从各自职责解释同一机制。主体保留理解当前设计所需的深度，不按长度删减机制、异常出口或交互状态。工作包编号、短暂协议和逐次样式修订不进入当前说明。

可调默认值、超时、容量和资源限额只写在运行参数说明。产品、Harness、架构和设计说明写行为和边界种类，需要数字时链接该页。界面尺寸以样式和组件为准。背景中的历史实验数字按当时条件阅读，不随默认值改写。

成组方案完成后，主体维护当前机制，背景保留问题分析及方案形成的因果链，专题计划保留有效设计、模块责任、实施依赖、完成条件与实际状态。完成方案可以按同一问题合并，不因已完成就删除；过渡协议、重复草案和逐轮日志可以从 Git 追溯，不能让 Git 替代正文应有的解释。历史验证种类只在维护入口简要概括，不保存独立验收记录、案例、日志、JSON 或产物；需要验证当前行为时重新建立条件。影响使用的边界随所属机制简要说明，历史结果不作为当前版本认证。课程准备稿只保留历史调整方向，正式同步依据最新源码与当前文档重新核对，课程实施另行授权。
