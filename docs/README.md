# 文档地图

`docs/` 概括项目的核心机制与当前事实，`lessons/` 展开推导与备选方案，源码是最终依据。当前文档以已实现能力为基线；旧计划和调研中的目标不自动成为产品承诺。

## 文档职责与更新条件

| 文档 | 唯一维护的内容 | 更新条件 |
|---|---|---|
| 产品说明 | 用户操作、可见结果与业务限制 | 用户行为或流程改变 |
| Harness 工程 | 职责分层、机制及工程代价 | 执行机制或职责划分改变 |
| 架构说明 | 模块边界、主要路径、状态与资源所有权、通信 | 这些结构发生变化 |
| 能力与边界 | 实现程度、证据类型、已知限制与未验证范围 | 能力或证据改变 |
| 设计取舍记录 | 结构性选择、理由与代价 | 新选择形成或旧选择被推翻 |
| 代码地图 | 机制到源码及定向检查入口的映射 | 路径或主要入口改变 |
| 阶段收尾与维护 | 阶段结论、关键验收索引、新工作的规划入口 | 阶段或实际计划范围改变 |
| 调研快照 | 带日期和代码基线的问题分析 | 新增独立调研；原快照不追加实施日志 |
| 演进背景 | 演进动因、关键转折、资料来源与证据修正 | 核实了新的重要历史事实 |
| 冻结参考 | 原工作包设计与逐章课程准备，保留版本和当时判断 | 不随产品维护更新；只修正链接或明确的事实错误 |
| 服务与实验指南 | 运行命令、配置、开发与检查方法 | 所属服务或实验入口改变 |
| UI 设计说明 | 设计原则、状态表达和组件契约 | 交互契约或设计规则改变 |

同层详细说明只维护一处，其他文档按需链接。样式、图标、间距和局部文案调整通常只修改实现；数值以样式与组件源码为准。用户行为、能力边界或结构发生变化时才更新对应文档，直接替换原说明，不追加日期补丁。历史验收保留原版本、条件和结果，不随界面微调改写。文档的深度由职责决定，不以长度判断是否冗余：设计依据、异常出口和交互状态值得保留；重复进度和逐次样式补丁退出当前说明。冻结参考不再承担现版本说明或待办管理。
