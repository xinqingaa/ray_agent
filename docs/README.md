| 文档 | 主要内容 | 更新条件 |

| 演进背景 | 按问题组织现象、观察、根因、备选方向、选择与重要转折 | 出现新的诊断或方案转折 |

同层详细机制只维护一处，其他页面保留理解本页所需的概括与链接。当前行为以主体说明和源码为准，专题方案解释设计关系，背景解释选择的形成。

### 内容组织

按信息之间的关系选择表达方式：

- 职责与独立规则通常用列表，动作顺序用编号；层级通过小节组织，不将多个维度塞进同一段。
- 原理、因果与取舍用短段落，先说明问题和机制，再解释必要细节。
- 只有读者需要按共同维度横向对照时才用表格，例如状态差异、参数、实现索引；不将一般说明拆成名词表。
- 表格单元格保持简短，不能为了对齐列名省略因果或重复填充同一结论。

先解释机制，字段和接口只保留必要部分；实现入口集中到代码地图，命令留在服务指南。模型指令、程序约束、实际观察和建议分别表述，避免将声明写成保证。

可调默认值、超时、容量与限额只在[参数页](limits.md)维护。界面尺寸以样式和组件为准，背景中的历史实验数字按当时条件阅读，不随默认值改写。

## 持续维护与审阅

### 按改动选择更新位置

- 局部样式、图标或短文案通常只改实现；默认值或限额更新参数页。
- 用户流程与边界更新产品说明，交互契约变化时核对 UI 设计说明。
- 决策、反馈与执行约束更新 Harness；模块职责、状态归属或通信变化更新架构，并核对调用方与前端投影。
- 入口、路径或检查位置变化更新代码地图，命令变化更新所属服务指南。
- 跨模块方案更新所属专题；背景只保留重要诊断与设计转折。

### 完成一项改动

1. 按影响选择所属说明，沿代码地图核对实现与检查入口；跨模块改动同时核对调用、事件、状态及资源归属。
2. 替换原有描述，将当前机制合入主体；详细规则保留一个归属，相关图和图注按实际机制核对。
3. 成组方案保留有效设计、责任、依赖、完成条件及状态，阶段结论与验证概况只在[维护入口](plan/README.md)简要更新。
4. 核对链接、术语、旧说法和验证口径。

不追加日期补丁、逐轮日志或独立验收资料。验证输出放临时目录，当前行为需要验证时重新建立条件，不将历史通过视为当前认证。

### 审阅标准

- **准确**：当前事实有实现依据，模型要求与程序保证分开。
- **易接手**：从问题能找到机制、实现和检查入口，无需翻历史拼接当前行为。
- **机制完整**：交代前置条件、状态变化、失败出口与恢复边界。
- **一致**：文、图、调用方及前端契约吻合，旧说法已替换。
- **易维护**：默认值和详细契约各有归属，局部修改不牵动无关说明。
- **验证明确**：区分静态核对与实际运行，未执行范围不记为通过。

这些标准用于审阅已有改动，不要求每次新增文档或全量重验。

### 制图约定

- **视觉基准**：沿用产品任务全景的浅色卡片与圆润线描图标。暖白背景，深蓝灰文字，淡黄标题笔刷和浅蓝副标题底纹；少量手绘线条只作强调，不添加水印、口号或与机制无关的装饰。
- **画布与字体**：默认 SVG、1600×900；沿用现有中文无衬线字体序列，优先 `PingFang SC`，回退到黑体类字体。标题约 46–48 px，节点标题约 26–32 px，说明约 21–25 px；空间不足时精简或重排，不靠缩小字体塞入段落。
- **卡片与分组**：主卡片约 24 px 圆角、3–4 px 描边，使用淡黄、淡蓝、淡绿或淡紫填充；虚线分组浅于主节点。图标用内联 SVG 线条与少量色块，表示对应对象，避免与文字重叠。
- **连线语义**：橙色表示调用与当前决策路径，蓝色表示反馈、事件读取或旁路，绿色表示数据访问与输入选取，紫色表示等待与续接，红色表示运行终止。每张图按实际用到的语义给出简短图例；调用图说明结果如何返回。连线接在节点边缘，绕开文字与其他节点。
- **内容边界**：图只写当前机制，保留理解主路径所需的分支与异常；节点优先使用短标题与一行说明，只有不同归属必须区分时才分行。恢复边界和收尾细节放在图注或正文，退出状态通过触发连线表达，与连线图例分开；配置数值在参数页维护。架构图概括组件与数据归属，循环图概括推进与退出，具体协议字段、收尾细节与状态寿命仍由正文说明。
- **维护与检查**：机制变化时同时核对对应图与图注，替换旧表达；数量由阅读问题决定。正式引用只使用 SVG，PNG 渲染预览放在临时目录。交付前检查 XML、标记、几何、连线与构图，并实际渲染、目视核对字体、溢出、遮挡和图文一致性。

通用的信息组织与检查流程见 [draw-tech-diagrams](../skills/draw-tech-diagrams/SKILL.md)，本节覆盖其默认视觉参数。
