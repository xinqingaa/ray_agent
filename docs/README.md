# 文档地图

`docs/` 是资料的**扫描层**：给结论，供人和 Agent 在几分钟内建立对项目的认识。推导过程在 `lessons/`，事实以源码为准。三层的定义与引用规则见[根工作指南](../AGENTS.md#资料分层与深度递进)。

## 按读者分流

**评估与认识**——想知道这个项目在做什么、做到了什么程度。读 [Harness 工程](harness.md)、[能力与边界](capabilities.md)、[设计取舍记录](decisions.md)。

**使用产品**——想知道界面上能做什么、怎么判断任务真的完成。读[产品说明](product.md)。

**修改代码**——想找到某个机制的实现位置和当前契约。读[代码地图](code-map.md)、[架构说明](architecture.md)。

**追溯依据**——想知道某条结论从哪来、当时的代码基线是什么。读[调研索引](research/README.md)。

## 各文档的唯一职责

| 文档 | 唯一维护的内容 | 什么时候更新 |
|---|---|---|
| [Harness 工程](harness.md) | 职责如何分层、每层解决什么问题、为此付出什么代价 | 职责划分或设计取舍发生变化 |
| [架构说明](architecture.md) | 模块边界、执行路径、状态归属、控制参数 | 模块职责、主要路径、状态所有权或跨服务通信方式变化 |
| [代码地图](code-map.md) | 机制到代码位置与回归测试的跨服务映射 | 路径或关键函数变动 |
| [产品说明](product.md) | 用户可见的交互、能力和使用建议 | 界面行为或用户可感知的能力变化 |
| [能力与边界](capabilities.md) | 每项能力的实现程度、证据类型与未验证范围 | 能力发生增减，或核对出新的不一致 |
| [设计取舍记录](decisions.md) | 影响面较大的选择及其代价 | 做出新的结构性选择，或推翻旧选择 |
| [调研索引](research/README.md) | 带日期和代码基线的研究快照 | 新增一次调研，快照本身不回溯修改 |

同一机制在 `docs/` 与 `lessons/` 各写一次是允许的，两者粒度不同；「只维护一处」约束的是同一层内部。
