# 文档地图

`docs/` 讲清当前 RayAgent Harness 的核心机制与实现事实，`lessons/` 详细展开推导和备选方案，源码是最终依据。当前说明不要求先阅读开发过程；历史按问题组织，专题计划保留优化设计与实施关系，明确授权范围和状态。

## 文档职责与更新条件

| 文档 | 主要内容 | 更新条件 |
|---|---|---|
| 产品说明 | 用户操作、可见结果与流程 | 用户行为或流程改变 |
| Harness 工程 | 核心职责、执行机制及工程代价 | 机制或职责改变 |
| 架构说明 | 模块边界、主要路径、状态及资源所有权、通信 | 系统结构发生变化 |
| 运行参数与限额 | 默认值、超时、容量和资源限额，以及对应源码 | 这些数字或其所在源码改变 |
| 代码地图 | 机制到源码及定向检查的映射 | 路径或主要入口改变 |
| 维护与优化计划 | 重要阶段结论与验证概况；专题目标、设计、责任、依赖、完成条件和实际状态 | 阶段、方案或授权范围改变 |
| 演进背景 | 按问题组织现象、观察、根因、备选方向、选择与重要转折 | 出现新的诊断或方案转折 |
| 服务与实验指南 | 配置、运行、开发与检查方法 | 所属服务或实验入口改变 |
| UI 设计说明 | 设计原则、状态表达和交互契约 | 交互契约或设计规则改变 |

同层详细说明只维护一处，其他位置按需链接；不同文档可从各自职责解释同一机制。主体保留理解当前设计所需的深度，不按长度删减机制、异常出口或交互状态。工作包编号、短暂协议和逐次样式修订不进入当前说明。

可调默认值、超时、容量和资源限额只写在运行参数说明。产品、Harness、架构和设计说明写行为和边界种类，需要数字时链接该页。界面尺寸以样式和组件为准。背景中的历史实验数字按当时条件阅读，不随默认值改写。

## 持续维护与审阅

每次维护、扩展或优化，先按上表判断改动影响的行为与文档归属，再沿代码地图核对实际实现。局部样式和短文案通常只改实现；参数变动更新参数页；用户流程、执行机制或模块边界改变，分别替换对应说明。跨模块改动核对调用方、事件、状态及前端契约，相关描述随同一项改动更新。

同一事实按职责解释，详细契约只维护一处，其他位置链接。函数改名或入口移动时更新代码地图的主入口、关联实现与检查位置；示例命令改变时更新所属服务指南。读者应能从问题找到说明，再到实现与验证入口，不需要翻阅历史方案拼接当前行为。

成组方案完成后，现行机制合入主体，专题保留有效设计、责任、依赖、完成条件及实际状态；背景只接收新的重要诊断或设计转折。阶段结论和验证概况在维护入口简要更新，不追加日期补丁、逐轮日志或独立验收资料。课程与配图同步另行确定范围。

审阅一项改动时，同时检查：

- **准确性**：说明对应真实实现，分清模型指令、程序约束与观察结论；未实现方案不写成当前事实。
- **接手效率**：入口能直接回答当前问题，代码地图区分主路径与关联实现，命令在正确服务环境执行。
- **一致性**：变更后的调用、状态和资源归属相互吻合，链接与方法名有效，旧说法已替换。
- **维护成本**：默认值仅在参数页，同层详细说明仅有一个归属；局部修改无需无关地扩写架构或历史方案。
- **验证口径**：说明本次实际检查的条件和结果，静态核对与运行验证分开；没有运行的范围不记为通过。

这些标准用于判断本次改动是否保持文档质量，不要求每次增加文档或全量重验。验证输出放在临时目录，当前行为需要验证时重新建立条件。
