# 模型目录与端点配置优化方案

状态：模型接入、Responses 通信、错误分类和最近模型偏好已实施；真实上游多轮工具与部署验证有限。用户界面只选择模型与思考，不展示渠道或运行配置对照。本方案已收尾。

用户只需要选择 DeepSeek 或 GPT 相关模型。上游地址和 API Key 属于部署配置，不进入普通用户的模型选择流程。方案优先修复现有接入问题并消除重复配置，不建设新的连接管理产品。

问题演进见 [交互与配置背景](../background/interaction-and-configuration.md#模型接入从猜域名转向明确目录)。它同时承接先前逐模型参数与切换方案；既有切换观察与后续接入检查使用不同条件，不能合成当前上游全面通过。

## 修改范围

保留现有会话模型 ID、思考选择、逐模型采样配置、单循环和工具流程。后端增加必要的内部模型到端点映射，前端只消费模型目录；不把部署端点变成会话选择项，不为此增加绑定 ID、数据库字段或连接管理 CRUD API。

前端只展示模型与模型支持的思考选项。沿用现有 DeepSeek／OpenAI 标签和关闭保存方式，切换厂商默认选中该组第一个模型。已有课程改动不由本轮撤销、扩写或同步。

## 后端接入保持简单

区分模型厂商与实际请求端点，但只在内部使用：

| 信息 | 维护位置 | 用途 |
|---|---|---|
| 模型 ID、厂商、视觉与思考能力、请求规则 | 后端模型目录 | 生成用户模型列表并正确编码请求 |
| 端点的 URL 与 Key | API 环境配置 | 实际访问上游 |
| 模型使用哪个端点 | 非敏感应用配置 | 让换上游和增加兼容上游主要修改配置 |

复用现有端点结构，将固定读取某一家上游的逻辑改为读取配置声明的端点。端点配置只记录 URL 和 Key 对应的环境变量名称，真实值仍来自所属 API 的进程环境或 `.env`，统一由端点加载器使用 Pydantic Settings 读取，不再通过全局 Settings 重复注入 DeepSeek；仅缓存配置类结构，不缓存凭据。非法 URL 只使所属端点不可用，显式清空 Key 不恢复旧值。

当前 DeepSeek 和 GPT 分别指定一个实际端点。一个模型在用户目录里只出现一次，不展示端点名称，不提供渠道下拉框。同一个模型有多家候选上游时，由维护者修改内部映射决定使用哪一家；第一版不做自动回退或多渠道调度。

示意配置只表达内部引用，不是新前端表单：

```yaml
llm_endpoints:
  deepseek:
    url_env: DEEPSEEK_URL
    key_env: DEEPSEEK_API_KEY
  gpt:
    url_env: XIAOYI_URL
    key_env: XIAOYI_API_KEY
model_endpoints:
  deepseek-flash: deepseek
  deepseek-v4-pro: deepseek
  gpt-6.1-sol: gpt
  gpt-6-luna: gpt
  gpt-6-astra: gpt
```

配置中保留现有环境变量名称用于部署兼容，不把这些名称发送到模型选择器。已有全局采样配置和 `model_profiles` 继续保留，不改为按渠道保存。

更换 Key 时修改原环境变量值；更换上游时修改 URL 和 Key，必要时调整内部映射。重新加载 API 环境后使用新值。新增兼容端点时增加配置项及环境变量，已有模型可以映射到新端点；新增模型仍需核验并补充能力目录，新增协议仍需适配代码。

## 修复已经确认的问题

- 默认模型按明确模型 ID 确定，不再通过 URL 的官方域名识别；代理地址不影响模型能力和默认选择。
- GPT 思考强度按真实快照字段恢复，区分未发送和显式 `none`，不根据 DeepSeek 的思考开关猜测。
- 端点缺失或缺少 Key 时报告模型不可用，不将 GPT 请求发往全局 DeepSeek 地址。
- 默认端点不可用不应阻止其他已配置模型、目录读取或容量预览；实际请求前再检查目标端点。
- 前端厂商和模型列表由后端提供，不另写固定模型白名单；实际端点信息不进入用户选择数据。
- 标题和摘要沿用现有辅助模型机制，明确其内部端点；不新增用户辅助模型管理页，辅助失败不连带阻塞主任务。

运行快照与续接修复作为内部正确性工作，不据此增加“本次运行／下次运行”界面。当前任务期间模型切换的具体行为沿现有契约单独核对，不在本方案中擅自增加限制、排队切换或新的用户操作步骤。

## 模型选择交互

模型入口只回答“我要用哪个模型”，菜单只包含 DeepSeek、GPT 模型和相关思考选项。模型行、菜单标题与触发器不出现小易、渠道、连接名称或上游地址。

按用户明确指定的交互，切换厂商标签默认选中该组第一个模型；重复点击当前标签保留当前选择。模型行不显示“支持看图”文字。

保留现有 DeepSeek／OpenAI 标签，不重做整个菜单。思考控件跟随选中模型，跨系列使用目标支持的默认值。

保留菜单内编辑、关闭时保存的既有方式，不增加取消和应用步骤。只有模型或思考实际改变才提交；切换厂商、模型和思考均只修改菜单草稿，关闭时一次保存，失败保持菜单和原因，不丢输入草稿。模型行支持方向键与 Home／End。

思考开关与档位由模型目录决定，继续使用已有组件。同系列支持当前档位时保留，跨系列使用目标支持的默认值；不新增渠道提示或运行配置对照区。

设置页保留已有逐模型参数编辑，本方案不增加连接、绑定、默认设置等新页签，不搬迁 URL 或 Key 的管理方式。普通错误信息只说明模型调用失败与必要的重试动作，部署信息由维护者在日志和配置中排查。

## 实施顺序与验证

用户已授权实施，按以下顺序完成：

1. 统一端点配置读取与内部模型映射，保留现有环境变量和会话结构。
2. 修复代理地址识别、GPT effort 续接、缺失配置和错误路由回退。
3. 模型目录向前端提供厂商信息，移除前端重复白名单。
4. 沿现有菜单修复标签浏览与模型选择的混用，移除运行配置展示。

验收覆盖更换同一端点的 URL／Key、新增第三个兼容端点、GPT 思考字段续接、缺 Key 时其他模型仍可用、端点移除时明确失败。前端核对厂商切换默认选中首个模型、选择失败恢复、模型与思考一致、输入草稿保留、键盘和窄屏。

自动检查与真实上游验证分开记录；代码参数声明不等于实际服务支持。配置方法维护在服务指南，课程同步另行授权。


## 实际状态

模型目录、内部端点映射、逐模型参数和菜单交互已实施并有定向检查；这些检查不证明实际 GPT 上游的参数、工具或视觉支持。当前配置方法维护在运行指南，交互契约维护在产品与 UI 说明。

## 逐模型参数与运行快照的承接

此前模型设置已改为逐模型保存温度、生成上限和上下文窗口，保存先完成整体合法性检查再提交，不能一部分成功一部分失败。切换模型时下一次新运行读取目标配置并重新估算容量，正在执行和等待的运行沿自身快照；同模型后续运行继续采用会话的参数契约。

思考开关、档位与请求参数由目录能力定义，不能假设同名档位跨系列等价。菜单保留目标支持的选择或退回目标默认值，设置与菜单不能各维护一份厂商规则。生成、缓存和推理用量继续按真实上游 usage 记录，容量估算不替代账单。

实施依赖是先统一配置和模型目录，再修正适配与续接，最后接入前端选择。完成条件包括逐模型原子保存、切换后容量重估、waiting 快照保持、GPT effort 精确恢复、目标端点缺失明确失败以及可用模型隔离。既有真实 Flash→Pro→Flash 观察支持当时切换行为，不证明新 GPT 上游的工具和视觉能力。

自动渠道回退、运行中强制切换、连接管理 CRUD、通用参数兼容转换和费用硬预算未进入范围，不从候选设计恢复为新待办。部署配置和操作方法只维护在 [应用运行指南](../../ray_agent/README.md)与 [API 指南](../../ray_agent/api/README.md)。


## Responses 通信与最近选择

授权范围：GPT 与 DeepSeek 同次更新使用 Responses，保留显式 Chat Completions 兼容配置；不引入服务端会话、托管工具或新的执行循环。模型通信仍通过基础设施适配，工具、审批、压缩和运行状态由 RayAgent 管理。

端点配置明确协议，新默认使用 Responses。适配负责 messages/input 与工具 schema 转换、完整终态组装、用量归一和厂商参数差异。推理条目随对应助手消息持久化，同模型回传；换模型不能将其他模型的加密推理转发。原 Chat 历史转换为输入条目，历史事件不改写；快照保存通信协议，等待续接按快照恢复。

流式 response.failed/error 与 SDK 异常统一分类，只有连接、限流、服务错误和明确暂时中断可有限重试。参数、鉴权、额度与未知 bad_response 不重试；部分文本和工具参数不作为成功结果执行。日志保留协议、错误码、状态和请求标识，不打印密钥或完整请求。

最近模型与思考强度成对存入同源 localStorage，新对话及项目新对话采用有效本地选择；已有会话保留服务端选择，仅浏览历史不改最近偏好。菜单确认成功或发送成功后更新，恢复值需进入实际请求。本地记录读完前不把目录默认值当作当前选择，目录不再支持时回退有效默认，存储不可用时仍可操作。

完成条件：两家请求编码、语义流终态、推理回传、历史转换、压缩/等待与错误分类的定向检查；前端实际选择、刷新、新对话及单行计划的组件和浏览器检查；当前上游的真实多轮工具任务与本地构建身份核对。真实上游未通过时不能记为全面迁移完成。课程更新不在范围内。
