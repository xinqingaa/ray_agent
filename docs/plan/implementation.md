## 备份与正式更新（留给 P10）

首个交付已落实：schema 升级前用 SQLite 备份接口写入数据根 `upgrades/`，旧二进制拒绝打开更新的 schema，内部包手动覆盖安装。P10 需要：

- 业务静止后的完整备份（业务库＋引用的内容对象清单与回收引用），工作区文件夹默认不打包进备份。
- 恢复到独立位置：核对 schema、内容哈希与引用，支持重新绑定文件夹，成功前不覆盖当前数据。
- 签名更新：核对空间、兼容范围与活动任务 → 停止旧核心 → 备份 → 升级；失败可切回旧二进制，若 schema 已新则必须配套恢复升级前数据。

## 交付检查口径（首个交付）

每个工作包交付实现、调用方、涉及的界面与行为检查，不能以组件存在、测试数量或编译成功替代产品闭环。首个交付至少满足：

- 不依赖开发机 Python／Node 或原服务栈，内部包在无开发环境的 Mac 上启动，配置模型并完成独立对话、工作区读写与脚本／浏览器短任务。
- 真实模型新会话可接续同工作区的工作方式、记忆与材料；其他工作区与独立对话不串用，Skill 来源及快照在等待续接后仍一致。
- 新材料、扫描件、修改删除与语义召回结果正确，用户可控制索引并定位采用的来源版本；过期或撤回内容不冒充当前原文。
- 请求读回、审批、停止、核心重启与解析／索引中断有明确结果，未知副作用不自动重放，不发布半份结果，不留下失控写入者或浏览器进程。
- 文件夹移动、复制、失联、外部编辑、并发写入与撤销按既定边界处理；覆盖安装保留工作区、记忆与会话，旧二进制拒绝打开新 schema。
- HTML 预览、流式重连、草稿、附件与成果交付在真实宿主可用；各服务检查入口、代码地图与正文描述一致。

具体失败条件按[收尾清单](first-delivery-remaining.md)定向重建，检查方法沿用[API](../../ray_agent/api/README.md#测试与数据库迁移)、[UI](../../ray_agent/ui/README.md#检查与构建)、[桌面](../../ray_agent/desktop/README.md#检查)和[运行指南](../../ray_agent/README.md#运行检查)。交付说明区分静态核对、替身检查与真实整包运行，未完成项不记通过。后续平台重复并补充平台边界；P10 另检签名公证、更新回退、离线组件与备份恢复。

## 风险出口（后续仍相关）

- 内部包未经 Developer ID：仅内部使用；公开分发在 P10 签名公证。
- 模型密钥明文在本机配置文件：单人内部使用靠文件权限；对外分发前评估系统凭据存储。
- 原生依赖与散装组件首次加载耗时：宿主显示启动中；组件可启动检查须容忍。
