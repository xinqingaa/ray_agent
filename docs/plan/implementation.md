# 实施工作包与交付条件

本页按已确认范围定义实施顺序，不是进度台账。所有工作包均未实施；本轮只维护计划。技术方案见[总览](README.md#技术基线)，已确认的产品范围见[决策清单](decisions.md)。

## 开工条件与实施规则

D1—D9 已确认，产品改动仍待实施授权。实施时先用宿主探针暴露打包风险，再冻结共享身份、权限、存储及协议契约，然后按里程碑交付可运行的产品链路；不额外建立工作区／RAG 概念样本或未经授权的 demo。

每个工作包交付实现、对应调用方、界面和行为检查。能力在所属工作包内接入上下文装配与工具，不集中到最后汇合；达到本包完成条件再进入依赖它的工作。不得以原有测试数量、开发服务器可启动或 UI 编译成功替代目标行为完成。

现有源码位置统一沿[代码地图](../code-map.md)定位。新的目录安排维护在[客户端专题](clients-and-distribution.md#工程布局)，具体机制与命令随落地分别合入正文和服务指南。

“Mac 工作区”是产品形态成立的最小版本：没有文档索引时，Agent 仍可用文件工具浏览和读取文件夹。后续里程碑扩大材料规模与平台范围，不改变工作区对象模型。Mac 先完成前两个里程碑，Windows 在 P9 补齐，同属首批桌面交付门槛；移动端不阻塞首批桌面交付。

## Web 与原服务部署移除

P2 将现有 UI 改为只供 Tauri 桌面／移动打包的共享界面，移除 Next 服务启动、独立网站发布目标、浏览器应用入口和对应认证会话引导；保留 Vite 本地开发调试。客户端与核心间的 HTTP／SSE、API 类型生成、外部网页及成果预览继续使用。移除放在 P2 的最后，桌面骨架可用之前不先拆掉现有入口。

P10 清理原 UI／API／Nginx Compose 编排、服务部署专用镜像与流水线、反向代理配置及只服务旧部署的环境配置。沙箱组件是否保留只取决于执行端口，不因名字含 Docker 而整目录删除。旧部署相关的专用检查替换为桌面安装与通信检查，服务指南、根入口和代码地图同步改为桌面使用与开发说明。

按 D3 不提供旧数据迁移，也不建设导出工具。删除仓库中的部署文件不销毁现存数据库、Docker 卷、模型配置或用户目录；需要旧数据的用户继续使用旧版本。交付检查确认安装包和发布流程无独立 Web 产物，核心不向本机浏览器托管应用，正式运行无需 Next／Nginx／Compose；共享界面、自动化浏览器与 HTML 预览仍工作。实际实现改变前，现有正文和服务指南继续描述真实代码，待相应工作包落地再替换说明。

## 备份与应用升级

业务静止后使用 SQLite 备份接口生成一致副本，并保存该副本所引用的不可变对象清单；备份操作固定这些对象的回收引用，再恢复新写入并按清单复制字节，完成或取消后释放备份引用。工作区文件夹是用户数据，备份默认只记录绑定与应用保存的内容对象，不声称打包了整个文件夹。检索索引可重建，不作为恢复必需字节。

恢复到独立位置先核对 schema、内容哈希与引用，支持重新绑定工作区文件夹，不静默改写不同机器上的任意路径。恢复成功前不覆盖当前数据；既有目录作为保留副本，后续清理需明确操作。

应用更新先核对空间、兼容范围和当前任务，阻止新受理后等待或让用户结束活动运行，停止所有旧核心与写入者，再备份并升级 schema。新版失败可切回旧二进制，但数据库超出旧版可读范围时必须配套恢复升级前数据，禁止旧版直接打开新 schema。

## 交付检查

| 真实行为 | 必须观察到的结果 | 检查层次 |
|---|---|---|
| 干净系统安装启动 | 不靠开发机 Python、Node、PostgreSQL、Redis 或 Docker 启动常规业务 | 各首批平台安装包 |
| 接收消息后断连／重启 | 同请求可读回，输入不会丢失或重复成为业务执行 | SQLite 集成、打包核心 |
| 跨会话与跨工作区 | 新会话读到同一工作区的工作方式与记忆；其他工作区、独立对话和不参与记忆的会话不串用 | 服务与 UI 集成 |
| 双会话并发与文件写入 | 只读与记忆可并行；文件写入按租约协调，冲突可恢复 | 核心与真实文件系统 |
| 审批等待、停止与核心崩溃 | 具体动作和权限重查，未知动作不自动重放，进程资源有核对结果 | 领域回归、平台进程 |
| 文件夹移动、复制、失联与外部编辑 | 标记认回或要求用户选择，工具不越界读写，旧版本不覆盖新文件，撤销不删用户文件 | 各平台文件系统 |
| 记忆纠正与提炼 | 人工结论不被静默覆盖，撤回项不再召回或重复生成，迟到提炼不覆盖编辑 | 服务与 UI 集成 |
| 新材料、扫描件、修改删除 | 解析与索引状态明确，来源定位正确，旧索引不作为当前原文 | 解析进程、知识集成 |
| Skill 重名、更新与等待续接 | 绑定来源与版本一致，资源不切换到当前目录的另一版本 | 包与运行集成 |
| HTML、文件、流式与草稿 | 预览不获原生权限；重连不丢持久事件；关闭行为保护草稿 | 真实客户端 |
| 备份、恢复及升级失败 | 恢复不删工作区文件夹，不混用新旧 schema，失败保留当前数据 | 完整数据链路 |
| 独立 Web 与原部署退出 | 无网站发布／浏览器应用入口和原服务部署依赖 | 构建配置、安装包与指南 |
| 手机配对与撤销 | 设备范围有效，桌面离线可理解，重复发送与审批幂等 | Android、iOS 真机与网络 |

沿现有指南复用相关领域与协议测试，将 PostgreSQL 相关检查中需保留的语义迁到 SQLite 集成检查；增加真正覆盖新失败窗口的测试，不机械复制每个实现字段。性能在固定机器和固定输入条件下记录首个响应、索引积压、峰值资源、取消收尾及 UI 连续性，再按实际结果确定参数页默认值；未测数值不写成保证。

## 风险与处理出口

- 原生依赖无法冻结、打包或签名：由 M0 先暴露，P2、P4、P7 在真实产物中复查；调整依赖或资源布局，不把用户手工安装开发环境作为默认修复。
- Tauri 特定目标的键盘／预览缺陷：先修平台适配；若影响核心流程且无可维护修复，回到 D1、D2 调整交付目标，不静默改用另一套 UI。
- SQLite 写入竞争：缩短事务、消除事务内 IO 和重复写入，保留 CAS 与唯一约束；不能通过无限等待掩盖锁问题。
- 本地模型或解析超出资源：暂停后台队列、明确组件与任务状态，允许缩小索引范围；保持对话和已完成材料可读。
- 自动记忆误记或重复：用户撤销与来源抑制兜底，可关闭自动提炼或更新提炼策略版本；不放宽对用户条目的保护。
- 用户文件在任务中变化：版本冲突与静止核对优先，保留失败结果，不自动进行全目录恢复。
- 外部 Skill 依赖与工具不兼容：报告具体来源与缺失能力，允许使用可用部分；不自动执行包内安装或 hook 来补齐。
