# 实施工作包与交付条件

本页按已确认范围定义实施顺序，不是进度台账。用户已授权按计划实施首个交付，各工作包的当前状态集中在[实施状态](#实施状态)。技术方案见[总览](README.md#技术基线)，已确认的产品范围见[决策清单](decisions.md)。

## 开工条件与实施规则

D1—D9 已确认，首个交付已获实施授权。实施时先用宿主探针暴露打包风险，再冻结共享身份、权限、存储及协议契约，然后按里程碑交付可运行的产品链路；不额外建立工作区／RAG 概念样本或未经授权的 demo。

首个交付只覆盖 macOS Apple Silicon：所有工作包在 Mac 上实现与检查，形成完整闭环后才进入后续阶段。共享端口与契约不写死 macOS 语义，为 Windows 与移动端保留位置，但不提前实现或检查。

每个工作包交付实现、对应调用方、界面和行为检查。能力在所属工作包内接入上下文装配与工具，不集中到最后汇合；达到本包完成条件再进入依赖它的工作。不得以原有测试数量、开发服务器可启动或 UI 编译成功替代目标行为完成。

现有源码位置统一沿[代码地图](../code-map.md)定位。新的目录安排维护在[客户端专题](clients-and-distribution.md#工程布局)，具体机制与命令随落地分别合入正文和服务指南：每个工作包落地时同步更新它改变的服务指南、代码地图、参数页与相关正文，使文档始终描述真实代码；首个交付结束时的最终合并见[完成后的文档归属](#完成后的文档归属)。

实施开始前已为 Web 版本建立 Git 标签 `web-final`；D3 所说需要旧数据时继续使用的旧版本即该标签。

### 宿主探针结论

M0 用现有依赖集验证了冻结、拉起、握手与退出，探针工程与运行方式见[桌面开发指南](../../ray_agent/desktop/README.md)。下列结论由对应工作包接手：

- **P2 桌面骨架**
  - 启动协议沿用探针：宿主经 stdin 写一行 JSON 启动参数并保持管道打开，核心在回环随机端口就绪后经 stdout 写一行握手，日志走 stderr；stdin 关闭即核心停止，宿主被强制结束时核心据此自退。启动参数与握手已是契约类型，握手带协议与事件版本、实例与构建身份、存储版本和能力声明，宿主按类型解析；P2 在此基础上填入令牌并核对协议／schema；模型密钥改由钥匙串按引用提供，不再经环境文件进入核心进程环境。
  - 现有核心依赖工作目录：`alembic.ini` 按当前目录读取，配置、附件与 skill 默认写相对路径。探针入口以资源目录为工作目录，并把写入路径改到数据目录；P1／P2 改为显式区分只读资源目录与数据根，去掉对工作目录的依赖。
  - 预览解析以 `sys.executable -m` 启动 worker，冻结后由入口按白名单分派；P2 改为明确的 worker 子命令。入口最早调用 `multiprocessing.freeze_support()`，但现有核心不使用 multiprocessing，这条路径尚未实际触发。没有 `__init__.py` 的命名空间包会被 `collect_submodules` 漏掉，冻结清单按文件枚举模块，新增子进程入口同步登记。冻结核心的构建身份沿用 API 容器的指纹输入，不含入口与冻结清单，P2／P9 的构建身份需覆盖它们。
  - macOS 在首次加载新出现的散装原生库时逐个检查：开发机上新冻结或新复制的 onedir 首次启动到握手约 15–40 秒（随系统负载变化），再次启动约 1–2 秒；ad-hoc 签名的 .app 整包复制到新位置后首启仍约 1–2 秒。宿主不按热启动设定握手期限，界面显示启动中；P9 在未装开发环境的 Mac 上复测带隔离属性的首次打开。
  - Tauri 复制资源时会把 onedir 中指向 `.dylibs` 的符号链接展开成重复文件，功能不受影响；P1 删除 PostgreSQL 等依赖后复核产物体积。.app 内的 onedir 随整包 ad-hoc 签名，能通过 `codesign --verify --deep --strict`。
  - 宿主在正常退出事件中关闭 stdin，等待后发送 SIGTERM，最后对自建进程组发送 SIGKILL，且在回收首进程之前完成，避免组号被复用。宿主被信号直接终止时不经过退出事件，只能依赖核心的自退期限；P2 处理终止信号，并把退出接入“停止受理、结束任务再退出”的流程。现有生命周期关闭时等待 Agent 服务的期限长于探针宿主的退出等待，活动运行收尾较慢时核心会被强制结束。
- **P4 本机执行与浏览器**
  - MCP stdio 服务以新会话启动，不在核心进程组内；核心被强制结束时宿主的进程组回收覆盖不到，执行 supervisor 需要登记并回收这类进程树。
  - MCP 子进程继承核心的完整环境，包括模型密钥，受控继承在本包落实。macOS 上冻结引导程序不设置 `DYLD_*`，但会向子进程传递 `_PYI_*` 标记；外部运行时启动前一并移除，启动另一个冻结程序时尤其需要。
  - Playwright 驱动自带的 Node 可执行文件占 onedir 一半以上，可从包内正常执行；浏览器组件化时决定驱动是否改用基础包的 Node 运行时，避免分发两份 Node。
- **P7 语义检索与 OCR**：LanceDB、ONNX Runtime 与 OCR 的原生库尚未冻结验证。引入时按探针方式复查隐式导入、数据文件、资源中的符号链接与首次加载耗时；按需下载的组件位于签名包之外，会遇到散装原生库的首次加载检查，组件可启动检查需容忍这段时间。

P1 之后核心不再支持原部署方式。P2 将现有 UI 改为只供 Tauri 打包的共享界面，保留 Vite 本地开发调试；客户端与核心间的 HTTP／SSE、API 类型生成、外部网页及成果预览继续使用。Next 服务与部署编排的移除放在 P2 的最后，桌面骨架可用之前不先拆掉现有入口；原部署专用检查同时替换为桌面构建与通信检查。

按 D3 不提供旧数据迁移，也不建设导出工具。删除仓库中的部署文件不销毁现存数据库、Docker 卷、模型配置或用户目录；需要旧数据的用户继续使用开工前标记的旧版本。交付检查确认构建产物不含独立 Web 产物，核心不向本机浏览器托管应用，正式运行无需 Next、Nginx、Compose 或 Docker；共享界面、自动化浏览器与 HTML 预览仍工作。

## 备份与应用升级

**首个交付的内部包升级**：schema 自 P1 起带版本与升级脚本。安装新内部包前先结束活动运行，停止旧核心与写入者；新核心启动时用 SQLite 备份接口生成升级前副本，再执行升级并完成重启扫描后才受理。旧二进制不能打开超出其可读范围的新 schema，需要回退时配套恢复升级前副本。首个交付不提供自动更新与恢复界面，内部包由用户手动覆盖安装。

**P10 的正式更新与备份恢复**：业务静止后使用 SQLite 备份接口生成一致副本，并保存该副本所引用的不可变对象清单；备份操作固定这些对象的回收引用，再恢复新写入并按清单复制字节，完成或取消后释放备份引用。工作区文件夹是用户数据，备份默认只记录绑定与应用保存的内容对象，不声称打包了整个文件夹。检索索引可重建，不作为恢复必需字节。

恢复到独立位置先核对 schema、内容哈希与引用，支持重新绑定工作区文件夹，不静默改写不同机器上的任意路径。恢复成功前不覆盖当前数据；既有目录作为保留副本，后续清理需明确操作。

签名更新先核对空间、兼容范围和当前任务，阻止新受理后等待或让用户结束活动运行，停止所有旧核心与写入者，再备份并升级 schema。新版失败可切回旧二进制，但数据库超出旧版可读范围时必须配套恢复升级前数据，禁止旧版直接打开新 schema。

## 交付检查

首个交付的检查全部在 macOS Apple Silicon 内部包上执行：

| 真实行为 | 必须观察到的结果 | 检查层次 |
|---|---|---|
| 未装开发环境的 Mac 安装内部包 | 手动允许打开后，不靠开发机 Python、Node、PostgreSQL、Redis 或 Docker 启动常规业务 | Mac 内部包 |
| 首次配置模型连接 | 密钥只存入钥匙串，界面只显示掩码与可用状态；覆盖安装新内部包后仍可使用或给出重新授权提示 | Mac 内部包 |
| 接收消息后断连／重启 | 同请求可读回，输入不会丢失或重复成为业务执行 | SQLite 集成、打包核心 |
| 跨会话与跨工作区 | 新会话读到同一工作区的工作方式与记忆；其他工作区、独立对话和不参与记忆的会话不串用 | 服务与 UI 集成 |
| 双会话并发与文件写入 | 只读与记忆可并行；文件写入按租约协调，冲突可恢复 | 核心与真实文件系统 |
| 审批等待、停止与核心崩溃 | 具体动作和权限重查，未知动作不自动重放，进程资源有核对结果 | 领域回归、macOS 进程 |
| 文件夹移动、复制、失联与外部编辑 | 标记认回或要求用户选择，工具不越界读写，旧版本不覆盖新文件，撤销不删用户文件 | macOS 文件系统 |
| 独立对话的附件、成果与执行 | 附件可读，成果作为附件交付，不写入任何用户文件夹；未启用本机执行时没有 Shell；删除会话回收会话工作目录 | 服务与 UI 集成、macOS 文件系统 |
| 记忆纠正与提炼 | 人工结论不被静默覆盖，撤回项不再召回或重复生成，迟到提炼不覆盖编辑 | 服务与 UI 集成 |
| 新材料、扫描件、修改删除 | 解析与索引状态明确，来源定位正确，旧索引不作为当前原文 | 解析进程、知识集成 |
| Skill 重名、更新与等待续接 | 绑定来源与版本一致，资源不切换到当前目录的另一版本 | 包与运行集成 |
| HTML、文件、流式与草稿 | 预览不获原生权限；重连不丢持久事件；关闭行为保护草稿 | 真实客户端 |
| 内部包升级 | 工作区、记忆与会话保留；旧二进制拒绝打开新 schema | Mac 内部包 |
| 独立 Web 与原部署退出 | 构建产物不含 Next 服务与部署编排，核心不向浏览器托管应用，运行不依赖原服务栈 | 构建配置、内部包与指南 |

后续阶段在各自工作包内补充检查：P10 检查签名公证包直接打开、签名更新与回退、离线组件包和备份恢复；P11 在 Windows 上重复上表并增加 Windows 文件与进程边界；P12 检查手机配对与撤销、设备范围、桌面离线时的提示，以及重复发送与审批的幂等。

沿现有指南复用相关领域与协议测试，将 PostgreSQL 相关检查中需保留的语义迁到 SQLite 集成检查；增加真正覆盖新失败窗口的测试，不机械复制每个实现字段。性能在固定机器和固定输入条件下记录首个响应、索引积压、峰值资源、取消收尾及 UI 连续性，再按实际结果确定参数页默认值；未测数值不写成保证。

## 风险与处理出口

- 原生依赖无法冻结或打包：M0 已确认现有依赖可冻结运行，已知代价与处理方向见[宿主探针结论](#宿主探针结论)；P2、P4、P7 在真实产物中复查新增依赖，调整依赖或资源布局，不把用户手工安装开发环境作为默认修复。
- 内部包未经 Developer ID 签名：首个交付只面向内部使用，说明首次打开的手动允许步骤，不报告为公开分发；签名与公证在 P10 处理。ad-hoc 签名身份随每次构建变化，覆盖安装后钥匙串可能再次请求授权；检查确认可重新授权且不丢配置，Developer ID 签名后身份稳定。
- Tauri 特定目标的键盘／预览缺陷：先修平台适配；若影响核心流程且无可维护修复，回到 D1、D2 调整交付目标，不静默改用另一套 UI。
- SQLite 写入竞争：缩短事务、消除事务内 IO 和重复写入，保留 CAS 与唯一约束；不能通过无限等待掩盖锁问题。
- 本地模型或解析超出资源：暂停后台队列、明确组件与任务状态，允许缩小索引范围；保持对话和已完成材料可读。
- 自动记忆误记或重复：用户撤销与来源抑制兜底，可关闭自动提炼或更新提炼策略版本；不放宽对用户条目的保护。
- 用户文件在任务中变化：版本冲突与静止核对优先，保留失败结果，不自动进行全目录恢复。
- 外部 Skill 依赖与工具不兼容：报告具体来源与缺失能力，允许使用可用部分；不自动执行包内安装或 hook 来补齐。

各工作包落地时已按[实施规则](#开工条件与实施规则)更新所改变的文档。P9 做首个交付的最终合并：产品说明与 UI 设计中残留的项目说明、笔记与托管副本描述替换为工作区、工作方式、记忆与文件夹；执行、记忆、检索和 Skill 机制归所属正文；模块与数据所有权变化更新架构；默认数值归参数页；实现与检查入口归代码地图和服务指南。本计划随后删除已落地的设计，只保留尚未开始的后续阶段，全部阶段完成后清理。安装与日常操作命令放服务指南，不在计划里维护两套；交付只概括检查条件和结果，不留独立历史验收目录或逐轮日志。
