# 实施工作包与交付条件

本页按已确认范围定义实施顺序，不是进度台账。所有工作包均未实施；本轮只维护计划。技术方案见[总览](README.md#技术基线)，已确认的产品范围见[决策清单](decisions.md)。

## 开工条件与实施规则

D1—D9 已确认，产品改动仍待实施授权。实施时先用宿主探针暴露打包风险，再冻结共享身份、权限、存储及协议契约，然后按里程碑交付可运行的产品链路；不额外建立工作区／RAG 概念样本或未经授权的 demo。

首个交付只覆盖 macOS Apple Silicon：所有工作包在 Mac 上实现与检查，形成完整闭环后才进入后续阶段。共享端口与契约不写死 macOS 语义，为 Windows 与移动端保留位置，但不提前实现或检查。

每个工作包交付实现、对应调用方、界面和行为检查。能力在所属工作包内接入上下文装配与工具，不集中到最后汇合；达到本包完成条件再进入依赖它的工作。不得以原有测试数量、开发服务器可启动或 UI 编译成功替代目标行为完成。

现有源码位置统一沿[代码地图](../code-map.md)定位。新的目录安排维护在[客户端专题](clients-and-distribution.md#工程布局)，具体机制与命令随落地分别合入正文和服务指南。

| 里程碑 | 包含 | 可观察的结果 |

“Mac 工作区”是产品形态成立的最小版本：没有文档索引时，Agent 仍可用文件工具浏览和读取文件夹。“Mac 闭环交付”是首个交付的终点；后续阶段扩大分发方式与平台范围，不改变工作区对象模型。

## Web 与原服务部署移除

P2 将现有 UI 改为只供 Tauri 打包的共享界面，移除 Next 服务启动、独立网站发布目标、浏览器应用入口和对应认证会话引导；保留 Vite 本地开发调试。客户端与核心间的 HTTP／SSE、API 类型生成、外部网页及成果预览继续使用。移除放在 P2 的最后，桌面骨架可用之前不先拆掉现有入口。

P1 之后核心不再支持原部署方式，P9 因此在首个交付内清理原 UI／API／Nginx Compose 编排、服务部署专用镜像与流水线、反向代理配置及只服务旧部署的环境配置。沙箱组件是否保留只取决于执行端口，不因名字含 Docker 而整目录删除。旧部署相关的专用检查替换为桌面构建与通信检查，服务指南、根入口和代码地图同步改为桌面使用与开发说明。

按 D3 不提供旧数据迁移，也不建设导出工具。删除仓库中的部署文件不销毁现存数据库、Docker 卷、模型配置或用户目录；需要旧数据的用户继续使用旧版本。交付检查确认构建产物无独立 Web 产物，核心不向本机浏览器托管应用，正式运行无需 Next／Nginx／Compose；共享界面、自动化浏览器与 HTML 预览仍工作。实际实现改变前，现有正文和服务指南继续描述真实代码，待相应工作包落地再替换说明。

## 备份与应用升级

**首个交付的内部包升级**：schema 自 P1 起带版本与升级脚本。安装新内部包前先结束活动运行，停止旧核心与写入者；新核心启动时用 SQLite 备份接口生成升级前副本，再执行升级并完成重启扫描后才受理。旧二进制不能打开超出其可读范围的新 schema，需要回退时配套恢复升级前副本。首个交付不提供自动更新与恢复界面，内部包由用户手动覆盖安装。

**P10 的正式更新与备份恢复**：业务静止后使用 SQLite 备份接口生成一致副本，并保存该副本所引用的不可变对象清单；备份操作固定这些对象的回收引用，再恢复新写入并按清单复制字节，完成或取消后释放备份引用。工作区文件夹是用户数据，备份默认只记录绑定与应用保存的内容对象，不声称打包了整个文件夹。检索索引可重建，不作为恢复必需字节。

恢复到独立位置先核对 schema、内容哈希与引用，支持重新绑定工作区文件夹，不静默改写不同机器上的任意路径。恢复成功前不覆盖当前数据；既有目录作为保留副本，后续清理需明确操作。

签名更新先核对空间、兼容范围和当前任务，阻止新受理后等待或让用户结束活动运行，停止所有旧核心与写入者，再备份并升级 schema。新版失败可切回旧二进制，但数据库超出旧版可读范围时必须配套恢复升级前数据，禁止旧版直接打开新 schema。

| 文件夹移动、复制、失联与外部编辑 | 标记认回或要求用户选择，工具不越界读写，旧版本不覆盖新文件，撤销不删用户文件 | macOS 文件系统 |

| 内部包升级 | 工作区、记忆与会话保留；旧二进制拒绝打开新 schema | Mac 内部包 |
| 独立 Web 与原部署退出 | 无网站发布／浏览器应用入口和原服务部署依赖 | 构建配置、内部包与指南 |

沿现有指南复用相关领域与协议测试，将 PostgreSQL 相关检查中需保留的语义迁到 SQLite 集成检查；增加真正覆盖新失败窗口的测试，不机械复制每个实现字段。性能在固定机器和固定输入条件下记录首个响应、索引积压、峰值资源、取消收尾及 UI 连续性，再按实际结果确定参数页默认值；未测数值不写成保证。

## 风险与处理出口

- 原生依赖无法冻结或打包：由 M0 先暴露，P2、P4、P7 在真实产物中复查；调整依赖或资源布局，不把用户手工安装开发环境作为默认修复。
- 内部包未经 Developer ID 签名：首个交付只面向内部使用，说明首次打开的手动允许步骤，不报告为公开分发；签名与公证在 P10 处理。
- Tauri 特定目标的键盘／预览缺陷：先修平台适配；若影响核心流程且无可维护修复，回到 D1、D2 调整交付目标，不静默改用另一套 UI。
- SQLite 写入竞争：缩短事务、消除事务内 IO 和重复写入，保留 CAS 与唯一约束；不能通过无限等待掩盖锁问题。
- 本地模型或解析超出资源：暂停后台队列、明确组件与任务状态，允许缩小索引范围；保持对话和已完成材料可读。
- 自动记忆误记或重复：用户撤销与来源抑制兜底，可关闭自动提炼或更新提炼策略版本；不放宽对用户条目的保护。
- 用户文件在任务中变化：版本冲突与静止核对优先，保留失败结果，不自动进行全目录恢复。
- 外部 Skill 依赖与工具不兼容：报告具体来源与缺失能力，允许使用可用部分；不自动执行包内安装或 hook 来补齐。

## 完成后的文档归属

P9 完成时，已实施机制合入正文与服务指南：产品说明与 UI 设计中的项目说明、笔记与托管副本描述替换为工作区、工作方式、记忆与文件夹；执行、记忆、检索和 Skill 机制归所属正文；模块与数据所有权变化更新架构；默认数值归参数页；实现与检查入口归代码地图和服务指南。本计划随后只保留尚未开始的后续阶段，全部阶段完成后清理。安装与日常操作命令放服务指南，不在计划里维护两套；交付只概括检查条件和结果，不留独立历史验收目录或逐轮日志。
