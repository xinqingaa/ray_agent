# 运行生命周期、事件与可靠性方案

状态：已实施并收尾。保留运行身份、受理、等待和控制的配套设计；当前机制见[架构说明](../architecture.md#结束路径与控制平面)，分析依据见[运行事实背景](../background/runtime-and-progress.md)。

## 目标与范围

让用户和维护者能确认请求是否受理、哪次运行仍在执行、为何等待或结束、停止传播到哪里，以及实际使用哪个构建与配置。

覆盖运行身份、事件、流式、请求重建、受理与准备、等待、停止和启动扫描。调度仍依赖当前进程任务注册表；项目准入与[文件保护方案](projects-and-data.md)联动。

## 状态、身份与事实源

会话、运行、轮次、请求尝试与工具调用分别标识，事件保留关联身份。页面显示不能反推进程存在。

- **状态与事件同事务**：终态、原因、调用及计数一起提交，避免页面看到半份状态。
- **提交后通知**：只发布会话新序号，通知丢失可补查，不能先通知未提交事实。
- **终态不可回改**：取消、失败、中断和完成分别记录，收尾失败不能掩盖原原因。
- **未知效果单独表达**：已开始但无结果的调用不按未执行重放。
- **前端按序号投影**：去重、补齐并阻止旧快照覆盖新事件，实时和历史沿同一依据。

完整状态迁移与调用补齐规则只维护在[控制平面](../architecture.md#结束路径与控制平面)。

## 模型请求和流式契约

运行快照保存提示、模型、协议、参数与工具声明，等待沿原配置。模型历史的每次变化记录为上下文事件，支撑适配前请求重建，不重新执行动作。

流式反馈分两条路径：

- 文本片段是无持久序号的临时展示，断线不补发。
- 完整响应保存为消息、调用与用量事件，参数完整且结束原因可用后才执行。

失败尝试与轮次耗时独立记录，不混入模型历史，也不将工具耗时视为全部墙钟。

流中断、空回复和截断继续受循环计数与有界恢复约束。缓存输入、推理用量、生成速度与费用各有口径，不用页面估算代替实际 usage。

## 受理与准备分离

1. 短事务保存输入并建立运行，返回可读回身份。
2. 后台准备环境；客户端超时或丢失响应时先核对受理，避免直接重发。
3. 服务端在准入边界检查已有运行和请求身份；迟到准备结果核对当前运行，取消后清理无主资源。
4. 项目另取得文件占用并执行保护；受理成功不代表环境已经可用。

计划确认携带来源运行、计划身份、事件版本与请求身份，事务内验证并绑定新运行。重复请求读回同一结果，过期引用返回冲突；自然语言确认不冒充结构化确认。计划语义见[计划方案](long-task-trust-and-delivery.md)。

## 提问、审批与续接

等待续接依赖可持久重建的输入，而不是原调用栈：

- 退出协程前保存响应、已执行结果、待处理调用与配置。
- 提问回复关联具体调用并补齐同批未执行结果，用户输入保留真实来源。
- 审批答复只作用于具体调用，批准不扩散到其他动作。
- 重建时恢复预算、有限反馈、浏览器引用和项目占用，重新确认资源归属。

API 重启中断遗留执行及审批，提问等待保留。详细迁移见[等待与续接](../architecture.md#等待与续接)。

## 停止与资源传播

- 先保存取消终态，再取消协程、终止登记的 Shell 进程组，控制结果另存。
- 独立对话保留沙箱，项目终态先确认旧写入者静止再释放占用；等待继续占用。
- 不回滚文件，不把终止进程、停止环境与回收附件视为同一动作。

信号顺序及未知效果处理见[停止传播](../architecture.md#停止传播与资源收尾)。

## 实际构建身份

| 身份 | 设计要求 | 不能证明什么 |
|---|---|---|
| API / UI 构建清单 | 内容指纹覆盖各自源码、锁定与构建输入，排除凭据、可变配置和缓存 | 不证明外部模型或运行配置正确 |
| Git 提交 | 辅助定位源码 | 不能区分同提交上的工作树修改 |
| 运行快照 | 保存 API 构建身份与实际提示，未知身份保持未知 | 不重写历史请求 |
| 部署核对 | 分别读回两端清单、健康和新运行提示，保留配置 | 任一端健康不等于两端匹配 |

新运行用当前提示，等待沿冻结提示；可与产物脱离的环境 SHA 不能作为唯一身份。

## 模块责任与依赖

| 模块 | 必须保持的关系 |
|---|---|
| 领域层 | 运行、轮次和调用身份一致，有限反馈及等待记录可恢复 |
| 应用层 | 受理、事件账本、调度与资源归属共用协调边界 |
| 基础设施 | 数据库先提交，模型响应完整后交出动作，进程与环境分别收尾 |
| 前端 | 持久事件与临时增量分开，重连按序号补齐 |

调用配对先于等待与停止；快照和上下文记录先于请求重建；迟到资源校验先于受理与准备解耦。

## 完成条件

- 通知丢失可补查，状态与事件同事务，终态不被迟到事件覆盖。
- 不完整参数不执行，响应丢失及重复提交不创建重复运行。
- 提问可续接，批准只作用于具体调用，重启使旧审批失效。
- 停止保持终态并传播到登记进程，项目静止后才释放占用。
- 新运行与等待各用正确提示，实际构建身份可读回。

不包含跨 worker 认领、任意中断点续跑或通用副作用幂等。验证入口见 [API 指南](../../ray_agent/api/README.md)和 [UI 指南](../../ray_agent/ui/README.md)。
