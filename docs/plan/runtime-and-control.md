# 运行生命周期、事件与可靠性方案

状态：运行事件、流式、等待与控制、可靠受理及构建身份已实施，验证覆盖按阶段分别记录于 [执行与控制报告](evidence/execution-and-control.md)。2026-10-13 依据 Git `b62fda5` 合并原方案，未重新运行服务。

分析依据见 [运行事实与控制背景](../background/runtime-and-progress.md)。当前状态和所有权见 [架构说明](../architecture.md)，本篇维护跨模块契约和实施关系。

## 目标与范围

让用户与维护者能回答：请求是否受理、哪次运行仍在执行、为什么等待或结束、停止传播到哪里、刷新读回什么、实际采用哪个构建和配置。

覆盖受理、运行身份、持久事件、流式、请求重建、等待续接、停止与启动扫描。保留现有进程内调度，不建设持久任务队列、跨 worker 自动认领或未知副作用重放。项目旧写入者和文件准入与本方案联动，详细设计见 [项目保护方案](projects-and-data.md)。

## 状态、身份与事实源

会话组织连续历史，运行组织一次执行，轮次组织一次模型尝试，工具调用组织一次请求与结果。关联身份随事件保存，不能通过页面状态反推进程是否存在。

| 路径 | 必须保留的事实 | 处理边界 |
|---|---|---|
| 正常结束 | 最终答复、运行终态、成果完整程度 | completed 不证明业务通过 |
| 失败 | 原因、已有结果、未执行或未知调用 | 失败不撤销外部副作用 |
| 停止 | cancelled、控制传播和环境收尾结果 | 停止不回滚文件 |
| 提问等待 | 具体问题、待回复调用和冻结配置 | 可以持久续接，不长期挂协程 |
| 审批等待 | 一次待批准调用与当时环境 | 重启使旧审批失效 |
| API 退出遗留 | 运行和项目操作的中断事实 | 不伪装持续运行，不自动重放 |

业务状态与事件同一数据库事务提交，按会话序号分配。Redis 通知只提供新序号，数据库是补查与回放依据。前端按 seq 去重和排序，旧快照不覆盖新事件；投影可以省略大字段，但不能改写事实。

## 模型请求和流式契约

运行快照冻结系统提示、模型、预算、实际参数与工具声明；上下文每次变化先记录，支持重建某次已保存的请求。页面事件投影与模型消息不同，不把界面可见内容视为完整输入。

模型文本增量是临时展示，不带持久序号，断线后无需补发每个片段。完整响应组装后保存，刷新按完整事实重建。工具参数必须完整且结束原因可用后执行；输出截断不执行半截调用。流式失败、空回复和传输重试仍遵守循环的计数与有界恢复。

轮次记录模型耗时、首段延迟、工具耗时与 usage。墙钟、生成速度、缓存输入和推理用量各有定义；工具时间不能自动覆盖准备、整形、上传与通知。

## 受理与准备分离

用户发送先用短事务保存输入并建立运行，再在后台准备资源。返回身份允许客户端在超时或响应丢失后读回受理状态，不能直接重发创造重复执行。

服务端在准入协调中检查已有运行及请求身份。迟到准备结果必须属于当前有效运行；取消或中断后停止并清理无主资源，不能将旧 sandbox_id 挂回新运行。项目另取得文件占用，受理成功不代表保护和准备已经成功。

确认计划请求携带 `source_run_id / plan_id / source_seq / request_id`。受理事务验证所属会话、来源运行、有效版本和当前准入，固定承接计划并发布新运行归属事件。相同请求读回相同结果，过期引用返回冲突。普通文字确认继续作为自然语言输入，计划语义由 [计划方案](long-task-trust-and-delivery.md)维护。

## 提问、审批与续接

等待前保存模型响应、已执行结果、待处理调用和配置，退出协程。用户回复作为具体提问调用的结果；提问之后的调用补为未执行，由下一轮重新判断。审批批准只执行那次调用，拒绝产生拒绝结果，其他动作不能继承批准。

恢复必须保留调用配对、预算计数、一次纠正额度、浏览器引用和项目占用。真实新用户输入与内部提醒来源不同。API 重启扫描将遗留执行与审批标为中断，审批失效；提问等待可重建运行器继续。

## 停止与资源传播

先保存 cancelled，再取消本次执行协程，逐个终止登记的 Shell 进程组，SIGTERM 后仍未退出再强制终止。控制结果单独保存，不能因为收尾失败回改为完成。仍需说明可能存在的未知效果。

独立对话保留沙箱用于复用，环境清理沿生命周期处理。项目终态另确认共享文件的旧写入者静止，再释放占用；等待时继续占用。终止进程、停止环境、回收资源和回滚文件不是同一种操作。

## 实际构建身份

API/UI 各有随构建产生的清单，内容指纹覆盖各自声明的源码、锁定或构建输入，排除凭据、可变配置、缓存和文档证据。Git 提交用于定位，工作树修改需要内容指纹区分；不能只填可与产物脱离的环境 SHA。

运行保存 API 构建身份及实际系统提示。旧身份未知就保持未知，新运行用当前提示，等待续接仍用冻结提示，历史请求不重写。部署保留实际配置并分别核对两端清单、健康及新运行的实际提示；服务健康不是身份匹配证明。

## 完成条件与验证边界

1. 状态与事件同事务；数据库提交失败不发出假完成通知；通知丢失可从序号补查。
2. 流式文本先可见，完整工具才执行；截断、重试、usage 和临时增量不混入持久完成事实。
3. 受理响应丢失、并发提交、旧计划引用与迟到资源各有正确出口；刷新不制造第二次运行。
4. 提问和审批能恢复必要状态，拒绝不执行，重启旧审批失效，调用结果不悬空。
5. 真实 Shell 停止后标记不继续增长；项目环境静止后释放占用；停止不承诺回滚文件。
6. API/UI 指纹分别可读，工作树改动可辨认；新运行与等待续接采用各自正确提示。

数据库原子性、实际进程、真实 UI 与脚本化模型分别验证，不用纯替身概括全部链路。历史基线停止失败保留；后续通过只覆盖当时模型、构建和环境。多 API 实例完整认领、任意异常点续跑、通用外部动作幂等均不在已完成范围。
