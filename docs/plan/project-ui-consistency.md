# 项目操作与记忆界面统一方案

状态：上一轮入口、设置、记忆面板和公共 Tooltip 已更新；本次追加的“滚动容器与摘要定位修订”已实施，正在进行实际浏览器验收。上一轮验证条件与边界见验收记录。

核对日期：2026-10-10。代码基线：`c6babc0` 加当前工作区；包含此前项目主页、文件预览、数据清理等未提交调整。本文件陈述的建议不代表已实现能力。

## 现状与问题

源码核对确认以下问题：

- 项目设置把名称保存、关闭、说明/笔记跳转、归档和删除纵向堆叠，保存按钮位于表单中部；对话框既编辑设置又承担导航，操作重心不明确。
- 侧栏项目行与主体页头重复提供项目菜单。用户本轮所说“侧边栏的更多可以删除”按移除该菜单入口理解，不是移除项目删除能力。
- 主体菜单“对话摘要与记忆预览”实际先打开摘要分区；查看使用内容还要进入面板内第二个菜单，入口名称承诺的结果与首次打开状态不一致。
- 记忆面板普通模式标题为“项目说明与笔记”，开发者模式标题为项目名称，内部却还包含摘要、修改记录和运行预览。同一容器因模式和内容变化而失去稳定名称。
- 会话中的说明/笔记入口只用浏览器原生 `title`，其他操作使用公共 Tooltip。原生提示的主题、出现时间和样式不能由应用统一控制；公共 Tooltip 目前使用前景色背景和反色文字。
- 记忆面板顶层“更多”隐藏修改记录和运行预览，摘要行又只有一个“编辑摘要”的菜单；对用户而言层级多于实际操作数量。

问题来源是入口、容器与内容分区的职责没有统一。局部换图标或颜色不足以解决。

## 建议的信息结构

保留既有四个主页页签和共用对话行，不重排对话列表。采用以下唯一命名和定位契约：

| 位置 / 入口 | 容器或目标 | 首次打开内容 | 关闭 / 返回 |
|---|---|---|---|
| 侧栏项目名称 | 项目主页 | 对话页；已有主页切换规则保持 | 正常页面导航 |
| 侧栏双气泡 | 项目主页输入区 | 准备新对话 | 保留已有草稿规则 |
| 主体页头“⋯ 更多” | 项目操作菜单 | 菜单，不打开其他页面 | Escape 或点击外部关闭菜单 |
| 更多 → 项目设置 | 项目设置对话框 | 名称、归档状态 | 返回原页面、原页签，焦点回到入口 |
| 更多 → 对话摘要 | 项目记忆侧面板 | 摘要分区 | 返回原页面，不切换文件页 |
| 更多 → 使用内容 | 项目记忆侧面板 | 使用内容视图 | 返回原页面；面板内可返回原分区 |
| 对话页项目记忆图标 | 项目记忆侧面板 | 默认说明分区 | 原对话阅读位置、输入草稿保留 |
| 主页说明 / 笔记页签 | 当前主页 | 对应全文及编辑操作 | 保持当前页签 |
| 说明 / 笔记的修改记录图标 | 项目记忆侧面板 | 修改记录视图 | 返回原说明 / 笔记页 |
| 更多 → 恢复项目文件 / 操作记录 | 对应独立管理弹窗 | 对应管理内容 | 原页签、搜索和草稿保留 |

侧栏项目行去掉菜单，仅保留展开箭头、名称与双气泡。项目删除入口保留在项目设置的危险操作区，不在主体菜单重复一份；在对话里可通过项目名称回到主页管理项目。

主体“更多”使用现有省略号图标与“更多”文字，属于用户本轮明确要求的例外。菜单每项使用统一 16px 图标和文字；不把菜单项目变成无标签图标。菜单排列为项目设置、对话摘要、使用内容，分隔后为恢复项目文件、操作记录；归档与删除由设置负责。

## 项目设置对话框

对话框仅承担名称和项目生命周期管理。移除说明/笔记链接，移除当前中部的关闭按钮。保留清晰文字的保存和危险操作，不用无文字图标代替不可逆操作。

建议桌面宽度约 480px，窄屏左右留 16px；沿用当前字体、颜色和圆角，正文超高时只滚动内容，标题和底部操作固定。示意：

```text
项目设置                                 ×

项目名称
[ harness学习                            ]

归档项目                         [归档]
从侧栏移除，保留对话、文件与记忆。
──────────────────────────────────────────
删除项目                         [删除]
永久删除项目及所属数据，无法恢复。
──────────────────────────────────────────
                             [取消] [保存]
```

标题不加“管理名称与项目生命周期”常驻说明。字段标签保持可读；归档与删除各用一条对齐操作行，提示放在各自操作下方，删除用危险语义文字，不用大面积红色填充。

- 名称未修改时保存禁用；比较裁剪空白后的有效名称，保存成功同步输入值，避免出现“保存后仍有修改”的假状态。
- 保存成功关闭设置并刷新项目名称；失败留在设置并保留草稿；并发冲突展示最新名称和当前草稿，不静默覆盖。
- 取消、关闭、Escape、遮罩点击采用同一未保存保护逻辑；保存进行中禁止重复提交和离开。
- 有名称草稿时归档、删除暂不可用，给出“先保存或取消名称修改”的短原因，避免另一操作遮盖草稿。
- 归档 / 取消归档成功后退出设置并更新导航；失败保留对话框。归档不新增永久删除等级的确认。
- 删除进入独立确认步骤，设置弹框暂时退出；取消删除回到设置，保留项目身份和焦点；查看占用对话时退出整个设置/确认链后导航。不得让两层可操作弹框同时存在。
- 删除范围、名称确认、占用保护、进度和失败重试沿用既有能力，本轮不改变数据清理协议。

## 项目记忆侧面板

正式容器名称统一为“项目记忆”，普通模式与开发者模式一致。项目名称作为次级文字，表示归属，不替代容器标题。对话入口无障碍名称与 Tooltip 同样叫“项目记忆”。

```text
项目记忆                                 ×
harness学习
[说明] [笔记] [摘要]
                          [修改记录图标] [使用内容图标]
──────────────────────────────────────────
当前分区内容
```

说明、笔记、摘要是内容分区；修改记录与使用内容是辅助视图。保留侧面板呈现，主页长文仍在现有页签阅读，不统一成一律跳页面或一律弹窗。

移除面板顶层“更多”。修改记录与使用内容使用有公共 Tooltip 的直接图标入口。辅助视图显示自己的内容标题及返回图标，返回提示明确为“返回说明”“返回笔记”或“返回摘要”；容器标题始终是“项目记忆”。编辑/切换中的未保存内容必须受同一保护规则约束，进入辅助视图保留草稿，不重新挂载清空编辑器。

摘要行移除只有一项的“更多”，直接提供编辑图标；编辑时优先复用面板内编辑视图，保留已有版本冲突、重新生成和失败处理能力，避免再叠加一个编辑弹窗。新增摘要仍需选择所属对话，选择完成进入同一编辑视图。

“使用内容”表示 API 返回的项目内容组合及已有的会话快照信息。存在会话快照时区分“当前项目内容”和“本次对话快照”；尚无快照时明确未取得。不得将当前组合称为已经用于该对话的内容，也不得把预估当成实测。开发者模式只增加细节，不能修改标题、入口或分区位置。

## 悬浮与浮层规范

不把菜单、Tooltip、侧面板和对话框统一成黑色底面，它们承担不同职责。

- Tooltip：短文字提示，统一公共组件；本方案建议使用 `bg-card / text-foreground`、边框与轻阴影，浅色跟随浅色主题、深色跟随深色主题。箭头同底色；鼠标与键盘焦点均可触发。建议延迟 300ms，图标按钮都有无障碍名称。
- 菜单 / Popover：有交互选项的卡片，使用相同表面颜色和边框规则，有键盘选项定位；不拿 Tooltip 放可点击操作。
- 对话框 / 侧面板：大内容容器，统一标题、关闭按钮与正文间距；所有关闭动作走当前容器的离开保护。关闭后焦点回到调用入口。
- 已有公共 Tooltip 的背景更改影响所有使用者，需要全局浅色/深色冒烟验收。名称截断的 `title` 可保留，但按钮提示不得同时出现原生 `title` 与公共 Tooltip 两份。

## 滚动容器与摘要定位修订

本节对应用户最新两点反馈，用户已授权实施。本节取代上文关于保留四个主页页签、普通模式提供“使用内容”的约定；其余已完成行为保持。主体菜单按最新要求仅显示三个点，公共提示和无障碍名称保留。实现已合入产品与设计说明。

### 源码确认的问题

1. 恢复项目文件、项目操作记录的外层弹窗滚动区域包住整个管理组件，包含组件标题；关闭按钮则由外层 Dialog 单独绝对定位。管理组件内还有内容滚动区域，因此标题会滚走，并且刷新与关闭不由同一工具栏布局。这是容器所有权问题，不能仅用边距补齐。
2. 项目记忆辅助视图的返回与标题在一行，修改记录与预览按钮另占一行；进入辅助视图后仍显示切换辅助视图的工具，形成截图中的空白和重复导航。
3. 主页提供说明与笔记，摘要却藏在“更多”中。摘要管理与上下文预览混在同一面板，没有区分内容维护和技术检查。
4. “使用内容”展示当前项目说明、笔记与经过数量/容量约束选入的其他对话摘要；它是项目上下文部分的组合预览，不是完整模型上下文，也不能证明当前对话已经使用了这些内容。API 的 `frozen` 当前取项目活动运行的快照，而非按所查看对话直接取快照；将其无条件标为“本次对话快照”可能指向另一对话，必须纠正归属。

### 一、统一固定标题栏和正文滚动

- 管理弹窗采用公共框架：固定标题栏、唯一正文滚动区、按需固定底部操作。标题栏由同一容器排列标题、刷新、关闭，禁止外层再叠一个关闭按钮。
- 标题左对齐；刷新、关闭右对齐，按钮统一 32×32px、图标 16px，同一纵向中心。返回图标仅在确实存在内部返回路径时出现，并与标题处于同一行。
- 操作记录、恢复项目文件，以及记忆面板的修改记录辅助视图逐项落实。文件预览核对相同规范，沿用已完成的单工具栏，不额外重做。
- 正文包含列表、说明、错误和加载状态；长内容只滚正文，标题和操作保持可见。避免内外两层同时滚动，刷新不清空当前视图、不意外重置草稿；加载时操作位置不变。
- 项目记忆保留固定容器名称；辅助视图的返回、当前视图名和相关操作集中在同一条固定上下文栏，不再多占一行重复显示历史/预览切换按钮。

### 二、摘要回到项目内容，预览退出普通流程

建议主页增加“摘要”页签，排列为对话、文件、说明、笔记、摘要。这里只增加一个有实际内容职责的入口，沿用现有页签和对话行样式，不重排对话列表。

| 内容 | 定位 | 普通用户入口 |
|---|---|---|
| 项目说明 | 后续任务需要遵守的长期要求 | 主页说明；对话内项目记忆 → 说明 |
| 项目笔记 | 共同维护的背景、结论与决定 | 主页笔记；对话内项目记忆 → 笔记 |
| 对话摘要 | 各对话的压缩内容，可作为其他任务的项目记忆来源 | 主页摘要；对话内项目记忆 → 摘要 |
| 项目上下文预览 | 检查当前选入的项目内容与活动运行快照 | 仅开发者模式的明确入口 |

- 主页摘要与对话内摘要共用数据和操作逻辑；显示来源对话、摘要内容与必要的生成/失败/过时状态，保留已有编辑和重新生成能力。摘要空态说明用途，不复制说明与笔记，也不声称所有摘要必定全部纳入。
- 移除主体“更多 → 对话摘要”，以主页页签作为稳定入口；对话里的项目记忆仍保留说明/笔记/摘要三个分区，避免为了查看摘要离开对话。
- 普通模式移除“使用内容”菜单项和眼睛图标；无需为了读已有说明、笔记再进一层重复全文。
- 开发者模式保留技术检查，命名为“项目上下文预览”，使用独立预览弹窗及固定标题栏，不再作为说明/笔记内的辅助视图。区分“当前组合”和“活动运行快照”，快照展示来源对话；不能把其他对话的活动快照标为当前所查看对话。无活动快照时明确空态。
- 不调整记忆选取、摘要生成、恢复和清理协议；本次优先根据 API 已有的活动运行与占用对话身份正确呈现，不顺带增加历史运行快照能力。
