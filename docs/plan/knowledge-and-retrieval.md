# 文档知识与检索

本专题定义工作区文件夹中的材料如何解析、索引与召回，按计划实施中，进度见[实施状态](implementation.md#实施状态)。技术基线为 SQLite FTS5 与 LanceDB Embedded（见[总览](README.md#技术基线)）；本仓库尚未验证其打包与召回质量，验证属于 P6、P7 的交付检查，不以选型 PoC 为前置条件。用户不要求另建工作区／RAG 样本证明该方向。

## 当前基础与目标

目前有项目文件保存、预览、项目说明、笔记和会话摘要；仓库依赖、迁移与应用装配中没有向量扩展、Embedding 或知识检索管线，文件预览也不等于完整解析。现状入口见[文件与交付](../code-map.md#文件与交付)、[上下文与记忆](../code-map.md#上下文与记忆)。

目标是让工作区文件夹中的大量材料持续接入、按问题检索、读回原文并定位依据，文件更新后仍能说明回答所依据的版本。检索对象包括文件夹中的文件、工作区记忆条目与会话摘要；记忆与摘要的语义归[工作区专题](workspaces-and-memory.md)，本专题负责共同的检索底座。

索引交付之前，Agent 仍可用文件工具浏览和读取文件夹；索引解决的是材料增多后的检索规模与依据定位。

## 存储与模型

SQLite 管理权威业务数据与 FTS5 全文索引，LanceDB Embedded 保存向量索引，检索服务融合两路结果。两者位于应用数据目录并按工作区隔离，用户无需维护向量数据库服务；依赖打包、索引维护及跨平台行为按实施包完成。

Embedding、OCR 和文档解析默认在本机执行，外部模型入口仅在用户明确启用后使用。资源按 D6 下载或离线导入；对话模型沿用户配置，不把桌面独立运行等同于所有模型完全离线。

[LanceDB Embedded](https://docs.lancedb.com/basics/lancedb-embedded)与[混合检索说明](https://docs.lancedb.com/search/hybrid-search)作为实现依据。

## 首批格式与处理方案

| 输入 | 默认实现与来源位置 | 能力边界 |
|---|---|---|
| TXT／Markdown／代码／JSON | UTF-8 文本、标题／行号、结构与原始偏移 | 明确编码错误，不执行代码或将 JSON 内容视为指令 |
| HTML | 现有解析基础提取正文与标题，保存来源及内容版本 | 不执行脚本，不自动抓取外部依赖 |
| PDF 文本层 | pypdf 按页提取并保留页与块位置 | 复杂排版和跨页表格可能降级为按页文本，不能伪造表格结构 |
| 扫描 PDF／常见图片 | pypdfium2 渲染 PDF 页，RapidOCR＋ONNX Runtime 本机识别，记录页／区域 | 组件缺失转待组件状态；识别不清或复杂公式标注不确定 |
| DOCX／PPTX | python-docx／python-pptx 读取段落、表格／幻灯片和块序号 | 不虚构 Word 页码；不执行宏或外部对象 |
| XLSX／CSV／TSV | openpyxl 与流式表格读取，保留工作表、表头与单元格范围 | 不重算公式，缺缓存值明确显示；完整统计走原表读取 |

首批不转换加密文档、旧二进制 Office、任意压缩包、音视频或任意网页整站。这些文件保留在文件夹中，界面给出不支持原因；新增格式走相同解析端口，不改变已有文档身份。

解析在可取消的独立 worker 中运行，不加载进 API 主事件循环。完整输出是带位置的结构块和内容对象，不采用当前预览的截断窗口；预览与入库共用格式识别和来源身份，分别提供完整解析与有界阅读。

## 接入与索引

1. 文件夹中符合排除规则的文件登记文档身份、相对路径、内容哈希与修订；添加进文件夹的文件走同一入口。
2. 按格式提取内容，尽量保留标题、章节、页码、段落和表格关系；扫描材料按需 OCR，解析失败可见。
3. 按结构切分，保存片段与原文位置，再生成全文与向量索引；索引不代替原文件和权威元数据。
4. 后台处理支持排队、取消、重试与重启核对，界面区分已登记、待解析、处理中、可检索和失败。
5. 文件变化后增量更新；新版本完整可用前保留清晰的旧版本状态，查询不混合半份索引。

## 结构、Embedding 与关键词基线

逻辑模型包含 `documents`、`document_revisions`、`content_blocks`、`chunks`、`index_publications` 和检索来源记录。每个片段关联工作区、文档修订、结构位置、文本哈希及解析／切分配置指纹；表格片段携带列标题，长表按行组划分，不能切掉必要表头。

默认本机 CPU 使用 ONNX Runtime 与固定版本的 `intfloat/multilingual-e5-small` 资源。实现相同 tokenizer、查询／正文前缀、池化和归一化，按模型有效输入上限切分；不可只截断向量输入而声称整段已经入库。导出模型、词表和处理配置纳入受管资源清单，首批不要求 PyTorch、GPU 或用户安装模型服务。

关键词检索使用 SQLite FTS5，入库与查询共享应用层中文分词和英文规范化流程；精确名称、标识符及原短语另保留匹配通道。采用可打包的 Jieba 分词与固定字典，不依赖 SQLite 默认分词器自动理解无空格中文。词法与向量结果按片段身份进行 RRF 融合，避免直接相加不同量纲的分数；首批不额外安装重排大模型。召回质量不足时，可替换分词、Embedding 模型或加入轻量重排，并建立新的索引空间。

可配置外部 Embedding 适配，默认关闭；模型、维度、预处理任一变化都生成新索引空间，不能混查。需要外部解析／OCR 时同样明确启用，不静默发送整个工作区。

## 分阶段交付

P5 建立检索端口与 FTS5／中文分词底座，先接入记忆与会话摘要。P6 向同一端口加入文件登记、解析、文件片段的全文索引、检索与来源读取工具、初始召回中的文件来源、引用界面与索引状态，不另建第二套检索。P7 加入 Embedding、LanceDB 向量索引、RRF 混合召回与 OCR 组件。

语义组件未就绪或失败时，全文检索继续工作，界面说明语义索引待处理；OCR 组件缺失时扫描材料停在待组件状态，不阻塞其他材料。

## 可取消、可恢复的索引发布

文件监听或重扫登记待处理修订；读取前后核对文件身份、大小和内容哈希，正在变化的材料延后重读。解析产物先写不可变暂存对象，完成后才提交可读版本；损坏、超额、取消与缺组件分别保存，不发布空正文冒充成功。

每个工作区串行化索引发布，解析与向量计算可在有界 worker 并行进行。LanceDB 表按工作区及 Embedding 配置隔离，写入新修订并生成确定表版本；SQLite 在短事务中更新全文片段与 `index_publications` 的可见表版本／代次。查询在短只读事务中取得全文候选、权限／修订视图与发布指针，再关闭事务并固定对应 LanceDB 表版本执行向量查询，不读取中途的最新表头，也不在向量计算期间持有 SQLite 长事务。

向量写完但 SQLite 未发布时，旧代次继续可见；发布后任务结果丢失时按操作身份确认，不重新制造文档。重启核对暂存、发布指针和哈希，可复用已完成的派生内容；孤立对象由引用回收，旧表版本不在活动查询期间淘汰。结果返回前再校验撤权／删除；已用于历史请求的片段另存内容对象，不依赖无限保留 LanceDB 历史版本。

删除或撤销先在 SQLite 变更权威可见状态；向量查询前下推可访问文档／撤销范围的过滤，返回后再次核对修订与范围。如果过滤条件过大或无法可靠下推，暂用已授权的全文检索并等待重建，不做无范围语义查询后再将私有片段交给模型。索引恢复不能复活已删除的文档或记忆。

## 索引与数据生命周期

索引按工作区限定，缓存同样包含范围与版本。文件移动、修改、删除，或记忆被纠正、撤回时，派生索引要更新或失效；原文已删除后不能继续把旧片段作为有效来源。

保存解析、切分及 Embedding 配置身份，以便模型或解析方案变化后重建。索引可重建，原文由用户文件夹保存，业务元数据与内容对象需要独立备份；索引发布与业务事务之间的失败用持久任务协调。

本机文件监听需要结合启动重扫和内容核对，不能把收到通知视为唯一依据。文件夹失联、移动与删除的归属见[文件专题](files-and-execution.md)和[工作区专题](workspaces-and-memory.md#文件夹绑定与身份标记)。

## 召回与使用

- 先限定工作区与可访问材料，再结合关键词与向量召回；按需要去重、扩展相邻片段。
- 返回稳定的文档、版本、页码或章节定位，并允许读回原文；来源缺失或版本失效时明确说明。
- 与当前会话问题及有效记忆共同装配有界上下文，检索结果不是无条件追加的全部背景。
- 全文总结、完整统计、系统审阅等任务支持枚举与完整读取，不能只靠相似片段推断全部材料。
- 中文术语、精确名称、跨文档比较、表格及扫描材料按实际支持范围处理；内容不足时报告依据不足。

检索作为现有单循环的工具接入，保留已有工具策略与事件观察，不因引入检索更换 Agent 框架或另建意图模型。

## 检索工具与引用交互

新增工作区范围的搜索与来源读取工具，模型只提供查询、来源类型与可选文档身份，工作区由当前会话解析。文件修订、记忆版本与会话摘要通过统一检索条目关联，不混淆来源类型；全文候选在工作区与活动修订条件内排序后截取。结果包含可复读的来源 ID、修订、定位、文本、确定性类别和是否过时；工具结果继续计入统一容量预算。

新运行以当前用户问题做一次有界初始召回，与工作方式、常驻记忆共同形成运行背景清单；需要更多材料时由同一 Agent 循环继续搜索与读取，不另建规划 Agent。检索内容不能覆盖用户明确要求，也不能被当作执行授权。

来源引用在界面中打开对应版本：PDF 到页，Word 到标题／块，表格到单元格范围，文本到行。为了读回旧依据，已入库修订保留应用内容对象；用户撤销或删除后不继续开放旧字节。回答中的引用由渲染器校验来源身份，无法匹配的引用显示未匹配，不猜测关联到当前文件。

全文总结或统计使用文档枚举、完整读取与结构化表格读取，报告处理范围及未处理项。跨文档问题可多次检索并合并证据；没有相关结果时返回依据不足，不以低质量片段强行生成肯定结论。

## 资源、界面与实施检查

打开文件夹不等于把其中全部内容送去解析。文件夹按统一排除规则登记可索引材料，凭据、数据库、依赖缓存、版本控制内部文件与 `.rayagent/` 始终排除；首次登记与规模明显变化时先显示数量、大小与异常，允许按子目录排除、暂停或关闭索引。

界面区分已登记、待组件、解析中、索引中、可全文检索、可语义检索、过时及失败。用户可暂停、取消和重试；索引错误不阻断对话或原文件阅读。后台 CPU、内存、队列与模型加载由统一调度限制，参数在实施时归参数页。

实施检查覆盖模型预处理一致性、精确词与中文、扫描件、长表、跨文档、来源定位、删除与撤权、发布前后崩溃以及完整读取；这些是正常交付检查，不是额外要求用户批准工作区样本。

参考 [E5 模型卡](https://huggingface.co/intfloat/multilingual-e5-small)、[ONNX Runtime](https://onnxruntime.ai/docs/get-started/with-python.html)、[pypdf 提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)、[RapidOCR](https://rapidai.github.io/RapidOCRDocs/latest/)、[SQLite FTS5](https://www.sqlite.org/fts5.html)与 [LanceDB 过滤](https://docs.lancedb.com/search/filtering)。这些是实现依据，非本项目已通过的结果；各模型及转换产物的许可随资源清单单独核对。

## 责任与依赖

材料服务维护文档身份与版本；解析服务产生可定位内容；索引任务管理发布、更新与删除；检索服务执行范围约束与召回；上下文装配与工具层读取依据；UI 展示材料状态与原文引用。

依赖[工作区身份与记忆](workspaces-and-memory.md)、[本机任务与存储](local-runtime-and-storage.md)及[文件生命周期](files-and-execution.md)，按 P5、P6、P7 实现，不新增独立的概念验证项目。

## 完成条件

- 约定格式的材料可接入与检索，解析失败、索引延迟及取消状态可见。
- 回答依据能够定位回原文与版本，工作区隔离覆盖召回、缓存与读取。
- 修改删除、重启重试、配置改变后重建及不完整索引均有明确处理。
- 语义组件缺失或失败时全文检索仍可用；不把引入向量库本身当作知识能力完成。
