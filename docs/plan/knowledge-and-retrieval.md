# 文档知识与 RAG

大量文档需要进入工作区知识能力，是本轮明确的规划方向。用户不要求建立工作区／RAG 样本来证明该方向；本专题直接细化设计，不以选型 PoC 为前置条件。具体存储、解析与模型方案仍待讨论，尚未实施索引。

## 当前基础与目标

目前有文件保存、预览、工作区说明、笔记和会话摘要；仓库依赖、迁移与应用装配中未发现向量扩展、Embedding 或知识检索管线。已有 PostgreSQL 及文件预览不等于已经具备 RAG。现状入口见[文件与交付](../code-map.md#文件与交付)、[上下文与记忆](../code-map.md#上下文与记忆)。

目标是让用户提供的大量资料可持续接入、按问题检索、读回原文并定位依据，文件更新后仍能解释结果所依据的版本。知识检索与[长期记忆](workspaces-and-memory.md)共享底座，分别维护材料与已确认事实的语义。

## 接入与索引

1. 从工作区材料根或导入入口登记文档身份、来源、内容哈希和版本，区分原文件与应用副本。
2. 按格式提取内容，尽量保留标题、章节、页码、段落和表格关系；扫描材料按需要 OCR，解析失败可见。
3. 按结构切分，保存片段与原文位置，再生成向量与全文索引；索引不能代替原文件和权威元数据。
4. 后台处理支持排队、取消、重试与重启核对，界面区分已接收、待解析、处理中、可检索和失败。
5. 文件变化后增量更新；新版本完整可用前保留清晰的旧版本状态，查询不混合半份索引。

首批格式、复杂表格及图像理解范围待定。不承诺任意格式上传后都能正确理解，也不将预览截取内容直接当作完整文档入库。

## 召回与使用

- 先限定工作区与可访问材料，再结合关键词和向量召回；按需要重排、去重与扩展相邻片段。
- 返回稳定的文档、版本、页码或章节定位，并允许读回原文；来源缺失或版本失效时明确说明。
- 与当前会话问题和有效记忆共同装配有界上下文，检索结果不是无条件追加的全部背景。
- 全文总结、完整统计、系统审阅等任务支持枚举与完整读取，不能只靠相似片段推断全部材料。
- 中文术语、精确名称、跨文档比较、表格及扫描材料按实际支持范围处理；内容不足时报告依据不足。

可向现有单循环提供工作区搜索与来源读取工具，保留已有工具策略和事件观察，不因引入 RAG 强制更换 Agent 框架或另建意图模型。

## 索引与数据生命周期

索引按工作区限定，缓存同样包含范围及版本。文件移动、修改、删除，或记忆被纠正、撤回时，派生索引要更新或失效；不能在原文已删除后继续把旧片段作为有效来源。

保存解析、切分及 Embedding 配置身份，以便模型或解析方案变化后重建。索引可重建，原文及业务元数据需要独立备份；索引发布和业务事务之间的失败用持久任务协调。

本机文件监听需要结合启动重扫和内容核对，不能把收到通知视为唯一依据。具体材料归属、外部目录删除与恢复见[文件专题](files-and-execution.md)。

## 存储与模型建议

当前建议 SQLite 管理权威业务数据，LanceDB Embedded 保存检索索引，并提供全文／混合检索。嵌入式方案适合桌面独立运行，不要求用户维护向量数据库服务，但依赖打包、索引维护及跨平台行为仍需落实。

Embedding 可使用本地模型或外部 API，需明确安装体积、首次处理成本、网络依赖及文档是否发往外部。重排、OCR 与解析也应明确本地或远端执行位置，不能把桌面独立运行自动等同于所有模型完全离线。

[LanceDB Embedded](https://docs.lancedb.com/basics/lancedb-embedded)提供应用进程内的检索存储；[混合检索说明](https://docs.lancedb.com/search/hybrid-search)可作为方案依据，尚不构成本项目选型已完成的结论。

## 责任与依赖

材料服务维护文档身份和版本；解析服务产生可定位内容；索引任务管理发布、更新与删除；检索服务执行范围约束和召回；上下文与工具层读取依据；UI 展示材料状态和原文引用。

依赖[工作区身份](workspaces-and-memory.md)、[本机任务与存储](local-runtime-and-storage.md)及[文件生命周期](files-and-execution.md)。数据库、模型与格式范围明确后再安排实现，不新增独立的概念验证项目。

## 完成条件

- 约定格式的材料可接入和检索，解析失败、索引延迟及取消状态可见。
- 回答依据能够定位回原文与版本，工作区隔离覆盖召回、缓存和读取。
- 修改删除、重启重试、配置改变后重建及不完整索引均有明确处理。
- 实施检查覆盖来源定位、中文与结构化材料、跨文档使用、依据不足及完整读取边界；不把引入向量库本身当作知识能力完成。
