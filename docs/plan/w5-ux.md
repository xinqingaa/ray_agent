所属：[二次开发总计划](README.md)。规模：大，3–4 个对话，分三个阶段：

| 阶段 | 内容 | 前置 | 对话数 |
|---|---|---|---|
| 一 | 设计说明、设计 token、运行视图全部组件与状态，用夹具开发 | W1 | 1–2 |
| 二 | 接入 W4 视图模型，重组会话页、工作台、开发者视图、会话列表与首页 | W4、阶段一 | 1 |
| 三 | 设置页重做 | 阶段一 | 1 |

## 目标与不做

**目标：** 以行业同类产品为标准重做对话、运行视图与设置页。操作者在任一时刻不用展开任何东西，就能看清运行状态、当前动作、计划进度、已用时间与用量；需要时能逐层展开到工具参数、完整输出和模型实际收到的上下文。界面只展示后端真实产生的数据，数据缺失时明确显示不可用及原因。

**不做：** 执行过程回放、费用估算、排队发送、移动端专门布局（窄屏保证可读可操作即可）、新的后端设置能力、营销式落地页。流式增量的数据接入属于 W6，审批的接口接入属于 W7.2，本包只提供它们的组件与全部状态。

## 现状

- 技术栈：Next 16、React 19、Tailwind 4、Radix 与 shadcn 风格基础组件（`components/ui/`）、lucide 图标、react-markdown、sonner、noVNC（[`package.json`](../../ray_agent/ui/package.json)）。
- `globals.css` 只有 shadcn 默认的浅色中性 token，没有暗色 token；依赖中有 next-themes，但应用没有挂载主题切换；业务组件中约 110 处直接写 `gray-*` 类名，颜色与间距没有统一来源；布局没有指定字体。
- 会话页是“对话 + 右侧工具预览”两栏（[`session-detail-view.tsx`](../../ray_agent/ui/src/components/session-detail-view.tsx)），工具预览按工具类型显示 Shell 输出、文件内容、浏览器截图，并可打开 VNC（`tool-preview-panel.tsx`，W5 已删除；[`vnc-overlay.tsx`](../../ray_agent/ui/src/components/vnc-overlay.tsx)）；Shell 输出通过 `GET /sessions/{id}/shell` 读取。
- 工具行只有图标、工具名与参数摘要（`tool-use/`，W5 已删除）；计划面板是独立组件；用量是输入框旁的上下文占用环。
- 设置页是一个 866 行的单文件，含通用配置、模型提供商、A2A、MCP 四个分区（`manus-settings.tsx`，W5 已删除）。

## 设计方向

实施时读取项目 skill [frontend-design](../../skills/frontend-design/SKILL.md)，按其两遍流程工作（先写设计方案并对照需求自审，再实现，实现中截图自评）。以下项目约定覆盖该 skill 的默认倾向：

- **产品类型：** 给操作者长时间使用的专业工具，不是营销页面。没有 hero；首屏就是任务输入与最近会话。信息密度与可扫读优先于视觉冲击。
- **参照：** 信息组织参照 Manus（对话与“电脑”工作台并列）、Cursor 与 Codex（计划清单随执行勾选、每个工具一行动词摘要、审批按钮）、ChatGPT 与 Claude（工具行折叠、运行中指示、可折叠的过程细节）、[Vercel AI Elements](https://elements.ai-sdk.dev/) 的组件划分（Tool、Plan、Task、Confirmation、Context、Shimmer、Terminal）。参照结构与交互，不照搬视觉。
- **记忆点只放一处：** 运行视图，即状态条、计划条与工具流。其余区域安静克制。
- **颜色：** 中性底色加一个强调色；状态色语义固定（运行中、等待、成功、失败、已停止、已中断），亮暗两套主题都满足 WCAG AA 对比度。不采用 skill 列出的生成式默认组合。
- **字体：** 中文使用系统中文字体栈；西文与数字选一款有等宽数字的无衬线字体，所有计时与计数用等宽数字；命令、路径与代码用等宽字体。
- **动效：** 只用于回应操作（展开、确认、状态切换）和“正在运行”的指示，同屏只有当前动作一处持续动画；遵守“减少动态效果”系统设置。
- **文案：** 用户视角的动词与名称（“读取文件”“运行命令”“交付文件”），内部工具名只在展开详情和开发者视图出现；错误说明发生了什么和怎么处理，不道歉、不含糊。

## 设计

### 布局

```text
┌──────────┬───────────────────────────────┬────────────────────┐
│ 会话列表  │ 运行状态条                      │ 工作台（可收起）     │
│ 状态徽标  │ ───────────────────────────── │ 终端 | 浏览器 | 文件 │
│          │ 时间线                         │                    │
│          │                               │                    │
│          │ ───────────────────────────── │                    │
│          │ 计划条（折叠时显示当前项）        │                    │
│          │ 输入框 · 上下文环 · 停止         │                    │
└──────────┴───────────────────────────────┴────────────────────┘
```

开发者视图是会话页的一个可切换视图（与对话视图同位置切换），不另开页面。窄屏时工作台与会话列表改为抽屉。

### 组件与状态

每个组件在组件状态目录页中逐一列出下表的全部状态。数据来自 [W4 视图模型](w4-ui-data.md#视图模型契约)。

| 组件 | 内容 | 必须覆盖的状态 |
|---|---|---|
| 运行状态条 | 状态、实时走秒的已用时间、第 N 轮/上限、当前动作一句话、本次运行 tokens、停止按钮；W6 后增加生成速度 | 空闲、模型思考中、工具执行中、等待回复、等待审批、停止中、已完成、失败（含原因）、已停止、已中断 |
| 计划条 | 进度（如 3/5）、当前项与其用时；展开为完整清单与说明；更新时标记变化项 | 无计划、进行中、全部完成、运行结束时有未完成项、计划被修改 |
| 工具卡 | 按 `family` 的图标、动词标题、关键参数、状态、耗时、结果摘要（退出码、“完整输出已保存”）；展开看参数与结果原文；点击在工作台打开 | 运行中、成功、失败、被拒绝、未执行、已取消、结果被截断、参数过长 |
| 工具组 | 一轮多个调用时的分组标题（如“3 个操作”）与整体状态 | 部分完成、全部成功、含失败 |
| 旁白与最终回复 | Markdown；最终回复下方附运行汇总（用时、轮数、工具数、tokens） | 短文本、长文本与代码块、表格 |
| 用户消息 | 文本与附件；运行中注入的消息标“补充要求” | 普通、带附件、补充要求 |
| 提问卡 | 问题；输入框提示“回复将继续当前任务” | 等待回复、已回复 |
| 审批卡 | 工具、参数高亮、批准与拒绝按钮，支持键盘 | 待审批、提交中、已批准、已拒绝、已失效（运行中断） |
| 交付卡 | 文件类型图标、名称、大小、预览、下载、全部下载 | 单文件、多文件、预览不可用 |
| 压缩提示 | 一行说明与前后估算量 | — |
| 失败尝试提示 | “第 N 次请求失败：原因，已重试” | 已重试、最终失败 |
| 终态条 | 失败原因（可读文字）、已停止、服务重启导致中断；失败时的“以相同内容重试” | 各非 completed 终态 |
| 上下文环 | 占用百分比、剩余量、最近一轮用量；发生过压缩时标记 | 无数据、正常、接近水位、已压缩 |
| 会话列表项 | 标题、时间、状态徽标（运行中、等待你、失败） | 各状态、选中、长标题 |

### 工作台

- **终端：** 显示所选或最新 Shell 调用的输出；调用运行中时按现有 `GET /sessions/{id}/shell` 间隔轮询刷新，结束后停止；W7.1 修复前长命令可能在结束后才返回，如实显示。
- **浏览器：** 所选调用的截图；可打开 VNC 实时画面（沿用现有能力）。
- **文件：** 所选文件工具调用的内容预览；会话文件（上传与交付）列表，可预览与下载。
- **跟随：** 默认跟随最新的工具调用；用户手动选择某个调用后固定显示，直到点击“回到最新”。

### 开发者视图

- **事件流：** 表格列出 seq、时间、类型、所属运行与摘要，可按类型过滤，展开看 JSON 原文。
- **轮次：** 每轮一行：用时、模型耗时、工具耗时、tokens、`finish_reason`、上下文构成条（系统提示词、工具 schema、历史、工具结果）；W6 后增加首字延迟与尝试次数。选中一轮时，通过 W3 的请求重建接口显示模型实际收到的消息列表。
- **压缩：** 列出每次压缩的前后估算量与摘要全文。
- **导出：** 下载会话的运行与事件 JSON。

### 首页与空状态

首页是任务输入框加最近会话；没有会话时给出 3 条可直接发送的示例任务（取自评测任务的改写）。各面板在无数据时说明“这里会显示什么、什么时候出现”。

### 设置页（阶段三）

- 拆分为分区组件：通用、模型提供商、A2A、MCP，各自一个文件；预留“工具策略”分区位置，由 W7.2 实现内容；
- 统一表单体验：字段说明、即时校验、保存中与保存结果、未保存离开提示；MCP 与 A2A 列表显示启用状态与配置摘要；
- 只使用现有设置接口，不新增后端能力。

### 质量底线

亮暗主题与跟随系统；所有交互元素可键盘操作并有可见焦点；图标按钮有可读名称；遵守减少动态效果；时间线在数百条事件时保持流畅（必要时虚拟化）；窄屏（390 px 宽）可读可操作。

## 实施修正（2026-09-29）

阶段二以代码为准，相对本文原稿有这些差别：

1. 会话页改为只消费 `useSessionDetail` 的 `view`。停止调用 hook 的 `stop()`。运行中输入框可以发送，不再被停止按钮替换。
2. 旧时间线已删除。`session-events.ts` 只保留事件归一化。`eventsToTimeline`、`collapseRetriedTurns`、`getLatestPlanFromEvents` 以及按步骤渲染的 `tool-use/`、计划面板、旧工具预览不再存在。
3. 工作台的终端轮询沿用现有客户端 `sessionApi.viewShell`，这是 `POST /sessions/{id}/shell`，不是原稿写的 GET。调用仍在运行且参数里有 `session_id` 时，约每 1.5 秒读一次，结束后停止。
4. 工具标题用投影里的动词（「读取文件」「运行命令」），完成后不再显示「正在…」。等待中的会话在侧栏是「等你回复」徽标，不是加载图标。
5. 审批卡只渲染视图里的 `approval` 条目，不调用批准或拒绝接口。
6. 运行已经是 `running`、但还没有 `turn started` 时，状态条仍显示「模型思考中」：状态条把这种运行归到模型相。开发者视图在轮次事件到达前写「还没有轮次记录」。
7. 详情里的运行没有 `maxTurns`，状态条的轮次上限留空。时间线没有做虚拟化。`watermarkRatio` 由轮次开始事件的水位 token 数除以 `context_window` 得到，不是配置里的 0.75 原样抄入。
8. 视图模型类型没有增删字段。投影补读了事件里的真实键名：`context_estimate.system_prompt` 与 `tool_results` 写入构成；`watermark` 是压缩水位的 token 数，有窗口时 `watermarkRatio` 为二者之商。契约已回写 [W4](w4-ui-data.md#视图模型契约)。
9. 2026-09-29 用 Playwright 在 `http://localhost:8088` 走查。状态条工具相的文案是「执行工具」加上动词，不是「正在执行工具」。E2 交付下载、E3 提问、E4 在执行工具时停止、多工具与计划条、工作台跟随、开发者视图的构成和重建请求、暗色与窄屏已截图。刷新不重复只发生在仅有 2 条事件时。运行中断网补齐没有做成。API 重启中断文案未走查。「停止中」没有单独截到。对比度自动检查和设置页逐项保存仍未做。

## 完成后界面微调（2026-09-29）

用户反馈了状态视觉、开发者视图操作以及展开行为，本次只处理这三项：

- 侧栏和运行状态条改为语义色纯文字，不再叠图标或底色；侧栏时间靠左、需提示的状态靠右，已完成与已停止只显示时间。运行状态条在桌面宽度固定高度内垂直居中。
- 开发者视图把事件类型筛选与 JSON 导出收进紧凑页头，事件类型加中文名称。事件摘要区分上下文追加、清理推理字段、替换和真正的压缩；`context` 不再一概写成「上下文压缩」。
- 事件原文和轮次请求面板点击展开、再点收起，提供短过渡与减少动态效果适配。轮次请求面板应紧跟所点击的轮次；2026-09-29 首版错误地放在整个轮次列表底部，复核后改为逐轮内联。
- 事件表格的摘要曾把“原文”等短列挤成竖排。固定短列宽度，摘要使用剩余空间；可用宽度不足时只在表格内部横向滚动。
