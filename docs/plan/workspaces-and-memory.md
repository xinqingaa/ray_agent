# 工作区与长期记忆

本专题处于设计讨论。工作区间隔离、工作区内共享是已确认需求，具体对象结构、记忆模型与界面尚待细化；本轮不实施领域模型或提示词改动。

## 目标与当前基础

项目应成为可长期维护的工作区，容纳目标与工作方式、共享材料、多个会话、记忆、笔记、工具及成果。不同工作区之间不自动共享私有背景，同一工作区的会话能使用相关且仍有效的共同信息。

当前项目已保存说明、版本化笔记、文件与其他会话摘要，并在新运行受理时选择、冻结背景。笔记主要通过整体替换维护，跨会话背景主要依靠有限近期摘要，尚无完整的逐条知识维护与检索机制。现状见[长期背景](../harness.md#什么进入长期背景)、[项目记忆](../product.md#项目记忆)与[实现索引](../code-map.md#托管项目与记忆)。

## 对象职责

| 对象 | 建议职责 |
|---|---|
| 工作区 | 稳定身份、目标、要求、配置与数据归属 |
| 工作方式／角色模板 | 可复用的配置，不承载其他工作区的私有事实 |
| 会话 | 具体问题的消息、运行与局部工作上下文 |
| 长期记忆 | 可独立更新的事实、偏好、决定及其来源与适用范围 |
| 笔记与文档 | 用户可编辑和组织的完整材料，不强行全部转成记忆条目 |
| 知识索引 | 帮助寻找材料与记忆的派生数据，详见[知识检索](knowledge-and-retrieval.md) |

角色名称不作为隔离身份，也不成为通用系统提示中的固定业务分类。相同角色模板可以用于多个互相隔离的工作区。

## 建议的记忆维护方式

- 将长期记忆拆为可独立维护的条目，记录来源会话或材料、内容版本、适用范围、确认状态及被替代关系。
- 用户明确要求记住、纠正或删除时有直接入口；Agent 提炼内容保留依据，不把推断或文档中的陈述自动升级成已确认事实。
- 自动整理先形成可追踪的变更，避免逐轮追加日志和整篇改写丢失旧结论；冲突、去重、替代和失效需要独立规则。
- 保留自由笔记与完整材料。记忆条目帮助召回，用户不必将所有表达拆成固定结构。
- 用户可以查看、编辑、撤销或删除记忆，并设置某些会话或材料不参与自动记忆；相关派生索引同步失效。

当前笔记和摘要迁移时保留原文与来源，不将既有摘要批量视为经过确认的事实。是否允许默认自动记忆、何种变更需要人工确认，继续讨论。

## 读取与上下文装配

每次任务结合精简的稳定说明、当前会话工作上下文、相关记忆与检索材料。共享不等于将全部历史和文档塞进每次请求，未召回也不等于删除。

保留本次运行所用背景和来源的版本身份。新编辑何时对活动运行生效、是否提供明确刷新入口，需要与运行快照、审批及请求重建共同确定，不能静默重写已经发生的模型输入。

检索出的原文作为材料进入上下文，不改变工具权限。用户要求、确认事实、历史摘要、模型推断和外部文档保持可区分的来源。

## 隔离与并发

由服务端绑定工作区身份，覆盖数据库访问、检索范围、缓存、文件资源、任务和工具配置，不能依赖模型自行避免串用。用户级通用 Skill 可共享方法，不能据此共享项目记忆。

多个会话的记忆编辑采用版本与冲突处理。共享文件写入的占用见[文件专题](files-and-execution.md)；纯对话、只读检索和记忆维护不应无条件套用整个项目的文件写锁，具体并发规则仍需明确。

## 责任与依赖

工作区应用服务维护身份、配置、准入和数据生命周期；记忆服务维护条目、来源、版本与变更；上下文装配选择材料并记录实际版本；UI 提供说明、记忆、笔记、资料及来源阅读入口。

依赖[本机存储](local-runtime-and-storage.md)，向[知识检索](knowledge-and-retrieval.md)、[文件环境](files-and-execution.md)和[Skill](skills.md)提供统一范围。工作区是否直接复用现有项目 ID，以及独立对话如何进入工作区，需要在数据迁移前确定。

## 完成条件

- 工作区内多会话可使用相关共同记忆，不同工作区的查询、工具与缓存不会自动串用私有内容。
- 记忆可追溯、纠正、替代和删除；写入失败、版本冲突或未确认推断不会被表述为已记住的事实。
- 用户能区分说明、记忆、笔记、文档和会话上下文，并理解实际纳入运行的材料。
- 旧项目背景迁移保留来源与内容，活动运行背景的更新规则可重建。

## 待讨论

工作区与项目的身份关系、是否允许无工作区会话、角色模板结构、记忆类型、自动记忆准入、用户确认方式、条目与自由笔记的关系、活动运行刷新、并发会话及工作区导出删除范围。
