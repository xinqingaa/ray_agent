# 工作区与长期记忆

本专题定义工作区的组成、文件夹身份、工作方式、记忆维护与上下文装配，按计划实施中，进度见[实施状态](implementation.md#实施状态)。工作区形态与身份标记按[决策 D7、D8](decisions.md)，自动记忆强度按 D4。

## 目标与当前基础

用户为一件长期的事打开一个本地文件夹，在其中分多次对话推进。新对话不必重新交代背景：工作区保存这里的工作方式、从历次对话沉淀的记忆，以及文件夹中的材料与成果。不同工作区之间不共享任何私有内容。

原托管项目保存平台文件副本、用户设置的说明、用户与 Agent 整篇维护的版本化笔记，以及其他对话的摘要，新运行受理时冻结这些背景；说明与笔记都要求用户维护文档，跨会话背景主要依靠有限近期摘要，没有逐条记忆与检索。P1 已删除托管项目的接口、服务、存储与事件，当前只有独立对话，新运行没有长期背景段，运行快照仍保留冻结与等待沿用的位置。有来源的会话摘要生成逻辑保留给 P5 的会话摘要：材料选择、生成与多会话注入预算及其规则（材料截止序号、生成代次、失败不覆盖、迟到不写回）位置见[代码地图](../code-map.md#上下文与记忆)，当前没有调用方。现状见[长期背景](../harness.md#什么进入长期背景)。

## 工作区由什么组成

一个工作区绑定一个本地文件夹，并拥有以下状态：

| 组成 | 职责 | 权威存储 | 进入运行的方式 |
|---|---|---|---|
| 文件夹 | 用户材料与 Agent 成果 | 用户磁盘原位 | 文件工具直接读写；已登记文件经检索进入 |
| 工作方式 | 在这里 Agent 是谁、怎么做、什么不做 | 应用库中带版本的短文本 | 每次新运行整段进入系统提示 |
| 记忆 | 从对话沉淀的事实、偏好、决定与约束 | 应用库中的记忆条目 | 常驻层每次注入，检索层按问题召回 |
| 会话 | 一次次具体推进，含消息、运行与事件 | 应用库 | 只注入当前会话历史；其他会话经摘要被检索 |
| 检索索引 | 文件、记忆与会话摘要的全文和向量索引 | 应用数据目录，派生且可重建 | 初始召回与检索工具 |

工作区不设笔记，也不设独立的说明页。需要长期保存的长文就是文件夹里的文件，与其他材料走同一条登记和检索管道；待办沿用计划清单；会话摘要自动生成且只读。同一类内容只有一个归属：做事方式在工作方式，沉淀的结论在记忆，材料与成果在文件夹，用户不必维护几份内容相近的文档。

独立对话不属于任何工作区，`workspace_id` 为空，不写入记忆，也不查询任何工作区的索引。会话创建后归属不变；用户要把独立对话的内容带进工作区时，显式选择内容并保存为该工作区文件夹中的文件。

角色名称不是隔离身份，也不进入通用系统提示的固定分类。两个使用相同工作方式的工作区仍各自隔离。

## 文件夹绑定与身份标记

新建工作区在默认位置创建空文件夹；打开工作区则由桌面原生选择器登记已有文件夹。登记记录规范路径与文件系统身份。工作区文件夹不能互相嵌套，也不能是应用数据目录或系统目录；文件夹规模很大时先展示扫描结果，由用户决定索引范围。

文件夹中写入 `.rayagent/workspace.json`，只保存身份信息：本机安装身份与 `workspace_id` 的对应，不含名称、工作方式、记忆或会话内容。`.rayagent/` 始终排除在索引、文件列举和 Agent 文件工具之外。业务库、索引与备份对象保存在系统应用数据目录，不写进文件夹。

- **移动或改名**：原路径失效后，用户打开新位置，应用凭标记认回原工作区并更新绑定，随后按内容核对重新索引。
- **文件夹失联**：工作区标为文件夹不可用，会话与记忆仍可阅读并继续对话，文件工具与索引更新暂停；不在原路径自动创建空目录替代原材料。
- **复制出的文件夹**：打开一个带有已知标记、但文件系统身份与当前绑定不同的文件夹时，要求用户选择作为新工作区（重写本机条目）或改绑到这里（原文件夹解除绑定），不允许两个文件夹共用一个工作区。
- **标记不可写**：文件夹只读或写入失败时，退回按路径与文件系统身份绑定，并提示移动后需要手动重新定位。
- **同步盘**：其他电脑上的应用只追加自己的安装身份条目，不改写其他条目；首批不提供多设备共享同一工作区。

删除工作区通过持久清理任务回收会话、记忆、索引与备份对象，并尝试移除本机写入的标记条目；文件夹及其中的用户文件从不删除。标记移除失败或文件夹失联时，之后再打开该文件夹按新工作区处理。

## 工作方式

工作方式是挂在工作区上、带版本的一段短文本，表达这个工作区里 Agent 的角色、做事原则与禁止事项。它在每次新运行时整段进入系统提示，不经检索；长度有上限，较长的方法论与资料放进文件夹，由工作方式指明使用。上限在实施时归参数页。

用户可以在创建工作区时填写，也可以之后在设置中修改。用户在对话中表达长期要求时，Agent 通过提议工具生成新版本草案，界面展示差异，用户确认后才发布；提议不阻塞当前运行，未确认不生效。记忆提炼任务不能修改工作方式。

模板是工作方式与工具启用建议的副本，由用户把现有工作区“另存为模板”产生，新建工作区时可选。应用模板只复制配置，不带记忆、文件、路径或凭据；产品不内置领域角色模板。

## 记忆模型

记忆分两层：

- **常驻层**：少量最重要的条目，每次新运行在预算内注入。用户钉住的条目优先，其余按类型（约束、偏好、决定先于一般事实）与最近被使用排序。
- **检索层**：其余活动条目，与会话摘要一起按当前问题召回，或由 Agent 经检索工具读取。

条目退出常驻层只表示不再每次注入，仍可检索；首批不做自动遗忘删除。常驻预算在实施时归参数页。

| 对象 | 必要内容与约束 |
|---|---|
| 工作区 | 稳定 ID、名称、文件夹绑定、工作方式当前版本、归档状态、记忆与执行设置 |
| 工作方式版本 | 正文、版本、变更来源（用户编辑或经确认的提议） |
| 记忆条目 | ID、工作区、内容、类型、来源类别、确定性、状态、是否钉住、版本 |
| 记忆来源 | 会话与事件区间，或文件及其修订位置；保留来源可用状态 |
| 记忆变更 | 旧／新版本、操作来源、理由、请求身份、替代关系；撤销产生新变更 |
| 提炼任务 | 会话、材料截止位置、策略版本、代次、结果身份及提交状态 |
| 会话摘要 | 会话、覆盖截止位置、正文、生成代次；只读，可重新生成 |
| 运行背景清单 | 工作方式版本、常驻记忆版本、初始召回来源与实际内容对象 |

类型首批提供事实、偏好、决定和约束。来源类别区分用户操作、用户要求下的 Agent 写入与自动提炼；确定性区分用户确认、材料陈述与模型推断。只有用户操作能设置确认，模型不能通过工具参数把推断标为已确认。

条目状态为 `candidate / active / superseded / retracted`：候选等待用户处理，不参与注入；替代保留前后关系；撤回项不参与召回。

## 记忆写入与提炼

- **明确要求**：用户要求记住或忘掉某事时，Agent 经记忆工具新增或撤回条目，结果作为工具事实进入后续请求；界面给出轻量提示与撤销入口。
- **自动提炼**：运行正常完成后，后台提炼任务读取本会话允许参与记忆的用户消息、最终回复和已引用的有效材料，生成候选事实。对每条候选先在同一工作区检索相似的活动条目，再由模型判定新增、更新、删除或不变，并指明目标条目。
- **生效规则**：按 D4，新增直接生效并标为自动提炼；更新或删除只能直接作用于自动提炼产生且未经用户确认的条目。目标是用户创建、用户要求写入或已确认的条目，或依据不足时，结果保存为候选，原条目不变。
- **用户控制**：工作区可关闭自动提炼；单个会话可设为不参与记忆，适合敏感谈话；被撤回的条目记录来源抑制，同一截止材料不再重复生成，新的明确要求可以解除抑制。

相似检索在语义索引交付前使用全文检索。去重与矛盾判断依赖模型，不是程序保证；用户撤销与版本约束承担最终控制。提炼固定截止位置并先提交代次，迟到结果不能覆盖用户编辑；失败不改变主运行结果，也不能宣称已记住。提炼不读取其他工作区、独立对话或全部工具日志，辅助模型用量单独记录。

会话摘要沿用现有有来源摘要的生成方式，用于会话列表与跨会话检索，不提供正文编辑，也不提升为记忆条目。

## 上下文装配

新运行受理时，上下文装配按以下顺序组织内容并记录运行背景清单：

1. 产品基础系统提示。
2. 当前工作方式版本。
3. 常驻层记忆。
4. 以当前用户问题在本工作区做一次有界初始召回，覆盖检索层记忆、会话摘要和已索引文件。
5. 当前会话历史，沿用现有压缩与容量治理。

工作方式、记忆与检索内容都计入统一请求预算。未进入本次请求不等于已删除；初始选择与剔除原因可在“本次参考”中查看。

活动运行和等待续接沿用已冻结的版本，后台新增条目不自动进入正在执行或等待的请求。Agent 可经检索与记忆工具显式读取当前版本，读取结果形成新事件；自己写入成功的条目作为工具事实进入后续请求。删除、撤回或撤销访问优先于冻结引用：下一次请求前移除不再可用的内容并记录上下文修订。撤回记忆不删除来源会话；历史上已发送给外部模型的内容无法撤回。

检索出的材料只作为参考，不改变工具权限；工作方式、用户确认事实、模型推断、会话摘要与文件内容在请求中保持可区分的来源标记。

## 隔离与并发

工作区身份由服务端从会话解析，覆盖数据库访问、检索范围、缓存、文件、后台任务与工具配置；模型工具不接受工作区参数。用户级 Skill 可在各工作区复用方法，不能借此共享记忆或材料。按 D5 启用的 Shell 以当前系统用户权限运行，可能访问文件夹以外的文件，因此隔离成立于应用数据与工具服务，不是进程沙箱。

同一工作区的多个会话可以并行对话、检索和维护记忆；记忆变更按版本协调，冲突返回最新版本。文件写入的协调见[文件专题](files-and-execution.md#写入与撤销)。模型服务没有对任务正确性的恰好一次保证，提炼结果按来源截止与内容身份幂等发布。

## 界面与用户操作

- **工作区主界面**：左侧会话列表，中间对话，右侧文件夹面板（文件树、索引状态、本次成果）；记忆不占主界面。
- **本次参考**：每条回复可展开查看实际使用的工作方式版本、记忆条目与检索来源，点击来源回到对应会话或文件修订；失联来源如实标明，不伪造跳转到新版本。
- **记忆**：自动保存与明确记住的结果以轻量提示出现并可撤销；记忆面板按常驻、检索、候选列出，可查看来源、修改、钉住、确认与撤回。
- **设置**：编辑工作方式、另存为模板、自动记忆开关、本机执行开关与索引范围；归档后工作区只读，删除走统一清理。

## 责任与依赖

工作区服务维护身份、文件夹绑定、标记、准入与生命周期；记忆服务维护条目、来源、版本与变更；提炼与摘要由后台任务调度；上下文装配选择内容并记录运行背景清单；UI 提供会话、文件夹、记忆、本次参考与设置入口。

依赖[本机存储与后台任务](local-runtime-and-storage.md)和[文件夹访问](files-and-execution.md)，向[知识检索](knowledge-and-retrieval.md)提供记忆与摘要条目，向 [Skill](skills.md) 提供工作区范围。

## 实施检查

P3 交付工作区身份、文件夹绑定与标记；P5 交付工作方式、记忆、提炼、会话摘要、上下文装配与对应界面，并建立检索端口与全文底座，记忆与摘要的检索不等待文档索引。检查覆盖两个工作区与独立对话互不可见、新会话读到同一工作区的工作方式与常驻记忆、同主题矛盾转候选、用户编辑期间迟到的提炼、撤回后再次提炼、不参与记忆的会话、等待续接期间的新条目、删除后的缓存，以及文件夹移动、复制与失联。

## 完成条件

- 新会话无需重新交代背景即可使用同一工作区的工作方式、记忆与相关材料；其他工作区与独立对话读不到这些内容。
- 用户无需维护说明或笔记文档；工作方式经用户确认才变化，记忆可追溯、纠正、撤回与撤销。
- 写入失败、版本冲突或未确认推断不会被表述为已记住的事实。
- 文件夹移动、复制、失联与删除工作区有明确结果，用户文件不被删除。
- 用户能从“本次参考”理解一次运行实际使用了哪些背景。
