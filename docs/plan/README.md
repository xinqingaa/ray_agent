# 维护与优化计划

RayAgent 已完成单循环 Harness、托管项目及随后多轮优化，转入维护。当前机制见 [Harness 工程](../harness.md)和 [架构说明](../architecture.md)。本入口维护重要阶段结论、验证概况和按问题归并的优化方案。已完成方案保留设计、依赖与完成条件，状态明确标注，不自动恢复为待办。

## 关键验收

历史验证覆盖以下种类：

- 脚本化模型：循环、计划、上下文、审批与停止。
- 独立 PostgreSQL 与临时磁盘：事务、文件保护和恢复。
- 受控 Chromium 与 UI 走查：浏览器契约与页面交互。
- 有限真实模型及独立产物核对：交付、内容口径和业务行为。

验证条件各不相同，不能合成当前版本全面认证。真实任务曾完整交付却未通过业务或交互核对，不能由 completed 推断正确。

最终规划粒度、最新 Responses 上游兼容、多实例、真实 COS 与完整移动设备交互未完成全面运行验证。历史报告和产物不留存，需要验证时按服务指南重新建立条件与独立预期。

输入命令菜单维护包含稳定高度、鼠标高亮与键盘滚动分离、移除项目命令及共用上下文圆环。验证覆盖菜单与输入组件回归、圆环一致性、命令禁用、开发者显隐、类型检查与生产构建；浏览器通过临时只读来源注入长 Skill 列表，核对键盘选中可见、滚轮不回拉、过滤高度、Tab 保留草稿、Escape 关闭及会话占用圆环。未调用真实压缩或发送模型任务，应用容器未更新。

## skill 实施与效果验收

[全局 skill 方案](skills.md)已获完整实施授权。产品功能包括完整包导入、设置维护、显式与自动加载、内置 `find-skills`、持久运行引用及沙箱材料准备，当前机制合入[skill 说明](../skills.md)。

新增、文件阅读、删除和排序的[管理体验优化](skills.md#管理体验优化方案)已获实施授权并完成：保留 GitHub 与本地内容两种来源，材料获取后直接打开内容；支持包文件阅读、待安装正文修订、安装后留在详情，以及内置优先排序。删除修复公共受理层对空 JSON 正文的误解析，保留运行版本引用。

管理优化验证包含真实 HTTP 路由与公共依赖、临时包资源和完整性、独立 PostgreSQL 的删除受理及引用保留、设置组件与异步读取回归，以及真实浏览器的 GitHub 获取、ZIP 自动打开、包内链接与 YAML 阅读、安装前修订、手工创建、编辑保存、包更新和桌面／窄屏走查。核心与协议回归、类型检查、lint 和生产构建通过；条件性数据库及外部测试并未因此全部覆盖，完整移动设备、深色主题和全部文件格式未做全面交互验收。临时浏览器验证曾发生连接中断，同一操作经独立 HTTP 核对成功，恢复后可继续读取；未据此认定服务端发生故障。运行中的应用容器未更新。

工程验证包含包安全和脚本化模型、既有核心回归、独立 PostgreSQL 的并发更新与受理事务、公开 GitHub 固定来源、真实沙箱的相对路径脚本及篡改恢复，以及 skill 设置的交互回归、浏览器设置/输入走查、前端类型检查与生产构建。设置走查包括 Markdown 阅读、文件来源与多候选预览、编辑保存、更新叠层、返回输入及窄屏布局。它们证明相应实现链路，不能证明模型会选择正确方法或成果质量普遍提高。

真实模型对照因开发环境未配置可用 API Key 而未完成；实际请求在模型阶段失败，未获得成果，不能记为有效的无 skill / 显式 / 自动对照。后续配置可用模型后按方案核对发现相关性、兼容性、独立成果、耗时与用量，并检查无关任务回归。产品实施不包含生产部署。

## 维护方式

1. **确认范围**：日常修复按实际影响推进，跨模块工作先说明目标、责任、依赖与完成条件；方案不自动授权实施。
2. **更新设计**：同一问题继续获授权时更新所属专题，独立新问题另建方案，不恢复旧编号或追加逐轮日志。
3. **合入结论**：当前机制进入主体，重大诊断与转折进入背景，专题保留有效设计及实际状态。
4. **简记验证**：只在本入口维护重要验证概况，输出放临时目录。

日常文档更新按[文档地图](../README.md#持续维护与审阅)执行。根 [PLAN.md](../../PLAN.md)仅作导航，阶段结论与验证概况以本页为准。
