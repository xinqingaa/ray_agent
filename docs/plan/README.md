# 维护与优化计划

RayAgent 已完成单循环 Harness、托管项目及随后多轮优化，转入维护。当前机制见 [Harness 工程](../harness.md)和 [架构说明](../architecture.md)。本入口维护重要阶段结论、验证概况和按问题归并的优化方案。已完成方案保留设计、依赖与完成条件，状态明确标注，不自动恢复为待办。

## 阶段结论

| 阶段 | 重要结果 | 定位 |
|---|---|---|
| 旧版教学工程 | Plan + ReAct 双循环，原 16 章验收完成 | 标签 `baseline-v1`；课程正文仍在该基线 |
| 单循环 Harness | 一份记忆、计划工具、上下文治理、运行事件、流式、审批及停止 | 标签 `v2` |
| 托管项目 | 平台文件、快照恢复、占用协调、透明记忆 | 综合验收已完成 |
| 后续维护 | 按需资源、文本/视觉观察、统一预览、稳定范围与阶段、版本核验、分项成果和有限收尾、模型端点配置；会话主区执行状态、消息文件引用和子步骤维护已完成本地定向与真实任务验收 | 已实施并经历定向与有限真实验证 |

这些阶段可以收尾，不表示任意复杂任务稳定或全部能力已验证。最新多模型接入有定向与组件检查，没有该轮真实上游或部署验证；长任务有完整交付但业务口径与交互失败，效率也未全面收敛。部署状态不能仅由源码提交或历史健康检查推断。

原工作包、多轮专项和已结束调研按同一问题合并。主体解释当前机制，[演进背景](../background/README.md)解释问题与选择的形成，下面的专题方案保留跨模块设计和实施关系。逐轮日志、重复草案和完全被替代的协议退出正文；未实施或退出范围的目标不自动转为待办。

## 关键验收

曾运行脚本化模型驱动的循环、计划、上下文、审批与停止检查，独立 PostgreSQL 和临时磁盘的事务及文件保护检查，受控 Chromium 与实际 UI 走查，以及有限真实模型任务和独立产物核对。各阶段条件不同，不能合成当前版本全面认证。最终规划粒度和最新 Responses 上游兼容等范围未完成真实运行验证。

历史报告、案例、日志、JSON、工作簿和其他产物不再留存。需要测试或验收时，按服务指南重新建立条件和独立预期。

## 新工作与维护方式

专题实施已经收尾。Responses 通信、错误分类、计划面板和最近模型偏好已进入源码，实际范围分别见模型与交互方案。配图和课程另行评估，课程入口见 [课程同步范围](../course-sync.md)。

日常修复按实际影响修改、验证并替换所属说明。跨模块成组工作按同一问题规划，写清依据、目标、范围、依赖和完成条件；计划本身不授权实施。已有专题在同一问题继续获授权时可更新有效设计和状态，不恢复工作包编号或追加逐轮日志；独立新问题另建方案。

完成后将现行机制合入主体，背景保留诊断与重大转折，方案保留有效设计、责任、依赖和验收条件，验证概况在本入口简要维护，运行输出留在临时目录。过渡草案和重复材料可退出，不能用“已完成”作为删除整个方案的理由。
