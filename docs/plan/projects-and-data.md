# 托管项目、文件与记忆优化方案

状态：托管项目、文件保护、透明记忆和后续数据清理已实施。本方案保留保护、协调与恢复设计。

分析过程见 [项目与数据保护背景](../background/projects-and-artifacts.md)，当前所有权及路径见 [架构说明](../architecture.md#托管项目执行与文件保护)。本篇保留方案中最重要的保护、协调和恢复设计。

## 目标与范围

项目作为长期材料容器，让多段对话共享文件和可见背景，同时保护原材料、提供恢复入口，并在失败或重启时留下可处理状态。

使用平台文件副本，不接入宿主机任意目录或 Git 身份，不提供本地实时回写。范围覆盖项目文件、快照、上传、交付副本、记忆、占用和资源清理；不建设通用文件版本控制、多实例执行调度或业务内容自动验收。

## 文件、环境与记忆的所有权

| 对象 | 保存与读取 | 寿命及边界 |
|---|---|---|
| 项目文件 | API 文件卷长期保存，沙箱挂载工作子目录 | 与用户原件独立，沙箱销毁不删除长期文件 |
| 快照 | 内容对象与完整清单，由 API 管理 | 沙箱看不到；只保护文件，不回滚记忆 |
| 会话附件 | 本地或 COS 存储与元数据 | 原交付即使文件恢复仍可下载 |
| 沙箱环境 | 某次运行访问项目文件的环境 | 终态收尾，进程和登录状态不保证跨运行 |
| 项目说明与笔记 | 版本化、可查看和编辑 | 新运行冻结，等待沿原快照 |
| 对话摘要 | 来源、截止 seq 和生成代次 | 帮助新对话了解其他工作，不替代原历史 |

API 只读查看和下载不依赖沙箱存活。命名卷子路径只挂 files，快照不暴露；卷名由实际运行环境解析，不能写死 Compose 前缀。API 不在容器时沿所属配置使用本地开发挂载。属主和权限统一，使 API 发布材料后沙箱能够修改。

## 统一文件 IO 与发布

路径验证、目录遍历、快照、统计、下载、预览和恢复使用同一套无跟随语义。普通文件按字节读取；链接保存目标文字，不读取卷外目标；FIFO、socket 等特殊项有明确拒绝或降级。逐级父目录与最终类型核对，不能只在最后一段加 O_NOFOLLOW。

哈希用于实际内容身份，不仅依赖长度和 mtime；对象不复用 Agent 可修改的硬链接。临时文件完整后再发布，准备与发布失败不产生可用清单。项目总量统计注明时间和过期状态，上传准入重新检查，不把缓存当实时数据。

上限约束上传和保护等操作，不是沙箱写入硬配额。超限可以使保护跳过或下载降级，但 IO 损坏必须明确失败；两类出口不能混淆。

## 运行占用与旧写入者

运行、上传、快照、恢复和环境收尾共享协调边界。活动运行包含执行、准备和等待，不能在等待用户时释放文件占用。终态登记 settling，停止项目沙箱并读回静止，之后才允许下一次文件操作。

不能只终止登记的 Shell：后台进程或浏览器也可能写共享目录。Docker 不可达或无法确认时保留失败标记，阻止新运行、上传、恢复及相关写操作，允许重试环境收尾。run 终态不回改，收尾结果另记。

下一次运行先保护文件，再启动环境。迟到准备结果按运行所有权丢弃并清理，不能把旧容器关联回新运行。启动扫描核对遗留执行和项目环境，失败隔离到具体项目。

## 快照与恢复事务

运行前保护当前文件，保留份数可配置，默认值及范围见[运行参数与限额](../limits.md)；上传前和恢复前保护另计。磁盘对象与清单完整发布后才登记 ready，再淘汰旧记录。回收检查对象引用，失败保留可重试状态，不能因为列表为空就断言全部字节已释放。

恢复固定目标及恢复前清单，验证对象哈希与类型，在共享根目录中应用而不替换根身份。进入 applying 后失败或 API 重启保留阻止标记；只读查看可用，用户可重试目标或回到恢复前。

目标损坏、缺失、非法类型或超限时拒绝，保护当前文件。恢复只作用于文件：笔记、摘要、会话、原附件和运行记录不回滚。文件成功恢复也不能证明旧写入者已处理，必须遵守占用流程。

## 上传预检与响应恢复

目录扫描按条件排除依赖、版本库和系统文件，疑似凭据给出明确提醒。普通资料目录不能仅因名称与 build 等相同就被排除；未扫描目录不伪造数量或大小。只上传文件及必要父目录，空目录语义明确。

规则由 API 下发，前端说明与服务端复核共用版本。确认带规范化路径、大小、哈希、冲突与用户选择；服务端按实际字节、当前总量和链接父路径复核。规则或冲突变化返回冲突并要求重新预检，确认不能绕过始终排除项和路径上限。

同名覆盖先保护，发布临时对象再登记。响应丢失时按上传身份读回；相同字节可复用，部分接收、错误哈希和未完整发布对象不能成为当前文件。上传断连、服务端发布成功和客户端收到成功分别核对。

## 交付副本

文件成果上传成为附件时，项目内外路径均明确处理项目副本。附件和副本各自记录成功或失败；副本失败可在终态后按准入补存，不能重新发明一次模型调用或重复上传附件。版本交付的通用设计见 [成果方案](long-task-trust-and-delivery.md)。

## 透明记忆与并发编辑

说明表达固定要求，笔记保存长期结论，摘要记录其他对话做过什么。新运行冻结说明、笔记版本及近期其他对话摘要，当前会话历史不重复注入。背景按容量预算组合，固定输入过大有出口，不能靠无限压缩历史解决。

笔记更新使用版本比较，内容与审计同事务；用户与 Agent 并发写入冲突时返回最新状态，不静默覆盖。说明和笔记分别保存版本。摘要记录覆盖截止位置及代次，手动编辑和重新生成推进代次；迟到自动响应不能覆盖新编辑，生成失败保留原内容。

查看当前组合和活动运行快照需要注明来源。历史笔记取回先进入草稿，保存后生效。摘要有损失，不承诺长期质量、向量检索或所有知识自动纳入。

## 归档、删除与业务清空

归档保留材料与历史并停止新工作，可恢复；永久删除和全局业务清空是持久清理任务。受理时固定目标、资源清单和准入，活动运行、等待、文件操作、摘要生成及压缩未结束时拒绝。

按清单依次处理环境、项目目录、附件和输入流，成功后事务删除业务记录。共享附件还有其他引用时保留。失败保存阶段并允许重试，重启未完成任务成为可重试失败；迟到回调不能复活已删除对象。

全局清空保留模型和服务配置，完成后同步清除相关草稿并刷新列表。这不是跨数据库、Docker 和 COS 的原子事务；未登记云对象也不扫描删除。真实删除验证只使用隔离数据，不用用户材料制造故障。

## 实施依赖与完成条件

| 顺序 | 工作 | 必须保留的检查 |
|---|---|---|
| 1 | 文件归属、挂载、统一 IO 与上传发布 | 属主、链接逃逸、类型、哈希、字节与冲突 |
| 2 | 快照索引、对象发布、回收及恢复 | 多阶段 IO 失败、损坏、超限、根身份、回退 |
| 3 | 项目占用、旧写入者及重启核对 | 等待仍占用、静止后释放、迟到环境不复活 |
| 4 | 说明、笔记、摘要及冻结背景 | 版本冲突、摘要代次、来源、容量与等待 |
| 5 | 项目页面、修复入口与交付副本 | 只读不启环境、失败保留、草稿与异步归属 |
| 6 | 归档、删除与业务清理 | 准入互斥、共享附件、失败重试、迟到回调 |

应用协调器负责准入与事务，文件适配负责真实 IO 和发布，领域模型保存版本和来源，运行器管理环境与副本，前端说明保护状态和修复操作。入口见 [代码地图](../code-map.md)，命令见 [API 指南](../../ray_agent/api/README.md)。

真实 Docker、PG、磁盘、HTTP 和 UI 分别覆盖不同环节。历史恢复故障注入和进程退出支持保护契约，但没有证明多 API 实例、Linux 宿主或真实 COS 的全链路。长期摘要质量与运行间进程连续性仍不承诺。
