# 托管项目、文件与记忆优化方案

状态：已实施并收尾。保留文件保护、写入协调与恢复设计；当前归属和流程见[架构说明](../architecture.md#托管项目执行与文件保护)，问题形成见[项目背景](../background/projects-and-artifacts.md)。

## 目标与范围

让多段对话共享长期材料和可见背景，保护原材料，并在失败或重启后留下可修复状态。采用平台副本，不接宿主机任意目录或 Git，不提供本地实时回写。

范围覆盖文件、快照、上传、交付副本、记忆、占用与清理。

## 文件、环境与记忆的所有权

| 对象 | 设计选择 | 代价或边界 |
|---|---|---|
| 项目文件 | API 文件卷长期保存，只将工作子目录挂进沙箱 | 平台副本与用户原件独立 |
| 快照 | 内容对象与完整清单 | 沙箱不可见，只保护文件 |
| 附件 | 存储适配保存字节，数据库保存关联 | 文件恢复不撤回原交付 |
| 环境 | 运行访问长期文件的执行资源 | 进程和登录状态不保证跨运行 |
| 项目背景 | 版本及来源可见，新运行冻结 | 摘要有损，不是检索系统 |

API 阅读不依赖沙箱。挂载卷名从实际环境解析，不写死 Compose 前缀；本地开发沿所属挂载配置，发布后统一属主和权限。

## 统一文件 IO 与发布

文件操作共用安全访问与发布语义：

- 按描述符逐级遍历并核对父目录和最终类型。链接只保存目标文字，不跟随读取卷外内容；FIFO、socket 等特殊项明确拒绝或降级。
- 版本使用实际内容哈希，不能只依赖大小与 mtime；快照对象不复用 Agent 可写硬链接。
- 临时内容完整后才发布并登记可用清单，不能暴露半份结果。
- 统计注明时效，上传准入重新核对，缓存不作为实时用量。

操作上限不是沙箱写入硬配额。保护超限和 IO 损坏分开处理：前者明确未保护，后者失败，不能混用出口。

## 运行占用与旧写入者

1. 运行、等待、上传、快照和恢复共用协调边界。
2. 运行终态后先登记环境收尾，停止项目沙箱并读回静止；仅终止登记 Shell 不能覆盖后台进程或浏览器。
3. 确认后释放占用。Docker 不可达或状态未知时保留阻止标记，提供收尾重试，不回改运行终态。
4. 下一运行先保护文件再准备环境；迟到回调校验身份，不能挂回旧容器或释放新占用。

启动扫描处理遗留运行与环境，失败隔离到具体项目。

## 快照与恢复事务

快照先完整发布，再登记可用；恢复在已有根目录内应用，二者不共享一个跨磁盘与数据库事务。

- 创建保护前确认当前文件可读取且满足操作限制，失败说明原因，不登记半份快照。
- 对象与清单完整发布后登记可用，再淘汰旧记录。回收先核对引用，失败保留重试状态，不能以空列表推断字节已释放。

恢复单独按以下顺序执行：

1. 校验目标哈希、类型和容量，固定目标及恢复前清单。
2. 保护当前材料，在原根目录内应用，保留根身份。
3. 应用失败或重启后保留阻止标记，允许重试目标或回到恢复前。

只读查看仍可用。恢复不改变笔记、摘要、会话、旧附件或运行记录，也不替代旧写入者静止检查。保存份数等见[运行参数与限额](../limits.md)。

## 上传预检与响应恢复

- **规则统一**：API 下发规则并复核，目录排除结合条件，不因普通资料目录叫 build 就一概排除；未扫描项不伪造大小。
- **确认内容**：规范路径、大小、哈希、冲突及用户选择；服务端按实际字节、当前总量和链接父路径复核。
- **变化处理**：规则或冲突改变要求重新预检；确认不能绕过始终排除项及路径限制。只发布文件和必要父目录，明确空目录处理。
- **覆盖发布**：同名覆盖先保护，完整临时对象发布后登记；部分接收、错误哈希和未完成对象不成为当前文件。
- **响应丢失**：按上传身份读回，同字节可复用，不直接重传覆盖。传输、发布、收到响应分别确认。

## 交付副本

附件和项目副本分别记录成功或失败。副本失败可在终态后按准入补存，不重新执行模型业务动作，也不重复上传已成功附件。通用版本设计见[成果方案](long-task-trust-and-delivery.md#分项成果与交付版本)。

## 透明记忆与并发编辑

- **说明与笔记**分别版本化，笔记内容与审计同事务保存；冲突返回最新状态，历史取回进入草稿后再保存。
- **摘要**保存来源、截止序号与生成代次。编辑和重生成推进代次，迟到响应不覆盖新内容，失败保留原文。
- **运行背景**冻结所选材料，排除当前会话重复历史。等待沿原快照，固定背景超限时明确失败。
- **技术预览**区分候选背景与实际快照，标明来源，候选不冒充已使用输入。

不承诺摘要无损、长期知识质量、向量检索或全部材料自动纳入。

## 归档、删除与业务清空

归档保留材料并停止新工作；永久删除与业务清空采用持久清理任务。

1. 固定目标与资源清单后关闭相关写入准入；活动运行、等待、文件操作、摘要及压缩未结束时拒绝受理。
2. 先处理环境、目录、附件及输入流，再事务删除业务记录；其他会话仍引用的附件保留。
3. 失败及重启保留可重试状态，删除标识阻止迟到回调复活对象。
4. 全局清空保留模型和服务配置，完成后刷新列表并清除相关草稿。

不是数据库、Docker 与对象存储的跨资源原子删除，也不扫描未登记云对象。详细准入和锁关系见[架构清理流程](../architecture.md#删除与业务清空)。

## 模块责任与依赖

| 模块 | 必须先成立的基础 |
|---|---|
| 文件适配 | 无跟随 IO、类型核对与完整发布 |
| 应用协调器 | 活动运行、文件操作及环境收尾共用准入 |
| 运行器与持久模型 | 版本、来源和回调归属可校验 |
| 前端 | 当前文件、冻结背景、冲突及修复入口可区分 |

依赖顺序为：旧写入者静止后释放占用，完整发布后登记快照，恢复前保护当前文件，资源清理成功后删除业务记录。

## 完成条件

- 路径、链接、属主、类型和哈希保持一致，半份发布不可见。
- 上传冲突及响应丢失可读回，快照与恢复失败可修复。
- 等待保持占用，迟到回调不释放新操作，无法确认静止时不继续写入。
- 笔记冲突、摘要代次、共享附件和清理重试保持各自约束。

不提供通用文件版本控制或沙箱项目写入硬配额。验证按 [API 指南](../../ray_agent/api/README.md)选择检查入口，删除及故障注入使用隔离数据。
