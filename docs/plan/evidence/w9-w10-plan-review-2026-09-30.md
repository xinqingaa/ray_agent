## 原计划与 W11 草稿的逻辑问题

1. 初稿只解除长期项目/设置两项限制，却写“用户拍板决策 8–10”；本轮实际授权是整体评估收益/投入，不能冒充用户原话或固定剩余排除项。
2. W11 顶部仍全局“新建对话”，无法从当前项目连续新建；项目行仅定义展开按钮，没有明确点名称怎样打开。收起态只剩新建与设置又使项目入口消失。应规定导航、展开和作用域操作各自行为。
3. “POST session 与绑定同事务，所以两步就不会留空会话”逻辑不成立，后续 chat 仍可失败；不能把 W10 的发送恢复问题全部延期给 W11。
4. 后台建沙箱的建议没有定义 preparing 的所有权。当前 chat 若看到 running 却无 task，会中断旧 run。若只把创建挪后台，第二条消息、stop、迟到创建和审批续接都会出现竞态。
5. 同项目多个 session 有各自会话锁，却直接改同一个目录。无 worktree 又无项目互斥，会相互覆盖；最小替代是同项目单活动运行，waiting 仍占用。
6. 删除项目直接级联删全部任务增加数据损失和资源清理成本，且未定义并发创建/删除。首版归档收益更高、复杂度更低。
7. 项目说明固定首次任务，而 Git 身份 TTL 重建时读取最新设置，导致同一任务环境不一致。两者应统一首次受理快照，并纳入请求重建/容量。
8. 不设 Git 身份并不必然 commit 失败：仓库可能已有身份；“允许 push”也不等于认证成功。身份、认证和策略须分别陈述。
9. 初稿拒绝新加嵌套项目，却打算无条件回填所有旧路径，迁移可能直接违背新规则；没有清点就声称只是“一条 SQL”低估投入。
10. 初稿新增项目接口缺少分页、selected task 不在最近五项时的呈现、归档/不可用历史、多标签同步、草稿切换、外部已有改动含义、临时容器文件寿命。
11. 只叠只读 hooks/config 并用 mock mount 验证，不能证明宿主机隔离。worktree 的 .git 文件、共用目录、缺失路径和脚本执行要明确限制，不能静默降级。
12. 初稿引用的 W10 报告与四张截图在检查开始时缺失，期间已补回。报告记录 API 发起后的挂载/宿主机改写/沙箱停止后仍可读，以及浏览器首发失败；但名为 home 的图实际是 502 页面，两张 changes 图处于读取中，不能证明选择器和两段 diff 完成态。要分别登记原文字记录、实际图片与本轮验证，不能用笼统“通过”覆盖浏览器失败。
13. 课程草稿仍以 v2 为最终代码基线，与总计划延后到工作区验收冲突；已改为首轮基线，开工再核对。
