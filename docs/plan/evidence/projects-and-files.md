## 文件保护与故障验证

专项日期 2026-10-01 至 10-02，包含 `203fa083`、`abaff8b`、`a22e1ca`/`1a37012` 及后续 `89aa642` 的不同基线，未将早期故障注入说成最终提交全部重跑。

| 机制 | 条件及观察 |
|---|---|
| 文件归属与旧写入者 | 真实 Docker 命名卷子路径，ubuntu 可修改项目文件、看不到快照目录；旧后台标记停止增长，等待提问环境保留 |
| 恢复异常 | 四个 IO 阶段注入 OSError 或 worker 退出，16 个隔离场景分别重试/回到恢复前；80 个写入请求被拒、32 个只读请求成功 |
| API 进程退出 | HTTP 恢复中四阶段退出，两种修复共 8 场景，重启及字节/链接/属主/根 inode 核对通过；未保存完整八条 Docker die 事件 |
| 快照发布与回收 | 八场景注入故障，ready 快照保持可加载，未发布对象收敛，回收失败可重试；同长度且恢复 mtime 的改写仍有新内容哈希 |
| 损坏与超限 | 损坏/缺失对象恢复拒绝且当前文件不变；501 MiB 材料使保护降级或恢复拒绝，真实超限任务之后另因模型 401 失败，不能称模型任务通过 |
| 上传断连 | 真实 Nginx/HTTP/PG/磁盘，响应体丢失后读回已发布；同内容复用，中断及错误哈希未发布；到期通过改时间字段触发，不是连续等待十分钟 |
| 真实界面修复 | 恢复失败的只读与阻止状态、两种修复、归档与快照回收、目录上传实际走通；迟到响应竞争另有组件替身检查 |
| 项目交付副本 | 工作区外附件可下载，副本失败单独补存，不新增工具事件；终态停止项目环境后仍可补存 |

探针错误、半关闭 TCP 未成功模拟响应丢失等首次检查失败没有解释为产品成功；修正方法后的观察也没有外推为所有 UI 网络故障恢复。
