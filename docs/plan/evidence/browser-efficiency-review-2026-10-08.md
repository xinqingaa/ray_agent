## 收益证据的含义

复用首轮同模型、同提示、本地受控页面的单次观察；本次没有重新调用真实模型。

| 任务 | 模型轮数 | 墙钟 | 可支持的结论 |
| --- | --- | --- | --- |
| 网页取数 | 3 → 2 | 12.023 → 11.286 秒 | 导航观察可减少一次补读；零自动截图已验证 |
| 表单与截图 | 16 → 5 | 34.064 → 13.499 秒 | 标准动作和显式截图消除了大量绕路；最终只有一个截图附件 |
| 纯回答 | 1 → 1 | 9.801 → 7.749 秒 | 尚未消除固定准备成本；改造后沙箱准备 6048 ms、模型 684 ms |

表单基线包含 8 次 Shell 调用及截图脚本返工，不能把差额全部归因于取消自动截图或模型合批。缓存冷热不同，输入 tokens 下降也不能直接当作账单下降。原镜像无 commit 标签，前后数据只能作为本机观察，不能外推普遍提速比例。

## 本次定向复核

按 API 指南的浏览器检查入口，在当前锁定依赖和本机 Chromium 1217 上运行 `test_browser_efficiency.py`：**6 项通过，4.72 秒**。随后用临时脚本补充受控场景；没有修改产品或测试源码。下表是缺陷复现结果，不是新增通过用例。

| 编号 / 优先级 | 复现方式 | 实际结果与影响 |
| --- | --- | --- |
| R1 / P1 | 观察按钮取得 ref；用 `cloneNode(true)` 复制节点、改变按钮文字和点击行为，再替换旧节点；用旧 ref 点击 | 返回 success=true，执行了新按钮。`_target()` 只校验标记唯一及 tag/href/type，无法证明仍为原 DOM 节点；旧引用可能执行不同动作 |
| R2 / P1 | 输入框已有焦点；点击另一个会阻止 mousedown 默认行为的非输入区域，调用坐标输入 | 返回 success=true，原输入框由 old 改为 WRONG。坐标路径直接 fill 当前 `:focus`，没有证明焦点就是指定位置的输入目标 |
| R3 / P1 | 在一次性 Chromium/CDP 中观察现有页取得 tab/ref；为同一浏览器新建第二个适配器，重放调用 | 指定旧 tab 时返回“标签页不存在或已关闭”；省略 tab 时旧 ref 也失败，新适配器当前页是 about:blank，原页面仍存在。应用审批续接会新建任务和适配器，再重放原调用，因此该组件问题会影响浏览器审批；本次未走真实 HTTP 审批全链路 |
| R4 / P2 | ScriptedLLM 一批返回 click(observe=text) 与 input；前一个工具返回 action_success=true、observation_status=failed | 后一个 input 仍执行 1 次，没有 skipped。批次只判断 success，状态观察失败不会使其停下；同批后续写操作可能在状态未确认时执行 |
| R5 / P2 | 页面包含隐藏祖先中的 main 和另一段可见正文；调用 mode=text | content 为隐藏的 HIDDEN_VALUE（Markdown 转义下划线），可见的 VISIBLE_VALUE 被遗漏，incomplete=false。优先根节点选择没有核对祖先可见性 |

R1、R2、R5 使用实际无头页面；R3 使用独立临时用户目录与两次真实 CDP 连接；R4 使用实际循环和工具管线、脚本化模型与浏览器替身。全部临时浏览器及目录已关闭/清理，未操作用户网页或业务数据库。详细机制入口见[代码地图](../../code-map.md#执行环境)。

这解释了“已有测试通过”和“仍有缺口”可以同时成立：既有场景覆盖重新观察失效、不同 tab 隔离与普通失败；没有覆盖节点克隆替换、旧焦点、适配器重建和观察失败的批次组合。
