# 本机核心与存储

本专题描述待讨论的桌面运行底座，尚未开始实现。独立运行是需求；Python sidecar、SQLite 和本机消息协调是建议技术，尚未逐项定案。

## 目标与现状

桌面应用不依赖另行部署 RayAgent 服务器。建议安装包及应用管理的组件提供核心所需运行时，由应用启动、观察与回收，避免要求用户手工运行现有 Compose 服务栈。

当前业务依赖 PostgreSQL、Redis 和文件存储，API 装配连接 Docker 沙箱；数据库包含 JSONB、PostgreSQL 专有 SQL、索引与 advisory 锁。输入流和变更通知依赖 Redis，实际执行协程仍由 API 进程持有。现有边界见[状态与持久化](../architecture.md#状态与持久化)，实现见[代码地图](../code-map.md#状态与持久化)。

## 建议的职责划分

- **Python 核心**：保留单循环、模型与协议适配、工具管线、计划、审批、运行记录和项目应用服务；暴露 HTTP／SSE，不重写成第二套 Rust Agent。
- **Tauri 宿主**：启动随包发布的核心，确认就绪与实例身份，处理版本不兼容、崩溃、退出和托盘生命周期，只回收本应用拥有的进程。
- **业务存储**：SQLite 保存会话、运行、事件、配置、工作区记忆与持久操作；核心是业务写入入口，前端不直写数据库。
- **检索存储**：嵌入式索引由[知识检索专题](knowledge-and-retrieval.md)负责，原始材料和权威业务数据不由向量索引代替。
- **输入与通知**：本机输入协调与事件通知替换 Redis；受理、去重、持久状态和重连补读以数据库记录为准，通知不能成为唯一依据。
- **执行资源**：文件、Shell、浏览器和可选隔离环境按[执行环境契约](files-and-execution.md)准备，不要求所有会话先启动容器。

建议以 PyInstaller 产物随安装包发布 Python 核心，各系统与架构分别构建。原生依赖、子进程模块、模型 SDK、解析库和浏览器组件必须实际核对，不能由“Python 可打包”推导本项目依赖已兼容。

## 通信与生命周期

默认本机 API 只接受本机访问，并建立应用实例级的访问边界；移动远程入口单独配对和授权，不因启用桌面客户端自动暴露到局域网。

桌面 UI 使用本机核心，移动客户端如实施则使用桌面提供的同一业务协议。协议包含运行、事件序号、资源身份及能力范围，保留流式重连和审批去重；手机不直接访问桌面数据库或本地路径。

关闭窗口、留在托盘、真正退出和操作系统休眠分别定义。核心异常后从持久记录核对运行与外部资源，不自动重放结果未知的工具调用。现有提问续接、审批失效和重启中断语义应保留或明确替换，不承诺任意位置自动续跑。

## 存储迁移与数据保护

1. 明确现有会话、事件、运行快照、项目、文件、Skill 引用及配置的目标存储与身份映射。
2. 替换 JSONB 操作、锁、唯一约束、事务与并发协调；确认单机 SQLite 写入方式和后台任务的连接边界。
3. 将数据库、附件、项目文件和引用关系作为配套迁移对象，支持备份、校验与失败恢复，不只复制表数据。
4. 固定迁移输入和目标版本，保留可读回的结果；迁移成功前不删除旧数据，明确回退后新旧写入不能自动合并。
5. 用户选择的原目录与应用自有文件分开管理；清空业务数据、卸载和工作区删除不能误删外部目录。

本地化不自动扩大执行恢复承诺，也不取消跨数据库、磁盘和外部副作用的一致性边界。文件迁移、删除与恢复规则见[文件专题](files-and-execution.md)。

## 责任与依赖

应用层负责启动协调、受理、迁移与清理；领域层继续维护运行规则与端口；基础设施层提供 SQLite 仓库、本机队列、通知和平台资源适配；原生外壳负责进程宿主和安装更新。

先确定[工作区身份与数据范围](workspaces-and-memory.md)，再约定文件、索引、Skill 与持久记录的位置。是否继续维护 PostgreSQL／Redis 服务部署模式，须在实现双存储适配前确认，不能默认将两套运行方式永久并行维护。

## 完成条件

- 已约定桌面平台无需手工部署 PostgreSQL、Redis、Nginx 或默认 Docker 环境即可进行常规工作区操作。
- 并发受理、等待、审批、停止、核心重启与 SSE 补读沿明确语义工作，未知副作用不会被自动重放。
- 现有数据迁移后可核对文件、版本和引用；失败时保留旧数据并能定位或恢复。
- 安装、更新、数据备份及退出收尾有服务指南入口，实际支持范围明确。
