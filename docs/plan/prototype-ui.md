# 原型落地计划

**已批准，实施中。** 以 P5 为本轮实施和验收的上限。按[定稿原型](../../prototype/DESIGN.md)升级 `ray_agent/ui` 的公共界面、独立对话、工作区任务流程、设置、开发者视图，以及 P5 的工作方式、记忆和参考清单。P6–P9 已有部分实现，仍待验收。知识、语义检索、OCR 和多来源 Skill 的具体改造按各工作包推进，在对应验收中一起修前端和服务端。

## 还原标准

- 还原本轮范围内的空间层级、操作位置、信息顺序、关键状态及交互反馈。轨道和列表分工、工作区视图接在位置面包屑后、主纸面留缝、审批与交付的视觉重量、右侧查看方式都属于验收项。系统字体的渲染、少量间距及动效参数可随真实内容微调。
- 保留真实流程和现有业务状态。会话深链接、提交后读回、审批去重、运行配置冻结、草稿、归档与失联、文件授权、预览及撤销版本仍由现有代码和契约处理。原型未展示的设置分区和已有操作继续可达。
- 复杂度高时优先换实现方式，交互结果按原型。若涉及删去动作、改变入口语义、弱化关键反馈或调整已支持的行为，列明影响和可选方案，取得同意后再按新方案实施。

## 先升级组件，再装配页面

先在现有主题与组件上补齐变体和布局能力。共用组件须有至少两个已确定的使用场景，并共享结构或交互语义。单页业务状态留在原组件和 hooks 内。

| 先处理的封装 | 复用场景与改造方式 | 复杂度 |
|---|---|---|
| 主题与基础控件 | 在现有主题补齐暖灰画布、轨道、纸面、次级面和状态色，按原型调整阅读列、系统字体、图标及圆角。沿用字号偏好。升级 `Button`、`IconAction`、`Tooltip`、`Dialog`、`Sheet`、`Popover` 与提示组件，统一焦点、层级、撤销反馈及减少动态效果。 | 中 |
| 应用外壳与列表 | 升级 `AppShell`、`SidebarProvider`、`LeftPanel` 和 `SessionItem`。应用外壳统一承载画布、透明顶栏、主纸面。独立对话和工作区共用列表表头、滚动区和选中行。现有 `Item` 优先承接重复行结构，工作区使用中性开合文件夹图标。 | 高，涉及路由和列表状态 |
| 切换控件与右侧面板 | 升级 `SegmentedControl`。会话的聊天／日志常显文字，工作区顶栏与右侧面板使用选中项展开文字的样式。按链接与页内切换分别保留导航和键盘语义。复用 `Sheet` 与已有工作台拖宽手柄，统一工作区首页、工作区会话和独立对话的右侧容器。 | 中到高，涉及挂载、焦点及宽度 |
| 输入、菜单与文件入口 | 升级 `ChatInput`、`SlashCommandList`、`ModelPicker`、`LevelSlider` 和 `ContextRing`。两个首页和已有会话共用输入、菜单和拖入反馈，真实上下文用量沿用会话数据。交付、附件和目录复用 `FileRow`、`FilePreview` 与预览操作。 | 中到高，涉及上传、草稿和锚点 |
| 可展开行、操作卡与管理控件 | 优先扩展现有行和展开结构，供执行过程、参考清单和背景使用。审批、Agent 建议与组件安装共用卡片视觉规则，各自保留提交逻辑。设置沿用表单、错误显示和离开保护。 | 中 |

**图标统一沿用原型。** 将[原型图标](../../prototype/icons.js)的路径移入产品 UI 的共用 React 图标组件，直接渲染内联 SVG，统一 `viewBox`、线宽、圆角线端和 `currentColor`。导航、控件和状态图标使用同一套线描规则，图标按钮沿用可访问名称与提示。原型未覆盖的现有动作，按同一套规则补 SVG。优先迁移公共组件和本轮页面，后续页面在对应工作包验收时迁移。产品包通过自己的源码渲染，`lucide-react` 在全部引用迁移后移除。

**沿用现有依赖。** React、React Router、Tailwind CSS 和 `next-themes` 承载路由、布局和主题，Radix 提供菜单、弹层、抽屉和焦点管理，`cmdk` 可用于顶栏搜索，Sonner 用于反馈。拖宽和磁吸可用现有指针处理，选中块和展开用 CSS 过渡，记忆拖放与重排可用浏览器事件、CSS 或 Web Animations，并提供键盘钉住入口。文件落点复用现有浏览器文件事件及上传链路，交付时在真实 WebView 检查。若实际遇到平台限制，再按具体问题评估依赖，新增运行依赖需说明理由、代价与替代做法后确认。依赖及检查入口见 [UI 开发指南](../../ray_agent/ui/README.md)。

## 页面装配顺序与改动范围

组件共用能力成形后，按下列顺序接入真实页面。高复杂度主要来自状态归属和异步请求。

| 顺序 | 页面与组件 | 实施内容 |
|---|---|---|
| 1 | 全局外壳、工作区入口和两个首页 | 加入常驻轨道、按范围切换的目录、透明顶栏与纸面间距。工作区目录可展开多个工作区，按展开范围按需读取列表，当前区域沿用已有分页与实时更新。没有工作区时主面板提供新建和打开文件夹入口。首页使用居中输入，工作区接入真实的最近会话、待处理背景和可定位的成果。新工作区在最近对话区提示当前为空。保留已有深链接，新建背景入口。后续功能已有入口可接入导航外壳，继续进入现有界面，独立专题页随所属工作包落地。 |
| 2 | 独立与工作区会话、工作台和开发者视图 | 改造同一个会话壳、时间线、计划条、审批、交付和回复统计。右侧按「文件夹／成果／查看／修改」组织真实文件树、交付版本、工具输出及修改记录，独立对话显示适用项。复用日志、上下文环、终端和导出，切换时保持草稿、会话与日志各自滚动和已展开状态。保留文件变更提示、写入占用及冲突撤销。 |
| 3 | 背景与回复中的 P5 依据 | 背景页顶部显示工作方式版本、常驻记忆用量和待处理数。工作方式建议显示改动，记忆候选并排显示当前与建议内容。记忆按钉住和其余分组，组内标出常驻与按需取用的界线，保留版本、候选、钉住和撤回操作。候选与当前目标变化时重新审阅。修复「本次参考」加载、重试和迟到响应，按实际采用的工作方式、常驻记忆及其版本展示。需要补服务的 P5 交互见下节。 |
| 4 | 设置与 P4 运行组件 | 设置保留覆盖方式、现有配置分区与未保存保护。运行组件外壳复用 P4 浏览器组件的安装、取消、重试和跨页恢复。语义检索与 OCR 的可用性及安装后联动在 P7 验收。 |

### 原型里尚待接实的四个入口

| 入口 | 实施建议 |
|---|---|
| 发送与停止 | 现有输入已经有按钮、Enter 提交与停止链路。共享同一发送逻辑，继续处理中文输入法、Shift／Alt + Enter、受理读回、停止中及终态。 |
| 顶栏搜索 | 建议用 `⌘K`（或 `Ctrl+K`）打开当前范围的导航搜索。工作区查本区会话标题，独立对话查独立会话标题。用现有分页接口逐页匹配并说明覆盖范围。工作区资料和摘要的全文检索归 P6 知识页。扩大到跨工作区或全量内容需要另定范围与查询方式。 |
| 重新定位 | 将原型的失联入口接现有宿主选择器和重新定位流程。保留取消、授权失败、标记冲突、占用、成功重读目录及对话继续可用。 |
| 计划历史 | 将现有计划历史入口移到计划条附近，复用实际计划和运行记录。当前无计划、旧运行有记录时会话内仍保留可达入口。 |

## P5 及以前的逻辑核对

先使用真实数据完成公共组件和页面。下列改动涉及补接口或业务规则时，具体方案按批准范围继续。

| 差距 | 现有依据 | 建议与批准边界 |
|---|---|---|
| 工作方式历史与建议 | 核心会保存递增版本，现有接口可读当前版、发布新版、采纳或拒绝原建议。原型需要历史列表、差异、恢复与编辑后接受，当前客户端接口未覆盖完整流程。 | 完整还原建议补历史读接口，恢复旧正文沿用发布新版本及并发核对。编辑后接受需要能同时记录最终正文与建议处置，避免两次提交产生部分成功。批准扩展契约后实施。 |
| 记忆采用与回流 | 「本次参考」清单记录实际采用的工作方式和常驻记忆版本。记忆来源接口支持回查，回复与本次新增记忆的完整关联仍需核对。 | 在 P5 修复清单加载、可读的记忆来源跳转及候选重新审阅。回复处的新增和待确认入口使用实际运行关联的数据，缺字段时评估最小契约补充。参照 [F05 和 F10](first-delivery-remaining.md#f05-本次参考持续加载已复现待修复p5)。 |
| 文件拖入的落点与进度 | 随消息发送的附件先上传为内容对象，提交时按会话与工作区规则落盘。仅加入文件夹的文件直接写到选定目录。工作区文件夹失联或文件命中限制时，附件有会话目录回退。 | 还原两个落点，沿用实际写入、同名另存和回退规则。只有实际索引状态可读时才展示解析或可检索反馈。若要让「仅作为附件发送」改变持久落点，需要另行批准。现有语义见[文件与交付的跨模块协作](../architecture.md#跨模块协作)。 |

| 工作包 | 前端与服务端一起核对的原型交互 |
|---|---|
| P6 全文知识 | 知识页检索、文件预览与引用到新任务。文档引用角标与历史来源定位依赖真实的引用映射、版本和访问规则。索引暂停、范围排除／重新纳入和重试与中断恢复一起闭环。见[文档知识与检索](knowledge-and-retrieval.md)。 |

## 实施节奏与 P5 集中验收

1. 先做公共组件，再按页面顺序接入。实施中以源码、类型和调用链自查为主。卡在挂载、焦点、布局测量或宿主行为时，只做能定位问题的最小验证。单项尝试超过三次仍未达到预期，换实现路径或记录现象、影响及备选，继续独立工作。需要接受界面降级时由你决定。
2. 本轮页面齐备后集中验收。执行受影响的现有检查、lint 和构建，结合 `/dev/components` 核对展示状态，再在真实桌面窗口与原型对照。宽窗口、桌面最小窗口、更窄的 UI 视口和移动尺寸同批核对，覆盖抽屉、键盘焦点、长标题、深浅主题和减少动态效果。移动尺寸检查共享 UI 的布局适配，原生移动端仍属后续阶段。
3. 真实窗口至少走通新建与带材料发送、运行／停止及审批、回复与成果预览、文件失联及恢复、撤销、P5 背景与记忆、已有设置和 P4 浏览器组件、开发者日志与返回聊天。用既有机制构造失败、迟到响应、工作区隔离和旧记录。公共组件若影响 P6–P8 已有入口，检查入口和原操作仍可用，各包的完整行为留到对应验收。修复后定向复验受影响项，汇报实际结果和经同意的差异。
4. 验收通过后，将落地交互合入 [UI 设计说明](../../ray_agent/ui/DESIGN.md)，按实际变更同步产品说明与代码地图。剩余服务工作继续由所属工作包跟踪。
