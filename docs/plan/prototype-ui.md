# 原型落地计划

**已批准。** 桌面主流程包括公共外壳、独立对话和工作区、发送与文件、会话与工作台、开发者视图、设置、P4 浏览器组件，以及 P5 的工作方式、记忆和「本次参考」。全文、语义检索与 OCR 行为见[产品说明](../product.md#工作区)。视觉与交互目标见[定稿原型](../../prototype/DESIGN.md)，现行交互见 [UI 设计说明](../../ray_agent/ui/DESIGN.md)，整包联动及后续工作见[首个交付收尾清单](first-delivery-remaining.md)。

## 还原标准

- 目标是 100% 还原本轮范围内的空间层级、操作位置、信息顺序、关键状态和反馈。轨道与列表分工、透明顶栏、纸面间距、审批与交付的视觉层级、右侧查看方式均纳入对照。系统字体渲染、少量间距和动效参数可随真实内容微调。
- 沿用原型 SVG、现有主题和共用控件。共用组件服务于至少两个已确定的相同结构或交互场景。原型未覆盖的现有操作和设置继续可达。需要增加运行依赖时，说明理由、代价与备选方案后确认。
- 保留会话深链接、受理读回、审批去重、运行配置冻结、草稿、归档与失联、文件授权、预览和撤销版本。遇到逻辑冲突或确需降级时，列明差异、影响和备选，取得用户同意后实施。

## 验收方式

- 开发中以源码、类型和调用链检查为主。遇到挂载、焦点、布局测量或宿主行为问题，做能定位问题的最小验证。单项尝试超过三次仍未达到预期时，换实现方式或记录问题及备选。
- 先用现有自动化检查和组件目录覆盖状态，再在真实桌面窗口集中对照原型。走通创建、带材料发送、审批与停止、计划历史、成果预览、失联恢复、撤销、工作方式与记忆、浏览器组件和聊天／日志切换。用可重建的条件覆盖失败、迟到响应、隔离和历史记录。
- 窄窗口、共享 UI 的移动视口、焦点、深浅主题和减少动态效果放在集中验收。共享组件影响 P6—P8 时检查现有入口，完整行为随所属工作包验收。
