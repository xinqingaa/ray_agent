# 计划可信度、核验与成果收尾方案

状态：计划进度、可靠承接、预算收尾和成果交付已实施并收尾。当前机制见 [Harness 工程](../harness.md#计划清单)，观察与方案形成见[长任务背景](../background/plans-and-delivery.md)。

## 目标、依据与范围

用户需要知道最初要求还剩什么、当前在做什么、为何返工及最终能拿到什么。计划完成声明、运行成功、完整交付和业务正确分别表达。

范围包括计划、用户来源、承接、事件恢复、核验与返工、分项交付、预算收尾及清单展示。设计由同一循环、计划工具、成果记录、运行器与前端承接；案例只用于检查，不进入通用规则。

## 计划身份、阶段与范围

- 同任务保持稳定计划身份，改名和细化不改变阶段及步骤的原有归属。
- 整体阶段与子步骤分层，生命周期和本轮/后续安排分开，局部展开不膨胀顶层计数。
- 完整目标与本次范围保留真实用户来源，模型建议不自动缩减要求。
- 正文与文件成果分别登记身份、必要性、来源及归属，不能通过缺省列表消除必要成果。
- 清单完整更新原子校验，非法身份、引用或状态不覆盖原记录。

当前结构约束见[计划清单](../harness.md#计划清单)。设计还要求：

- 正常细化、排序、诊断和修复自主推进并说明原因；取消或推迟已有阶段需要用户来源，预算或环境不足保留受阻。
- 重开保留原完成声明，关联新要求或反证；阶段与子步骤各最多一个进行中，未完成子项阻止父项完成。
- 用户仅授权部分时保留其他安排，无关新任务不被旧缺口阻塞。

程序检查引用存在、归属及顺序，不证明自然语言授权含义或需求覆盖程度。

## 规划语义、时机与清单粒度

需要计划的任务在主要工作前登记路径，可与首批动作同轮，已发生动作如实记录，不补造事前规划。

- 阶段围绕具体问题、关键判断和成果组织，不只罗列工具操作。
- 条目用动作与对象组成短标题，规格留在目标或正文，不能用结构合法证明粒度合适。
- 先列整体阶段与首阶段关键步骤，其余进入时展开；简单问答或明确单次操作可无计划。
- 产物中的讲解、建议或模拟与 Agent 实际执行分别记录，形式检查不替代内容核对。

系统提示、计划模式、工具说明与步骤提醒保持一致，不加入固定案例阶段、数量或业务关键词。规划质量需要不同类型实际任务判断，结构检查只能验证契约。

## 确认承接与必要核对

1. 确认按钮携带具体版本与请求身份，受理事务验证并绑定新运行；重复请求读回原结果，过期引用返回冲突。
2. 首批业务动作前承接计划，用户补充后核对来源与范围变化；文字确认仍按普通消息处理。
3. 正常执行按实际进展更新，不固定每批工具核对。阶段未展开或没有当前子步骤时提供有限非阻断提醒，记录可恢复。
4. 必要声明遗漏使用有限纠正，未执行调用配对回填，不自动重放旧参数；结束时核对实际缺口。

服务端承接见[运行方案](runtime-and-control.md#受理与准备分离)。简单回答不附额外计划报告。

## 内容保真与风险核验

- 改写、整理与汇总保留原事实、范围及确定程度；假设单独说明，不补造完成状态、效果或因果。
- 验证针对主要风险：数据看计算与口径，内容看关键事实，界面看真实交互与视口。
- 需要来源且允许查证时核对原材料；禁止联网时遵守限制，检查已有材料和内部一致性，说明关键缺口。
- 格式、命令成功或同一模型自检不代替证据，不默认逐条增加第二模型审查或自动换更贵模型。
- 主体与关键检查先完成，可选扩展随后处理；实际修复定向复验，未变化证据可复用。

这些是通用任务原则，程序记录只覆盖可观察部分，不判断断言是否充分。

## 核验按实际版本与条件记录

关键核验随业务调用登记身份、成果、条件及观察，执行前确认实际版本，执行后读取真实结果。通过记录需要显式 `passed` 布尔断言；退出码、截图或口头“已检查”不足以构成业务通过。

| 条件 | 设计处理 |
|---|---|
| 同版同条件已通过 | 复用记录 |
| 文件改版或条件变化 | 保存新条件并按相关影响复验 |
| 版本未知 | 先读回，不沿用旧通过 |
| 失败次数达到限制且仍未通过 | 再执行说明新条件或换方法，实际修复改版的必要复验有例外 |
| 成功调用没有显式断言 | 记录已执行；明确执行失败或断言为假可记录失败 |
| 持续有成果相关调用却无核验记录 | 有限非阻断提醒，不新增纯登记调用 |

文件哈希不能发现未登记遗漏和全部语义重复，独立产物核对仍必要。次数见[运行参数与限额](../limits.md)。

## 分项成果与交付版本

1. **登记成果**：保存身份、正文或文件形式、必要性与来源，路径尚未确定也保留要求。
2. **确认版本**：读取实际文件字节和哈希，模型声明不替代版本依据。
3. **上传附件**：逐项返回结果，同路径同字节复用，改版保留旧关联。
4. **保存副本**：项目副本独立记录，只补失败项，不重复业务动作或已成功上传。
5. **形成说明**：依据同一任务累计成果及缺口，结果未知先读回，不静默发布错误版本。

主体完整且主要风险检查完成后交付首次可用版本，不以可选美化推迟必要成果，也不为每次样式微调建立永久附件。正文成果提供完整正文，一项成功不代表其他必要成果完成。

## 请求预算与有限收尾

预算收尾依赖已有任务与成果身份：

- 计数识别真实用户输入和内部消息，审批沿原预算，补充与提问回复按契约重新计数。
- 提醒和末段限制不改稳定系统前缀，不提供隐藏预算。
- 文本补写只处理收尾前登记的成果，并校验实际路径和类型；已有文件另存系统预留版本，保留原字节及旧交付。
- 成功与尝试次数有限，未知结果先读回，不自动重放，不绕过模式、策略或审批。
- 不增加任意成果和路径，不以补写继续开发或生成二进制。

具体动作规则维护在 [Harness 决策层](../harness.md#决策层)，阈值维护在[参数页](../limits.md)。Shell 等待直接返回已有输出以减少往返；本方案不包含候选文件扫描、崩溃自动补存或异常自动发布。

## 结束检查、累计说明与恢复

从有效计划、用户来源、成果及核验构造精简任务状态，有限纠正结束缺口。`completed` 与完整交付状态分开，缺失成果、交付失败及当前版本明确失败的核验保持可见。

最终说明按实际交付组织：简单问题直接回答，正文成果保留完整内容，文件或修改交付说明版本、累计状态、关键核验及缺口。分段交付同时说明本次范围、整体位置和后续安排依据。

累计说明仅围绕同一任务。压缩区分用户要求、模型建议、内部提醒和实际成果；最新结构从事件恢复，等待与刷新保留身份和有限反馈记录。重启不自动重放执行。

## 用户界面与投影

- 主清单显示短标题、描述、整体进度与当前阶段/步骤，展开保留层级，不重复计数。
- 成果在交付区查看，范围改变与阻碍在对话说明，内部核验用于恢复和技术观察。
- 准备、工具活动、计划阶段与终态分别投影；旧事件不能覆盖新清单，工具名不证明业务阶段完成。

详细展示见[界面方案](interface-and-preview.md)。

## 模块责任与依赖

| 模块 | 依赖关系 |
|---|---|
| 计划与成果记录 | 先稳定身份和用户来源，再记录版本核验与交付 |
| 循环与管线 | 承接、预算和结束共享最新状态，模型仍决定动作 |
| 应用运行器 | 先确认版本，再上传、副本与受限补写；未知结果先读回 |
| 持久化与前端 | 完整事件可恢复，旧序号不覆盖新状态，展示不证明业务通过 |

分项成果先于有限补写，版本和条件先于证据复用，持久状态先于压缩与等待恢复。API/UI 配套使用，不猜测迁移旧对话结构。

## 完成条件与状态

- 身份、阶段分母与范围来源稳定，非法更新原子拒绝，必要成果不消失。
- 同版复用、改版复验，部分交付只补失败项，未知写入先读回。
- 压缩、等待和刷新保持身份，结束说明保留真实缺口。
- 不同任务中的规划及时、具体且简练，结构检查不替代语义判断。

最终规划粒度调整未再做真实模型采样；不提供自动业务证明、崩溃发布或通用并发路径所有权。后续验证入口见 [API 指南](../../ray_agent/api/README.md#构建身份计划承接与真实视口)。
