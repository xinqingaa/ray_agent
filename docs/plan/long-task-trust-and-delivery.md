# 计划可信度、核验与成果收尾方案

状态：计划进度、可靠承接、预算收尾和成果交付已实施。本方案保留有效设计与实施关系，当前机制见 [Harness 工程](../harness.md)。

## 目标、依据与范围

会话执行体验维护：已实施并完成本地定向和有限真实验收。范围为复杂阶段展开可独立推进或核验的子步骤，开始、完成、切换或受阻时随业务动作更新。分阶段清单当前阶段尚未展开，或已有子步骤但无当前步骤时，每份计划的每阶段提供一次非阻断提醒，提醒记录从持久上下文恢复；简单问答和单次明确操作可无清单。最终回复按需求交代累计成果、关键结果、使用方式、验证和实际缺口，通过交付附件使用文件。配套状态、文件引用和清单展示见[界面方案](interface-and-preview.md)。保持现有单循环、事件和预算，不增加额外评审调用，不按工具次数或业务关键词判定复杂度；完成条件包含不同类型真实任务及恢复与版本回归。

用户应能回答四个问题：最初要求还剩什么、现在做什么、为什么返工、最终能拿到什么。计划完成声明、运行成功、完整交付和业务正确分别表达。

实际观察包括父子步骤混层、纯核对占用请求、必要成果被收尾限制阻止、说明与实现口径不一致。具体轨迹及压缩并非全部根因的分析在 [长任务背景](../background/plans-and-delivery.md)。本方案将这些问题按契约处理，个案材料留在证据与测试，不写入通用提示或判定规则。

范围覆盖计划结构、范围来源、承接受理、持久事件及恢复、核验和返工记录、成果交付、有限收尾、累计说明和清单展示。保持自研单循环，不增加独立 Planner、常驻通用评审模型、自动业务证明、历史数据迁移、崩溃自动发布或课程同步。

| 优先级 | 工作 | 完成条件 |
|---|---|---|
| 核心 | 目标、阶段和范围稳定 | 局部展开不改整体分母，必要工作不被删除或悄悄推迟 |
| 核心 | 核验与返工有依据 | 取消定时纯核对，检查关联实际版本、条件和调用 |
| 核心 | 分项成果与收尾 | 必要文件分别核对，失败只补失败项，末段可补预登记文本 |
| 后续组织 | 累计说明与展示 | 答复对应同一任务累计成果，主清单简洁，正文交付完整 |

## 计划身份、阶段与范围

同一任务延续一个 plan_id，整体阶段与所属步骤最多两层，均有稳定身份。阶段说明目标由哪些部分构成，步骤说明当前阶段如何完成；未展开阶段不强制创建子步骤，简单任务不凑清单。

| 信息 | 保存目的与契约 |
|---|---|
| 标题与描述 | 简短用户展示，与完整目标分开 |
| 完整目标与来源 | 引用本会话真实用户消息，模型解释可修订但不成为授权 |
| 本次范围 | 保留能力和交付要求，区分用户安排与模型执行建议 |
| 整体阶段 | 身份、顺序、生命周期与执行安排分开；已有阶段不直接删除 |
| 所属步骤 | 每项只属于一个阶段，不与父阶段共同计数 |
| 必要成果 | 稳定身份、回复或文件形式、必要性及来源 |
| 变更理由 | 细化、重开、取消或安排变化有可追溯依据 |

完整更新原子校验，身份、父子归属、状态或引用错误时不替换有效清单。最多一个进行中阶段和一个进行中子步骤；未完成子项仍存在时不能声明父阶段完成。状态更新可以保留原标题和描述，省略成果列表保留原记录。

正常细化、排序、诊断与修复继续自主进行，说明原因。整体阶段取消和将已有工作推迟需要真实用户来源；预算或环境不足记录受阻。已完成项重开保留原声明，关联新要求或反证。不能用 reset、无需计划声明或缺省列表消除必要成果。

用户明确本轮仅做部分时保留其余阶段和安排；模型建议分段不自动缩减目标。无关新任务可以直接回答或建立新计划，原缺口留在原任务中，不阻塞新问题。程序验证消息存在、归属和顺序，不能证明自然语言已授权某种取舍。

## 规划语义、时机与清单粒度

需要计划的任务在主要工作前登记已知执行路径，可与首批业务动作同轮；已发生的动作如实记录，不补造事前规划。阶段围绕目标中的具体问题、关键判断和成果组织，推导与方案选择也是执行工作，不只罗列工具操作或制作形式。

条目用动作与具体对象或结果组成短标题；大纲、规格和核验条件留在目标、范围或正文。按阶段成果合并相关动作，首次列全部阶段和首阶段关键步骤，其余进入时展开，不复述父阶段或机械铺开细节。普通与计划模式采用相同口径，简单问答和单次明确操作仍可无计划。

产物讲解、建议或模拟的步骤不等于 Agent 已实际执行。主题要求和交付约束均需承接，格式与交互检查不能代替内容核对。规则作用于通用任务，不加入案例术语、固定阶段、条目数量或业务关键词门禁。

系统提示、计划模式、工具描述与步骤提醒共同维护上述规则；既有层级、来源和成果校验保持不变。完成条件是不同类型任务中能观察到及时、具体、简练的计划及真实状态推进，结构检查只能验证契约，不能代替模型质量判断。

## 确认承接与必要核对

确认按钮携带具体计划版本，受理事务验证会话、来源运行、计划 seq 和请求身份；绑定新运行后立即发布准备执行清单。相同请求读回原受理结果，过期引用返回冲突。普通确认文字仍按自然语言消息处理。服务端责任见 [运行方案](runtime-and-control.md)。

首批业务动作前承接计划，用户补充范围后核对来源和变化，正常执行由模型更新阶段。取消固定业务批次核对，不要求每个动作先声明仍在当前步骤；必要记录可以随计划或业务动作同批完成。遗漏声明最多纠正一次，所有未执行调用配对回填，不自动重放被拦截的旧参数。

简单回答无计划和额外报告。准备结束时核对当前任务的缺口，但不增加独立总结模型或无限纠正循环。

## 内容保真与风险核验

整理、改写和汇总材料保留原事实、范围及确定程度，不把未提供的完成状态、效果或因果补成事实；表达所需假设单独说明。验证按主要风险选择：数据核对计算与口径，内容核对影响结论的关键事实，界面核对真实交互与视口。

需要来源且允许查证时核对原材料或可靠原文；明确禁止联网时继续遵守，先检查已有材料和内部一致性，在实际影响结论的缺口处说明限制。格式正确、页面可用、命令成功和同一模型自检都不能代替事实依据。规则作用于全部任务，业务样例只用于独立回归和验收。

不默认增加第二个模型审阅每条回复，不自动切换更贵模型，不用机械重复检查制造通过感。主体完整和主要风险核验先于可选扩展，实际修复后定向复验，未变化的检查可以复用。下面的记录机制只约束程序可观察部分，是否选到了充分条件仍需判断。

## 核验按实际版本与条件记录

关键检查随业务调用登记，至少关联核验身份、目标、条件、成果、实际调用与观察。执行前使用当前文件版本，执行后读取实际结果；文件路径和模型声称不代替实际字节版本。

实际工具结果中的显式 `passed` 布尔断言才形成通过记录。退出码成功、运行中输出、截图和口头“已检查”不能直接等同业务通过。核验条件来自需求和独立预期，不把实现当前返回值当作正确答案。

| 情况 | 处理 |
|---|---|
| 同版同条件已有通过 | 复用记录，不再机械重复执行 |
| 文件已改版 | 原版证据过期，针对相关影响复验 |
| 输入、环境或外部条件改变 | 保存新条件再核对，不冒用旧通过 |
| 版本尚不确定 | 先确认实际文件版本，不能乐观沿用 |
| 记录失败次数达到上限且当前未通过 | 再执行需说明新条件或更换方法；已有修复说明和实际改版的必要复验有例外。上限见[运行参数与限额](../limits.md) |
| 有实际修复或反证 | 记录修复理由，允许必要定向复验 |
| 未登记检查但持续有相关调用 | 一次轻量记录提醒，不拦截正常业务 |

普通执行但无显式断言记为已执行，不算通过，也不自动累计失败次数。这个机制约束记录和引用，不自动判断所有检查的语义等价性、断言充分性或外部条件变化。阶段完成仍是模型声明。未登记的遗漏和重复不能靠文件哈希自动发现，独立产物检查继续必要。

## 分项成果与交付版本

回复正文和文件成果分别登记。每项保留必要性、来源、计划归属及当前路径；后续文件尚未确定路径时可以先保留成果身份，不能为了通过校验省略要求。最终实际版本、附件和项目副本由工具结果回填。

文件生成、附件上传、项目副本保存和业务通过分别表达。一张截图或一个成功附件不能满足其他必要成果。相同路径与相同字节复用已有附件，改版保留旧关联；附件成功但项目副本失败时只补副本，不重复上传或重做业务动作。

交付失败逐项返回原因，结果未知先读回确认；不得静默发布错误版本。独立对话附件与项目文件副本各有所有权，项目保护继续生效。正文就是成果时提供完整正文，不用简短总结替代。

交付时机是主体完整、主要风险检查已完成后的首次可用版本。可选美化与临时清理可以随后做，不能为了提前交付跳过关键口径，也不为每次样式微调产生永久附件。

## 请求预算与有限收尾

计数从最近真实用户输入起算，普通请求、重试和压缩请求都计入。运行中补充消息和提问回复按当前契约重新计数，审批续接沿用。上限足够大时先提醒，最后一段进入收尾；更小上限只保留耗尽失败。阈值见[运行参数与限额](../limits.md)。

提示追加到工作记忆，不改稳定系统前缀，不算用户新要求。收尾只允许读取、交付、更新计划和受限文本补写，模式与策略限制优先；仍不遵循或余额耗尽时可以失败，不赠送隐藏预算。

受限补写依靠进入收尾前登记的成果。调用使用成果身份，运行器解析并校验路径和类型；已不存在的文本路径可以写入，已有文件保留原字节并使用系统预留新版本路径。每项的成功次数和尝试次数有限，结果未知时先核对，不能自动重放。次数见[运行参数与限额](../limits.md)。

该通道不能新增任意成果或路径，不绕过审批，不提供任意 Shell、依赖安装、重构或二进制生成。必要二进制应在正常阶段准备，缺失就说明未完成。现有保护仍不等于通用路径所有权、原子并发写入或崩溃自动补存。

Shell 等待在结束后直接返回已有输出，超时也说明进程状态并附输出，避免等待后再读一轮。候选文件扫描与异常自动发布没有进入本次最终范围。

## 结束检查、累计说明与恢复

循环从有效计划、用户来源、成果及核验构造精简任务状态。结束最多追加一次缺口纠正；仍有未满足项时保留真实说明。completed 表示运行正常结束，完整交付状态另记；登记成果缺失、交付失败和当前版本明确失败的关键检查不能消失。

| 答复方式 | 必须保留 |
|---|---|
| 简单直接回答 | 用户所问答案，无额外计划报告 |
| 正文交付 | 完整正文、必要假设和实际缺口 |
| 文件交付 | 文件与版本、同一任务累计能力、关键核验和未完成项 |
| 分段交付 | 本次范围、整体位置、后续安排依据 |
| 修改已有成果 | 新旧关系、改动及新版整体状态 |

累计说明只围绕同一任务，不能混入会话里的全部无关主题。正文长度遵从需求，长段落可按内容组织；统计与口径不能由通用字符串比较证明，应依独立检查。

压缩区分用户要求、模型建议、内部提示、范围、检查声明与实际成果。最新结构化状态从事件恢复，不只依赖摘要记住 id。等待、审批及刷新保留状态和反馈额度；新用户消息更新范围。API 重启沿既有中断规则，不引入检查点重放。

## 用户界面与投影

主清单呈现简短标题、描述和分层任务项。收起时保留整体进度、当前阶段和当前子步骤；展开及历史清单通过勾选、层级和状态呈现各阶段已知的子步骤，不重复显示计数。成果在交付区查看，范围变化与阻碍在对话说明，内部核验记录用于执行恢复与开发者观察。

准备执行、实际工具活动、计划阶段和终态分别投影。已取消项保留原因，受阻项不伪装完成；旧事件 seq 不能覆盖新清单。不能从工具名称自动推断业务阶段完成，也不能通过隐藏恢复异常制造可信。

计划历史复用相同投影。首次界面实施过多展示内部信息，最终已按用户要求收简；该调整不删除内部目标、成果与检查数据。

## 实施顺序与模块责任

| 批次 | 工作 | 依赖与交付 |
|---|---|---|
| A | 固定失败与输入基线，定义稳定阶段、范围和成果 | 保留实际失败，不将旧协议猜测迁移 |
| B | 计划原子校验、承接、事件与简洁投影 | A；同层计数、来源、身份、刷新一致 |
| C | 核验、版本、条件、重复与修复理由 | B；使用实际调用和显式断言 |
| D | 分项版本交付、项目副本与收尾补写 | A/B/C；部分失败和旧文件保护 |
| E | 动态任务状态、累计说明与压缩恢复 | B/C/D；正文和直接回答不退化 |
| F | 有限真实模型/UI 与独立产物核验 | A–E；身份匹配，失败如实保留 |

领域层维护计划与成果记录及纯校验；循环决定注入、继续和结束；管线执行授权与一次动作；应用运行器取得真实版本并处理上传与副本；前端投影，不判断业务通过。复用事件 JSON，没有新增数据库表；API/UI 配套使用新协议，不兼容猜测旧对话结构。部署要保留数据与配置，不能宣称旧镜像能继续解释全部新事件。

## 验收矩阵

以下保留原方案的完成条件，这些条件用于后续重新验证，不表示每条都经过真实模型验证。

| 组 | 场景 | 必须观察的行为 |
|---|---|---|
| 计划结构 | 三阶段、当前阶段四步骤 | 顶层仍三项，父子不重复计数 |
| 阶段边界 | 当前阶段完成、整体尚未完成 | 原目标缺口仍存在，不显示整体全完成 |
| 调整与范围 | 细化、重开、取消、非法引用 | 身份及理由保留，失败更新原子拒绝 |
| 受阻 | 预算或生成失败 | 必要成果保持未完成，不能被移出范围 |
| 核对效率 | 同阶段连续多批动作 | 无定时纯 review 往返，必要承接可同批完成 |
| 来源 | 确认执行和用户追加 | 具体版本承接，真实来源不与模型建议混用 |
| 版本核验 | 同版复用、改版、条件变化 | 有效证据可复用，过期证据不能冒用 |
| 返工 | 失败计数达到阈值且当前未通过 | 新条件、改法或修复依据明确 |
| 多成果 | 只交付一项、截图成功 | 其余必要成果缺口仍存在 |
| 交付重试 | 附件成功/副本失败、同版与改版 | 只补失败项，同版不重复，新版保留旧关系 |
| 补写 | 预登记文本、已有路径、未知结果 | 原材料保留，限定路径和次数，先读回 |
| 预算 | 最后请求、重试、压缩、审批 | 正确计数，无隐藏额度，已有最终答复不丢 |
| 输出 | 正文、文件、混合、简单回答 | 正文完整、累计说明明确、简单回答直接 |
| 恢复 | 压缩、等待、刷新和断连 | 身份、子项、成果和来源可恢复，旧 seq 不覆盖 |
| 协议 | 新记录读回、非法旧结构 | 不猜测迁移，非法更新不产生半份计划 |
| 项目 | 会话/项目、附件/副本 | 通用目标契约一致，文件保护不退化 |

真实任务包含一次和分轮方案/原型、多文件数据、正文、简单问答及项目改版；输入先冻结，使用不同类型防止规则偏向单一样例。失败保留，只补测受定向修复影响的场景；压缩没触发就记录未覆盖，不为了触发扩大业务任务。
