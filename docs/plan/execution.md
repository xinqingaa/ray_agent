## 阶段 A：确认起点与状态设计

核对 HEAD、未提交变更和总计划最新记录，保留已有计划、证据及用户改动。按服务指南确认本机、Compose 与开发服务实际运行的版本，区分静态核对和已运行检查。

沿已确认 W11 路径核对组件状态：独立草稿 → 项目加号 → 打开/添加项目 → 工作区空白输入 → 项目内对话 → 返回项目开启另一对话 → 关闭/归档。状态写在 W11，不在 DESIGN 里再写一套。覆盖 loading/error/empty/unavailable、启动中、等待、失败恢复、长列表、两分区折叠、整栏收起与窄屏。

**阶段出口：** 主路径与异常状态无概念冲突，项目名导航和折叠各有独立点击目标，分区加号语义固定，执行任务开始时将相关包更新为进行中。无需先把目标改写成 UI DESIGN 的已实现事实。

## 阶段 B：先修复服务端和发送恢复

先做 W10 R1–R3：项目可用性原因、每次启动校验、及时受理、后台启动所有权、迟到容器清理、首次发送草稿与受理核对。随后完成 R4 的真实挂载边界与默认监听地址，保持受信任单人定位。

做 W9 U3–U6：真实 usage 与估算的来源/快照、命令状态单一来源、同步压缩总期限与忙碌状态/恢复、有效计划判断。准备环境状态与输入容量字段同步相关事件、路由适配、API 类型和 W4 视图模型；沿原分层实现，不塞进路由或新建另一套执行器。

**阶段出口：** 相关行为测试通过；慢创建不阻塞受理和停止，第二消息不误开 run；超时先读回而非自动重发；压缩失败原子性和同会话并发冲突有证据；占用与计划入口来自真实数据。mock 挂载参数测试不替代真实 Docker。

## 阶段 C：恢复输入交互与工作台

完成 W9 U1–U2、U4 的轻量加号、回形针、斜杠与纯圆环，接入阶段 B 的真实数据。完成 W10 R5 的 Git 边界、两段 diff、文件/分支刷新、防止乱序返回覆盖和异常呈现。

**阶段出口：** UI 类型、lint、build、观察脚本及实际投影检查按指南完成；真实浏览器核对浅色/深色、悬停/聚焦/点击、390×844、Plan 后续与手动压缩。环旁和环内均无常驻占用数字；不能用截图里的“加载中”冒充完成态。

## 阶段 D：项目实体、工作区和侧栏闭环

按 W11 实现项目模型/迁移、创建绑定、目录唯一与嵌套校验、分页、说明/身份快照、同项目互斥、归档/恢复与实时可用性。先用临时空库验证迁移单 head；不得为满足空库原则擅自清空用户正在使用的库。若保留旧本地数据，先清点再选择一次性回填或明确处理，不建设长期兼容层。

接入项目页、两分区加号/折叠/对话置底、每项目最近对话与查看全部、项目内空白输入和草稿恢复。无 session 的项目页复用项目级文件/Git 接口，已有对话继续使用结果/终端/浏览器；保持左侧导航与右侧工作台分工。

**阶段出口：** 数据与并发验收通过；浏览器能打开项目、发起并返回多个项目内对话、切回独立对话；同项目冲突指出占用对话，waiting 仍占用；打开/关闭不误建或误停运行，归档保留历史与目录；长项目列表不会把对话区挤出视口。

## 阶段 E：真实验收与事实文档收口

按三个子计划完成剩余自动检查、临时 PostgreSQL 检查、镜像/Compose 验证、无项目 E1/E2/E3/E4/E7 回归，以及临时宿主机 Git 项目的真实浏览器全链路。准备临时目录和仓库、临时测试数据库与覆盖配置，结束后恢复本次改动过的运行配置、清理仅本次创建的测试资源；保留用户数据与其他工作资源。

浏览器发起打开项目 → 首次发送 → 受理 → 修改文件 → 终态 → 工作台读取 → 宿主机核对，再覆盖失败/超时/停止/迟到创建、waiting 续接、多标签恢复、上下文、设置快照与归档。截图必须显示完成态；记录来源、环境和观察含义。macOS Docker Desktop 做实际挂载验证，没有 Linux 环境如实记录未验证边界。

完成后同步子计划要求的产品说明、架构、能力边界、代码地图、W4 契约、UI DESIGN、服务指南；只描述已经验证的实现。本次不改课程，不追加 worktree/快照回滚/Git 写界面/凭据托管。既有故障先核对基线与影响，不把环境前提缺失写为测试通过。

**最终出口：** W9 U1–U7、W10 R1–R5、W11 当前全部验收和仍适用的原验收满足；三个包分别更新完成并链接证据；已知未验证边界明示。代码写完或计划改完不足以宣布产品目标完成。
