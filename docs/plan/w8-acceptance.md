# W8：综合验收与项目文档收口

所属：[二次开发总计划](README.md)。前置：W2、W6、W7（因而包含全部前序包）。规模：中，1–2 个对话——对话一完成综合验收与对比报告；对话二完成 docs 收口、配图重绘与冻结。

## 目标与不做

**目标：** 在干净部署上用全部评测任务验证整合后的系统，给出与基线的对比结论；把 `docs/` 与项目级配图收口到新实现；冻结代码基线，作为课程同步的依据。

**不做：** 课程正文与课程配图（另立课程计划）；新功能；为了通过评测而调整任务或检查。

## 工作内容

### 综合验收

1. 按运行指南从空库、新数据目录启动完整 Compose；
2. 运行 E1–E7 各至少 2 次，记录每次结果；失败时定位原因，修复后复验并保留失败记录；
3. 跨包组合检查（手动或脚本，逐项记录）：
   - 流式生成中停止：临时内容消失、运行为 cancelled、沙箱进程已退出；
   - 触发压缩的长任务中途提问、回复后继续：压缩事件存在，回复后任务正确完成；
   - 等待审批时重启 API：运行为 interrupted，页面显示原因；
   - 任务运行中刷新与断网恢复：事件完整且不重复；
   - 触发压缩后的一轮：开发者视图显示的重建请求包含摘要与用户原文，与调试接口返回一致；
4. 既有能力最小回归：浏览器访问受控页面取事实、MCP 夹具调用、A2A 夹具回复与远端失败各一次，均通过产品界面发起；
5. 界面综合走查：在最终代码上重跑 [W5 子计划](w5-ux.md#验收)的真实浏览器走查与 Web Interface Guidelines 审查，确认 W6、W7 的接入没有破坏组件状态目录页中的任何状态；亮暗主题与窄屏各一遍。

## 典型场景：销售表合并与结果核对（2026-10-08）

场景编号：S01。用户要求先记录为典型测试；本节定义输入、判断标准和留证要求，不修改产品提示词或执行逻辑。执行状态统一见[总计划](README.md#典型用户任务验收2026-10-08)。不因登记本场景重跑历史综合验收。

### 要回答的问题

非技术用户提交三份销售表后，能否直接从最终回复和交付文件理解处理范围、重复与缺失处理、计算结果及待办，而不必检查工具日志。分别判断成果正确、说明充分和核对有据，不预设当前实现不合格，也不以回复篇幅或固定措辞评分。

### 已有依据与本次基线

登记时产品基线为 `7c8b7864d555ca537a8f9e4e598c8cb76fe81385`；正式执行时另记当时源码、模型及配置。既有 [2026-10-02 原始验收](evidence/w9-w11-eval-2026-10-02-89aa642.json)的 E2 最终回复已包含三条记录、`12 + 18 + 30 = 60`、源文件未修改及附件交付；E7 回复还包含 JSON 解析、字段类型/长度及源文件哈希核对说明。这说明已有输出可以提供具体结果和检查说明，不能把“已完成，请看附件”当作当前产品的固定表现。

上述历史任务没有覆盖三表重复与缺失处理。当前结束反馈针对已识别的交付缺口和未完成计划，尚不构成销售表业务正确性的独立验收。S01 用来观察自然任务下的实际表现，不先改提示词再把改后结果冒充基线。

### 用户输入

初始上传 `销售表A.csv`、`销售表B.csv`、`销售表C.csv`。使用以下自然任务提示，不把预期数字或验收清单提供给模型：

> 帮我合并这三份销售表，重复订单只保留一条，按渠道统计销售额。缺少金额的订单单独列出来。生成销售汇总.xlsx 给我下载，不要修改原始文件。

若模型询问业务规则，记录问题和人工介入；只回答所问规则，不提示答案或要求逐项复述验收清单。输入不存在同订单号内容冲突，不测试如何裁决冲突订单。

### 固定材料规格

### 验收标准

| 维度 | 通过条件 |
| --- | --- |
| 交付可用 | 最终附件可下载，确为能解析的 xlsx；包含有效明细、渠道汇总及待补充订单，可用工作表或清晰分区表达，不限制名称与版式 |
| 数据正确 | 有效订单集合及金额与夹具逐条一致，无重复/漏项；待补充恰为 S0284–S0288；线上 18,640、线下 12,760、有效合计 31,400 |
| 处理可追踪 | 三份原始文件字节未变；交付文件能定位保留/待补充订单，去重规则明确；验收端能核对 300 = 12 + 5 + 283，不仅检查合计数 |
| 用户能判断 | 最终回复说明输入 300 条、去掉 12 条重复、5 条缺金额、283 条参与统计、各渠道与合计、交付文件，以及待补金额不在当前合计内；允许等价简洁表达，不要求复刻示例文案 |
| 核对有依据 | 对“已核对”“一致”等声明，运行记录存在相应计算、比较或产物读回结果；验收端独立打开交付文件，与夹具标准答案比较，不能只信模型文字或它自己写的核对标记 |
| 结论有边界 | 不编造金额、不把缺失按零填平；不把算术一致性说成源数据真实完整，不把 31,400 元称为所有订单的完整销售总额 |

“成果正确但说明遗漏”“说明完整但缺少实际核对”“数据错误”分开记录。一次通过证明本次表现，不外推稳定成功率；出现问题先定位材料、模型执行、交付或说明环节，再决定是否需要修改实现。
