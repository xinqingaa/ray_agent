# W11：项目工作区与对话模式

所属：[二次开发总计划](README.md)。前置：W10 返工 R1–R4 的启动、恢复与挂载契约；界面接入需 W9 的命令入口与上下文契约。规模与投入比较只维护在总计划。本文是用户于 2026-09-30 确认、经最后两项交互调整后收敛的目标设计，不代表已实现。执行顺序见[执行入口](execution.md)，进度与证据只记在总计划。

## 目标与范围

让用户能够打开一个长期项目，在其中连续建立和返回任务；也能在项目之外开始独立对话。先完成一个可靠的工作区闭环。

包含项目实体、项目说明与可选 Git 身份、打开与关闭项目、侧栏导航、项目内新对话、文件与当前 Git 变更、归档与恢复、同项目运行互斥。界面统一使用“对话”，任务仍是后端与计划中的工作概念，不保留“新建任务”按钮。旧 W10 的“不做”清单不再是约束；逐项收益、成本和追加条件以总计划的评估表为准。自动 worktree、完整快照回滚、Git 写操作界面、凭据托管暂不随本包实施。

## 授权与现状

用户要求审计现有修改、变更计划、推翻 W10 原有“不做”限制，并强调优先投入收益高的工作；随后确认其余方案，并明确移除“新建任务”、分区右侧使用加号、对话区置底与折叠、上下文入口只保留圆环。本轮完成计划收敛；产品实施在后续目标模式任务中启动。2026-09-29 的历史决策保留在 W9/W10，冲突时采用当前返工与本文契约。

## 设计契约

### 产品概念与任务边界

| 概念 | 用户含义 | 关系与寿命 |
|---|---|---|
| 项目 | 已登记的宿主机目录及其设置 | 长期存在，可归档；不依赖某个会话或沙箱 |
| 项目工作区 | 打开项目后的界面与文件操作环境 | 从项目入口进入，不再建一个同义数据库实体 |
| 对话 | 项目之外的一段连续交流，也可调研或交付文件 | `sessions.project_id` 为空；不限制为单条消息 |
| 项目内对话（任务） | 项目中的一段连续工作对话，界面仍称对话 | 一个 session 可有多个 run，追问留在原对话 |
| 运行 | 一次受理后的执行，直至等待或终态 | 沿用现有 run，不把每条消息都新建为任务 |
| 工作台 | 右侧查看文件、变更、终端、浏览器与交付的面板 | 与左侧项目导航分别承担职责 |

普通对话沿用现有工具与临时沙箱，不新造“纯聊天”执行器。对话/项目是归属，普通/计划是执行模式，两者独立。“继续改”进入当前对话的新运行；从项目工作区或独立空白入口发送，才建 session。新建入口本身不创建运行。

### 数据、资源与生命周期

- 新增 `projects`：id、唯一规范路径 path、name、可空 instructions（最多 8000 字符）、可空 Git 姓名/邮箱（成对设置）、archived_at、创建/修改/最近活动时间。设置修改和最近任务活动分开；打开项目不伪造活动。
- `sessions.project_id` 可空外键，删除 `project_path`，目录只有一个事实来源。根目录是部署配置，可用性实时派生。首次运行前可换归属，首次受理后固定；旧任务不能悄悄换挂载。
- 唯一路径由数据库约束保证；并发重复添加返回已有实体。按路径段拒绝嵌套项目，避免互斥不能覆盖重叠目录。linked worktree 先检查并说明支持状态，不承诺可直接挂载。
- 归档隐藏入口并禁用新运行，保留历史和宿主机文件；恢复重新校验。活动运行含启动中、running、waiting，有活动运行归档返回 409。关闭项目只离开界面，不归档、不停止运行。
- 首版不提供“删除项目并级联删除全部任务”。删除单个任务沿用现有机制并核对资源清理；外键不级联清除项目历史。用归档满足整理需求。
- 路径不可用时仍可看历史、改名和归档；恢复后可重新打开。目录移动不自动换路径，给出重新添加入口。
- 新 schema 按总计划空库原则。若确需保留本地 W10 会话，迁移前清点，只做一次路径去重回填，不建设兼容层。保持单 head；回填前识别嵌套路径，不能导入违反新规则的项目。
- 项目不拥有共享沙箱：每个任务仍有自己的沙箱、上传和临时输出，挂载同一项目目录。TTL 重建恢复挂载与设置快照，不代表临时文件已恢复。

### 同项目运行互斥与变更含义

不引入 worktree 时，同项目最多一个活动运行，包含启动、等待回复、等待审批，计划模式也遵守。可以打开多个任务和准备草稿；第二任务发送返回 409，指出占用任务并提供跳转。没有自动排队。

项目占用与新 run 在事务内协调，不能只靠会话锁或前端禁用。建议锁项目行并在同一事务查询活动 run；waiting 续接沿用占用，终态释放，启动扫描中断遗留 running 后释放。不同项目可同时运行。chat、审批续接、停止、归档使用一致锁顺序，避免死锁。

互斥只覆盖 RayAgent 内的任务，用户编辑器和宿主机 Git 仍可修改目录。工作台称“项目当前变更”，不能说全是本任务修改。首版仅在任务开始记录 HEAD 与是否已有未提交变更，提醒已有改动；不保存全文件快照，不生成“本任务 diff”或自动回滚。

### 设置怎样生效

- 项目说明与 Git 身份在任务首次受理时取快照，保存到可重建的任务/运行配置；后续运行与 TTL 重建沿用同一快照。修改只影响之后首次启动的任务。避免说明固定、身份却在重建时变化。
- 说明加入已有 system 的项目段，计入容量、压缩后保留与请求重建；无项目/无说明保持原行为。不自动解析仓库所有规范文件，不建设跨任务记忆。
- Git 身份通过四个 author/committer 环境变量提供，不改宿主机 `.git/config`；身份不是认证。没设置时，已有有效仓库/环境身份仍可能支持 commit，不能断言必失败或必成功。
- push 沿用现有 Shell 策略；缺少凭据时由操作者在外部处理认证与推送。不托管 SSH 私钥，不给任务沙箱挂载宿主机 home 或 Docker socket，不显示假“可推送”状态。

### 接口与数据契约

- 项目列表、创建、详情、改设置、归档/恢复；列表含 id/name/path/available/reason/archived/task_count/last_active_at。静态 `/roots`、`/browse` 在动态 `/{id}` 前声明；根目录项补具体原因，能力返回区分空配置与共享沙箱不支持。
- 项目级 tree/file/git status/diff 复用 W10 只读适配；会话内接口经 project_id 转发，避免两份逻辑。
- `POST /sessions` 可选 `{project_id}`，创建与关联同事务，不带体维持原行为。它只保证绑定原子性，后续 chat 仍可失败，不能宣称“两步就不会留下空会话”。
- 首次发送的 draft、session id、chat 结果遵循 W10 R3：失败回到同一草稿/会话，不再创建第二个空会话；超时先读回用户消息 seq 与活动 run，再决定重发。
- 首次运行前 PUT/DELETE 归属按 id 操作，与首次受理共用并发边界。详情和列表的 project 加 id；列表按项目批量核对可用性，不逐会话重复检查。
- 项目/任务列表独立分页，默认 50 条；侧栏每项目最近 5 个，工作区查看全部，不加载所有历史事件。当前选中任务即使不在最近 5 个也保持可见。改名、归档、状态在刷新/重连后同步。
- 同步后端 schema、UI API 类型、W4 视图模型、列表 SSE 与观察脚本；loading/error/disabled/empty 独立，不把读取失败当作未配置。

### 页面与导航

| 操作 | 结果 | 创建行为 |
|---|---|---|
| 全局首页发送 | 新独立对话 | 发送才建 session，进入首页不创建 |
| 打开项目（选已有或添加目录） | 项目工作区 `/projects/[id]` | 不建任务、不建沙箱 |
| “项目”分区右侧 `+` | 打开项目选择器，选择已有项目或添加目录 | 打开已有项目不新增实体；添加目录才登记项目，不建 session/沙箱 |
| 点击项目名称，回到工作区空白输入 | 同项目空白草稿与最近对话 | 自动继承项目；发送才建 session，不自动打开上次对话 |
| “对话”分区右侧 `+` | 全局独立对话草稿 | 明确离开项目归属；发送才建 session |
| 关闭项目 | 全局首页 | 运行继续，可从侧栏返回 |

全局首页直接对话是主入口，“打开项目”是紧凑次入口，不常驻“不选项目”芯片。项目内对话输入显示项目名。`/project` 打开项目入口，不在已开始的对话里偷偷改归属。

**侧栏：** 顶部只保留品牌首页入口与整栏折叠控件，移除“新建任务”及其折叠态同义入口。内容分为“项目”和“对话”；两个分区标题都可折叠，标题最右侧常驻 `+`，分别表示“打开项目”和“新对话”。箭头、标题导航、加号使用独立点击目标，加号不能触发折叠。

项目在上；对话区固定在导航底部、设置入口上方，始终位于项目区之下。项目区独立滚动；对话区展开后的列表限制高度并独立滚动，不能被长项目列表挤出视口。分区折叠后保留标题与加号，空态也保持这两个入口。设置作为固定底部工具保留，不属于对话列表。

每个项目名称是导航链接，独立箭头控制其对话列表收起/展开；展开显示最近 5 个和当前选中对话，更多从工作区查看。分区与各项目的展开状态本地保存，首次定位当前对话时展开所属分区/项目；用户手动收起后，SSE、刷新数据和标题更新不能强行重新展开。项目更多菜单含设置、归档。

项目内新对话从项目名称返回工作区空白输入后发送，不再增设“新建任务”文字按钮。侧栏“对话”加号始终创建独立草稿，不根据当前项目悄悄改变含义；保留的创建快捷键同样指向独立草稿，并更新提示。整栏收起后保留打开项目、独立新对话、恢复侧栏与设置图标，名称通过悬停/聚焦可读。窄屏抽屉使用相同内容与顺序。

**项目工作区：** 顶部项目名、低调路径、分支/当前变更与设置；主区最近对话、空白输入和查看全部。文件/变更复用右侧工作台，不另造一套文件浏览器。打开不自动恢复运行，不强跳历史对话；选择对话后进入对话页，标题项目名可返回工作区。

**工作台与 Git diff：** 左侧负责项目和对话导航，右侧工作台负责查看内容；在工作区未发送时也能直接查看项目文件与当前变更，不依赖 session 或沙箱。默认收起，由文件/变更入口打开，可切页签和关闭；打开已有对话沿用其结果、终端、浏览器和交付页。无对话的工作区只提供项目文件与变更，不虚构终端或浏览器会话。选文件看只读预览；选变更看带行号的统一 diff，有暂存和未暂存时上下分段明确标注，可在面板内滚动。改动列表与 diff 显示“项目当前变更”，不称本对话专属改动。刷新时保持选中路径，路径消失提示并清空旧内容；切项目不沿用旧项目数据。窄屏用右侧抽屉，代码区内部横向滚动。刷新与异常契约仍以 W10 R5 为准。

**视觉方向：** 沿用 UI DESIGN 的中性浅色、石墨深色、钴蓝交互强调、IBM Plex 字体与紧凑行高；用细分隔和层级区分导航/画布/工作台。分区加号、输入框加号使用同一图标语言，但各自含义固定。菜单只放短名称，说明按需展开；不引入大卡片、渐变或额外装饰。上下文入口只保留圆环，具体契约见 W9 U2。

**空态与异常：** 未配置时打开入口可见并给引导；根目录不存在、挂载未配置、Docker 不可用、共享沙箱不支持、读取失败分别呈现具体状态和下一步。不可用项目仍可看历史，只禁用新运行和文件操作。配置命令维护在应用运行指南，界面只给简短说明与文档入口。

**草稿与离开：** 切换项目/任务保留按作用域记录的文字、附件和 Plan 草稿；附件 id 仍有效才可重发。普通/计划切换不建任务。离开不自动停止；停止有独立入口。对话/开发者只是视图切换，不与项目归属混用。

## 改动清单与顺序

1. 用现有 token/组件制作首页、侧栏、工作区、对话页状态目录，先核对完整路径和异常，不先建 schema 再补体验。计划阶段不把目标写进已落地的 DESIGN；实现前新增“待实现”设计节，完成后转为事实。
2. 项目模型、仓库、迁移、接口、设置快照、活动互斥、归档/恢复；复用 W10 路径、读取、挂载。
3. UI 数据与分页、两分区加号/折叠/对话置底、工作区空白输入、草稿恢复；复用工作台和 W9 入口，不再复制 command context。
4. 端到端与 docs 收口。不增设未经用户要求的审批轮次；计划评审不自动授权实施。

## 验收

**自动与接口：**

- 路径唯一含并发重复添加、双向嵌套拒绝、设置校验、空配置/共享沙箱原因；空库迁移单 head；若回填，另测重复和嵌套。
- 绑定与首次 chat 竞争只产生合法归属；路径失效不启动；配置收窄后旧沙箱不继续未经校验写入。
- 同项目两个不同 session 同时首次 chat 只有一个受理；waiting 占用，审批不重复占用；停止/失败/重启可启动下一任务；不同项目可并行。
- 说明和身份跨运行、压缩、TTL 重建不变，请求重建含说明；没有身份不注入凭据。
- 归档保留任务与宿主机文件，有活动拒绝，恢复校验；不可用时历史可读。
- 项目/会话读取一致；分页、选中可见、批量校验、重连多标签更新；UI 类型、lint、build 和观察脚本通过。

**真实端到端（临时目录/仓库、Compose、真实模型，全程浏览器发起）：**

1. 未配置/读取失败仍可找到打开项目入口及原因；正确配置后添加，不靠直接 API 代替。
2. 打开不建任务/沙箱；发送并改临时文件，及时受理、达到终态、宿主机结果正确。
3. 第二任务继承项目；刷新、返回、三标签切换保持归属；独立对话进入对话区。
4. running/waiting 时第二任务不能执行，可返回或停止占用任务；已有改动明确属于项目当前状态。
5. 首次发送失败/超时、附件/Plan 草稿恢复，先读回再重发，不重复建任务或运行。
6. 改设置后新任务生效，旧任务续接/重建保持快照；临时 commit 核对作者，不把身份测试当认证或 push 测试。
7. 归档/恢复、目录失效/恢复，历史与宿主机文件保留。
8. 桌面浅色/深色、390×844、收起侧栏、键盘完成同一主路径，截图记录。
9. 全局及项目页面没有“新建任务”按钮；分区加号含义固定；两分区和项目子列表可收起；长项目列表滚动时对话区仍置底可达；手动收起不被数据刷新覆盖；从项目名称回工作区发送第二个项目内对话。无 session 时文件与 Git 查看仍工作。

复跑 E1、E2、E3、E4、E7 的无项目回归，另做上述绑定项目场景。macOS Docker Desktop 必须实测；没有 Linux 环境则记录属主/挂载未验证。进度和证据只登记总计划。

## docs 同步与交接

完成后更新产品说明（归属、打开与新建）、架构（项目/会话、快照与资源）、代码地图、能力与边界（共享目录、临时文件寿命、外部修改）、W4 契约、UI DESIGN 与所属服务指南。命令只在服务指南维护。本轮不修改已实现正文与课程。

给课程同步：项目是长期资源，任务是连续对话，run 是执行单位；打开、关闭、归档、停止生命周期不同。后续需要并行隔离、可归因 diff、回滚时，按总计划追加条件设计 worktree/变更集，不能把共享目录包装成已有隔离能力。
