## 目标与范围

平台完成部署与模型配置后，日常使用者在 Web 界面里新建项目或从本地文件夹上传创建项目，无需配置宿主机目录或 Git，在其中连续开多段对话；每段新对话能访问项目文件，并自动读取项目说明、项目笔记和有限的近期摘要。有效快照覆盖的文件修改可以整体恢复，产出可以下载。项目之外仍可开始独立对话。项目文件按需由工具读取，不把全部文件自动装入上下文。

**包含：** 项目实体与托管目录、新建与上传创建、项目文件上传与下载、项目内对话的附件与交付落入项目文件、运行前文件快照与整项目恢复、清理已归档项目的快照、项目说明与项目笔记、对话摘要索引、打开与关闭项目、侧栏导航、项目内新对话、归档与恢复、同项目运行互斥、Git 与宿主机目录代码的移除。

**不做：** 任何 Git 功能（状态、diff、分支、身份、提交与推送边界、包装脚本）；宿主机目录挂载与实时双向同步；浏览器文件系统访问接口回写本地；worktree 与并行隔离；单文件版本历史、按运行归因的变更集；项目内全文检索、向量记忆与隐式记忆；压缩时自动写笔记；笔记版本列表界面（全文保留在事件中，见项目记忆）；工作台里在线编辑文件；删除项目（首版只归档）；沙箱空闲回收与全局沙箱上限（沙箱积压是独立对话与项目对话共有的问题，不在本包处理）；编码专用能力。

## 设计契约

### 产品概念

| 概念 | 用户含义 | 关系与寿命 |
|---|---|---|
| 项目 | 一组材料、产出和记忆的长期容器 | 长期存在，可归档；文件由平台托管，不对应用户电脑上的某个目录 |
| 项目文件 | 用户上传的材料与 Agent 在项目里的产出 | 存在托管目录，沙箱销毁后仍在；与用户本地原件是两份独立副本 |
| 文件快照 | 某次运行开始前的整项目文件副本 | 运行前快照默认保留最近 5 份，设置可调为 1–7 份；上传前、恢复前快照另计，最多 3 份 |
| 项目说明 | 用户写给 Agent 的固定要求 | 用户编辑；每次运行开始时读取 |
| 项目笔记 | 项目里沉淀的结论、决策、待办、重要文件 | 用户与 Agent 都可改；每次运行开始时读取 |
| 对话摘要 | 每段项目内对话“做了什么”的一句话 | 运行结束后生成，供新对话了解历史 |
| 对话 | 项目之外的连续交流 | `sessions.project_id` 为空，沿用临时沙箱，没有项目文件与记忆 |
| 项目内对话 | 项目中的一段连续工作 | 一个 session 多个 run，追问留在原对话 |
| 工作台 | 右侧查看项目文件、结果、终端、浏览器与交付 | 与左侧导航分工 |

对话/项目是归属，普通/计划是执行模式，两者独立。新建入口本身不创建运行；从项目工作区或独立空白入口发送才建 session。

### 数据、托管目录与生命周期

- `projects`：id、name（1–160）、可空 instructions（≤ 8000 字符）、可空 notes（≤ 8000 字符）、notes_version 与 settings_version（整数，乐观并发）、archived_at、创建/修改/最近活动时间。**删除** `path` 唯一约束、Git 身份两列；目录由 id 派生，不由用户输入。
- `sessions.project_id` 可空外键；删除 `project_snapshot` 中的 Git 与目录身份字段。说明与笔记不再冻结在会话快照里，改为每次运行开始时读取并写入该运行的配置快照（系统提示词全文已在运行快照中，满足“模型可见即已记录”与请求重建）。归属在创建会话时确定，已打开的对话不改所属项目。
- `sessions` 增加可空 `summary`（≤ 200 字符）、`summary_source`（auto/manual）、生成时间、摘要覆盖到的最终回复事件序号，以及摘要生成代次（手动编辑、重新生成均递增）。
- `projects` 另记快照清理信息（最近一次清理时间与释放大小）、缓存的项目大小及统计时间/是否过期。项目文件操作记录包含 operation_id、kind（settling/upload/snapshot/restore/cleanup）、state（running/failed）、所属 run（可空）、阶段、目标快照/恢复前快照（可空）、起止/最近活动时间与错误。没有占用时为空；失败是否阻止工作按「文件操作互斥与失败收敛」规定。该记录用于单进程启动核对，不自动续跑，不建持久调度系统。
- 项目级审计事件单独持久化（project_id、项目内 seq、type、payload、created_at），保存用户笔记修改、文件操作结果与保护状态；不强塞给任意 session。项目详情提供只读分页事件接口，项目工作台详情可查看事件 JSON；项目内运行的笔记修改继续写会话 `project_notes` 事件，同时写项目审计事件，两者与笔记版本同事务。不新增笔记版本列表界面。
- 迁移 `f9c2a7b4d110` 尚未在用户库执行，直接改写这份迁移，保持单 head，不叠加兼容迁移。**不兼容旧数据（2026-09-30 用户确认）：** 删除旧路径回填、嵌套与多活动预检及相关测试，迁移直接删除 `sessions.project_path`；本地库里的旧项目关联、与新 schema 冲突的记录等脏数据直接移除，必要时清库重建，不写兼容或回填逻辑。
- **托管目录：** 项目文件放在 API 文件存储卷（默认 Compose 的 `file_data`，API 容器内 `/data/files`）下的 `projects/<id>/files/`，快照放在 `projects/<id>/snapshots/`；沙箱只把 `files/` 挂到 `/workspace`，看不到快照。
- **挂载方式：** 沙箱挂载命名卷的子目录，不用宿主机路径。API 启动时经 docker.sock 读取自身容器挂在 `/data/files` 上的卷名（Compose 会给卷名加项目前缀，不能写死）；创建沙箱时以 `type=volume`、该卷名、`VolumeOptions.Subpath=projects/<id>/files`、`NoCopy` 挂载到 `/workspace`。子目录须在挂载前由 API 建好。依据：卷子路径需 Docker 引擎 API ≥ 1.45，2026-09-30 本机为 Docker 29.7.2、API 1.55；锁定的 Docker SDK 7.1.0 的 `Mount` 没有子路径参数，按字典补 `VolumeOptions` 字段。默认 Compose 下不需要宿主机路径、`.env` 配置或 macOS 文件共享。API 不在容器中运行（本地开发）时才回退到 bind 挂载，需要一个配置项。启动自检解析不出卷名时项目功能不可用，界面显示原因，不静默降级。
- **文件属主：** API 以 root 运行（持有 docker.sock），沙箱以 ubuntu（uid 1000）执行；命名卷位于 Docker 的 Linux 虚拟机里，macOS 上同样按 uid 判断权限，root 写入的 644 文件沙箱改不了。API 对托管目录的所有写入（建目录、上传、恢复、附件与交付落盘）走同一个写入函数，完成后属主改为沙箱用户（默认 1000:1000，可配置），目录 0775、文件 0664。
- **遍历与符号链接：** 快照、打包下载、大小统计、目录树、预览、恢复都用同一个遍历函数：`os.scandir` 不跟随符号链接，打开文件带 `O_NOFOLLOW`。符号链接只作为链接记录：快照保存链接目标文字、恢复时重建链接，zip 与大小统计跳过，预览显示为链接、不读取目标。原因：Agent 可在 `/workspace` 建指向 API 容器内路径的链接，API 若跟随，容器内的配置与密钥会进入下载、快照或恢复后的项目文件。
- 遍历只处理普通文件、目录、符号链接；FIFO/socket/设备等特殊项显示不可预览/下载，不阻塞读取，快照遇到它们明确失败并列出路径；恢复拒绝非法清单类型。以目录描述符逐级无跟随检查父目录，最终打开后核对类型；`O_NOFOLLOW` 只保护最后一段，不能单独作为父目录防逃逸措施。哈希对象是普通文件，不复用 Agent 可修改的硬链接。
- 项目文件读取、上传与下载都经过项目内相对路径校验（拒绝 `..`、绝对路径、符号链接逃逸），复用 W10 的相对路径检查，去掉根目录配置部分。
- **项目大小：** 每次快照扫描得出并缓存（超限跳过也完成大小统计），上传、附件、交付、恢复后更新；工具写入时标记缓存过期，项目运行终态确认旧写入者停止后重新统计。列表读缓存并返回统计时间/过期标记，运行中显示“上次统计，运行中可能变化”，不假称实时大小；上传准入必须重新核对当前总量，不信任缓存。项目总量上限只约束上传；Agent 在沙箱内写入没有配额，超过上限后禁止上传、快照跳过，项目页常驻说明。运行与单文件下载仍可用；整项目 zip 超限时拒绝并说明，已有有效快照仍可查看，恢复条件见快照一节。用户可让 Agent 删除/精简文件，或分文件下载后另建项目；不新增在线编辑或文件删除界面。
- 项目文件固定放在本地卷，与会话附件使用本地存储还是 COS 无关。
- 归档隐藏入口并禁用新运行、上传与恢复，保留文件、快照与历史；恢复重新可用。有活动运行时归档返回 409。关闭项目只离开界面。首版不删除项目；已归档项目可清理全部快照释放空间（见运行前文件快照），项目文件与历史保留。
- 每个任务仍有自己的沙箱与临时输出；`/workspace` 之外、又没有按「上传与下载」复制进项目文件的沙箱文件，随沙箱回收丢失。这一点写入提示词与能力边界。

**旧写入者收尾：** run 的 completed/failed/cancelled/interrupted 不等于共享目录已经静止。项目内运行终态后登记 settling 操作，停止该项目关联的动态沙箱容器，确认 Docker 状态为 stopped/exited（已不存在也算停止）后才释放文件占用；不能只杀登记的 Shell，因为后台子进程、浏览器或未登记进程也可能写文件。先走正常停止，10 秒后仍运行则强制终止并读回确认；Docker 不可达或无法确认时记录失败，阻止新运行、上传、恢复、归档与清理，给出“重试环境收尾”入口。run 终态不回改，收尾结果单独入事件。等待回复/审批不是终态，不停沙箱，仍占用项目。迟到容器沿 W10 所有权规则停止并清理，不允许旧启动结果重新挂上。

API 启动时先按 W3/W7 处理遗留运行，再按持久化项目关联和容器标签（project_id/session_id/run_id）核对所有项目沙箱：没有活动运行的容器必须停止；遗留文件操作按下文处理。核对失败的项目不可写，其他项目仍可使用。独立对话的沙箱寿命不改；这项是共享项目写入保护，不是全局空闲回收。下一次项目运行先完成快照，再启动已停止的可用容器或创建新容器；不得在快照之前启动旧进程。代价是项目运行之间不保证浏览器登录、终端进程和沙箱服务状态延续；waiting 续接保持原环境，项目文件与对话历史保留。已停止的容器可保留到原生命周期清理，恢复仍不得替换 `files/` 根目录。

### 上传与下载

**上传入口：** 新建项目时可选“从本地文件夹创建”；已有项目的工作台文件页可上传文件或文件夹。按相对路径逐个上传，服务端还原目录结构。

**浏览器扫描方式：** 拖放用 `webkitGetAsEntry` 逐层遍历，支持 `showDirectoryPicker` 的浏览器用它选择文件夹；两者都在遍历时跳过排除目录，不先列出其中的文件。只支持 `<input webkitdirectory>` 的浏览器会先列出全部文件，含大型依赖目录时可能明显变慢，选择前提示。文件名统一转为 NFC。

跳过的目录显示“未扫描，大小未统计”，不伪造 0 或精确大小；用户勾选可选目录后再扫描其中内容，扫描完成后才能确认。有条件目录先读取同级清单名称和必要标志（如 pyvenv.cfg），再决定跳过。浏览器已枚举到的排除项才显示已知大小。首版不保留空目录，预检说明“仅上传文件及其父目录”。

**上传前检查与弹框（前后端同一套规则，前端预检、服务端复核）：** 阈值与名单由 API 以一份 JSON 下发，前端预检与服务端复核读同一份。选择后先在浏览器端扫描，弹框展示：文件数、总大小、将排除的内容及各自大小、超限项与敏感文件提醒。用户确认后才上传，取消不产生任何写入。

“各自大小”只适用于已扫描项；单次阈值按最终待上传集合计算，项目总量按覆盖替换后的实际字节计算。确认请求带规则版本、NFC 后的路径清单、每项文件大小与内容哈希、用户选择上传的可选排除项、覆盖项；API 检查规则版本和当前冲突，规则变化/冲突变化返回 409 要求重新预检。默认排除项只有明确逐项确认后可上传；始终排除项、路径限制和大小上限不可由确认覆盖。服务端按实际接收字节、文件数量和内容哈希核对，拒绝重复规范化路径、文件/目录冲突与超限，不能只相信前端声明。父目录检查也不跟随符号链接，文件发布使用临时文件与原子改名；扫描/写入不得经链接父目录访问卷外路径。

| 检查项 | 规则（首版默认值，协调者按收益评估确定） | 弹框表现 |
|---|---|---|
| 单次上传 | ≤ 200 MB、≤ 2000 个文件 | 超出时禁用“上传”，说明超出多少 |
| 单个文件 | ≤ 50 MB | 列出超限文件并排除 |
| 项目总量 | 上传后项目文件总量 ≤ 500 MB | 超出时禁用“上传” |
| 依赖目录（确定） | `node_modules`、`bower_components`、带 `pyvenv.cfg` 的目录、`site-packages`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.tox`、`.parcel-cache`、`.turbo` | 默认排除，列出目录和大小；说明“依赖可由清单文件重新安装，清单文件（如 `package.json`、`requirements.txt`、`pyproject.toml`、锁文件）会保留”；用户可逐项改为上传 |
| 构建与依赖目录（有条件） | 仅当同级存在对应清单时排除：`dist`、`build`、`.next`、`.nuxt`（`package.json`）；`.venv`、`venv`（任一 Python 清单或 `pyvenv.cfg`）；`target`（`Cargo.toml`、`pom.xml`）；`.gradle`（`build.gradle*`）；`Pods`（`Podfile`）；`vendor`（`composer.json`、`go.mod`、`Gemfile`） | 满足条件时同上；没有清单时按普通资料目录上传。RayAgent 面向非编码场景，同名的普通资料目录不能被误排除 |
| 版本库与系统文件 | `.git`、`.svn`、`.hg`、`.DS_Store`、`Thumbs.db` | 总是排除，不可勾选 |
| 疑似凭据 | `.env`、`.env.*`、`*.pem`、`*.key`、`id_rsa*`、`*.p12` | 默认排除并提示可能含密钥；用户可逐项勾选上传 |
| 同名文件 | 已有项目中存在相同相对路径（NFC 后比较） | 列出冲突，选择“覆盖”或“取消”；覆盖前自动做一份“上传前”快照。只有大小写不同的路径单独提醒：项目卷区分大小写，下载到 macOS 或 Windows 会冲突 |

- 运行中（含启动中、等待回复、等待审批）禁止上传与恢复快照，界面禁用并说明原因，服务端返回 409。
- 上传部分失败时已写入的文件保留，弹框列出失败项并可重试失败部分；不宣称全部成功。
- 上传使用有开始/完成/取消入口的项目级 operation_id；从服务端准入到完成或取消整个批次占用项目文件操作，不在逐文件请求之间释放。客户端关闭、断连不等于批次完成；10 分钟无活动或总计 30 分钟到期后结束为部分失败，保留成功清单、删除未发布临时文件、重新统计大小并释放占用，不自动再传。API 重启将遗留上传按部分失败结束；详情能读回逐项结果。失败项重试重新预检并开启新批次；已成功的相同路径/哈希项不重复上传。
- 超限阈值为配置默认值，不暴露到设置页；数值在验收时按实测体验复核。

**项目内对话的附件与交付（2026-09-30 用户确认写入项目文件）：**

- 输入框附件在消息受理时写入 `files/uploads/`，套用同一套检查规则；同名时自动改名、不覆盖。沙箱里仍同步到 `/home/ubuntu/upload` 供本次运行使用。因为只新增、不覆盖，运行中追加消息时的附件也允许写入，不受“运行中禁止上传”限制。独立对话的附件不变。
- 附件受理采用已上传附件暂存→消息/run/待落盘关联同事务提交→后台发布的次序，不在 HTTP 受理路径做沙箱同步或等待旧容器停止。按 `(project_id, attachment_id)` 保存落盘相对路径、内容哈希和 pending/ready 状态，同一上传附件 id 重试复用该副本，不同附件 id 即使同名也自动改名。首次运行后台确认旧写入者停止后，短时文件锁下分配路径并发布附件，更新 ready 关联，然后做快照、启动沙箱、同步 `/home/ubuntu/upload`，最后 invoke。文件发布后的 ready 更新明确失败时仅清理本次未确认副本，保留已受理的 pending 关联供失败读回；结果未知时先查关联和实际文件哈希，不盲删、不重复复制。启动核对根据已受理消息与关联协调暂存/发布记录，清除无消息关联的本次孤儿，不删除既有 ready 副本。受理后落盘或沙箱同步失败走 W10 环境准备失败，不把已受理报告为未发送，不删除 ready 项目副本。
- 附件预检和可选排除确认也适用于输入框上传；chat 只引用已上传 id，不重新传文件。运行中新增附件与同名分配逐文件串行，不与快照/恢复/普通上传批次交叉；准备快照期间的注入附件先排入当前 run 输入通道，快照结束后发布，模型下一次请求前才消费。注入附件准备失败形成可识别的处理错误且原消息仍可读回，不消费缺失附件、不自动重复提交消息。waiting 提问续接可发布附件，等待审批仍不能发 chat。
- `deliver_files` 照旧上传为会话附件（交付时的副本，交付卡下载它）；路径在 `/workspace` 之外的，另外复制到 `files/outputs/`（同名自动改名），使产出在沙箱回收后仍留在项目里。路径已在 `/workspace` 内的不再复制。
- 交付结果逐文件分别返回会话附件结果与项目持久化结果；会话附件成功、项目复制失败时仍保留可下载交付卡，明确“交付可下载，但未保存到项目”，工具向模型返回部分失败及原因，不宣称两者都成功。相同 run/call_id/源路径的补存复用已成功部分，只重试失败复制；不自动重试整次副作用工具。实际路径按沙箱解析结果判断，不能以字符串前缀把 `/workspace-other` 或指向外部的链接当作工作区内文件。项目复制通过统一写入函数；终态收尾等待已开始复制完成或明确失败。

**下载：** 单文件下载；整项目打包下载（zip，流式生成，受项目总量上限约束，不含符号链接）。下载不需要沙箱，运行中也允许，提示“运行中下载的内容可能不完整”。

### 运行前文件快照

- **时机：** 每次项目内运行开始前、沙箱调用之前做一份快照（运行启动显示为“准备执行环境”的一部分）；等待回复、审批续接属于同一运行，不重复快照。上传覆盖和恢复快照之前同样先做一份，并标注来源（运行前 / 上传前 / 恢复前）。
- **存储：** 按内容存储，不打包整目录。每份快照是一份清单（相对路径、类型、大小、权限、修改时间、内容哈希；符号链接记录链接目标文字），文件内容按哈希存放在项目的对象目录里，多份快照共用未变的文件。首版在确认旧写入者停止后逐文件读取并计算内容哈希，不按大小/mtime/inode 相同直接复用旧哈希；相同内容只复用对象，不重复存储。不用硬链接去重：Agent 原地改写文件时，硬链接会让快照内容一起变化。
- **发布与回收：** 新对象先写临时文件，核对哈希并 flush/fsync 后原子改名；清单同样先完整落盘，再事务登记为 ready，只有 ready 快照可列为可恢复。完成前不得淘汰旧快照。异常留下的临时对象/未登记清单由启动核对清理；先对照持久化操作与 ready 清单，不删除创建中或恢复中被保护的对象。回收在同一项目文件操作占用下，按所有 ready 清单及被固定的目标/恢复前清单计算引用；清单撤销提交后才回收未引用对象。回收失败只记录待重试与实际释放量，不否定已成功发布的快照、不误报已释放。恢复前校验每个对象存在、大小与哈希正确；缺失/损坏返回具体文件错误，不破坏当前文件或其他快照。
- **保留：** 运行前快照的保留份数为全局设置，默认 5，可设 1–7，设置页通用分区可改；上传前与恢复前快照另计，合计最多 3 份，不挤占运行前快照。调小后在下一次快照时淘汰最旧的。淘汰在操作成功后执行；恢复期间目标快照被锁定，保留份数为 1 时也能恢复。
- **跳过与失败：** 项目文件超过快照上限（与项目总量上限一致）时跳过本次运行前快照，时间线和项目保护状态显示“项目超过快照上限，本次运行没有快照”，在任何 Agent 工具执行前发布该状态，运行照常进行。超限跳过是明确的保护降级例外，不承诺每次运行都有快照。磁盘空间不足或读写出错导致快照失败时，本次运行以“环境准备失败”结束，不启动/创建沙箱、不执行，原因写明快照失败；“没有保护时不执行”仅适用于此错误路径。快照在线程中执行，返回后先确认运行仍是活动的；运行已被停止时不启动沙箱，已生成的 ready 快照保留。停止协程不能提前释放快照占用，须等线程退出或核对完成，避免下一项操作交叉。
- **恢复：** 工作台“快照”列表显示时间、来源、关联对话与大小；“恢复到此快照”只在无活动运行且旧写入者已停止时可用，二次确认后先做一份“恢复前”快照，再按清单**原地恢复**：删除清单外的文件，内容有变化的文件先写临时文件再改名覆盖，重建目录与链接，按“文件属主”一条设置属主。不得删除或改名替换 `files/` 目录本身；保留容器下一次启动后必须看到同一个托管目录的恢复结果。此前“其他项目对话的运行中沙箱仍存活时恢复”改为停止容器后恢复再启动验证，避免旧进程同时写入。首版不做单文件恢复与差异对比。
- **恢复失败收敛：** 先固定目标清单、确认旧写入者停止、校验全部对象，再成功发布并固定恢复前快照，最后持久化 restore 的 applying 阶段才开始修改文件。恢复前快照无法生成（含当前项目超限）时拒绝恢复，不沿用运行前的超限跳过规则；提示先下载/精简当前文件。修改中磁盘/权限错误或 API 退出时保留 failed restore、目标与恢复前快照，项目显示“恢复未完成”，禁止新运行、上传、归档和清理；只读查看/单文件下载仍可用，下载提示当前文件可能是混合状态。允许手动“重试本次恢复”或“回到恢复前”，两者固定使用该操作已有清单，不再为混合状态生成并淘汰恢复前快照；不自动恢复、不把失败报成成功。按清单幂等重做并校验最终路径集合和内容后才清除占用、更新大小与恢复事件。恢复生成链接时不跟随链接设置属主，不允许清单中的链接父目录参与写入。启动核对将 applying 标为 failed；未进入 applying 的失败可清理暂存并释放，不影响原文件。
- **清理已归档项目的快照（2026-09-30 用户确认纳入）：** 已归档项目的快照页提供“清理全部快照”，二次确认后删除全部清单并回收对象，项目文件与对话历史保留；项目上记录最近一次清理的时间与释放的大小，快照页显示。未归档项目不提供该操作。项目恢复后从下一次运行重新积累快照。
- 快照是“最近几次之前的版本”，不是完整历史，也不说明哪次运行改了哪个文件；这一点写入能力边界。

### 项目记忆

- **注入内容：** 每次项目内运行开始时读取一次项目段，依次包含项目说明、项目笔记（带当前 `notes_version`）、最近对话摘要（最多 10 条、合计不超过 1500 字符，按最近活动倒序，不含当前对话），本次运行内保持不变。摘要最常变化，放在最后，减少前缀缓存失效的范围。计入容量估算，压缩后保留，请求重建可见。独立对话没有项目段，行为不变。
- **注入方式：请求时拼接，不写入记忆。** 现有代码在会话首次运行时把 system 写进记忆，之后不再改变（`agent_loop.py` 的 `_add_messages`）；`config_snapshot()` 记录的也是记忆里那条；`build_system_prompt` 目前把项目说明直接拼进基础提示词。照此实现，同一对话的后续运行会一直看到首次运行时的说明与笔记。改为与计划模式后缀相同的方式：记忆里的 system 只保存基础提示词；项目段与计划模式后缀在 `_request_messages()` 中拼到 system 末尾；`config_snapshot()` 记录拼接后的全文，请求重建因此与实际请求一致。`build_system_prompt` 不再接收项目说明，项目段由独立函数生成，中英文各一份。
- **手动压缩的估算（与 W9 U3 同步）：** 项目内对话的手动压缩在估算时按当前项目内容现场生成项目段，并标明“按当前项目内容估算”，不用记忆里只有基础提示词的 system 代替。
- **笔记工具：** 项目内运行提供 `update_project_notes(content, base_version)`，整体替换。成功时返回新的 `notes_version`，同一次运行里再次更新用它；版本不一致时不写入，工具结果附带当前全文与版本，模型据此合并后重试，不需要单独的读取工具；超过 8000 字符时返回错误，要求精简后重试。每次成功写入产生 `project_notes` 事件，**携带写入后的全文**，笔记被误改时可从开发者视图的事件原文取回。计划模式按允许清单默认拒绝该工具；工具策略可对其设 ask/deny。独立对话不注册该工具。
- **何时写笔记（提示词约定）：** 在任务结束或得出可复用的结论、决策、待办、重要文件位置时更新；不逐轮记录过程，不写入可从文件直接读到的内容。是否写由模型决定，程序不校验。
- **用户编辑：** 项目设置里可查看和编辑说明与笔记，同样按版本保存，冲突时提示重新加载（每次运行开始时读取，2026-09-30 用户确认）。运行中允许编辑，本次运行仍用开始时读到的内容，下一次运行生效。
- 用户笔记修改和 Agent 修改共享 notes_version；用户写入后的全文、版本、来源 user、时间写项目审计事件，与更新同事务，失败不留下假历史。Agent 来源为 agent，关联 run/session。修改说明记录同样的项目审计信息；设置保存用项目设置版本条件更新，防止两个标签互相覆盖说明。事件只供追溯，首版不提供完整历史记忆检索或笔记版本列表。
- **对话摘要：** 项目内运行进入 completed 后异步生成一句话摘要（复用标题生成的独立模型请求路径）。请求输入是首条用户消息加该对话每次运行的最终回复（各自截断），不发送整段历史。`sessions` 增加 `summary_source`（auto/manual）：自动结果只在当前来源为 auto 或为空时写入，写法与 `title_source` 的条件更新相同，手动改写不会被后续运行覆盖；“重新生成”把来源改回 auto。进程重启导致的丢失可在项目页手动补生成。被停止、失败或一直在等待回复的对话没有自动摘要，可手动生成。摘要只供新对话参考，不替代历史消息。
- 摘要请求冻结输入截止的最终回复 seq 与生成代次；提交时同时检查来源、代次和已存摘要截止 seq，旧任务不能覆盖较新结果。手动修改递增代次并设 manual；重新生成递增代次并设 auto，使此前在途结果全部失效。自动更新只在覆盖范围不旧于当前摘要时提交；空结果/失败保留已有摘要并显示可重新生成原因。说明、笔记、摘要和版本从一致的数据库快照读入本次 run，waiting 续接沿用该 run 冻结全文。笔记工具成功后的全文通过工具结果可见，不暗改本次冻结 system。
- **容量与记忆边界：** 基础提示词、项目段、模式后缀与工具 schema 都计入固定输入；它们本身超过可用输入上限时，不循环摘要、不静默裁说明/笔记，普通运行以 context_limit 结束并提示精简项目说明/笔记或调整模型窗口。手动压缩在相同条件下返回明确容量错误，记忆不变，细节由 W9 U3/U5负责。最多十条/1500 字符摘要、≤8000 字符笔记只提供有限近期背景；较早细节可能不在下一段上下文，模型按需读材料，不能承诺完整历史记忆。
- 首版不提供“按需读取历史对话全文”的工具，不做压缩时自动写笔记，不做笔记版本列表界面。

### 同项目运行互斥

同项目最多一个活动运行（启动中、running、waiting 回复或审批），计划模式也遵守；多个对话可以同时打开和准备草稿，第二个任务发送返回 409。**waiting 继续占用项目（2026-09-30 用户确认）**，不设自动超时释放、不排队、不强制接管：409 提示指出占用对话与原因（等你回复/等你批准），给出「跳转」与「停止占用的运行」；项目页和侧栏项目行在存在 waiting 运行时显示「等待中」。归档、上传、恢复快照、清理快照在有活动运行时同样返回 409 并说明需先回复或停止。

项目占用与新 run 在事务内协调：锁项目行并在同一事务查询活动 run；chat、审批续接、停止、归档、上传、恢复、清理使用一致锁顺序。不同项目可同时运行。

### 文件操作互斥与失败收敛

统一锁顺序为项目行→会话行→run 行；操作登记/准入用短事务，文件 IO 不长持数据库事务，跨请求占用由持久化 operation_id 表达，单进程协调器保证同项目仅一项。准入同时检查活动 run、文件操作和旧写入者核对结果，不能在检查后、登记前留竞争空档。所有后台完成必须核对 operation_id/run_id，旧回调不能释放新占用。操作状态随项目详情/列表通知更新；409 返回操作类型、所属对话（如有）和处理入口。

| 操作 | 活动 run（含 waiting） | 文件操作占用/恢复未完成 | 准入和结束条件 |
|---|---|---|---|
| 新 run（普通/计划） | 拒绝另一 run | 拒绝 | 同事务登记 run；先核对旧容器，再快照，后启动沙箱 |
| 回复提问/审批、运行中补充消息 | 只路由当前 run；审批不接 chat | 准备中的消息排入同一输入通道；恢复占用拒绝 | 不另建 run；注入附件按上传一节发布 |
| 普通文件/文件夹上传 | 拒绝 | 拒绝 | 整批占用；覆盖前快照必须成功，超限时不允许无保护覆盖；部分失败可读回后结束 |
| 快照恢复 | 拒绝 | 拒绝新恢复；允许当前 failed restore 的两种修复 | 旧写入者停止、对象完整、恢复前快照成功后才修改 |
| 归档、归档恢复、快照清理 | 拒绝 | 拒绝 | 归档/恢复只改元数据；清理全程占用并记录实际释放量 |
| 说明/笔记、摘要编辑 | 允许 | 允许 | 版本更新；不修改本次 run 冻结输入，不触碰文件 |
| 树/预览/下载/事件查看 | 允许 | 允许 | 标明运行中/上传中/恢复未完成的不一致风险；zip 大小上限不豁免 |

snapshot 中断时未发布部分丢弃，旧 ready 快照保留；cleanup 中断时保留待回收记录，可重复执行；upload 中断按部分失败结束；restore applying 中断阻止写入直至手动修复；settling 失败阻止写入直至停止状态核对成功。读取状态不等待长文件锁。启动核对先处理旧写入者，再处理遗留操作，不能仅清掉 busy 标记。即使单进程，也用真实数据库测试准入事务和异步回调交叉，不以 UI 禁用替代服务端互斥。

### 接口与数据契约

- 项目：列表、新建（名称、可选说明）、详情、改设置（说明带 settings_version，笔记带 notes_version）、归档/恢复；列表含 id/name/archived/task_count/last_active_at/has_waiting/files_size（读缓存）、大小统计时间/过期标记、当前文件操作与阻止写入原因。项目功能可用性（启动自检的卷解析结果与原因）随项目列表或状态接口返回；详情另含最近保护状态（ready/skipped/failed 与 run/快照关联），等待环境收尾不伪装成活动 run。
- 项目文件：上传预检规则只读下发（含版本）、批次开始/逐项上传/完成/取消/结果读回；目录树、读文件预览、单文件下载、整项目 zip 下载。批次接受确认项并返回 operation_id，逐项结果带规范化路径、哈希、是否已发布、错误；结果读回保留到项目历史中供核对。
- 快照：列表（仅 ready 可恢复）、恢复、当前失败恢复的重试/回到恢复前、清理全部（仅已归档项目，无活动运行或其他文件占用时）；环境收尾重试与文件操作状态读回。保留份数在应用设置中。
- 项目审计：按 seq 分页只读事件，事件带来源、版本、操作/运行关联与必要全文，不执行回放。
- 对话摘要：手动改写、重新生成。
- 删除：`/projects/roots`、`/projects/browse`、项目级与会话级 `git/status`、`git/diff`，以及项目登记接口中的路径参数。
- `POST /sessions` 可选 `{project_id}`，创建与关联同事务；首次发送的草稿、session id、chat 结果遵循 W10 R3。
- 项目/对话列表独立分页，默认 50 条；侧栏每项目最近 5 个，当前选中对话始终可见。同步后端 schema、UI API 类型、W4 视图模型、列表 SSE 与观察脚本；loading/error/disabled/empty 独立。

11. 用有明确检查答案的非编码项目完成连续工作：上传原始 CSV 与说明（含不得覆盖原材料、统计口径），第一段分析交付并写笔记；第二段根据摘要/笔记追加分析与文件产出；用户修改笔记后下一次运行生效；随后恢复快照、销毁测试沙箱并下载项目/交付。核对源文件哈希、计算结果、传递约束、笔记版本、摘要来源、恢复后的路径/字节、沙箱销毁后下载字节；区分模型未主动写笔记与系统未保存，失败如实记录。统计用户必须重复输入的背景、人工操作次数、运行请求/tokens/耗时与快照准备耗时；不设未经基线支持的提速或成功率承诺。

第 11 项固定材料为 `source.csv`（category,amount 三行 A/10、B/20、A/30）和项目说明“金额单位为元；不得覆盖原材料”。第一段输出 `totals.json`（total=60），写笔记记录统计口径与文件位置；第二段只要求“沿用项目口径做分类汇总，预算为100元”，不得再灌第一段背景，输出 `categories.json`（A=40、B=20、remaining=40）并至少把一份 `/workspace` 外产出交付到项目 outputs。用户再将笔记中的报告阈值设为25元，下一运行输出 `threshold.json`（count_above=1），请求重建证明新版笔记被注入。恢复第二段运行前快照后，source 与 totals 字节保留，第二段之后新增的文件消失；既有交付卡仍能下载交付时副本。截图、事件、快照清单与下载哈希共同作证。该场景以项目评测定义纳入既有评测支撑；API 编排用于稳定检查，浏览器另走同一完整场景，不以脚本直接改笔记或文件替代 Agent/用户真实操作。

最终提交上复跑 E1–E7、E6-deny 各一次（2026-10-02 用户要求加快、测试从简；保留全部八类，取消重复轮次），另经产品界面完成受控浏览器、MCP 批准/拒绝、A2A 成功/远端失败最小回归各一次，再做上述项目场景。报告记录实际模型、温度、窗口、工具策略、部署和资源清理条件，E7 调低窗口如实标注；不得沿用返工前报告代替。属主问题在 macOS 上同样存在，第 1 项即覆盖；Linux 宿主机如无环境记录未验证。验收报告记录完整产品SHA、迁移、API/UI/沙箱镜像及Compose解析结果；验收后产品变动复验受影响项，文档整理可单独提交。验收tag为v2-projects，不移动旧v2；进度与证据只登记总计划。

## docs 同步与交接

完成后更新产品说明（项目、上传下载、快照、记忆）、架构（托管目录与卷子路径挂载、项目段请求时拼接、快照存放）、代码地图、能力与边界（副本不回写、快照不是完整历史、快照失败时不执行、沙箱临时文件寿命、无删除项目但可清理已归档项目的快照、Agent 写入无配额、上传规则、笔记只保留事件全文而无版本界面）、设计取舍记录（放弃 Git 与宿主机目录的原因）、W4 契约、UI DESIGN 与所属服务指南；运行与 Docker 指南删除 `PROJECT_ROOTS` 与覆盖文件说明。本轮不修改课程。

上述文档同时校准：部署与模型配置是前提；快照超限是保护降级例外；恢复失败必须先修复；项目运行终态后容器停止、浏览器/终端状态不保证跨运行保留；项目摘要/笔记不等于完整历史记忆。架构同步项目审计、文件操作占用与沙箱写入寿命，不为局部字段另加章节。W9 负责容量显示与手动压缩错误，W10 负责受理读回及附件失败草稿，W11 负责文件关联与环境收尾，不把责任互相推给下游。

给课程同步：项目是材料与记忆的容器，任务是连续对话，run 是执行单位；项目记忆是透明、可编辑的笔记加摘要，而非隐式记忆；文件安全靠运行前快照而非版本控制。
