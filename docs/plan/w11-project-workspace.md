## 目标与范围

让没有部署经验的用户在界面里新建项目或从本地文件夹上传创建项目，在其中连续开多段对话；每段新对话能读到项目文件、项目说明、项目笔记和之前对话的摘要；Agent 的修改可以按运行前快照整体恢复，产出可以下载。项目之外仍可开始独立对话。

**包含：** 项目实体与托管目录、新建与上传创建、项目文件上传与下载、运行前文件快照与整项目恢复、项目说明与项目笔记、对话摘要索引、打开与关闭项目、侧栏导航、项目内新对话、归档与恢复、同项目运行互斥、Git 与宿主机目录代码的移除。

**不做：** 任何 Git 功能（状态、diff、分支、身份、提交与推送边界、包装脚本）；宿主机目录挂载与实时双向同步；浏览器文件系统访问接口回写本地；worktree 与并行隔离；单文件版本历史、按运行归因的变更集；项目内全文检索、向量记忆与隐式记忆；压缩时自动写笔记；工作台里在线编辑文件；删除项目（首版只归档）；编码专用能力。

## 设计契约

### 产品概念

| 概念 | 用户含义 | 关系与寿命 |
|---|---|---|
| 项目 | 一组材料、产出和记忆的长期容器 | 长期存在，可归档；文件由平台托管，不对应用户电脑上的某个目录 |
| 项目文件 | 用户上传的材料与 Agent 在项目里的产出 | 存在托管目录，沙箱销毁后仍在；与用户本地原件是两份独立副本 |
| 文件快照 | 某次运行开始前的整项目文件副本 | 默认保留最近 5 份，设置可调为 1–7 份 |
| 项目说明 | 用户写给 Agent 的固定要求 | 用户编辑；每次运行开始时读取 |
| 项目笔记 | 项目里沉淀的结论、决策、待办、重要文件 | 用户与 Agent 都可改；每次运行开始时读取 |
| 对话摘要 | 每段项目内对话“做了什么”的一句话 | 运行结束后生成，供新对话了解历史 |
| 对话 | 项目之外的连续交流 | `sessions.project_id` 为空，沿用临时沙箱，没有项目文件与记忆 |
| 项目内对话 | 项目中的一段连续工作 | 一个 session 多个 run，追问留在原对话 |
| 工作台 | 右侧查看项目文件、结果、终端、浏览器与交付 | 与左侧导航分工 |

对话/项目是归属，普通/计划是执行模式，两者独立。新建入口本身不创建运行；从项目工作区或独立空白入口发送才建 session。

### 数据、托管目录与生命周期

- `projects`：id、name（1–160）、可空 instructions（≤ 8000 字符）、可空 notes（≤ 8000 字符）与 notes_version（整数，乐观并发）、archived_at、创建/修改/最近活动时间。**删除** `path` 唯一约束、Git 身份两列；目录由 id 派生，不由用户输入。
- `sessions.project_id` 可空外键；删除 `project_snapshot` 中的 Git 与目录身份字段。说明与笔记不再冻结在会话快照里，改为每次运行开始时读取并写入该运行的配置快照（系统提示词全文已在运行快照中，满足“模型可见即已记录”与请求重建）。归属在创建会话时确定，已打开的对话不改所属项目。
- `sessions` 增加可空 `summary`（≤ 200 字符）与生成时间。
- 迁移 `f9c2a7b4d110` 尚未在用户库执行，直接改写这份迁移，保持单 head，不叠加兼容迁移。**不兼容旧数据（2026-09-30 用户确认）：** 删除旧路径回填、嵌套与多活动预检及相关测试，迁移直接删除 `sessions.project_path`；本地库里的旧项目关联、与新 schema 冲突的记录等脏数据直接移除，必要时清库重建，不写兼容或回填逻辑。
- **托管目录：** API 在托管根目录下为每个项目建 `<id>/files/`，快照放在 `<id>/snapshots/`，沙箱只挂载 `files/` 到 `/workspace`，看不到快照。API 对托管根读写挂载；沙箱挂载源须是 Docker 守护进程能解析的宿主机绝对路径，因此配置区分“宿主机路径”和“API 容器内路径”。目标是默认 Compose 下用户无需任何配置即可使用；默认值与 macOS Docker Desktop 文件共享范围在实施时核对并实测。
- 项目文件读取、上传与下载都经过项目内相对路径校验（拒绝 `..`、绝对路径、符号链接逃逸），复用 W10 的相对路径检查，去掉根目录配置部分。
- 归档隐藏入口并禁用新运行、上传与恢复，保留文件、快照与历史；恢复重新可用。有活动运行时归档返回 409。关闭项目只离开界面。首版不删除项目，磁盘占用由用户归档后自行管理，此限制写入能力边界。
- 每个任务仍有自己的沙箱与临时输出；`/workspace` 之外的沙箱文件随沙箱回收丢失，这一点写入提示词与能力边界。

### 上传与下载

**上传入口：** 新建项目时可选“从本地文件夹创建”；已有项目的工作台文件页可上传文件或文件夹。浏览器用文件夹选择与拖放，按相对路径逐个上传，服务端还原目录结构。

**上传前检查与弹框（前后端同一套规则，前端预检、服务端复核）：** 选择后先在浏览器端扫描，弹框展示：文件数、总大小、将排除的内容及各自大小、超限项与敏感文件提醒。用户确认后才上传，取消不产生任何写入。

| 检查项 | 规则（首版默认值，协调者按收益评估确定） | 弹框表现 |
|---|---|---|
| 单次上传 | ≤ 200 MB、≤ 2000 个文件 | 超出时禁用“上传”，说明超出多少 |
| 单个文件 | ≤ 50 MB | 列出超限文件并排除 |
| 项目总量 | 上传后项目文件总量 ≤ 500 MB | 超出时禁用“上传” |
| 包依赖与生成目录 | 前端：`node_modules`、`bower_components`、`.next`、`.nuxt`、`dist`、`build`、`.parcel-cache`、`.turbo`；后端/Python 等：`.venv`、`venv`、带 `pyvenv.cfg` 的目录、`site-packages`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.tox`；其他：`target`、`.gradle`、`Pods`、`vendor` | 默认排除，列出目录和大小；说明“依赖可由清单文件重新安装，清单文件（如 `package.json`、`requirements.txt`、`pyproject.toml`、锁文件）会保留” |
| 版本库与系统文件 | `.git`、`.svn`、`.hg`、`.DS_Store`、`Thumbs.db` | 总是排除，不可勾选 |
| 疑似凭据 | `.env`、`.env.*`、`*.pem`、`*.key`、`id_rsa*`、`*.p12` | 默认排除并提示可能含密钥；用户可逐项勾选上传 |
| 同名文件 | 已有项目中存在相同相对路径 | 列出冲突，选择“覆盖”或“取消”；覆盖前自动做一份“上传前”快照 |

- 运行中（含启动中、等待回复、等待审批）禁止上传与恢复快照，界面禁用并说明原因，服务端返回 409。
- 上传部分失败时已写入的文件保留，弹框列出失败项并可重试失败部分；不宣称全部成功。
- 超限阈值为配置默认值，不暴露到设置页；数值在验收时按实测体验复核。

**下载：** 单文件下载；整项目打包下载（zip，流式生成，受项目总量上限约束）。下载不需要沙箱，运行中也允许，提示“运行中下载的内容可能不完整”。

### 运行前文件快照

- 每次项目内运行开始前、沙箱调用之前，对 `files/` 打包一份快照（运行启动显示为“准备执行环境”的一部分）；等待回复、审批续接属于同一运行，不重复快照。上传覆盖和恢复快照之前同样先做一份，并标注来源（运行前 / 上传前 / 恢复前）。
- 保留份数为全局设置，默认 5，可设 1–7，设置页通用分区可改；调小后在下一次快照时淘汰最旧的。
- 项目文件超过快照上限（与项目总量上限一致）时跳过本次快照，时间线显示“项目超过快照上限，本次运行没有快照”，运行照常进行。
- 工作台“快照”列表显示时间、来源、关联对话与大小；“恢复到此快照”只在无活动运行时可用，二次确认后先做一份“恢复前”快照，再整体替换 `files/`。首版不做单文件恢复与差异对比。
- 快照是“最近几次之前的版本”，不是完整历史，也不说明哪次运行改了哪个文件；这一点写入能力边界。

### 项目记忆

- **注入：** 每次项目内运行开始时，系统提示词的项目段依次包含项目说明、项目笔记、最近对话摘要（最多 10 条、合计不超过 1500 字符，按最近活动倒序，不含当前对话）。计入容量估算，压缩后保留，请求重建可见。独立对话没有项目段，行为不变。
- **笔记工具：** 项目内运行提供 `update_project_notes`（整体替换，携带读取时的 `notes_version`）。版本不一致时返回冲突，模型需重新读取后再改；成功写入 `project_notes` 事件。计划模式按允许清单默认拒绝该工具；工具策略可对其设 ask/deny。独立对话不注册该工具。
- **用户编辑：** 项目设置里可查看和编辑说明与笔记，同样按版本保存，冲突时提示重新加载（每次运行开始时读取，2026-09-30 用户确认）。运行中允许编辑，本次运行仍用开始时读到的内容，下一次运行生效。
- **对话摘要：** 项目内运行进入 completed 后异步生成一句话摘要（复用标题生成的独立模型请求路径），手动改写或重新生成都可以；进程重启导致的丢失可在项目页手动补生成。摘要只供新对话参考，不替代历史消息。
- 首版不提供“按需读取历史对话全文”的工具，不做压缩时自动写笔记。

### 同项目运行互斥

同项目最多一个活动运行（启动中、running、waiting 回复或审批），计划模式也遵守；多个对话可以同时打开和准备草稿，第二个任务发送返回 409。**waiting 继续占用项目（2026-09-30 用户确认）**，不设自动超时释放、不排队、不强制接管：409 提示指出占用对话与原因（等你回复/等你批准），给出「跳转」与「停止占用的运行」；项目页和侧栏项目行在存在 waiting 运行时显示「等待中」。归档、上传、恢复快照在有活动运行时同样返回 409 并说明需先回复或停止。

项目占用与新 run 在事务内协调：锁项目行并在同一事务查询活动 run；chat、审批续接、停止、归档、上传、恢复使用一致锁顺序。不同项目可同时运行。

### 接口与数据契约

- 项目：列表、新建（名称、可选说明）、详情、改设置（说明、笔记带版本）、归档/恢复；列表含 id/name/archived/task_count/last_active_at/has_waiting/files_size。
- 项目文件：上传（按相对路径，多文件，服务端复核规则）、上传预检规则的只读下发（前后端同一份阈值与名单）、目录树、读文件预览、单文件下载、整项目 zip 下载。
- 快照：列表、恢复。保留份数在应用设置中。
- 删除：`/projects/roots`、`/projects/browse`、项目级与会话级 `git/status`、`git/diff`，以及项目登记接口中的路径参数。
- `POST /sessions` 可选 `{project_id}`，创建与关联同事务；首次发送的草稿、session id、chat 结果遵循 W10 R3。
- 项目/对话列表独立分页，默认 50 条；侧栏每项目最近 5 个，当前选中对话始终可见。同步后端 schema、UI API 类型、W4 视图模型、列表 SSE 与观察脚本；loading/error/disabled/empty 独立。

### 页面与导航

| 操作 | 结果 | 创建行为 |
|---|---|---|
| 全局首页发送 | 新独立对话 | 发送才建 session |
| “项目”分区 `+` / `/project` | 项目选择器：已有项目、新建项目、从文件夹创建、已归档 | 新建只建项目与托管目录，不建 session/沙箱 |
| 点击项目名称 | 项目工作区空白输入与最近对话 | 发送才建 session |
| 项目更多菜单 / 对话页标题栏项目名旁「在此项目新对话」 | 跳到该项目工作区空白输入 | 不建 session |
| “对话”分区 `+` | 全局独立对话草稿 | 发送才建 session |
| 关闭项目 | 全局首页 | 运行继续 |

**侧栏：** 顶部只保留品牌首页入口与整栏折叠控件，不保留“新建任务”。内容分为“项目”和“对话”，两个分区标题都可折叠，标题右侧常驻 `+`；箭头、标题、加号是独立点击目标。项目区在上并独立滚动；对话区固定在导航底部、设置入口上方，限高独立滚动。每个项目名称是导航链接，独立箭头控制对话子列表；展开状态本地保存，数据刷新不强行展开。项目更多菜单含「在此项目新对话」、设置、归档。整栏收起后保留打开项目、独立新对话、恢复侧栏与设置图标。窄屏抽屉同内容同顺序。独立新对话没有快捷键。

**归档入口：** 侧栏项目菜单归档；项目选择器「已归档」列表恢复；项目页已归档时可恢复。

**项目工作区：** 顶部项目名、文件总量与设置；主区最近对话、空白输入与查看全部。不显示路径、分支或变更。打开不自动恢复运行，不跳历史对话。

**工作台：** 项目工作区（未发送时也可用）提供“文件”与“快照”两页：文件页含目录树、只读预览、上传、下载单文件、下载整个项目；快照页含列表与恢复。打开已有对话时另有结果、终端、浏览器与交付页；Agent 写文件或 Shell 结束后文件树与预览合并刷新，乱序返回不覆盖当前选择。无对话时不虚构终端或浏览器。窄屏为右侧抽屉。

**视觉方向：** 沿用 UI DESIGN 的中性浅色、石墨深色、钴蓝交互强调、IBM Plex 字体与紧凑行高；上传预检弹框用紧凑列表与分组（将上传 / 将排除 / 需要确认），不引入大卡片或装饰。上下文入口只保留圆环，契约见 W9 U2。

**界面状态：** 项目选择器覆盖读取中、读取失败、空、已有、已归档、新建中/失败。上传弹框覆盖扫描中、可上传、有排除、超限禁用、有冲突、敏感文件、上传进度、部分失败、运行中禁用。快照页覆盖空、列表、跳过记录、恢复确认、恢复中、恢复失败、运行中禁用。侧栏覆盖两分区折叠、项目子列表折叠、空态、长列表、选中对话不在最近五条、等待中标记。项目内对话覆盖准备环境、执行、等待、停止、准备失败、受理未知、同项目占用。

   - 基础镜像若间接带入 git，不作为平台能力，不写入提示词。移除后按 W8 方式复跑无项目回归。

5. 端到端与事实文档收口。

## 验收

**自动与接口：**

- Git 与宿主机目录代码移除后，全仓无 Git 读取、`PROJECT_ROOTS` 与 `git/*` 路由残留；API/UI/沙箱构建与既有测试通过；空库迁移单 head；迁移中没有旧路径回填与兼容分支。
- 上传规则：前后端对同一目录样本得出相同的排除与超限结论；依赖目录、版本库目录、敏感文件、超大文件、超总量、同名冲突、`..` 与绝对路径各有用例；服务端在前端被绕过时仍拒绝。
- 快照：运行前生成、续接不重复、保留份数 1–7 生效与淘汰、超限跳过并有事件、恢复前自动快照、运行中恢复与上传返回 409、沙箱看不到快照目录。
- 记忆：说明与笔记在下一次运行生效、本次运行不变；笔记版本冲突；计划模式拒绝笔记工具；摘要注入条数与字符上限；请求重建含项目段；独立对话无项目段与笔记工具。
- 互斥：同项目两个 session 同时首次 chat 只有一个受理；waiting 占用；停止/失败/重启后释放；不同项目并行；409 返回占用对话与原因。
- 分页、选中可见、多标签重连一致；UI 类型、lint、build 与观察脚本通过。

**真实端到端（Compose、真实模型、全程浏览器发起）：**

1. 默认 Compose 不做任何配置即可新建项目；macOS Docker Desktop 实测托管目录挂进沙箱可读写。
2. 从本地文件夹创建项目：弹框正确列出依赖目录、`.git`、`.env` 与大小，确认后目录结构还原；超限时上传按钮禁用。
3. 项目内对话修改文件并交付，文件页可预览、单文件下载与整项目下载内容正确；本地原文件夹未被改动。
4. 第二段对话能引用第一段的摘要与 Agent 写入的笔记；用户编辑笔记后下一次运行生效。
5. 运行前快照生成，恢复到上一份后文件回到运行前状态，并出现“恢复前”快照；设置改为 7 份后保留数正确。
6. running/waiting 时第二任务、上传、恢复、归档都被拒并给出跳转/停止入口。
7. 首次发送失败/超时、附件与计划模式草稿恢复，先读回再重发，不重复建任务或运行。
8. 归档/恢复后历史、文件与快照保留。
9. 桌面浅色/深色、390×844、收起侧栏、键盘完成主路径，截图记录完成态。
10. 没有“新建任务”按钮；分区加号含义固定；两分区与子列表可折叠；长项目列表下对话区仍置底可达；「在此项目新对话」可达空白输入且不建 session。

复跑 E1、E2、E3、E4、E7 的无项目回归，另做上述项目场景。Linux 下托管目录属主如无环境，记录未验证。进度与证据只登记总计划。

## docs 同步与交接

完成后更新产品说明（项目、上传下载、快照、记忆）、架构（托管目录与挂载、运行开始时读取项目段、快照存放）、代码地图、能力与边界（副本不回写、快照不是完整历史、沙箱临时文件寿命、无删除项目、上传规则）、设计取舍记录（放弃 Git 与宿主机目录的原因）、W4 契约、UI DESIGN 与所属服务指南；运行与 Docker 指南删除 `PROJECT_ROOTS` 与覆盖文件说明。本轮不修改课程。
