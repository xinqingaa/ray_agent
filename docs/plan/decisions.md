# 已确认的计划范围

本页维护已由用户确认的产品范围、隐私与交付选择，作为各专题和工作包的实施依据。计划范围确认不等于本轮开始产品实施，当前仍只维护计划文档。

技术基线采用 Tauri、React／Vite、Python sidecar、SQLite、LanceDB Embedded 和本地优先的材料处理。共享 React 前端仅交付到 Tauri 桌面与移动客户端，移除独立 Web 产品入口。

| 标识 | 范围 | 已确认方案 |
|---|---|---|
| D1 | 首批桌面平台 | macOS Apple Silicon 与 Windows x64；先打通 Mac，再完成 Windows，同属首批桌面交付 |
| D2 | 移动端投入范围 | 首批交付桌面；桌面稳定后交付同一共享前端的 Android 辅助端，iOS 随后 |
| D3 | 原 Web／服务端部署 | 移除独立 Web 客户端、本机浏览器应用入口与原 PostgreSQL／Redis／Nginx Compose 服务部署；不提供旧数据迁移，桌面版从空数据开始 |
| D4 | 自动记忆强度 | 明确的记忆要求直接保存；后台提炼的新条目直接生效并标为自动提炼；提炼只能直接替代自动提炼且未经确认的条目，涉及用户创建、用户要求写入或已确认的条目时进入候选 |
| D5 | 本机执行权限 | 工作区文件夹内的文件工具读写随工作区可用，有写前备份与撤销；Shell 与本机脚本需每个工作区明确启用，启用后沿工具策略使用，重要外部副作用继续按审批规则处理；不宣称强隔离 |
| D6 | 安装与离线组件 | 基础包包含核心与基础运行时；Chromium、Embedding、OCR 首次按需下载并校验，提供相同内容的离线组件包；对话大模型单独配置 |
| D7 | 工作区形态 | 一个工作区绑定一个本地文件夹，添加文件即复制进该文件夹；工作区由工作方式、记忆、会话与文件夹组成，不设笔记与独立说明页；模板由用户从现有工作区另存 |
| D8 | 文件夹身份标记 | 文件夹内写入 `.rayagent/workspace.json`，只含本机安装身份与工作区 ID，不含名称、工作方式、记忆或会话；标记不可写时按路径与文件系统身份绑定 |
| D9 | 首批执行与存储边界 | 首批不提供 Docker 或远程执行的产品流程；腾讯云 COS 不进入桌面运行时 |

## 产品边界

- 桌面自身保存权威工作区数据，移动端连接桌面；电脑休眠、关机或真正退出时不再执行任务。
- 默认文档解析、OCR、Embedding 在本机完成；调用外部对话模型会发送本次选择的上下文，外部 Embedding 或解析需用户另行启用。
- 保留独立对话，不参与任何工作区的记忆与检索；不会为了统一身份将全部独立对话并入一个共享工作区。
- 删除工作区、清空应用数据或卸载应用都不删除工作区文件夹及其中的用户文件。
- 删除仓库中的原部署文件不会删除已有数据库、Docker 卷或用户目录；需要旧数据的用户继续使用旧版本。
- Web 产品移除不影响 Tauri 使用 HTML／CSS／JavaScript、开发调试服务器、自动化浏览器或成果 HTML／网页预览，也不移除客户端与本机核心之间的 HTTP／SSE。

## 工程上已收口的处理

Python 保留现有 Agent，Tauri 只做宿主；SQLite 单核心写入，输入与后台任务持久化；索引是可重建派生数据；工作方式、记忆、文档和 Skill 均按实际版本引用；生成 HTML 不接触原生桥；用户文件夹与应用数据分别删除。对应细节见[共享契约](shared-contracts.md)和[实施工作包](implementation.md)。
