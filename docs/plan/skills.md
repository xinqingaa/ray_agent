# Skill 目录与运行兼容

本专题为实施设计，按计划实施中，进度见[实施状态](implementation.md#实施状态)。兼容常见 Agent Skill 目录是已确认需求；发现、重名、快照和标准加载采用本文默认方案。专有 Agent 扩展不混入首批标准兼容承诺。

## 目标与当前基础

让用户已有的 Skill 能被发现、阅读和使用，减少重复安装、强制复制与沙箱材料搬运。通用方法可跨工作区复用，工作区私有内容保持在所属范围。

现有实现维护应用独立全局库，支持包校验、不可变版本、显式／自动加载及资源准备。目录元数据、正文和参考材料的渐进加载已接近通行模式，主要缺口是本机多来源发现、工作区范围与执行路径衔接。现状见[Skill 机制](../skills.md)，实现入口见[全局 Skill 代码地图](../code-map.md#全局-skill)。

## 来源与发现

支持工作区级、用户级、应用内置及用户配置的额外目录：

- 工作区文件夹及用户范围的 `.agents/skills/`、`.codex/skills/`、`.claude/skills/`。
- 其他常见 Agent 目录按明确的兼容表接入，不声称扫描所有工具的任意配置路径。
- 保留应用管理安装的方式，同时允许直接引用已有目录，不要求全部复制导入应用库。

发现 `SKILL.md` 后登记名称、描述、来源、范围与内容身份，正文和资源按需读取。用户级目录需要按用户配置或平台目录约定解析，不能硬编码当前开发者的主目录。

工作区扫描止于工作区文件夹，不遍历其他工作区。监听变更结合重新扫描；明确不可读、已移除、格式错误与依赖缺失的状态。

## 首批来源与解析顺序

首批内置来源适配 `.agents/skills`、`.codex/skills`、`.claude/skills`，同时支持设置中的额外目录。用户来源从 OS 用户目录解析，并识别显式配置的 Codex 根，不硬编码某台机器路径；用户可以关闭自动发现或逐来源停用。

工作区来源只扫描工作区文件夹内的约定目录，不向上扫描父目录，也不进入其他工作区的文件夹。文件夹较大时只在登记范围内按实际使用的子目录发现更具体的 Skill，不在启动时递归遍历整个文件树。

发现服务产出 `SkillSource`、`SkillEntry`、`SkillVersion` 与运行绑定：记录来源类型、范围、原路径、规范路径、名称、描述、清单和内容指纹。扫描器限制层级、包大小及文件类型，并共享现有完整包校验；加载目录预算失败时明确要求缩小启用范围，不静默丢弃目录后半部分。

同一实际包的路径别名合并。不同包同名默认按工作区、用户外部目录、应用管理库、内置的次序解析；同层多份冲突要求明确选择，不依赖扫描顺序。界面始终显示来源，提供来源限定身份；显式选择发送稳定 ID 和版本，不以可见名称替代身份。内置命令保留命令命名空间，不与包名混用。

## 重名、链接与版本

- 同一实际目录被不同路径或软链接引用时去重，解析后的资源仍受来源范围约束。
- 同名不同来源保留可见身份，明确选择／覆盖规则；不能静默采用另一份正文。
- 外部目录是用户文件，应用停用或移除引用不删除其内容；外部包默认只读，用户可打开系统位置编辑。
- 活动运行记录实际加载的版本与来源，内部内容快照保留实际材料；源目录变化不静默改写已发生请求。
- 应用管理包与外部引用共用加载契约，但安装、更新、删除和回收分别遵守各自文件归属。

## 引用目录与内部版本缓存

外部 Skill 不要求手工导入，也不在外部目录写应用元数据；首次发现或变更后，内部按清单完整生成内容寻址快照，经校验发布再登记可用。用户看到的是引用来源，内部缓存用于等待续接、请求重建和资源一致性，不等同于再次安装或取得外部目录删除权。

复制前后核对清单与内容，变化中的包重新扫描，不能把部分新旧文件拼成一版。来源目录本身的软链接允许作为显式来源解析；包内链接只有目标仍在同一已解析包根内、可规范成普通资源时才收录，包外引用和循环链接明确不兼容。

用户级通用包的快照保存在受限用户库，工作区包的快照归该工作区；权限解析不因相同内容哈希跳过来源范围。工作区删除回收其私有引用，外部目录从不随回收删除。设置默认只读外部包，提供系统打开位置；正文编辑仅对应用管理包开放。

启停和来源更新影响新运行。受理冻结可用目录与版本引用，显式 Skill 在业务决策前加载；外部源随后更新或移除时，同一活动运行沿已授权快照，但用户明确撤销访问优先于快照引用。等待续接从快照恢复，无法恢复则报错，不偷换当前版本。

## 加载与执行

保留目录元数据先进入上下文、正文按需激活、参考材料按需读取的方式。用户显式选择与模型自动选择共用身份解析、预算和工具策略。

向工具提供稳定的 Skill 根路径和资源身份。文本阅读不需要启动执行环境；脚本与素材在实际使用时连接[本机执行器](files-and-execution.md)。本地路径可直接映射时减少搬运，使用容器或远程执行时再显式准备所需材料。

Skill 包不自动提升工具权限，依赖安装和脚本执行是独立动作。停止、等待续接、版本变化、资源丢失和执行失败沿运行契约处理，不能由“已加载正文”推导“已按要求执行成功”。

## 稳定资源路径与加载预算

所有已加载包在模型上下文中提供清楚的根路径、来源和运行版本；`SKILL.md` 与参考文本按既有渐进方式进入请求。内部快照可读而执行输出不可回写到包，脚本工作目录和产物目录位于获准的工作区，读取资源按 Skill 根解析。

在本地执行中，准备资源简化为取得已发布快照的稳定映射，正文／文本读取不需要启动 Shell 或浏览器。容器或远程后端才需要传输和映射；兼容旧工具名的适配应避免要求模型机械地调用一次无意义材料复制。

正文、目录、资源与依赖输出仍受统一预算。单包必须完整激活或明确失败，活动正文在压缩时保留；新运行重新选择当前版本。模式和工具策略约束加载／阅读／执行，缓存建立是内部资料读取，不等于安装依赖、执行代码或授予写权限。

## 兼容范围

区分目录发现、标准包格式与特定 Agent 的运行扩展。识别目录及 `SKILL.md` 不等于支持其 hooks、变量替换、权限字段、子 Agent 或专用工具；只解释已实现的扩展，其余明确展示兼容边界。

[Agent Skills 集成指南](https://agentskills.io/client-implementation/adding-skills-support)将 `.agents/skills/` 作为跨客户端共享约定，并允许多种发现来源和加载方式；该标准不强制安装目录，也不保证所有客户端扩展等价。

## 标准与扩展的实现清单

首批支持标准 frontmatter 名称／描述、完整正文、相对参考文件、脚本与素材目录、显式选择和按需激活。`agents/openai.yaml` 等客户端配置可阅读但不自动执行；只在有对应解析器和检查时解释附加元数据。

Claude hooks、动态命令替换、特定客户端变量、专用工具名与子 Agent 不做隐式模拟。读取详情时展示发现的扩展及不可用部分；模型按现有工具能力执行可兼容流程，无法完成则报告，不声称与原客户端完全等价。脚本依赖使用[独立工具环境](files-and-execution.md#进程与执行资源)，绝不因打开包自动安装。

应用管理库与内置 find-skills 保留；按 D3，桌面版的应用管理库从空开始，不迁移原部署中的安装记录。GitHub 获取仍走已有受限下载／候选／发布服务，不能将系统上的第三方 CLI 安装误报成应用库已登记。

## 责任与依赖

发现服务管理来源、范围、重名和变更；加载服务固定实际内容与上下文；资源适配提供稳定路径；执行器处理脚本依赖与进程；设置和输入框展示来源、可用性和显式选择。

依赖[工作区范围](workspaces-and-memory.md)、[存储与运行身份](local-runtime-and-storage.md)和[文件执行能力](files-and-execution.md)。移动端建议读取桌面核心提供的目录并发起使用，不假定能访问桌面路径或执行桌面脚本。

## 实施检查

P4 让现有应用管理库随执行端口在桌面可用；P8 交付扫描器、来源解析、内部快照、加载／路径适配和设置 UI，并接入运行装配。检查真实目录和软链接、多来源同名、源变更期间扫描、包外资源、无效编码、超预算、等待续接、删除引用与执行失败；参数和专有扩展覆盖边界写进服务指南。

## 完成条件

- 已约定目录中的标准 Skill 可直接发现、按需加载和读取参考材料，不要求重复导入。
- 来源、工作区范围、同名选择、软链接去重及变更状态可理解，不串用私有内容。
- 运行记录与实际正文／资源版本一致，用户外部目录不会因应用移除引用被删除。
- 脚本通过约定执行器工作，未实现的客户端扩展和依赖不会被冒充为兼容。
