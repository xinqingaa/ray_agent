# 全局 skill 安装与使用

## 目标与实施状态

**状态：原授权范围的产品功能已实现，工程验证已执行；真实模型效果验收待配置可用 API Key。新增管理体验优化已获实施授权并完成，见下节。** 当前行为见[skill 机制](../skills.md)，验证种类与缺口见[维护入口](README.md)。下文保留有效设计、依赖和完成条件，不将模型效果待验证写成已提高任务成功率。

让用户把可复用的方法安装为 Skill，在所有会话与托管项目中使用，通过输入框主动选择，或由 Agent 根据任务需要加载。第一版提供完整的安装、管理、加载和资源使用闭环，不引入独立 Agent 循环。

已确认的范围：

- 一套全局 skill 库，可安装多个 skill；不做项目级安装、覆盖和优先级。
- 支持 GitHub 地址，以及文件夹、ZIP、单个 Markdown 或 Markdown 加文本。
- 完整保存 skill 目录及其中的参考资料、脚本和素材，不只导入 Markdown。
- 设置页提供新增、查看、编辑、启停、更新和删除；聊天中可以要求安装 GitHub 上的 skill。
- 输入框支持 `/` 选择及 `/skill 名 任务`，也允许模型自主判断并加载。
- 安装和加载接入现有事件、上下文、权限、沙箱及任务生命周期。
- 随应用内置 `find-skills`，沿同一版本和加载体系发现及推荐社区 skill。

不在本次范围：项目记忆重做、评测平台建设、编码专用能力、模型路由、多 Agent、skill 市场、私有仓库认证、自动更新和独立依赖环境管理。冻结的 `lessons/` 不更新。

## 管理体验优化方案

**授权与状态：已获实施授权，功能已实现；验证概况见[维护入口](README.md)。** 本节保留新增操作、包内容阅读、删除可靠性与排序的有效设计。此前确认的完整包、版本、运行引用和权限边界继续适用，不将管理体验改善等同于真实模型效果提升。

### 新增与内容阅读

新增只保留 GitHub 和本地内容两类来源。本地内容统一承载文件、文件夹、ZIP 与直接编写，不将编写拆成第三来源。取消独立安装预览步骤；材料获取和正式安装仍由不同动作提交。

- GitHub：输入地址后点击“获取”，成功直接打开内容；多候选先选择要打开的 Skill。错误保留来源输入，失败或过期后重新获取，响应未知时查询原操作。
- 本地文件：选择或拖入后自动上传并校验，成功直接打开内容；缺名称与描述时在原区域补齐，再打开内容。空态保留紧凑的拖放、选择文件、选择文件夹和直接编写入口。
- 直接编写：在本地入口输入名称、描述和正文，可切换查看排版；点击“安装 Skill”完成校验与发布，不再单独进入预览。校验或发布失败保留输入和可查询的操作身份。
- 获取的包：直接阅读正文与文件，可编辑 `SKILL.md`；保存待安装正文时生成新的校验材料与指纹，保留其他包文件和来源，不在原预览上原地修改字节。
- 安装成功：转为同一布局的已安装详情并刷新列表，清除导入状态，列表定位到安装项；详情可继续阅读和管理。安装已成功而刷新失败时单独说明刷新失败，不误报安装失败。

新增、已安装详情及聊天中的只读查看共用包阅读器。宽屏采用目录与内容两栏，窄屏通过文件目录切换，避免挤压正文。标题与动作固定，仅内容滚动；继承 UI 设计说明的语义色、字体和焦点规则，具体尺寸以实现为准。

默认显示 `SKILL.md` 排版正文，可以切到源码核对 frontmatter。目录行整行可点，当前文件明确选中；YAML、JSON、代码及可解码文本提供源码、行号和复制，允许的栅格图片显示内容，其他二进制或未知编码说明不可阅读并提供下载。HTML 和 SVG 只作为源码，不执行。`agents/openai.yaml` 是包内普通文件，不解释为 RayAgent 配置。

Markdown 包内相对文件和图片按当前文档目录解析，只能访问清单内资源；越出包根的路径不能打开。当前文档锚点在阅读区域内定位，外部网页保持安全链接行为。脚本、配置与正文中的命令不会因为查看而执行。

安装后编辑显式进入，可切换查看排版，保存后返回正文。完整包更新沿用两种来源，材料获取后直接打开，点击“确认更新”发布新版本；关闭更新回到原详情。内置包可读取与停用，不开放编辑、手工更新和删除。

### 接口与资源归属

已安装文件读取携带 skill 名称、所见版本和清单相对路径；版本变化时拒绝混读并提示刷新。待安装文件读取携带操作、候选、指纹和相对路径，核对操作归属、阶段及有效期；设置接口不读取聊天私有导入。历史消息固定版本的独立阅读授权未在本轮扩展，沿用当前详情读取边界。

应用服务解析资源身份，存储适配核对路径、符号链接、大小和哈希；不开放任意主机路径或任意版本哈希下载。文件响应禁止嗅探与主动内容执行，前端按需获取字节；图片只为允许的栅格格式创建本地显示地址。文件切换与关闭后忽略迟到结果，局部失败保留目录和重试入口。具体可调预算仍只维护在[参数页](../limits.md)。

### 删除与排序

删除故障源于无正文 DELETE 被客户端标为 JSON，公共受理层直接解析空正文。本轮修复双方契约：客户端仅在有 JSON 正文时设置类型；受理层允许合法空正文，对非空畸形 JSON 返回客户端错误，保留数据清理的共享受理锁与项目归属判断。

删除携带所见版本，旧版本冲突要求刷新，重复删除幂等。连接中断后读回目录确认状态，删除成功但刷新失败分别说明。数据库只移除可见目录记录，已有运行固定版本和后续引用释放、回收规则保留。

列表统一采用“内置优先，同组名称升序”，禁用与搜索不改变相对顺序。服务端返回稳定顺序，设置列表直接沿用；不新增排序菜单、收藏或置顶系统。

## 用户如何新增 skill

### 设置页新增

设置中增加普通用户可见的“skill”页面，展示名称、描述、启停状态和来源。列表支持搜索，详情展示说明、文件目录和当前版本；不依赖开发者模式。沿用[界面设计约定](../../ray_agent/ui/DESIGN.md)及现有设置弹层、语义样式、键盘与窄屏行为，不新增独立管理工作台。

“新增 skill”提供两种来源：

| 来源 | 用户操作 | 系统处理 |
|---|---|---|
| GitHub | 粘贴公开仓库或 skill 目录地址 | 解析固定提交，发现 skill 目录，读取完整包 |
| 文件 | 选择文件夹、ZIP、单个 Markdown，或 Markdown 与文本；也可以直接编写 | 文件夹与 ZIP 按完整包校验，包内 ZIP 不再解压。单个 Markdown 作为 `SKILL.md`，缺少 frontmatter 时补名称和描述。文本按原文件名保留，再走相同预览与发布 |

“新增 skill”使用独立弹框，获取材料后直接打开内容，返回来源保留输入。CLI 安装边界放在帮助图标的悬浮与键盘焦点提示中；误贴命令时在输入附近直接提示。正常流程只保留字段、必要状态和操作，不常驻长篇说明。

本方案中的 skill 库由 RayAgent 独立管理，不扫描或同步用户电脑上其他 Agent 的 skill 目录；即使 RayAgent 部署在同一台电脑上，CLI 安装也不等于已导入。聊天中在沙箱执行 CLI 安装同样不登记全局 skill，不能据此报告 RayAgent 安装成功。

获取后直接打开包内容，展示名称、描述、来源、文件和必要校验结果，再点击“安装”。不设置独立预览动作，不追加多层确认。

若来源包含多个 skill，展示候选名称、描述和目录，用户选择一个后安装。第一版不做批量安装。无法解析或没有 `SKILL.md` 时给出具体原因，不创建空条目。

导入中的进度使用“获取来源、校验包、等待选择、发布”等真实阶段；能取得可靠字节总量时才显示下载进度。切换页面后可查询导入状态，不要求一直保持弹窗。

### 去哪里发现 skill

设置页的 skill 列表及新增弹框右上角提供带可访问名称和悬浮提示的社区图标入口，打开 [skills.sh](https://skills.sh/)，让用户搜索、浏览并挑选 skill。用户在站外选好后，复制对应的公开 GitHub 仓库或 skill 目录地址，回到 RayAgent 按上述 GitHub 流程预览和安装。

第一版只提供外部导航，不接入站点搜索、榜单同步、账号或一键安装协议。社区入口不占用主要内容行，不常驻安装说明；导入帮助提示本机命令安装不会自动同步。站点详情页、skill 合集地址及 `npx skills add …` 命令不作为安装源；粘贴安装命令时给出针对性提示，说明这里需要 GitHub 地址，并保留输入供用户修改，不执行命令或静默转换安装意图。安装仍由 RayAgent 的共享服务完成，不执行站点提供的 CLI 安装命令，也不因此扩展为内置 skill 市场。

社区收录与热度不表示 RayAgent 已验证其质量、安全性或运行兼容性；来源与包内容继续在安装预览中展示，实际可用性按当前工具及沙箱条件判断。这些边界维护在机制说明，界面按需提供帮助，不承诺所有收录 skill 都能直接使用。

### 内置 find-skills

随应用发布固定版本的 `find-skills`，默认启用，正文按需加载。保留理解需求、查找、核对和推荐的方法，使用 RayAgent 自有工具与共享安装服务，不执行 `npx skills`，也不扫描本机 CLI 安装目录。

1. 先检查当前运行的已安装 skill 目录，已有合适 skill 时直接加载，避免重复安装。
2. 确实需要时复用现有网页搜索、读取或浏览器查找 skills.sh 及对应 GitHub 来源，不新增社区搜索后端。搜索失败如实说明并提供社区入口。
3. 推荐前读取候选内容，核对用途、正文、依赖、工具要求及来源，说明适合理由与限制；热度仅作参考。
4. 用户仅要求寻找时返回候选；明确要求寻找并安装且候选明确时调用 `install_skill`，不重复确认，仍服从模式与工具策略。
5. 明确要求立即使用时追加当前运行目录再加载；安装成功不能代替依赖满足、工具可用或成果正确。

仅在用户明确寻找 skill、要求扩展能力，或当前任务确实缺少可复用方法时考虑加载，不对普通任务普遍增加搜索或安装步骤。计划模式允许查找、阅读和推荐，禁止安装。

内置 skill 共用普通 skill 的加载、上下文预算、版本绑定和运行引用。设置页标记“内置”，允许停用；第一版不开放编辑、删除或手工更新，由应用升级发布新版本，保留已有运行引用的旧版本。用户 skill 不得静默覆盖同名内置 skill。

### 聊天中安装

用户说“安装这个地址里的 skill”时，Agent 可调用 `install_skill(source_url, candidate_path?, operation_id?)`。首次调用创建或复用导入操作，候选选择后携带返回的操作 ID 续接，服务端核对来源和候选。工具调用共享安装服务，不能由模型临时拼接下载、解压或 Git 命令来写全局 skill 目录。

1. 工具通过现有模式与权限检查。
2. 安装服务解析来源，获取固定版本并发现候选。
3. 只有一个候选时校验并发布，返回实际安装结果。
4. 多个候选时返回候选信息，Agent 通过现有询问工具请用户选择，再提交同一导入操作中的选项。
5. 成功结果包含 skill 名称、描述、版本和文件概况；失败结果包含阶段、原因及可执行的下一步。

用户明确要求安装即构成本次操作授权，不强制再弹一遍产品确认；配置的工具审批规则仍照常生效。系统指令要求模型只在用户提出安装需求时使用该工具，skill 正文中的安装指令不等同于用户授权。这是模型行为要求，不能声称程序能准确证明自然语言授权。

用户只发一个地址、没有安装意图时，不默认安装。安装工具只处理公开 GitHub 来源；聊天上传的文件不自动当 skill 安装，本地材料使用设置页入口。

### 同名与更新

skill 名是稳定调用标识。相同名称、相同规范化文件内容的重复安装返回已有版本；同名但内容不同返回冲突，不静默覆盖。来源地址不同但内容一致，可以复用已有安装结果，并说明来源未替换。

更新是设置页的显式操作：从原来源重新获取、重新上传包，或编辑 `SKILL.md`，均先生成新版本并校验，再替换当前版本。更新前校验用户看到的旧版本，发生并发修改时提示刷新，不覆盖他人的修改。

第一版只提供正文编辑和包更新，不做任意包文件的在线 IDE。正文编辑保留包内其他文件；名称不在编辑时直接改写，需要改名时按新 skill 安装。停用后保留包，新任务不可使用；删除后从 skill 库移除，正在使用的版本按运行引用保留。

## skill 契约

### 文件与元数据

skill 根目录必须有 UTF-8 编码的 `SKILL.md`，包含 YAML frontmatter。`name`、`description` 为必填字符串，正文不能为空。使用安全 YAML 解析，禁止构造任意对象。

`name` 使用小写字母开头、字母数字及连字符组成的稳定标识，不与内置 `/` 命令冲突；名称及描述的长度限制集中维护在[参数页](../limits.md)。标题、描述和正文在所有入口使用同一解析结果，不由前端和模型各自推断。其他元数据可以保留，但不自动解释为权限、工具授权或安装钩子。

完整包保留 skill 根目录内的普通文件和相对目录，包括 `references/`、`scripts/`、`assets/`，不要求这些目录存在，也不只允许这些目录。根目录之外的仓库文件不导入；第一版不解析包外引用、子模块或 Git LFS 指向的实际大文件，发现相关依赖时在预览及结果中说明。

拒绝路径穿越、绝对路径、符号链接、硬链接、设备文件、规范化后的重名路径及不可移植的路径冲突。压缩包层级、文件数量、单文件大小和累计解压大小都有边界，不能仅检查压缩后体积。包哈希由规范化的路径与文件内容计算，不受 ZIP 时间戳和外层目录名影响。

安装不执行任何脚本、不自动安装依赖、不验证所有业务方法都有效。安装成功表示包完整可读、元数据合法且已登记；执行环境和任务效果在使用阶段判断。

### GitHub 地址解析

支持公开 GitHub 仓库根地址、目录地址和指向 `SKILL.md` 的文件地址。无版本地址解析仓库实际默认分支；分支或标签先解析成不可变提交，再按该提交下载。不能简单按斜杠截取分支名，因为引用名本身可能包含斜杠。

有明确 skill 目录时仅导入该目录。仓库根目录已有 `SKILL.md` 时将其作为一个 skill；根目录没有时，在受限扫描范围内寻找候选。发现多个候选必须选择，不根据目录顺序猜测。返回结果记录仓库、目录和提交，便于解释安装来源。

网络获取由受控适配器完成，只访问支持的 GitHub 官方下载与 API 目标，校验重定向，阻止转向本地或内网地址。下载流、解包和扫描都受限。不接受任意 URL 作为下载器，不在第一版接收 PAT、私有仓库或企业 Git 服务认证信息。

网络临时故障允许有限重试；固定提交不存在、格式错误、包校验失败和同名冲突直接返回，不能通过换分支或换目录悄悄“修好”。具体可调边界在实现时加入参数页，不在本方案重复维护默认值。

## 安装服务与数据归属

### 共享服务

设置页和聊天工具共用同一套应用服务：来源获取 → 候选发现 → 校验与预览 → 不可变文件发布 → 数据库登记。入口只负责输入和展示，不各写一套安装器。

安装操作持久化，包含操作 ID、请求幂等标识、来源、候选、阶段、失败原因和发布结果。前端重试提交或工具等待后恢复时查询原操作，不重复创建包。工具执行记录与安装操作 ID 建立关联，避免“工具超时但实际已安装”后误报未执行。

建议接口按资源职责组织，最终命名在实现中沿现有 API 风格统一：

| 能力 | 契约要点 |
|---|---|
| 创建导入 | 按 GitHub 与本地文件两种输入适配，共用操作与幂等契约 |
| 查询导入 | 返回真实阶段、候选、预览摘要、错误与已发布结果 |
| 发布候选 | 引用操作、候选、预览指纹及安装或更新意图，不能提交任意磁盘路径 |
| skill 列表与详情 | 返回稳定 ID、名称、描述、状态、当前版本和来源 |
| 编辑及更新 | 带预期旧版本，产生新版本，冲突可识别 |
| 启停与删除 | 修改新运行可见目录，幂等处理重复请求 |
| 读取资源 | 只接收 skill、版本与包内相对路径，服务端执行归属校验 |

预览不意味着调用方能改写已经校验的内容。发布校验操作所有权、候选及内容指纹；临时预览过期后要求重新获取。

### 存储与事务

数据库管理 skill、不可变版本、导入操作及运行引用；完整包保存在 API 持久卷的独立 skill 命名空间。它不属于附件记录、托管项目目录或项目快照，不直接复用与附件生命周期绑定的上传流程。

版本记录包含解析后的元数据、包哈希、清单、来源提交和文件位置。启停状态、当前版本和 skill 名唯一约束由数据库管理。第一版使用现有单实例部署边界，不引入额外对象存储服务；部署指南需要说明持久卷和数据库应配套备份与恢复。

网络获取及校验在数据库事务外完成。发布先将临时包校验并原子改名为不可变版本目录，再在短事务中登记可见版本及结果。同名竞争通过唯一约束和版本条件处理；失败时不暴露半安装条目。

文件系统和数据库不宣称具备跨资源原子事务。文件已发布而数据库提交失败时，留下可识别的孤立目录；重试先按幂等记录和内容哈希核对，维护回收只删除确认无引用的临时包与孤立版本。数据库已有可见版本但文件缺失时，明确标记资源不可用，不能以空内容继续加载。

重启后，将没有完成发布的旧导入操作标记为中断，允许用户重试；已完成登记的操作仍返回成功，不自动重新下载。取消操作只在发布提交前生效，已经提交的结果应如实返回。任务停止时取消其尚未提交的聊天导入；设置页导入有自己的操作生命周期，不随某个聊天任务停止。

### 删除与清理

删除、停用或更新影响后续运行可见目录，不改写已被运行引用的版本。等待中的同一运行继续使用原版本；版本回收依据持久引用，不能只依据当前进程是否持有对象。

清空会话、项目或业务数据时保留全局 skill 及配置。删除运行记录时释放相应版本引用；删除 skill 后，仅在没有运行引用时回收其版本。临时包清理与版本回收必须校验 skill 存储根目录及资源归属。

第一版不提供历史版本管理界面和紧急撤销已运行脚本的承诺。删除 skill 不等于撤销已经发生的外部副作用，也不删除用户任务产物。

## 已安装 skill 如何进入任务

### 输入框选择

沿用现有 `/` 菜单，增加 skill 分组，按名称和描述搜索。选择 skill 后展示可移除的标签，用户继续输入任务并发送；选择本身不立即执行。

支持以 `/skill 名 任务内容` 开头的快捷输入。发送前解析成结构化选择与剩余任务正文；不从 URL、文件路径或代码片段中猜测命令。内置命令保留原有行为，skill 名称在安装时排除冲突。直接 API 调用使用结构化字段，不依赖模型解析斜杠文本。

第一版一条用户消息显式选择一个 skill，Agent 可以按需要再加载其他 skill。选择不自动成为后续每条消息的默认值。不包含任务正文时保留草稿并提示输入任务。

选择同时进入首页、项目页和会话页草稿、发送请求、受理判断、用户消息事件与历史展示。发送不确定时核对受理结果必须比较 skill 选择，不能将“相同正文、不同 skill”当作同一消息。旧消息没有该字段时兼容为空。

客户端提交稳定 skill ID 及所见版本，服务端在受理边界校验可用性并固定版本；已经删除、停用或更新时返回可理解的冲突，保留草稿供用户刷新选择，不静默改用另一版本。

### 显式加载与自动加载

每个新运行固定一份启用 skill 目录快照，仅包含名称、描述和不可变版本引用。目录通过标记明确的 skill 上下文提供给模型，不把正文全部放入提示词。模型按任务语义决定是否调用 `load_skill(name)`，不增加独立分类器或额外主模型请求。

安装和启用时检查全局目录预算；并发操作仍需在提交边界核对。目录无法完整放入预算时拒绝使其超限的变更，提示缩短描述或停用不需要的 skill，不静默隐藏后半部分 skill。正文加载另按活动正文预算判断。

显式选择则由程序在下一次业务模型决策前加载所选正文，不依赖模型再次猜测用户意图。正文作为带来源、版本及内部类型标记的指令资料进入上下文，不伪造模型的工具调用；自动加载使用真实工具调用和结果。二者共享解析、版本解析、容量检查及记忆登记逻辑。

skill 内容不能提升系统权限或覆盖模式约束。模型应按相关性使用 skill；描述匹配及执行效果属于模型能力，需要真实任务检验，不能由“成功返回正文”推断。

运行期间设置页更新不刷新本运行目录。若用户明确要求“安装后立即使用”，安装成功后允许将这一个安装结果以追加方式加入本运行可见目录，持久化追加记录后才可加载；不顺便刷新其他 skill。与当前运行同名的旧版本冲突时继续保留旧绑定，说明新版本在新运行生效，不在中途替换。

运行中补充消息的 skill 选择在现有消息消费边界生效，先登记引用和加载，再进行下一次模型决策。等待用户回答时随回答处理；工具审批等待仍遵循现有审批通道，不借聊天选择绕过审批。

### 工具与模式

| 工具 | 职责 | 计划模式 | 收尾阶段 |
|---|---|---|---|
| `load_skill(name)` | 加载当前运行绑定版本的完整正文 | 允许 | 允许读取 |
| `read_skill_resource(name, path, range?)` | 读取包内参考文本；二进制返回资源信息 | 允许 | 允许读取 |
| `prepare_skill_resources(name)` | 将当前版本完整包准备到本运行沙箱目录 | 不允许 | 不允许 |
| `install_skill(source_url, candidate_path?, operation_id?)` | 安装公开 GitHub skill 并关联导入操作 | 不允许 | 不允许 |

工具的公开参数以名称和包内路径为主，版本、运行身份及主机存储位置由服务端解析，不能由模型任意指定。资源文本可以分段读取，并明确范围和是否还有内容；正文必须完整加载或明确失败，不能悄悄返回截断正文却声称已加载。

工具按现有注册、Schema、策略与执行管线接入。新增工具同步修改计划模式和收尾阶段允许范围、工具策略目录及前端契约，不设置绕过审批的特殊通道。工具声明中的只读属性仅用于真实只读操作，安装和沙箱材料准备都属于写入。

加载失败要区分不存在、未启用、版本缺失、格式错误和上下文容量不足。显式选择失败时先向用户解释，不能假装已经遵循该 skill 继续完成原任务；自动加载失败可根据原因选择其他方法，但必须保留失败反馈。

## 完整 skill 如何使用

只加载正文或读取参考文本时，API 直接读取不可变包，不为此提前启动沙箱。正文返回可读的包内资源清单及相对引用规则。

需要脚本、素材或供现有文件工具处理的资源时，调用材料准备工具。API 从已验证的不可变包准备材料，由受限的沙箱发布能力写入当前运行专属目录，验证文件清单后发布；不让模型传任意主机路径，也不通过不受控的 shell 解压命令安装全局 skill。

目录由运行、skill 及版本共同确定。准备过程可重复调用，完整成功才返回可用根路径；失败不返回可用状态。等待续接时检查材料是否仍存在且完整，缺失则从固定版本重新准备。沙箱内副本可能被任务修改，不能因此反向覆盖全局包，也不能仅凭路径存在就认定哈希一致。

准备后通过现有文件、Shell、浏览器等工具使用资源，包内相对路径在材料根目录解析。执行脚本仍走现有 Shell 权限和审批，按任务需要处理缺失依赖；不能假设装入包就自带 Python、Node 或系统依赖。

材料准备不自动运行脚本。依赖安装失败或当前沙箱不支持时，返回真实原因，由 Agent 决定替代、询问或终止，不扩展成自动环境修复平台。安装完成的 skill 可以包含暂时无法执行的脚本，界面和模型反馈要区分安装状态与本次执行状态。

新增沙箱材料发布能力属于本次实施范围；应沿现有 API 与沙箱访问边界实现，限定目标根目录、防止路径与链接逃逸，并核对身份、超时及清理归属。它不开放为任意主机目录映射或新的通用模型工具。

## 上下文、版本与恢复

### 记录什么

受理时的显式选择、运行 skill 目录、追加可用项、实际加载的版本和内容指纹都需要持久化。skill 正文只从不可变版本读取，并能核对哈希；不能恢复时只记住名称，再到当前 skill 库加载最新内容。

显式正文使用有类型标记的内部上下文块；自动加载使用真实工具调用激活，返回版本与激活结果，完整正文也由同一内部资料块提供。工具结果保留调用身份与所属运行，旧运行转为历史引用，避免正文重复或压缩器将其当作用户原始需求。已有用户需求保护规则继续适用。

用户消息在正文里展示所选 skill 的整段名称，点击打开只读预览；自动加载及安装沿现有工具过程展示。开发观察可查看绑定版本和导入操作，普通界面不堆放存储路径、哈希或原始协议字段。

### 压缩如何保留

当前运行维护活动 skill 引用集合，成功加载后加入，重复加载同一版本不重复注入正文。完整正文经独立资料块注入，不经过通用工具结果截断；工具结果不重复携带正文。

压缩时将活动 skill 正文与待摘要历史分开处理：历史正常生成摘要，压缩完成后从固定版本原样补回活动正文，再发下一次模型请求。补回使用相同内部类型标记及版本身份，不能靠摘要记住操作规则，也不能破坏保留消息中的工具调用与结果配对。

完整正文、目录和保留区一起参与上下文容量检查。压缩后仍超出预算时明确返回容量不足，要求减少当前任务使用的 skill 或拆分任务；不能静默丢弃用户选择的 skill，也不自动截短正文。加载前检查单 skill 及累计活动正文预算，失败不加入活动集合。

新运行不继承“已激活”状态；历史 skill 资料可作为历史引用保留，但不能自动重新激活旧正文。工作记忆重建时识别旧 skill 块和 skill 工具结果，将其转为可追溯历史引用，保留工具协议配对；新运行按自己的目录和选择重新加载。持久事件保留原记录，不改写历史事实。

### 等待、停止和重启

等待提问、工具审批后的同一运行恢复固定目录及活动版本，正文按原版本重建，不使用当前全局最新值。审批恢复继续现有一次性审批语义，不把加载 skill 当作审批豁免。

用户停止后不继续加载、下载或准备新材料。停止前已经提交的安装结果保留并可查询；未提交导入取消或标记中断。不能因任务停止而删除全局已安装 skill。

服务重启遵循当前运行生命周期，不借本功能承诺通用崩溃自动续跑。可恢复的等待运行需要恢复 skill 绑定；已经终止的运行保留历史。导入中断和文件缺失按安装服务规则处理，不留下永久“安装中”。

## 失败反馈与并发边界

| 情况 | 行为 |
|---|---|
| 下载临时失败、限流或超时 | 有界重试，失败后显示来源阶段及重试入口 |
| 地址不支持、找不到 skill 或候选不唯一 | 返回原因或候选；不猜测别的来源 |
| 非法包、超限或正文格式错误 | 终止导入，定位文件或元数据问题 |
| 同名不同内容或并发更新 | 明确冲突，保留原版本 |
| 请求超时但发布结果未知 | 通过操作 ID 查结果，不直接重做或声称回滚 |
| 数据库提交失败 | 不暴露半安装；重试核对幂等状态，回收孤立目录 |
| 包已登记但文件损坏或缺失 | 加载失败并提示重新导入，不返回空正文 |
| 沙箱准备或脚本执行失败 | 区分准备、依赖和业务执行错误，不把已安装状态改成执行成功 |
| 运行停止或服务重启 | 按持久操作与运行状态收敛，不虚构后台继续完成 |

下载使用独立总时限和阶段时限；外部请求重试受总预算约束。安装提交、更新和删除使用数据库约束处理并发，不能只用进程内锁。大量目录或包内容不能无界注入模型或前端。

计划新增的限额包括获取时限、重试预算、压缩及解压体积、文件数量、单文件大小、候选扫描范围、正文与目录上下文预算、分段资源读取和临时预览保留时间。实现时统一在参数页登记配置来源、默认值及边界，并在所属服务指南说明操作方法。

## 实施顺序与完成条件

以下顺序保留实现依赖和完成条件。安装、设置、运行加载、显式调用与资源使用已经接通；真实模型对照未完成，效果验收仍开放，不将调用链通过视为质量提升。

### 第一阶段：包、版本和安装内核

实现统一解析、校验、GitHub 获取、本地文件导入、临时区、不可变发布、数据库迁移和导入幂等。明确更新冲突、删除引用及数据清理边界；发布并登记内置 `find-skills` 的固定版本。

完成条件：GitHub 与本地文件可安装同一种规范包；非法和中断场景没有可见半成品；重复请求和并发冲突结果可解释；安装不执行包内代码。部署持久化及配置已有明确归属。

### 第二阶段：设置页维护闭环

实现 skill 列表、搜索、详情、候选预览、新增、正文编辑、包更新、启停及删除。接入设置页未保存提示，异步导入可查询，错误可操作；内置 skill 标识及只读管理边界明确。

完成条件：用户无需聊天或操作服务器即可完成日常管理；新增帮助提示本机 CLI 安装不自动同步，误贴命令可得到 GitHub 或本地文件导入指引；刷新能看到真实结果；编辑正文不丢资源；并发更新和超时未知结果不会静默覆盖或重复安装。

### 第三阶段：运行加载与聊天安装

实现目录快照、共享加载器、skill 工具、权限与模式适配，以及聊天安装操作关联。已获用户安装要求时直接安装唯一候选，歧义候选可询问后续接，安装结果可供当前运行追加使用。

完成条件：模型只先看到目录；正文按需完整读取；计划模式只能读；聊天安装不绕开共享服务、审批和冲突规则；停用或更新不改变当前运行绑定。

### 第四阶段：显式调用与上下文闭环

实现 `/` 分组、skill 标签、快捷输入、结构化消息、草稿恢复、发送受理比较、历史投影。实现压缩保留、活动正文去重、新运行去激活和等待恢复。

完成条件：同一 skill 可主动选择或自动加载；显式选择在业务决策前生效；压缩、重连和等待后版本一致；旧消息兼容；容量不足时不假装已加载。

### 第五阶段：完整资源使用与交付核验

实现受限沙箱材料发布、完整性核对及按需准备，跑通参考资料、素材与脚本使用。完成停止、导入故障、资源缺失和清理验证，更新当前机制文档及操作入口。

完成条件：从公开 GitHub 地址安装完整 skill，显式或自动使用正文、参考资料及脚本，得到可核对的任务结果；失败和环境限制如实可见。全部完成条件及下述验证通过后，才将状态改为已实施。

## 如何验证效果

### 确定性检查

围绕契约和状态边界验证，不为纯展示细节堆砌测试：

- 用本地固定来源与恶意包样本覆盖元数据、候选发现、路径逃逸、体积限额、规范化哈希、重复安装和冲突。
- 用独立 PostgreSQL 和临时持久目录验证并发、发布前后故障、响应丢失、重启中断、更新旧版本、删除引用及孤立文件回收。
- 用脚本化模型验证目录先行、自动加载、显式预加载、模式拒绝、审批、活动正文去重、压缩补回及用户需求识别。
- 验证事件重建、同一运行等待续接、新运行不自动激活旧 skill，以及相同正文不同 skill 的发送确认。
- 在真实沙箱中验证材料完整发布、恶意路径拒绝、相对资源读取、脚本执行、缺失依赖反馈和副本不能回写全局包。
- UI 检查覆盖 GitHub 与文件来源、多候选、编辑及更新冲突、未保存提示、启停删除、草稿、`/` 选择、未知发送结果和历史回放。

故障注入至少覆盖下载中、文件发布前后及数据库提交前后。未验证的网络、浏览器或沙箱条件要明确记录，不能用静态检查替代运行结果。

### 真实模型与真实来源

在可访问 GitHub 的环境中安装一个固定提交的公开 skill，核对来源、包清单与文件内容；再覆盖目录地址及包含多个候选的来源。公共网络不可用时标记未完成，不用本地替身宣称 GitHub 已验证。

选取不同类型的非编码任务，至少覆盖纯正文方法、参考资料以及脚本或素材使用，分别验证显式调用与自动判断。预先给出独立的成果预期，观察模型是否选择相关 skill、读取必要资源并实际遵循要求；同时加入无关任务，检查不会为了使用 skill 而强行加载。

在相同模型与工具条件下，对比无 skill、显式选择及自动加载，分别记录独立成果质量、人工纠正、耗时与用量。`find-skills` 另检查发现相关性、兼容性判断和无关任务是否增加不必要的搜索或安装；未取得真实对照结果不宣称成功率已提高。

脚本化模型证明调用链，真实模型及独立成果核对评价使用效果；不由工具成功或运行 completed 推断任务正确。验证若暴露通用加载问题，修机制与通用规则，不将某个业务样例写进所有任务的系统提示词。
