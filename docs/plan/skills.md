# 全局技能安装与使用

## 目标与实施状态

**状态：方案已确认，待实施。当前授权为制定计划，不包含产品实现。** 后续实现按本方案逐项推进；下文均为目标设计，不能当作当前能力说明。

让用户把可复用的方法安装为 Skill，在所有会话与托管项目中使用，通过输入框主动选择，或由 Agent 根据任务需要加载。第一版提供完整的安装、管理、加载和资源使用闭环，不引入独立 Agent 循环。

已确认的范围：

- 一套全局技能库，可安装多个技能；不做项目级安装、覆盖和优先级。
- 支持 GitHub 地址、ZIP 技能包、手工创建 `SKILL.md`。
- 完整保存技能目录及其中的参考资料、脚本和素材，不只导入 Markdown。
- 设置页提供新增、查看、编辑、启停、更新和删除；聊天中可以要求安装 GitHub 上的技能。
- 输入框支持 `/` 选择及 `/技能名 任务`，也允许模型自主判断并加载。
- 安装和加载接入现有事件、上下文、权限、沙箱及任务生命周期。

不在本次范围：项目记忆重做、评测平台建设、编码专用能力、模型路由、多 Agent、技能市场、私有仓库认证、自动更新和独立依赖环境管理。冻结的 `lessons/` 不更新。

## 用户如何新增技能

### 设置页新增

设置中增加普通用户可见的“技能”页面，展示名称、描述、启停状态和来源。列表支持搜索，详情展示说明、文件目录和当前版本；不依赖开发者模式。沿用[界面设计约定](../../ray_agent/ui/DESIGN.md)及现有设置弹层、语义样式、键盘与窄屏行为，不新增独立管理工作台。

“新增技能”提供三种来源：

| 来源 | 用户操作 | 系统处理 |
|---|---|---|
| GitHub | 粘贴公开仓库或技能目录地址 | 解析固定提交，发现技能目录，读取完整包 |
| ZIP | 上传技能包 | 在临时区安全解包，发现技能目录 |
| 手工创建 | 填写名称、描述和 Markdown 正文 | 生成合法的 `SKILL.md`，走相同校验与发布流程 |

“新增技能”面板在来源选择处常驻简短说明：**“在你电脑上通过 `npx skills add` 安装的技能不会自动出现在 RayAgent 中。请粘贴技能的 GitHub 地址，或上传包含 `SKILL.md` 及相关资源的 ZIP 包。”** GitHub 输入框与 ZIP 上传入口分别提供对应操作提示，不要求用户先理解服务部署方式。

本方案中的技能库由 RayAgent 独立管理，不扫描或同步用户电脑上其他 Agent 的技能目录；即使 RayAgent 部署在同一台电脑上，CLI 安装也不等于已导入。聊天中在沙箱执行 CLI 安装同样不登记全局技能，不能据此报告 RayAgent 安装成功。

获取后进入预览，展示名称、描述、来源、文件概况和可读的校验结果，再点击“安装”。预览确认就是安装操作，不追加多层确认。

若来源包含多个技能，展示候选名称、描述和目录，用户选择一个后安装。第一版不做批量安装。无法解析或没有 `SKILL.md` 时给出具体原因，不创建空条目。

导入中的进度使用“获取来源、校验包、等待选择、发布”等真实阶段；能取得可靠字节总量时才显示下载进度。切换页面后可查询导入状态，不要求一直保持弹窗。

### 去哪里发现技能

设置页的技能列表及“新增技能”入口提供“浏览社区技能”链接，打开 [skills.sh 技能目录](https://skills.sh/)，让用户搜索、浏览并挑选技能。用户在站外选好后，复制对应的公开 GitHub 仓库或技能目录地址，回到 RayAgent 按上述 GitHub 流程预览和安装。

第一版只提供外部导航，不接入站点搜索、榜单同步、账号或一键安装协议。“浏览社区技能”链接旁提示“选好后复制 GitHub 地址，或下载 ZIP 回到此处导入；本机命令安装不会自动同步”。站点详情页、技能合集地址及 `npx skills add …` 命令不作为安装源；粘贴安装命令时给出针对性提示，说明这里需要 GitHub 地址，并保留输入供用户修改，不执行命令或静默转换安装意图。安装仍由 RayAgent 的共享服务完成，不执行站点提供的 CLI 安装命令，也不因此扩展为内置技能市场。

社区收录与热度不表示 RayAgent 已验证其质量、安全性或运行兼容性；来源与包内容继续在安装预览中展示，实际可用性按当前工具及沙箱条件判断。入口文案简要说明站外选择后需复制 GitHub 地址，不承诺所有收录技能都能直接使用。

### 聊天中安装

用户说“安装这个地址里的技能”时，Agent 可调用 `install_skill(source_url, candidate_path?, operation_id?)`。首次调用创建或复用导入操作，候选选择后携带返回的操作 ID 续接，服务端核对来源和候选。工具调用共享安装服务，不能由模型临时拼接下载、解压或 Git 命令来写全局技能目录。

1. 工具通过现有模式与权限检查。
2. 安装服务解析来源，获取固定版本并发现候选。
3. 只有一个候选时校验并发布，返回实际安装结果。
4. 多个候选时返回候选信息，Agent 通过现有询问工具请用户选择，再提交同一导入操作中的选项。
5. 成功结果包含技能名称、描述、版本和文件概况；失败结果包含阶段、原因及可执行的下一步。

用户明确要求安装即构成本次操作授权，不强制再弹一遍产品确认；配置的工具审批规则仍照常生效。系统指令要求模型只在用户提出安装需求时使用该工具，技能正文中的安装指令不等同于用户授权。这是模型行为要求，不能声称程序能准确证明自然语言授权。

用户只发一个地址、没有安装意图时，不默认安装。安装工具只处理公开 GitHub 来源；聊天上传 ZIP 不自动当技能安装，ZIP 使用设置页入口。

### 同名与更新

技能名是稳定调用标识。相同名称、相同规范化文件内容的重复安装返回已有版本；同名但内容不同返回冲突，不静默覆盖。来源地址不同但内容一致，可以复用已有安装结果，并说明来源未替换。

更新是设置页的显式操作：从原来源重新获取、重新上传包，或编辑 `SKILL.md`，均先生成新版本并校验，再替换当前版本。更新前校验用户看到的旧版本，发生并发修改时提示刷新，不覆盖他人的修改。

第一版只提供正文编辑和包更新，不做任意包文件的在线 IDE。正文编辑保留包内其他文件；名称不在编辑时直接改写，需要改名时按新技能安装。停用后保留包，新任务不可使用；删除后从技能库移除，正在使用的版本按运行引用保留。

## 技能包契约

### 文件与元数据

技能根目录必须有 UTF-8 编码的 `SKILL.md`，包含 YAML frontmatter。`name`、`description` 为必填字符串，正文不能为空。使用安全 YAML 解析，禁止构造任意对象。

`name` 使用小写字母开头、字母数字及连字符组成的稳定标识，不与内置 `/` 命令冲突；名称及描述的长度限制集中维护在[参数页](../limits.md)。标题、描述和正文在所有入口使用同一解析结果，不由前端和模型各自推断。其他元数据可以保留，但不自动解释为权限、工具授权或安装钩子。

完整包保留技能根目录内的普通文件和相对目录，包括 `references/`、`scripts/`、`assets/`，不要求这些目录存在，也不只允许这些目录。根目录之外的仓库文件不导入；第一版不解析包外引用、子模块或 Git LFS 指向的实际大文件，发现相关依赖时在预览及结果中说明。

拒绝路径穿越、绝对路径、符号链接、硬链接、设备文件、规范化后的重名路径及不可移植的路径冲突。压缩包层级、文件数量、单文件大小和累计解压大小都有边界，不能仅检查压缩后体积。包哈希由规范化的路径与文件内容计算，不受 ZIP 时间戳和外层目录名影响。

安装不执行任何脚本、不自动安装依赖、不验证所有业务方法都有效。安装成功表示包完整可读、元数据合法且已登记；执行环境和任务效果在使用阶段判断。

### GitHub 地址解析

支持公开 GitHub 仓库根地址、目录地址和指向 `SKILL.md` 的文件地址。无版本地址解析仓库实际默认分支；分支或标签先解析成不可变提交，再按该提交下载。不能简单按斜杠截取分支名，因为引用名本身可能包含斜杠。

有明确技能目录时仅导入该目录。仓库根目录已有 `SKILL.md` 时将其作为一个技能；根目录没有时，在受限扫描范围内寻找候选。发现多个候选必须选择，不根据目录顺序猜测。返回结果记录仓库、目录和提交，便于解释安装来源。

网络获取由受控适配器完成，只访问支持的 GitHub 官方下载与 API 目标，校验重定向，阻止转向本地或内网地址。下载流、解包和扫描都受限。不接受任意 URL 作为下载器，不在第一版接收 PAT、私有仓库或企业 Git 服务认证信息。

网络临时故障允许有限重试；固定提交不存在、格式错误、包校验失败和同名冲突直接返回，不能通过换分支或换目录悄悄“修好”。具体可调边界在实现时加入参数页，不在本方案重复维护默认值。

## 安装服务与数据归属

### 共享服务

设置页和聊天工具共用同一套应用服务：来源获取 → 候选发现 → 校验与预览 → 不可变文件发布 → 数据库登记。入口只负责输入和展示，不各写一套安装器。

安装操作持久化，包含操作 ID、请求幂等标识、来源、候选、阶段、失败原因和发布结果。前端重试提交或工具等待后恢复时查询原操作，不重复创建包。工具执行记录与安装操作 ID 建立关联，避免“工具超时但实际已安装”后误报未执行。

建议接口按资源职责组织，最终命名在实现中沿现有 API 风格统一：

| 能力 | 契约要点 |
|---|---|
| 创建导入 | 按 GitHub、ZIP、手工三种输入适配，共用操作与幂等契约 |
| 查询导入 | 返回真实阶段、候选、预览摘要、错误与已发布结果 |
| 发布候选 | 引用操作、候选、预览指纹及安装或更新意图，不能提交任意磁盘路径 |
| 技能列表与详情 | 返回稳定 ID、名称、描述、状态、当前版本和来源 |
| 编辑及更新 | 带预期旧版本，产生新版本，冲突可识别 |
| 启停与删除 | 修改新运行可见目录，幂等处理重复请求 |
| 读取资源 | 只接收技能、版本与包内相对路径，服务端执行归属校验 |

预览不意味着调用方能改写已经校验的内容。发布校验操作所有权、候选及内容指纹；临时预览过期后要求重新获取。

### 存储与事务

数据库管理技能、不可变版本、导入操作及运行引用；完整包保存在 API 持久卷的独立技能命名空间。它不属于附件记录、托管项目目录或项目快照，不直接复用与附件生命周期绑定的上传流程。

版本记录包含解析后的元数据、包哈希、清单、来源提交和文件位置。启停状态、当前版本和技能名唯一约束由数据库管理。第一版使用现有单实例部署边界，不引入额外对象存储服务；部署指南需要说明持久卷和数据库应配套备份与恢复。

网络获取及校验在数据库事务外完成。发布先将临时包校验并原子改名为不可变版本目录，再在短事务中登记可见版本及结果。同名竞争通过唯一约束和版本条件处理；失败时不暴露半安装条目。

文件系统和数据库不宣称具备跨资源原子事务。文件已发布而数据库提交失败时，留下可识别的孤立目录；重试先按幂等记录和内容哈希核对，维护回收只删除确认无引用的临时包与孤立版本。数据库已有可见版本但文件缺失时，明确标记资源不可用，不能以空内容继续加载。

重启后，将没有完成发布的旧导入操作标记为中断，允许用户重试；已完成登记的操作仍返回成功，不自动重新下载。取消操作只在发布提交前生效，已经提交的结果应如实返回。任务停止时取消其尚未提交的聊天导入；设置页导入有自己的操作生命周期，不随某个聊天任务停止。

### 删除与清理

删除、停用或更新影响后续运行可见目录，不改写已被运行引用的版本。等待中的同一运行继续使用原版本；版本回收依据持久引用，不能只依据当前进程是否持有对象。

清空会话、项目或业务数据时保留全局技能及配置。删除运行记录时释放相应版本引用；删除技能后，仅在没有运行引用时回收其版本。临时包清理与版本回收必须校验技能存储根目录及资源归属。

第一版不提供历史版本管理界面和紧急撤销已运行脚本的承诺。删除技能不等于撤销已经发生的外部副作用，也不删除用户任务产物。

## 已安装技能如何进入任务

### 输入框选择

沿用现有 `/` 菜单，增加技能分组，按名称和描述搜索。选择技能后展示可移除的标签，用户继续输入任务并发送；选择本身不立即执行。

支持以 `/技能名 任务内容` 开头的快捷输入。发送前解析成结构化选择与剩余任务正文；不从 URL、文件路径或代码片段中猜测命令。内置命令保留原有行为，技能名称在安装时排除冲突。直接 API 调用使用结构化字段，不依赖模型解析斜杠文本。

第一版一条用户消息显式选择一个技能，Agent 可以按需要再加载其他技能。选择不自动成为后续每条消息的默认值。不包含任务正文时保留草稿并提示输入任务。

选择同时进入首页、项目页和会话页草稿、发送请求、受理判断、用户消息事件与历史展示。发送不确定时核对受理结果必须比较技能选择，不能将“相同正文、不同技能”当作同一消息。旧消息没有该字段时兼容为空。

客户端提交稳定技能 ID 及所见版本，服务端在受理边界校验可用性并固定版本；已经删除、停用或更新时返回可理解的冲突，保留草稿供用户刷新选择，不静默改用另一版本。

### 显式加载与自动加载

每个新运行固定一份启用技能目录快照，仅包含名称、描述和不可变版本引用。目录通过标记明确的技能上下文提供给模型，不把正文全部放入提示词。模型按任务语义决定是否调用 `load_skill(name)`，不增加独立分类器或额外主模型请求。

安装和启用时检查全局目录预算；并发操作仍需在提交边界核对。目录无法完整放入预算时拒绝使其超限的变更，提示缩短描述或停用不需要的技能，不静默隐藏后半部分技能。正文加载另按活动正文预算判断。

显式选择则由程序在下一次业务模型决策前加载所选正文，不依赖模型再次猜测用户意图。正文作为带来源、版本及内部类型标记的指令资料进入上下文，不伪造模型的工具调用；自动加载使用真实工具调用和结果。二者共享解析、版本解析、容量检查及记忆登记逻辑。

技能内容不能提升系统权限或覆盖模式约束。模型应按相关性使用技能；描述匹配及执行效果属于模型能力，需要真实任务检验，不能由“成功返回正文”推断。

运行期间设置页更新不刷新本运行目录。若用户明确要求“安装后立即使用”，安装成功后允许将这一个安装结果以追加方式加入本运行可见目录，持久化追加记录后才可加载；不顺便刷新其他技能。与当前运行同名的旧版本冲突时继续保留旧绑定，说明新版本在新运行生效，不在中途替换。

运行中补充消息的技能选择在现有消息消费边界生效，先登记引用和加载，再进行下一次模型决策。等待用户回答时随回答处理；工具审批等待仍遵循现有审批通道，不借聊天选择绕过审批。

### 工具与模式

| 工具 | 职责 | 计划模式 | 收尾阶段 |
|---|---|---|---|
| `load_skill(name)` | 加载当前运行绑定版本的完整正文 | 允许 | 允许读取 |
| `read_skill_resource(name, path, range?)` | 读取包内参考文本；二进制返回资源信息 | 允许 | 允许读取 |
| `prepare_skill_resources(name)` | 将当前版本完整包准备到本运行沙箱目录 | 不允许 | 不允许 |
| `install_skill(source_url, candidate_path?, operation_id?)` | 安装公开 GitHub 技能并关联导入操作 | 不允许 | 不允许 |

工具的公开参数以名称和包内路径为主，版本、运行身份及主机存储位置由服务端解析，不能由模型任意指定。资源文本可以分段读取，并明确范围和是否还有内容；正文必须完整加载或明确失败，不能悄悄返回截断正文却声称已加载。

工具按现有注册、Schema、策略与执行管线接入。新增工具同步修改计划模式和收尾阶段允许范围、工具策略目录及前端契约，不设置绕过审批的特殊通道。工具声明中的只读属性仅用于真实只读操作，安装和沙箱材料准备都属于写入。

加载失败要区分不存在、未启用、版本缺失、格式错误和上下文容量不足。显式选择失败时先向用户解释，不能假装已经遵循该技能继续完成原任务；自动加载失败可根据原因选择其他方法，但必须保留失败反馈。

## 完整技能包如何使用

只加载正文或读取参考文本时，API 直接读取不可变包，不为此提前启动沙箱。正文返回可读的包内资源清单及相对引用规则。

需要脚本、素材或供现有文件工具处理的资源时，调用材料准备工具。API 从已验证的不可变包准备材料，由受限的沙箱发布能力写入当前运行专属目录，验证文件清单后发布；不让模型传任意主机路径，也不通过不受控的 shell 解压命令安装全局技能。

目录由运行、技能及版本共同确定。准备过程可重复调用，完整成功才返回可用根路径；失败不返回可用状态。等待续接时检查材料是否仍存在且完整，缺失则从固定版本重新准备。沙箱内副本可能被任务修改，不能因此反向覆盖全局包，也不能仅凭路径存在就认定哈希一致。

准备后通过现有文件、Shell、浏览器等工具使用资源，包内相对路径在材料根目录解析。执行脚本仍走现有 Shell 权限和审批，按任务需要处理缺失依赖；不能假设装入包就自带 Python、Node 或系统依赖。

材料准备不自动运行脚本。依赖安装失败或当前沙箱不支持时，返回真实原因，由 Agent 决定替代、询问或终止，不扩展成自动环境修复平台。安装完成的技能可以包含暂时无法执行的脚本，界面和模型反馈要区分安装状态与本次执行状态。

新增沙箱材料发布能力属于本次实施范围；应沿现有 API 与沙箱访问边界实现，限定目标根目录、防止路径与链接逃逸，并核对身份、超时及清理归属。它不开放为任意主机目录映射或新的通用模型工具。

## 上下文、版本与恢复

### 记录什么

受理时的显式选择、运行技能目录、追加可用项、实际加载的版本和内容指纹都需要持久化。技能正文只从不可变版本读取，并能核对哈希；不能恢复时只记住名称，再到当前技能库加载最新内容。

显式正文使用有类型标记的内部上下文块；自动加载使用带来源元数据的工具结果。保留两者身份，避免压缩器将技能正文当作用户原始需求。已有用户需求保护规则继续适用。

用户消息展示选择的技能标签，自动加载及安装沿现有工具过程展示。开发观察可查看绑定版本和导入操作，普通界面不堆放存储路径、哈希或原始协议字段。

### 压缩如何保留

当前运行维护活动技能引用集合，成功加载后加入，重复加载同一版本不重复注入正文。通用工具结果整形需要识别技能正文，不能把它变成只有头尾的预览。

压缩时将活动技能正文与待摘要历史分开处理：历史正常生成摘要，压缩完成后从固定版本原样补回活动正文，再发下一次模型请求。补回使用相同内部类型标记及版本身份，不能靠摘要记住操作规则，也不能破坏保留消息中的工具调用与结果配对。

完整正文、目录和保留区一起参与上下文容量检查。压缩后仍超出预算时明确返回容量不足，要求减少当前任务使用的技能或拆分任务；不能静默丢弃用户选择的技能，也不自动截短正文。加载前检查单技能及累计活动正文预算，失败不加入活动集合。

新运行不继承“已激活”状态；历史技能资料可作为历史引用保留，但不能自动重新激活旧正文。工作记忆重建时识别旧技能块和技能工具结果，将其转为可追溯历史引用，保留工具协议配对；新运行按自己的目录和选择重新加载。持久事件保留原记录，不改写历史事实。

### 等待、停止和重启

等待提问、工具审批后的同一运行恢复固定目录及活动版本，正文按原版本重建，不使用当前全局最新值。审批恢复继续现有一次性审批语义，不把加载技能当作审批豁免。

用户停止后不继续加载、下载或准备新材料。停止前已经提交的安装结果保留并可查询；未提交导入取消或标记中断。不能因任务停止而删除全局已安装技能。

服务重启遵循当前运行生命周期，不借本功能承诺通用崩溃自动续跑。可恢复的等待运行需要恢复技能绑定；已经终止的运行保留历史。导入中断和文件缺失按安装服务规则处理，不留下永久“安装中”。

## 失败反馈与并发边界

| 情况 | 行为 |
|---|---|
| 下载临时失败、限流或超时 | 有界重试，失败后显示来源阶段及重试入口 |
| 地址不支持、找不到技能或候选不唯一 | 返回原因或候选；不猜测别的来源 |
| 非法包、超限或正文格式错误 | 终止导入，定位文件或元数据问题 |
| 同名不同内容或并发更新 | 明确冲突，保留原版本 |
| 请求超时但发布结果未知 | 通过操作 ID 查结果，不直接重做或声称回滚 |
| 数据库提交失败 | 不暴露半安装；重试核对幂等状态，回收孤立目录 |
| 包已登记但文件损坏或缺失 | 加载失败并提示重新导入，不返回空正文 |
| 沙箱准备或脚本执行失败 | 区分准备、依赖和业务执行错误，不把已安装状态改成执行成功 |
| 运行停止或服务重启 | 按持久操作与运行状态收敛，不虚构后台继续完成 |

下载使用独立总时限和阶段时限；外部请求重试受总预算约束。安装提交、更新和删除使用数据库约束处理并发，不能只用进程内锁。大量目录或包内容不能无界注入模型或前端。

计划新增的限额包括获取时限、重试预算、压缩及解压体积、文件数量、单文件大小、候选扫描范围、正文与目录上下文预算、分段资源读取和临时预览保留时间。实现时统一在参数页登记配置来源、默认值及边界，并在所属服务指南说明操作方法。

## 实施顺序与完成条件

以下工作均待实施，顺序体现依赖。可在各阶段做局部验证，但对用户交付以完整闭环为准，不把只有加载工具的中间状态视为本方案完成。

### 第一阶段：包、版本和安装内核

实现统一解析、校验、GitHub 获取、ZIP 导入、手工建包、临时区、不可变发布、数据库迁移和导入幂等。明确更新冲突、删除引用及数据清理边界。

完成条件：三种来源可安装同一种规范包；非法和中断场景没有可见半成品；重复请求和并发冲突结果可解释；安装不执行包内代码。部署持久化及配置已有明确归属。

### 第二阶段：设置页维护闭环

实现技能列表、搜索、详情、候选预览、新增、正文编辑、包更新、启停及删除。接入设置页未保存提示，异步导入可查询，错误可操作。

完成条件：用户无需聊天或操作服务器即可完成日常管理；新增及社区浏览入口明确说明本机 CLI 安装不自动同步，误贴命令可得到 GitHub 或 ZIP 导入指引；刷新能看到真实结果；编辑正文不丢资源；并发更新和超时未知结果不会静默覆盖或重复安装。

### 第三阶段：运行加载与聊天安装

实现目录快照、共享加载器、技能工具、权限与模式适配，以及聊天安装操作关联。已获用户安装要求时直接安装唯一候选，歧义候选可询问后续接，安装结果可供当前运行追加使用。

完成条件：模型只先看到目录；正文按需完整读取；计划模式只能读；聊天安装不绕开共享服务、审批和冲突规则；停用或更新不改变当前运行绑定。

### 第四阶段：显式调用与上下文闭环

实现 `/` 分组、技能标签、快捷输入、结构化消息、草稿恢复、发送受理比较、历史投影。实现压缩保留、活动正文去重、新运行去激活和等待恢复。

完成条件：同一技能可主动选择或自动加载；显式选择在业务决策前生效；压缩、重连和等待后版本一致；旧消息兼容；容量不足时不假装已加载。

### 第五阶段：完整资源使用与交付核验

实现受限沙箱材料发布、完整性核对及按需准备，跑通参考资料、素材与脚本使用。完成停止、导入故障、资源缺失和清理验证，更新当前机制文档及操作入口。

完成条件：从公开 GitHub 地址安装完整技能，显式或自动使用正文、参考资料及脚本，得到可核对的任务结果；失败和环境限制如实可见。全部完成条件及下述验证通过后，才将状态改为已实施。

## 如何验证效果

### 确定性检查

围绕契约和状态边界验证，不为纯展示细节堆砌测试：

- 用本地固定来源与恶意包样本覆盖元数据、候选发现、路径逃逸、体积限额、规范化哈希、重复安装和冲突。
- 用独立 PostgreSQL 和临时持久目录验证并发、发布前后故障、响应丢失、重启中断、更新旧版本、删除引用及孤立文件回收。
- 用脚本化模型验证目录先行、自动加载、显式预加载、模式拒绝、审批、活动正文去重、压缩补回及用户需求识别。
- 验证事件重建、同一运行等待续接、新运行不自动激活旧技能，以及相同正文不同技能的发送确认。
- 在真实沙箱中验证材料完整发布、恶意路径拒绝、相对资源读取、脚本执行、缺失依赖反馈和副本不能回写全局包。
- UI 检查覆盖三种新增来源、多候选、编辑及更新冲突、未保存提示、启停删除、草稿、`/` 选择、未知发送结果和历史回放。

故障注入至少覆盖下载中、文件发布前后及数据库提交前后。未验证的网络、浏览器或沙箱条件要明确记录，不能用静态检查替代运行结果。

### 真实模型与真实来源

在可访问 GitHub 的环境中安装一个固定提交的公开技能包，核对来源、包清单与文件内容；再覆盖目录地址及包含多个候选的来源。公共网络不可用时标记未完成，不用本地替身宣称 GitHub 已验证。

选取不同类型的非编码任务，至少覆盖纯正文方法、参考资料以及脚本或素材使用，分别验证显式调用与自动判断。预先给出独立的成果预期，观察模型是否选择相关技能、读取必要资源并实际遵循要求；同时加入无关任务，检查不会为了使用技能而强行加载。

脚本化模型证明调用链，真实模型及独立成果核对评价使用效果；不由工具成功或运行 completed 推断任务正确。验证若暴露通用加载问题，修机制与通用规则，不将某个业务样例写进所有任务的系统提示词。
