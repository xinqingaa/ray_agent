# 工作区文件与执行环境

本专题定义工作区文件夹的访问、写入保护与本机执行，按计划实施中，进度见[实施状态](implementation.md#实施状态)。工作区形态与文件夹身份按[决策 D7、D8](decisions.md)，本机执行与组件供给按 D5、D6，首批执行边界按 D9。

## 问题与现状

原托管项目保存平台副本，用户材料要经过选择、预检、上传与发布，动态沙箱挂载托管目录执行；本地修改不会回到项目，成果要下载才能回到用户手里，纯讨论也承担环境成本。P1 已删除托管项目与沙箱装配：核心只有独立对话，附件、超长工具结果与截图写入会话工作目录，文件、Shell 与浏览器工具按能力声明关闭，公开网页读取在核心中完成。P3 已接入工作区文件夹与限根文件工具、写入租约、写前备份与撤销，现状见[执行环境与限制](../architecture.md#执行环境与限制)、[数据归属](../architecture.md#数据归属)及[文件与交付代码地图](../code-map.md#文件与交付)。

## 工作区文件夹

每个工作区绑定一个本地文件夹，Agent 的文件工具直接在原位读写，不复制进容器或应用副本。新建工作区时应用在默认位置创建文件夹，默认位置可在设置中修改；绑定、身份标记与失联处理见[工作区专题](workspaces-and-memory.md#文件夹绑定与身份标记)。

- **添加文件**：在工作区会话或文件夹面板中添加的文件复制进文件夹，默认放在根目录，用户可选子目录；同名不覆盖，改用不冲突的名称或询问。复制完成后与已有文件一样登记和索引，不存在只在索引中、文件夹里却没有的文档。
- **外部修改**：用户在其他应用中修改、增删文件，经文件监听与重新扫描被发现，内容核对后更新索引；收到通知不是唯一依据。
- **独立对话附件**：继续按消息附件保存，并放入会话工作目录供读取，不进入任何工作区；用户可以显式另存到某个工作区文件夹。

选择文件夹只授权该文件夹，不扩大到全盘访问。首批每个工作区只有一个文件夹，不支持额外的参考目录。

## 会话工作目录

每个会话在应用数据目录中有一个会话工作目录，承接原沙箱固定路径的职责：本会话的附件、超长工具结果、截图与临时文件。它不在用户文件夹中，随会话删除或应用数据清理回收。P1 已实现：会话创建时在数据根的 `sessions/` 下建立并登记为 `root_id`，分 `uploads`、`outputs`、`screenshots`、`tmp` 子目录，删除会话时由清理任务回收；位置与接口见[代码地图](../code-map.md#状态与持久化)。

- **独立对话**：会话工作目录就是工作目录。文件工具在其中读写，成果经交付成为附件，沿用现有附件语义；用户可以显式另存到某个工作区文件夹。Shell 与脚本按应用设置中的独立对话执行开关启用，默认关闭。
- **工作区会话**：工作目录是工作区文件夹，附件按上文复制进文件夹；超长结果、截图与临时文件仍放会话工作目录，不写进用户文件夹。

文件工具的可访问根是当前工作区文件夹（如有）与本会话工作目录，两者走同一套限根 IO。系统提示词的运行环境说明按平台、工作目录与能力声明生成，不再描述 Linux 沙箱或免密 sudo。

## 文件身份、内容对象与工具端口

工作区文件夹与会话工作目录各登记为一个 `root_id`，文件 API 使用 `root_id` 与相对路径。UI 可以显示真实位置，移动客户端不能提交桌面绝对路径，新文件夹只能由桌面原生选择器登记。模型工具与 Shell 使用同一种路径：真实绝对路径或相对工作目录的路径，执行前解析到可访问根，越界拒绝。

文档修订、写前备份、交付版本与 Skill 快照保存为应用内容对象，按工作区或用户级 Skill 库归属管理；相同内容哈希不跨工作区提供存在性查询。索引、缩略图与临时预览是可重建数据。磁盘不足时停止新发布，保留当前有效对象和可恢复状态，不先删已引用版本腾空间。

原 Sandbox 职责拆为 WorkspaceFiles、ProcessExecutor、BrowserSession 和 RuntimeComponents 端口。文件工具、Shell 工具、浏览器工具、公开网页读取、截图、预览与交付分别依赖所需端口；纯对话和公开 HTTP 读取不创建浏览器或进程。四个端口的接口与值类型在核心定义（位置见[代码地图](../code-map.md#共享契约)）；WorkspaceFiles 由 P3 实现，ProcessExecutor、BrowserSession 与 RuntimeComponents 由 P4 实现并经能力声明与执行开关装配。

## 跨平台 IO

POSIX 使用目录描述符与不跟随链接的访问，Windows 通过原生文件句柄、最终路径／卷身份与 reparse-point 检查提供等价边界。先核对根身份再逐级访问，拒绝路径穿越、特殊设备与越界链接；符号链接默认显示目标文本，不当普通文件展开。合法大文件流式读取，预览有明确边界。

扫描、索引与工具共享排除和文件类型规则；`.rayagent/`、版本控制内部目录、依赖缓存、凭据与数据库文件始终排除。UI 预检只帮助理解，实际 IO 再次核对。文件名大小写冲突、Windows 保留名、跨卷原子替换和权限失败分别处理，不为兼容去掉根检查。首个交付只实现与检查 macOS 的 POSIX 路径，随 P3 交付；端口不写死 POSIX 语义，Windows 实现在后续阶段 P11 完成。

## 写入与撤销

文件工具写入采用同目录临时文件，发布前核对版本，并把被覆盖或删除的原字节保存为写前备份。应用内并发由写入租约协调；对不合作的外部编辑器只能检测冲突，不承诺跨进程原子比较交换。发布窗口内文件身份或内容改变时，保留冲突或结果未知与备份，不宣称已成功覆盖。

写入租约覆盖整个工作区文件夹。只读文件操作、检索与记忆不取租约；任意 Shell 都按可能写入处理，不能因模型声称只读而豁免。普通文件工具短持租约，Shell、下载到工作区及其他长写入保持到写入者实际静止。租约持久记录所有者运行／操作、核心实例及状态 `preparing / held / settling / blocked`；其他会话的写入返回当前占用者与原因，不无限等待。审批未执行前不占用空闲租约，批准后再次检查版本与准入；已有进程等待用户时不提前释放。

停止时先阻断后续动作，再取消运行与子进程，确认退出后释放租约；无法确认时转 `blocked` 并提供重试收尾，只读与记忆功能继续可用。迟到结果必须核对租约身份，不能释放新运行的租约。

每次运行提供“撤销本次修改”：逐项核对文件当前版本，展示将恢复的内容，保存撤销前版本后再写回；文件之后又被外部修改时要求处理冲突，不自动删除运行前不存在的用户文件。撤销只改变选中的文件，不回滚会话、记忆或工作方式，文件变更正常触发重新索引。Shell 写入只提供运行前清单与变更摘要，不宣称完整捕获任意进程写入。首批不把文件夹自动改造成 Git 仓库。

## 成果交付

交付工具在工作区会话中把文件夹内已写入的文件登记为本次成果，同时保存交付时的内容对象；消息与“本次成果”引用该版本，可以预览，也可以打开文件所在位置。文件之后被修改不改写已交付的版本。独立对话从会话工作目录交付为附件。

## 执行环境

| 能力 | 准备时机 | 边界 |
|---|---|---|
| 对话、记忆与检索 | 本机核心可用时 | 不需要进程或浏览器 |
| 文件读写 | 调用文件工具时 | 限工作区文件夹与会话工作目录；文件夹写入有写前备份与写入租约 |
| Shell 与脚本 | 实际执行时，且所在工作区（独立对话为应用设置）已启用本机执行 | 进程、工作目录、环境、取消与输出归属 |
| 自动化浏览器 | 首次需要浏览器时 | 独立浏览器实例、资料目录与运行资源身份 |

首批不提供 Docker 或远程执行的产品流程；执行端口保留扩展位置，需要时另立工作包，不影响本机常规使用。原部署留下的容器与卷不由桌面应用管理或删除。

## 进程与执行资源

原生执行 supervisor 管理进程身份、进程组／Windows Job Object 与输出通道，Python 核心经私有 IPC 请求执行。创建前先保存操作与租约，进程启动确认后登记实际所有者；核心崩溃或宿主退出、失联时 supervisor 停止本次写入者，重启不凭 PID 判断旧进程属于本应用。

POSIX 用受管进程组发送终止信号并按策略升级，Windows 用 Job Object 管理子树与关闭回收；子进程标准输入输出、超时与交互 Shell 会话均绑定运行。冻结 worker 与工具进程使用明确入口，不把 PyInstaller 可执行文件当作系统 Python。

基础工具提供受管的正常 CPython 解释器和 Node，独立于冻结核心；命令 PATH 只添加这些运行时与允许的系统工具。Mac 使用系统兼容 Shell；后续 Windows 基线使用系统 PowerShell，不要求存在 WSL 或 Bash；依赖 Bash、原生编译器或未提供模块的 Skill 明确报告环境不兼容。额外依赖进入独立工具环境并经授权安装，不修改核心依赖集。

本地执行继承当前用户的系统能力，不提供硬隔离：Shell 的工作目录是工作区文件夹，但目录检查不能限制任意命令访问其他路径。不支持主动 daemonize 或脱离监管的后台服务作为可靠任务模式；进程或写入者结果无法确认时保留阻止标记，不宣称彻底终止。

## 浏览器与组件

自动化 Chromium 由桌面应用管理，与 Tauri 界面 WebView 分离，版本匹配当前 Playwright。每个工作区使用独立浏览器资料目录，独立对话使用各自目录；不接管用户默认浏览器资料，不跨工作区共享登录态。首个交付默认无界面运行，不在用户桌面弹出窗口，Agent 经截图观察页面；让用户在自动化浏览器中登录或人工接管属于后续增强。浏览器按需启动，运行时先取得相应操作租约，记录标签页、视口与下载归属；已有截图、元素引用及视口所有权沿工具契约表达。

同一工作区的浏览器状态变更串行准入，持久文件写入另取文件租约。截图与观察保留调用时内容；浏览器下载先进入运行临时目录，再经文件发布流程进入文件夹。网络副作用不能由数据库回滚，停止与恢复沿现有未知结果语义。

组件安装是持久操作，状态为未安装、获取中、校验中、可用、失败或取消；完整发布前旧版本继续可用，网络失败可按同身份读回并受控重试。首个交付从组件清单固定的上游发布地址下载并校验哈希，不自建分发服务；上游没有可直接使用的产物时，由所属工作包确定托管位置。浏览器经 Playwright 拉取 Chromium；Embedding（`embedding-e5`）从 Hugging Face 拉取 E5 ONNX；OCR（`ocr`）从 `rapidocr_onnxruntime` 包内复制并校验，文件级清单见 `resources/component_files.json`。散装原生库首次可启动检查可能较慢，须容忍。P10 的离线包走相同校验路径，不从用户粘贴的任意 URL 执行安装脚本。核心与运行时的打包方式见[客户端与分发](clients-and-distribution.md)和[本机核心](local-runtime-and-storage.md)。

## 责任与依赖

工作区服务登记文件夹与访问范围；文件服务维护身份、版本、写前备份、预览与交付；执行适配管理进程与环境；浏览器适配管理自动化资源；运行器负责停止传播与资源收尾，不能只替换 Docker 实现类而保留原有耦合。

依赖[工作区身份](workspaces-and-memory.md)与[核心生命周期](local-runtime-and-storage.md)，向[检索](knowledge-and-retrieval.md)提供文件变更，向 [Skill](skills.md) 提供稳定资源路径与执行能力。

## 实施检查

P3 检查文件夹移动、复制、失联与替换，大小写、链接、特殊文件、版本冲突、写前备份与撤销，以及会话工作目录的越界拒绝、附件读取、成果交付与回收；P4 在 Mac 检查真实进程子树停止、核心崩溃、下载与浏览器资料隔离；后续 P11 在 Windows 重复同一组文件与进程检查。实际跨系统边界必须由真实文件与进程确认，不能仅由模拟适配器断言通过。

[Playwright 浏览器管理](https://playwright.dev/python/docs/browsers)及[冻结程序支持](https://playwright.dev/python/docs/library)作为组件实现依据。

## 完成条件

- 桌面直接打开本地文件夹作为工作区，外部修改能被重新发现，不需要上传副本。
- 独立对话的附件、成果与执行沿会话工作目录工作，不写入任何用户文件夹。
- 对话、记忆与检索不因没有浏览器或未启用本机执行而受阻，执行资源按实际需要准备。
- 文件写入、并发修改、撤销、停止与重启后的旧写入者有明确处理；用户文件不因工作区删除或卸载被误删。
- 文件与进程边界在 macOS 上经实际检查，自动化浏览器与界面 WebView 职责分开；Windows 在 P11 重复同一组检查。
