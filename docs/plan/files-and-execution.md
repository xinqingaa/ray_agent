# 工作区文件与执行环境

本专题处于方案讨论。改善本机文件使用、解除常规工作区对沙箱的耦合是升级目标；本地执行、浏览器打包和 Docker 可选化尚未实施。

## 问题与现状

当前项目保存平台托管文件副本，用户材料经过选择、预检、上传与发布后进入项目；项目沙箱挂载托管目录。批量上传和文件夹选择不能消除副本搬运与后续同步成本。

项目运行还涉及文件保护、占用和沙箱准备，纯讨论、记忆及知识读取不应无条件承担相同的环境成本。现状见[项目文件保护](../architecture.md#托管项目执行与文件保护)、[沙箱生命周期](../architecture.md#沙箱生命周期与限制)及[执行代码地图](../code-map.md#执行环境)。

## 文件空间建议

- **本地目录**：用户选择现有文件夹后持续使用原目录，外部修改可被发现，用户无需反复上传同一材料。
- **应用托管目录**：由应用创建和保存，适合没有现成目录的工作区，以及导入的手机材料或成果。
- **临时附件**：保留消息时点和来源，可选择是否纳入长期材料；不能把临时上传自动等同于工作区知识已经索引。

目录选择只建立范围，不自动授权任意全盘访问。需要明确一个工作区是否支持多个材料根、只读材料与可写成果目录，以及桌面路径到工具路径的映射；不要求各系统使用相同的字面路径。

## 版本、修改与恢复

统一文件身份、来源与实际内容版本，供知识索引、交付和预览引用。区分用户原目录、应用副本、附件和索引，明确谁有权修改、移动与删除。

外部编辑与 Agent 写入可能并发。写前核对版本、保护必要内容，发布与回调绑定具体操作；有文件副作用的 Shell 和后台进程不能仅由数据库终态判定已经静止。只读会话与纯记忆操作不沿用不必要的全项目写占用。

快照及恢复在用户原目录中的范围需要重新设计，不能直接套用托管卷的全目录恢复。恢复前保护现状、停止旧写入者、解释冲突与失败出口；移除工作区或卸载应用默认不删除用户原目录。

跨系统处理大小写、链接、路径与权限差异。当前安全 IO 使用的 POSIX 机制需为 Windows 实现相应边界，不通过去掉校验来获得兼容。

## 执行环境建议

将工作区、文件访问、命令执行、自动化浏览器和可选隔离环境按职责拆开：

| 能力 | 建议准备时机 | 边界 |
|---|---|---|
| 对话、记忆和知识检索 | 本机核心可用时 | 不要求创建容器或自动化浏览器 |
| 文件读取与写入 | 调用所属能力时 | 工作区范围、版本与写入协调 |
| Shell／脚本 | 实际执行时 | 进程、工作目录、环境、取消与输出归属 |
| 自动化浏览器 | 首次需要浏览器时 | 独立浏览器实例、配置与运行资源身份 |
| Docker／远程执行 | 用户选择或能力需要时 | 显式环境差异与材料传输／挂载 |

本地执行器需要定义操作系统 Shell、运行时与依赖、进程树终止和结果未知处理。目录检查可以约束文件工具，不能将任意 Shell 宣称为严格限制在工作区内；更强隔离仍需要专门环境。

保留 Docker 作为可选后端的建议，不让常规桌面操作依赖安装 Docker。同机 Docker 可挂载本机目录，远程执行则需要显式的材料传输与成果回收，不能直接使用客户端路径。

## 浏览器与运行时交付

建议由桌面应用管理 Playwright 和 Chromium，Tauri 的界面 WebView 不代替 Agent 自动化浏览器。首次准备、更新、浏览器资料归属和退出回收需明确；已有截图、元素引用及视口所有权继续沿工具契约表达。

Python 核心、工具所需 Node 等运行时，以及浏览器组件的内置或受管下载方式由[分发](clients-and-distribution.md)和[本机核心](local-runtime-and-storage.md)共同确定。应用可独立运行不意味着所有社区 Skill 的任意依赖都已预装，也不承诺保留 Linux 容器中的全部系统命令。

## 责任与依赖

工作区服务登记材料根和访问范围；文件服务维护身份、版本、预览、快照和交付；执行适配管理进程与环境；浏览器适配管理自动化资源；运行器负责停止传播和资源收尾，不能只替换 Docker 实现类而保留原有耦合。

依赖[工作区身份](workspaces-and-memory.md)和[核心生命周期](local-runtime-and-storage.md)，向[检索](knowledge-and-retrieval.md)提供内容变更，向[Skill](skills.md)提供稳定资源路径与执行能力。

## 完成条件

- 桌面可直接打开约定范围的本地目录，外部修改能够重新发现，不要求重复上传。
- 对话、记忆与检索不因无 Docker 或浏览器而被阻断，执行资源按实际需要准备。
- 文件更新、并发修改、交付版本、停止与重启后的旧写入者有明确处理；用户原目录不被业务删除误伤。
- 约定系统上的文件与进程边界经实际检查，自动化浏览器与界面 WebView 职责分开。
