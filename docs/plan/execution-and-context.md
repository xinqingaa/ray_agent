# 执行循环、上下文与效率优化方案

状态：已实施并收尾。保留单循环、容量治理和按需准备的设计依赖，当前机制见 [Harness 工程](../harness.md#决策层)，形成过程见[执行循环背景](../background/execution-and-context.md)。

## 目标与范围

- 用一份工作记忆连续决策，所有模型调用与真实结果完整配对。
- 分别控制单条结果与累计输入，保留原要求和可读回材料。
- 减少资源预热、展示补读及重复交接造成的往返。

覆盖循环、工具管线、模型适配、上下文、资源准备与外部发现。预算收尾依赖[计划与成果方案](long-task-trust-and-delivery.md)，等待和停止依赖[运行方案](runtime-and-control.md)。

## 单循环与工具管线

循环与管线按以下顺序配合：

1. 模型适配先组装完整响应并检查结束原因，再由循环使用动作；截断调用不执行。
2. 管线对解析、校验、禁止和执行异常生成配对结果，工具异常不隐式重放。
3. 循环先将结果写入记忆，再发布完成；应用运行器复用当次结果供展示。
4. 新输入在请求前纳入，不取消当前工具或创建重复流程；无调用时基于最新状态有限收尾。

调用配对是压缩、等待及有界并发的前置条件。停止或失败后的未知效果不能通过重试抹去；挂起调用按[控制平面](../architecture.md#调用配对与未知结果)修复。

## 上下文治理的三道边界

- **单条结果**先完整保存，再返回预览与读取路径；落盘失败明确说明不可再读。
- **请求容量**用同模型 usage 校准已知部分，对新增内容近似估算；固定输入或保留区仍超限时拒绝。
- **历史长度**通过摘要较早完整轮次控制，保留近期内容、用户原文和任务状态；摘要失败或压缩无效时明确结束。

源头提取先保留有效内容：浏览器提前丢失的正文无法由整形恢复，协议裁剪也必须先保留完整材料。模型预览和页面预览各有预算，不能视为历史全文。

估算用于准入，不代替实际用量计费。模型切换首轮不能沿用另一模型的计数；窗口、输出预留、思考和图片规则共同决定可用输入。

压缩切分点必须在调用及全部结果之后。内部提醒保持来源，用户原文和最新成果状态不完全依赖摘要；保留历史不意味着任意中断点恢复。

## 手动压缩与容量可解释性

1. 固定项目背景、模式与工具配置；固定输入超限时直接说明，不请求摘要。
2. 按完整轮次摘要，成功后原子替换工作记忆，保留持久事件且不创建产品运行。
3. 异常、取消与空摘要不发布半份状态；服务端有总期限，客户端等待覆盖该期限。
4. 超时或断连先按事件序号和忙碌状态读回，不自动再次执行。

容量展示分别标注实测输入、请求前估算和压缩后估算，估算增大不能称为释放空间。忙碌状态对发送与重复压缩返回明确原因，并可从会话详情读取；这项协调仍在单进程内，活动运行保持冻结背景。

具体数值见[运行参数与限额](../limits.md)。

## 准备资源与发现能力

- 独立对话首次需要才准备沙箱，附件使用前同步，准备结果必须有取消归属与清理出口。
- 项目先占用、处理旧写入者并保护文件，再准备环境，不能套用独立对话顺序。
- 浏览器首次调用连接 CDP，连接与等待续接遵守环境所有权。
- MCP/A2A 按需发现，实际集合与声明随运行保存，续接不改变条件或破坏别名路由。
- 整批独立白名单读取才有界并发，校验、后处理及结果按序提交，取消时收敛所有已启动读取。

不将读取并发推广为同页动作、写操作或未知外部副作用并发。

## 模块责任与依赖

| 模块 | 完成前必须成立的条件 |
|---|---|
| 循环与管线 | 完整响应、调用配对成立，再引入整形、压缩和并发 |
| 应用运行器 | 资源所有权、等待续接和取消出口明确，再延迟准备 |
| 模型与环境适配 | 能力编码一致，副作用异常不隐式重放 |
| 事件与前端 | 可区分请求输入与页面投影，配置和上下文变化可重建 |

## 完成条件

- 所有短路与多调用出口配对，未知结果不误记为未执行。
- 超长结果可读回，落盘和压缩失败有明确出口，压缩不拆调用轮次。
- 纯回答无需沙箱，项目仍先保护，等待保持发现与配置快照。
- 并发读取保持数量限制、结果顺序和取消语义。

本方案不包含通用并发调度、跨运行费用硬预算或摘要无损保证。验证入口见 [API 指南](../../ray_agent/api/README.md)；性能比较另行固定模型、输入、缓存与资源条件。
