# 执行循环、上下文与效率优化方案

状态：单循环、上下文治理和后续按需准备已实施。本方案保留成组设计、责任和依赖。

问题与取舍过程见 [执行循环背景](../background/execution-and-context.md)。本篇保留成组设计、责任和依赖；当前核心机制维护在 [Harness 工程](../harness.md)。

## 目标与范围

以一套执行上下文持续推进任务，完整配对模型调用和真实结果；控制单条与累计输入容量；减少由资源准备、展示补读和重复交接制造的往返。计划记录范围与进度，模型仍决定动作。

范围包含循环、工具管线、模型适配、上下文治理、资源准备、外部发现和必要事件投影。不引入独立 Planner、第二套调度器、框架迁移、通用并发执行或崩溃检查点。预算收尾与版本核验的成组设计维护在 [计划与成果方案](long-task-trust-and-delivery.md)。

## 单循环与工具管线

每次请求前装配工作记忆、补充用户输入和最新任务状态。模型响应完整后保存全部调用，以 call ID 关联结果。未知工具、参数错误与工具异常成为失败结果，供模型重新判断；工具不因执行异常自动重试。模型传输错误和空回复按有界重试处理，每次尝试有独立记录。

| 环节 | 契约 | 责任 |
|---|---|---|
| 请求模型 | 明确能力、预算、配置与消息来源；记录每次尝试 | 循环与模型适配 |
| 完整响应 | 参数组装完成，检查截断原因后才使用 | 模型适配与循环 |
| 执行前 | 工具解析、轻量参数校验、模式限制、策略及动作条件 | 工具管线 |
| 执行 | 一次真实动作；异常不隐式重放 | 工具与环境适配 |
| 执行后 | 原始结果、耗时、整形和附加事实 | 管线与应用运行器 |
| 回填 | 已执行结果先写记忆，再发布完成事件 | 循环 |
| 结束 | 无调用回复经过有限缺口检查；必要事实与业务判断分开 | 循环与成果记录 |

完整更新与短路都需要结果配对。提问、审批、失败或停止导致剩余调用未执行时，续接补齐其未执行或结果未知状态，不丢调用也不自动重放。模型输出被长度截断时不执行半截调用，缩短后有界重试，再失败明确结束。

运行中新输入不取消正在执行的工具，在下次模型请求前加入。这样既保留用户最新要求，也避免通过换流程制造悬空调用。等待和停止的持久化责任见 [运行方案](runtime-and-control.md)。

## 上下文治理的三道边界

### 单条结果

工具原始结果进入模型记忆前统一整形。超出单条上限的完整内容先保存，再返回首尾预览、长度与读回路径。模型可以按行读取所需部分；落盘失败时明确说明不可再读，不假装仅预览就是全量。

源头提取必须先保留有效内容。浏览器提前截断导致的缺失不能由通用整形补回；外部结果截断也需要在完整内容仍可取得的边界交给整形。模型输入预览与用户界面预览各有预算，不能混为同一历史全文。

### 请求前容量

容量分系统提示、工具声明、历史和结果等部分估算。利用当前模型上一响应的 prompt_tokens 作为已知部分，新增内容按字符近似；模型切换首轮不能继承另一模型的计数。上下文窗口与输出预留共同决定可用输入，思考、图片等规则来自模型目录。

估算用于决定压缩或拒绝，不是 tokenizer 精确计费。实际 usage、缓存与推理 tokens 另按上游返回记录，不能用字符估算替代费用数据。

### 历史压缩与恢复

越过水位时摘要较早完整轮次，保留近期轮次原样。切分点必须位于完整调用和全部结果之后，摘要请求不带业务工具。用户原文在预算内重新注入，内部提醒保留自己的来源；最新计划、范围、成果和检查由结构化事实补回。

摘要失败、保留区过大或压缩后仍超限，明确以容量失败结束。禁止静默丢掉约束、孤立工具结果或未满足要求。新用户输入可以重新开启执行，但不能将保留历史等同于任意中断点恢复。

## 手动压缩与容量可解释性

手动摘要沿同一完整轮次和原子替换契约，成功不删除持久事件，也不创建新的产品运行。摘要可能使估算增大；这种结果说明“已摘要，估算空间未减少”，不能声称释放空间。不可摘要的情况与模型请求失败分别表达。

压缩前固定同一份项目背景、模式与工具配置，检查固定输入是否已经超限。若基础提示、项目说明/笔记等固定段本身放不下，直接返回容量原因和明细，不请求摘要、不替换记忆。运行中项目段仍沿冻结版本，不把后来编辑混进旧输入。

手动压缩设总期限，客户端等待长于服务端期限，异常、取消和空摘要都不发布半份状态。压缩期间其他发送或重复压缩及时返回忙碌原因，会话详情能读取操作状态；超时或断连后核对事件 seq 和忙碌状态，不自动再次压缩。忙碌协调仍是单进程边界，不伪装多实例互斥。

容量展示区分实测输入、请求前估算与压缩后估算，同一份快照提供窗口、输出预留和可用输入上限。无数据不是零，占用与输出预留后的可用余量不是同一个数。水位表示下次请求前检查，不能保证实测环越线立刻触发压缩。逐模型配置与实际 usage 的关系见 [模型方案](model-connections-and-selection.md)。

## 准备资源与发现能力

独立对话首次需要才准备沙箱，纯回答无需启动容器。附件在使用前同步，浏览器 CDP 在首次调用时连接。项目运行先取得文件占用、完成旧写入者收尾与保护，保留安全顺序。

MCP 服务和 A2A 卡片按需发现，集合和实际工具声明随运行保存，等待续接恢复相同条件。工具目录减少无关输入，但不能每轮任意改写稳定前缀，或让别名冲突破坏路由。

有界读取并发只适用于整批独立白名单读取，并发数有上限，见[运行参数与限额](../limits.md)，结果仍按原顺序和 call ID 回填。写操作、同页依赖动作和未知外部副作用不推广成并发。取消、异常和等待需要收敛所有已启动读取，不能因为并发而失去每项结果。

## 模块责任与实施依赖

| 实施顺序 | 工作 | 依赖与交付 |
|---|---|---|
| 1 | 建立旧任务与调用协议基线 | 冻结输入、模型、环境，保留停止失败 |
| 2 | 单循环和三段管线，完整响应与结果配对 | 可脚本驱动的循环；删除重复规划与步骤 JSON 依赖 |
| 3 | 结果整形、容量估算、摘要及恢复 | 依赖完整配对；持久上下文变化可重建 |
| 4 | 事件投影与配置快照 | 区分模型输入、历史事实和用户展示 |
| 5 | 优化源头观察、按需资源和有限独立读取 | 依赖等待、控制、文件保护契约稳定 |
| 6 | 条件匹配的有限真实对照及说明更新 | 功能和质量先通过，再分析开销 |

领域层维护循环与纯协议，应用运行器协调沙箱、附件与外部资源，基础设施适配负责真实调用，前端投影事件。模型规则由目录与适配维护，运行命令和源码入口统一见 [API 指南](../../ray_agent/api/README.md)与 [代码地图](../code-map.md)。

## 完成条件与关键检查

- 多调用、未知工具、非法参数、异常与管线短路都有正确 call ID 结果；工具异常仅执行一次。
- 提问位于批次中间、审批续接、停止后再发消息和运行中补充输入，不产生悬空调用或重复副作用。
- 超长结果可按需读回；落盘失败有出口；容量预览、模型切换和压缩不静默裁剪约束。
- 压缩发生在完整轮次边界，用户原文与内部消息来源不混淆，结构化任务状态恢复。
- 纯回答不准备沙箱；项目仍先保护；外部发现和等待快照一致。
- 有限读取并发保持上限、配对、原顺序和取消语义。性能只比较受控条件。

确定性检查以脚本化模型驱动实际循环与管线；数据库、浏览器和真实模型分别记录条件。低窗口触发压缩不代表默认窗口下的所有长任务已验证；同任务单次对照也不提供稳定成功率。

## 完成情况与仍需保留的边界

上述机制已经进入现行实现。历史对照支持减少重复规划交接，受控并发支持独立读取的等待优化；后续真实任务仍有重复检查和额外协议声明。截图、缓存、冷启动及产物差异不能混算成统一提速比例。

无跨运行的任务总费用硬预算，无通用副作用重放、任意 worker 迁移或摘要无损保证。这里记录已完成方案及验证入口，新的优化须按实际问题单独授权，不续写旧工作包日志。
