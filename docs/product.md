# RayAgent 产品说明

RayAgent 围绕会话组织任务：目标、输入资料、执行计划、工具记录和产物共同构成一次可查看的工作过程。本文说明用户在界面上能做什么、怎么判断任务是否真的完成。

![RayAgent 产品全景：上下文与记忆、控制与观察、工具与环境、外部协作围绕单循环 Agent](assets/product-overview.svg)

*产品能力与 Harness 职责。中间是一份记忆的单循环：调用工具直到给出答复，`update_plan` 只记录清单、不按清单调度，没有工具调用的回复就是最终答复，事件先落库、页面按序号回看。左侧是上下文（请求前估算容量，越过水位先压缩，超长结果只给预览）和控制（补充、停止、提问，策略可 ask）。右侧是沙箱（ubuntu 执行，并设内存与 CPU 配额；交付之后文件才成为附件）和外部协作（MCP、A2A，策略可 allow、ask 或 deny）。只有控制与观察是双向的。*

本文只讲用户可见的部分，系统内部如何实现不在这里展开。

## 会话与任务

创建会话、发送目标、上传附件，也可以打开历史会话继续交流。上传的文件会同步到沙箱，作为任务可读取的输入。

Agent 收到目标后在同一个过程里调用工具、查看结果、决定下一步，直到给出最终回复。复杂任务会先列出计划清单，并在推进时更新各项状态；计划条在输入框上方，折叠时显示当前项，简单任务可能不列清单。调用工具前 Agent 可能附带一两句说明，作为进展旁白显示在时间线里。缺少必要信息时，Agent 会向用户提问并等待回复，输入框提示回复会继续当前任务。

运行中可以补充要求。输入框在运行期间仍然可以发送，补充的内容会在当前这批工具动作结束后、Agent 下一次思考前读取；正在执行的工具动作不会中断，所以一个长时间运行的命令仍会跑完。停止在运行状态条上，终态事件到达前状态是停止中。

有些工具调用要先经你批准才会执行，默认是 MCP 工具和委派给远程 Agent 的任务，可以在设置的工具策略里调整。需要批准时，时间线出现审批卡，列出要调用的工具和参数，MCP 工具显示服务器名和原始工具名；状态条显示「等待批准」和这次操作。点「批准」或按 Y，只执行这一次，结果写回同一张卡，也可以在工作台查看；点「拒绝」或按 N，这次调用不执行，Agent 收到“用户拒绝执行”后接着做，通常会说明情况或换一种办法。等待批准期间输入框不能发送，提示先批准、拒绝或停止；刷新页面后审批卡仍在，可以继续批准或拒绝。此时停止，这次调用不会执行，审批卡标为已失效，运行显示已停止。

一次会话可以先后进行多次运行。运行过程中发送的内容进入当前这次运行；Agent 正在等你回复时，发送的是回答；这次运行结束后再发送，会开始新的一次运行。失败、停止或中断留下的过程留在会话记录里，再次发送相同内容不会把它们去掉。

## 工具与执行环境

| 能力 | 已有操作 | 运行条件 |
|---|---|---|
| 文件 | 读取、写入、文本替换、内容搜索、文件查找 | 操作沙箱内文件；写入的文件需经交付才成为附件 |
| Shell | 执行命令、读取输出、等待进程、写入输入、终止进程 | 使用沙箱进程环境，权限和依赖取决于镜像 |
| 网页检索 | 按查询词检索并返回网页信息 | 需要搜索适配及目标站点可达 |
| 浏览器 | 导航、查看、点击、输入、按键、选择、滚动、脚本与控制台操作 | 需要沙箱浏览器可连接，目标页面可访问 |
| 计划与交付 | 维护计划清单；把沙箱中的文件交付为消息附件 | 交付的文件必须已写入沙箱 |
| 用户交互 | 提出问题并等待回复 | 由会话消息与任务输入承接 |

侧栏用“对话 / 项目”胶囊切换，默认显示独立对话；项目内对话在项目树中查看。切换标签保留当前页面与草稿，列表使用全部剩余高度。“新对话”进入独立空白输入；项目名称直接打开工作区，新建菜单提供空白项目和从文件夹创建，已归档项目单独管理。打开项目或「在此项目新对话」只导航，发送时才创建会话；已有对话不更换项目归属。当前项目在列表分页之外也会定位到导航顶部。

输入框加号提供计划模式、压缩上下文，回形针直接添加附件；项目名称统一在页面标题区表达归属。斜杠命令提供筛选与短说明，两处共用操作可用性。上下文入口仅显示圆环。悬停一行给出已用百分比和具体数值；点击后每项一行，名称在左、数值在右，包括最近一轮、压缩阈值，以及本会话的输入、输出、缓存命中和命中率。缺少数据时数值为「—」。有效计划运行完成后才提供「按计划执行」。

会话页中间是运行状态、时间线与输入框，右侧工作台按操作显示结果、终端、浏览器或文件。进入会话时工作台关闭，点击入口或记录打开；默认跟随新操作，手动选择后固定。窄屏侧栏和工作台以抽屉呈现。

时间线上的工具记录用动词说明做了什么（例如「读取文件」「运行命令」），完成后不再用进行时。模型收到的工具结果是另一份内容；两者相关，但不是同一份完整数据。开发者视图与对话在同一位置切换，按轮显示用时、输入、输出、缓存命中、命中率、首字延迟、尝试次数、生成速度和上下文构成，并列出压缩预算；点击某轮可在该轮下方展开或收起实际发给模型的消息。事件流可按类型筛选、展开原文并导出运行与事件 JSON；只有真正的压缩事件才标作「上下文压缩」，一般上下文追加与清理会分别显示。

## 项目、文件与记忆

项目文件由平台托管，上传本地副本、下载结果，不回写本地，也没有 Git 或宿主机目录接入。导入审核以可展开文件树显示层级、大小、状态和排除原因，节点详情承载敏感项与覆盖确认，底部汇总与操作保持可见；版本库目录不上传，依赖与敏感文件按规则排除，可选项需明确确认。项目文件页提供目录、预览、单文件与整项目下载；附件和工作区外的交付分别持久化到 uploads 与 outputs，交付副本失败可单独重试。

每次项目运行前保存文件快照，默认保留 5 份，可调 1–7 份。快照读写失败时不开始执行；项目超限则明确显示本次没有快照，作为保护降级例外。恢复整项目前保存当前文件，恢复失败保留占用，提供重试或回到恢复前。归档保留文件与对话，可恢复；归档项目可清理快照，残留对象清理失败可重试。项目没有删除入口。

项目设置包含说明与可编辑笔记。Agent 可以按版本更新笔记，计划模式禁止写笔记；笔记变化有审计记录。自动对话摘要保留来源、截止位置及代次，也可由用户编辑或重生成。每次新运行冻结说明、笔记与近期摘要，等待续接使用原冻结版本；文件恢复只改变文件，不回滚这些记忆。

同项目只允许一个活动运行，等待回复或审批也占用项目。运行中、文件操作中、环境收尾或恢复未完成时禁止新的写入，界面给出所属对话、原因及处理入口。项目被占用时，首次发送被拒绝，不会因此新增一条没有运行的会话。

## 外部工具与远程 Agent

MCP 把外部服务提供的工具接入任务。在设置中添加服务后，可以查看连接状态和发现到的工具，随后让 Agent 在任务中调用它们。

A2A 用于发现远程 Agent 并委派任务，支持提交后的状态查询和结果回传。远程工作的结果回到本地 Agent，参与后续执行。

两种协议都由本地 Agent 循环作为工具使用，默认在执行前要你批准。接入成功不代表支持协议的全部可选能力——需要多轮交互或协议层额外授权的调用当前会按失败返回。

设置页分为通用、外观、模型提供商、MCP 服务器、远程 Agent 和工具策略。外观可跟随系统或选浅色、深色，只保存在当前浏览器。通用设置与模型接口地址保存在 API 的配置文件里，对所有会话生效。已知模型各自保存温度、单次回复上限和上下文窗口；对话第一次运行时记下这三项，之后改设置只影响新建对话。在一条对话里改用另一个模型时，下一次新运行使用那个模型当时保存的数值。MCP 与远程 Agent 列表显示启用状态和配置摘要。工具策略给每类工具选「直接执行」「执行前询问」或「禁止」：所有 MCP 工具、所有远程 Agent、单个 MCP 服务器或远程 Agent、内置的文件、终端、浏览器、检索与交付各一行，也可以按单个函数或 MCP 工具加规则；越具体的规则优先，没有规则的调用直接执行，「恢复默认」回到 MCP 与远程 Agent 询问、其余直接执行。计划与提问不受策略约束。策略保存在 API 的配置文件里，从下一次执行起生效，包括批准或回复后的继续执行。被禁止的调用不执行，时间线标明是工具策略禁止的。模型凭据的填写位置和生效方式属于部署事项，不在本文展开。

## 观察、历史与交付

执行或等待时，输入框上方只显示用时和轮次；当前一句写在时间线末尾。完成或停止后状态行收起，标题旁显示终态。失败或中断的原因只留在时间线终态条。顶部不显示累计 tokens 或速度。本会话的输入、输出、缓存命中和命中率在上下文环的点击面板；每一轮的这四项、生成速度，以及可用输入上限、输出预留、安全余量和快照时间在开发者视图。运行汇总仍显示合计 tokens。模型正在写出可见文本时，时间线末尾逐步增长；开发者视图中，轮次速度在有用量与首字延迟时由 completion tokens 和生成耗时计算，推理 token 有值时先扣除。时间线展示消息、工具、提问、交付、失败尝试和终态。模型请求中断、空回复或被拒绝时，时间线说明原因；用户停止显示「已停止」，不会写成已经达到重试上限。上下文环优先使用最近请求的实测输入，没有可比值时显示估算或原因；手动压缩具有独立的处理中与失败提示。打开或刷新会话会先取回已保存的记录，再接上之后的新事件，已经看过的不会重复出现。还没保存的半截文本不会在刷新或断线之后留下来。用量来自每一轮结束时的记录。

会话列表显示已保存的标题和时间；首次消息后异步生成一次简短标题，列表菜单和会话顶部都可手动重命名，也可请求 AI 标题建议，建议须保存才生效。选中项用弱底和稍重的字重。运行中、压缩中、等你回复、等你批准、失败和已中断写在标题右侧；列表还不知道是回复还是批准时写「等你」。尚无运行、已完成和已停止不写状态；尚无运行的可访问名称只有标题，已完成和已停止仍带状态。正在查看的会话，状态跟着这次运行更新：再发消息时先标成运行中，发送失败或还没有运行时回到时间，结束后不再停在「运行中」。状态行只在执行和等待时显示用时与轮次。项目行和对话行分别显示占用与运行结果，等你回复和等你批准都留着处理入口。

Agent 通过交付工具把指定的沙箱文件上传为消息附件；只写入沙箱而没有交付的文件不会出现在附件里。交付出现在时间线上，也可以在工作台的文件页预览和下载，支持情况取决于文件类型。

## 怎么判断任务真的完成了

界面上的"结束"有几种不同含义，需要分开看：Agent 在等待回复或批准、任务正常完成、执行失败、用户主动停止、进程重启导致中断，都会让页面停止更新。会话状态分别是 waiting、completed、failed、cancelled、interrupted。completed 只表示循环正常结束，不表示目标达成。

建议按下面三步确认：

1. **看回复。** Agent 的最终回复说明了它认为做了什么，但这是它的陈述，不是证据。
2. **看工具记录。** 声称写入的文件是否有对应的工具调用记录，调用是否成功。
3. **看产物。** 需要取得成果时，确认消息里的附件能打开或下载。Agent 提到某个文件路径不等于交付完成。

还有几点值得提前知道：请求停止不会回滚已经产生的文件修改，也不保证远程任务同步结束；本次运行里已经启动的 Shell 会话会收到终止请求，进程组里的子进程也会被结束，但正在执行的那次工具调用可能没有完成记录。再次发送不会清掉上一次失败的工具记录和错误，刷新页面也不会把同一段过程显示两遍。独立对话的沙箱按会话复用；项目运行终态后停止项目沙箱，确认旧写入者静止后才释放文件操作占用。API 重启后，当时还在运行的任务标为中断，状态条与时间线显示「服务重启导致运行中断」；等待回复的任务可以继续，等待批准的任务同样标为中断，审批卡失效，需要重新发送任务。工具策略只决定某个工具能否执行、要不要先问你，不看参数内容，也不限制沙箱里能访问的路径和网络。计划清单全部勾选不等于目标达成，系统目前没有独立的成果验收机制，完整边界见[能力与边界](capabilities.md)。
