# 能力与边界

本文记录 RayAgent 当前实现到了什么程度：哪些能力已经可用，哪些只搭了骨架，哪些完全没有，以及每条结论依据什么证据。其他文档在介绍机制时不再逐句设防，边界统一在这里查。

核对日期 2026-09-16，基线为当前工作副本；运行观察的证据来自 [2026-09-14 的 Harness 能力评估](research/harness-capability-review-2026-09-14.md)。判断一项能力能否用于某个场景时，请同时看结论和证据类型。

## 证据类型

| 标记 | 含义 |
|---|---|
| 代码核对 | 读源码确认逻辑，未运行 |
| 本地测试 | 有测试用例覆盖该行为，使用替身而非真实模型或环境 |
| 运行观察 | 有带日期的实际运行记录 |
| 未验证 | 既没有测试覆盖，也没有运行记录 |

"代码里存在某个工具"不等于"这个工具在任务里组合使用时可靠"。下面的三态分级针对的是后者。

## 已具备

| 能力 | 说明 | 证据 |
|---|---|---|
| Plan + ReAct 双层编排 | 外层计划调度与内层工具循环分离，步骤边界交接明确 | 代码核对、本地测试、2026-09-14 运行观察 |
| 假完成守卫 | 识别声称完成但没有对应工具记录的步骤，置为失败 | 代码核对、本地测试 |
| 内置工具集 | 文件读写查找、Shell 执行与进程管理、网页检索、浏览器操作 | 代码核对；文件与 Shell 有 2026-09-14 运行观察 |
| 沙箱执行环境 | 动态创建容器或连接已有地址，文件、终端、浏览器在同一环境内 | 代码核对、2026-09-14 运行观察 |
| 文件同步与附件交付 | 上传同步到沙箱，文件工具事件与消息附件两处触发同步 | 代码核对、本地测试、2026-09-14 运行观察 |
| 事件流与历史回放 | 计划、步骤、工具、用量事件实时推送并保存，刷新后可重看 | 代码核对、本地测试、2026-09-14 运行观察 |
| 状态分层与持久化 | 会话、记忆、事件历史、文件元数据各有明确归属 | 代码核对、本地测试 |
| MCP 工具接入 | 发现、别名路由、调用、错误分类、超时分层、结果截断 | 代码核对、本地测试、labs 可复现 |
| A2A 远程委派 | 能力卡片读取、消息委派、Task 轮询、取消尝试 | 代码核对、本地测试、labs 可复现 |
| 协程级取消 | 停止请求能取消执行协程并写入终态事件 | 代码核对、本地测试 |

## 已具备但较浅

这些能力能跑通主路径，但缺少让它们在压力下仍然成立的机制。

| 能力 | 当前做法 | 缺什么 |
|---|---|---|
| 上下文清理 | `compact()` 按工具类型定点裁剪浏览器正文、删除推理字段 | 不按 token 预算触发，未命中的长结果仍会累积，裁掉的内容不可还原 |
| 重试 | 模型调用与工具调用各重试固定次数 | 不区分可重试与不可重试错误，重试不携带幂等保护 |
| 超时 | 连接、发现、调用、请求各有独立超时 | 没有跨调用的任务总预算，超时后远程副作用状态未知 |
| 结构化输出 | 规划阶段用 `json_object` 并禁用工具 | 解析失败直接终止流程，没有约束修复重试 |
| 可观测性 | 事件类型齐全，实时流与历史一致 | 没有 trace/span，没有贯穿一轮的关联 ID，时间戳取整到秒 |
| 跨进程控制 | 单进程内任务注册表与协程管理 | 多实例部署时停止请求可能落到没有该任务的进程上并静默失败（未验证） |
| 动作授权 | 系统提示要求敏感操作前确认 | 没有执行前的审批闸门，提示词是约定不是技术约束 |

## 尚未具备

| 缺口 | 影响 |
|---|---|
| 流式输出与增量 `tool_calls` 拼装 | 模型生成期间页面没有增量内容，首字延迟等于整次响应耗时 |
| 并行工具调用 | 请求层关闭并行，执行层每轮只取一条调用，互不依赖的动作只能串行 |
| Context 预算 | `context_window` 只用于展示，没有基于预算的裁剪或拒绝 |
| 幂等键与请求去重 | 响应丢失后重试可能重复产生副作用 |
| 步骤级检查点与执行恢复 | 进程重启后不能从中断处继续，只能重新开始 |
| 跨进程执行所有权 | 没有会话级认领或租约，多实例下的归属未定义 |
| 独立的目标验收 | 计划完成和 Agent 总结不能替代成果验收，没有通用检查系统 |
| 长期项目工作区 | 任务以会话为单位，没有跨会话的项目、基线或变更集模型 |
| 沙箱资源配额与权限策略 | 创建容器时未设 CPU/内存上限，工作目录只解释相对路径，不构成访问围栏 |
| MCP 多轮交互与凭据 | 不支持 `input_required` 续接，不订阅工具列表变化，不支持完整 OAuth |
| A2A 多轮交互与产物落地 | 不支持 `input_required`/`auth_required` 续接，远程产物不会自动成为可下载附件 |

## 已知不一致

以下是代码核对中发现的、当前实现与配置或说明不吻合的地方。

**沙箱存活时间的环境变量命名不一致。** API 在创建容器时注入 `SERVICE_TIMEOUT_MINUTES`，沙箱服务读取的是 `SERVER_TIMEOUT_MINUTES`。两侧默认值都是 60 分钟，所以默认行为一致，但修改 API 侧的 `sandbox_ttl_minutes` 不会改变沙箱的实际存活时间。

**沙箱服务的执行身份与提示描述不一致。** 镜像创建了 `ubuntu` 用户并把工作目录放在 `/home/ubuntu`，但没有切换执行身份，服务以 root 运行。涉及权限的行为判断应以实际身份为准。

## 未验证的范围

下列行为既没有测试覆盖，也没有运行记录，不应假定它们可用：

- SSE 连接中断后的重连与补齐
- 多 worker 部署下的并发竞争、重复提交与停止投递
- API 进程崩溃后的任务恢复与资源回收
- 沙箱 TTL 自动到期回收、容器异常退出后的清理、进程树回收
- 容器逃逸、多用户隔离、资源耗尽场景
- 沙箱公网出口、DNS 与受限网络条件
- 完整的浏览器端到端任务
- 接真实模型的 MCP / A2A 完整 Web 任务
- 大文件、并发文件操作、沙箱销毁后的历史附件下载
