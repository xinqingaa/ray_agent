# 能力与边界

本文记录 RayAgent 当前实现到了什么程度：哪些能力已经可用，哪些只搭了骨架，哪些完全没有，以及每条结论依据什么证据。其他文档在介绍机制时不再逐句设防，边界统一在这里查。

核对日期 2026-10-02。证据类型见下表：代码核对以当日源码为准；本地测试指仓库内用例（含 ScriptedLLM 与临时 PostgreSQL）；运行观察指[总计划第 6 节](plan/README.md#6-证据记录)所引评测报告与带日期的浏览器走查。W0–W8 的结论已写入下列条目；各包当次报告与走查截图在 Git 提交 `2e68aa3`，当前证据目录只保留总计划第 6 节列出的最终材料。W9–W11 的当前验收见[W9–W11 最终验收](plan/evidence/w9-w11-acceptance-2026-10-02.md)，文件保护专项见[W11 文件保护验证](plan/evidence/w11-file-safety-2026-10-02.md)。2026-09-14 的运行观察仍只作为历史记录，见[背景说明](background/README.md#能力评估的真实任务记录)。判断一项能力能否用于某个场景时，请同时看结论和证据类型。

## 证据类型

| 标记 | 含义 |
|---|---|
| 代码核对 | 读源码确认逻辑，未运行 |
| 本地测试 | 有测试用例覆盖该行为，使用替身而非真实模型或环境 |
| 运行观察 | 有带日期的实际运行记录 |
| 未验证 | 既没有测试覆盖，也没有运行记录 |

"代码里存在某个工具"不等于"这个工具在任务里组合使用时可靠"。下面的三态分级针对的是后者。

## 已具备但较浅

这些能力能跑通主路径，但缺少让它们在压力下仍然成立的机制。

| 能力 | 当前做法 | 缺什么 |
|---|---|---|
| 计划清单 | 模型调用 `update_plan` 维护清单，页面展示进度 | 只记录不调度，不校验与实际执行是否一致；模型可能不写或不及时更新 |
| 上下文治理 | 每轮请求前按上次 `prompt_tokens` 加字符估算检查容量，四部分构成随 `turn(started)` 记录；超过水位时自动压缩：较早轮次交给独立摘要请求，用户原文重新注入，保留区与调用配对不拆开；压缩失败或仍放不下以 `context_limit` 失败；服务端超长拒绝时先压缩一次再重试。单条结果超过 8,000 字符时完整内容写入沙箱文件，模型收到首尾预览与路径。证据：代码核对、本地测试（ScriptedLLM 与临时 PostgreSQL）；2026-09-28 W2 评测（Git 提交 `2e68aa3` 中的 `w2-2026-09-28-c0822dc`）E7 在 `context_window` 调低到 24576 时压缩 2 次、约束与 12 个校验码全部保留；同日手动会话 `seq 1 6000` 的结果被整形，模型按路径读回末行 | 估算是字符系数近似，没有分词器，只在有 usage 后校准；摘要质量依赖模型，细节会丢失，只有用户原文保证逐字保留。压缩只在请求前或服务端拒绝后触发，单轮内一次返回的多个大结果不会被拆开，保留区本身过大时只能以 `context_limit` 失败。服务端超长拒绝的识别按错误信息关键字，只覆盖 OpenAI 兼容客户端，没有真实拒绝的运行记录。E7 只跑 1 次。配置默认窗口为 131072；已知模型可以各自配置，实际取该模型配置与目录上限中的较小值。对话第一次运行时记下窗口、输出预留和温度，之后改设置不影响这条对话；还没有这三项的旧对话继续用上次运行快照里的窗口。该默认下的长任务压缩没有运行记录 |
| 重试与截断 | 只对模型请求的传输类错误与空回复重试，每次尝试计入单次运行的请求上限；输出被长度截断时丢弃并提示缩短，重试一次 | 可重试判定只覆盖 OpenAI 兼容客户端的错误类型；工具不重试，模型再次调用同一工具时没有幂等保护 |
| 超时 | 连接、发现、调用、请求各有独立超时 | 没有跨运行的任务总预算与 token 计费预算（上下文容量只按单次请求检查），超时后远程副作用状态未知 |
| 工具参数校验 | 参数 JSON 严格解析，按工具声明校验必填字段、顶层类型与枚举，失败回填模型 | 不校验嵌套结构与格式约束，不做 JSON 修复 |
| 可观测性 | 事件带会话内序号、运行 ID 与毫秒时间；每轮有成对的轮次事件（耗时、尝试次数、用量，流式时还有首字延迟）；失败的模型请求另有 `attempt` 事件。开发者视图只显示已结束轮次的生成速度：有 `completion_tokens` 与 `ttft_ms` 且 `model_ms` 更大时用公式，并在有 `reasoning_tokens` 时从分子扣除；缺少用量时按字符估算并标明估算 | 没有 trace/span。`attempts > 1` 时 `model_ms` 含失败尝试，速度偏小；推理 token 已从分子扣除，但首字之前的等待仍留在分母里 |
| 流式模型响应 | 默认按流式分片组装完整 message、`finish_reason` 与 usage，文本增量经 Redis 推给当前 SSE，不落库、无序号。会话页按 `(run_id, turn, attempt)` 把增量拼成时间线末尾的临时旁白，同一 attempt 的助手消息到达后替换它；更大 attempt、另一轮、该轮结束但没有对应助手消息、运行终态、刷新或重连时丢掉临时文本。推理分片进入最终消息，不推给页面、不计首字。流在结束原因前断开时重试，不执行工具、不进入模型历史。`turn(completed).ttft_ms` 是产出本次响应那次请求的首字延迟，非流式为空。`streaming` 与 `request_timeout` 只写在 `config.yaml`，设置页保存不会改它们。证据：代码核对、本地测试（伪造的模型流与 ScriptedLLM）、前端观察脚本（`ray_agent/ui` 下 `node scripts/check-event-observability.cjs`，2026-09-29 通过）。2026-09-29 对配置中的 `deepseek-flash` 做了一次流式请求：27 个分片里 24 个是推理分片（不进入增量回调），可见文本 1 片，`finish_reason=stop`，末片 usage 含 `prompt_tokens` 与 `reasoning_tokens`，`stream_options` 被接受 | 供应商不返回 usage 时，容量估算保留上一次的 `prompt_tokens`；从未收到过才全部按字符估算，页面速度也只标估算。`model_ms` 含失败尝试的耗时；公式已扣除 `reasoning_tokens`，但首字之前的等待仍在分母里，不要把结果当成可见文本的瞬时速度。增量通知丢失不补发，半截文本刷新后不在 |
| 跨进程控制 | 单进程内任务注册表、会话锁与协程管理 | 多实例时停止请求可能落到没有该任务的进程：运行会被写成 cancelled，但执行协程和已登记的 Shell 会话留在另一个进程（未验证） |
| 动作授权 | 工具管线执行前按应用配置的工具策略表授权：规则键为函数名、`<工具集>:*`、`mcp:<服务>:<工具>` / `mcp:<服务>:*` / `mcp:*`、`a2a:<id>:*` / `a2a:*`，越具体越优先，未命中为 allow；默认 `mcp:*` 与 `a2a:*` 为 ask。deny 回填“策略禁止”；ask 发出审批事件、运行进入等待（原因 `approval`），批准执行该调用一次，拒绝回填“用户拒绝执行”（`denied_by=user`）。计划与提问不受约束。会话页审批卡接入批准与拒绝，设置页工具策略分区读写整表。证据：代码核对；本地测试（ScriptedLLM：挂起、批准、拒绝、同批补结果、重复答复 409、deny、启动扫描）；前端观察脚本的审批投影用例（2026-09-29 通过）；2026-09-29 W7.2 评测（Git 提交 `2e68aa3` 中的 `w7-2026-09-29-b2d83c5`）E6 先 pending 再 approved，得到 6912；E6-deny 在该报告中因资源紧张请求超时，同日单独复跑通过（pending → rejected，add 结束事件为 `denied_by=user`，夹具没收到 add，运行正常结束，报告写在临时目录未入库）。同日 Playwright 走查 MCP 夹具：批准后得到 6912；拒绝后 Agent 说明被拒并改用 Shell 计算，夹具只收到批准那一次 add；刷新后审批卡仍可操作；设置页把 `mcp:w0eval:*` 改为禁止并保存，接口与刷新后的页面一致 | 策略只按工具判断，不看参数内容，不构成沙箱内的路径或网络围栏；内置工具默认直接执行，系统提示里的“敏感操作前确认”仍只是约定。批准只对一次调用有效，没有“本会话一直允许”。等待审批时 API 重启不续接，需要重新发起。A2A 的审批没有接真实远程 Agent 运行；策略禁止的调用与内置工具 ask 只有本地测试和观察脚本，没有浏览器走查 |
| 沙箱配额与执行身份 | 动态容器创建时设置内存 2048 MiB（swap 不超过该值）、2 CPU、512 个进程；存活时间由 `SANDBOX_TTL_MINUTES` 注入为沙箱读取的 `SERVER_TIMEOUT_MINUTES`。Supervisor 管理的服务进程以用户 ubuntu 运行，HOME 与工作目录为 `/home/ubuntu`，需要 root 时用免密 sudo。上传目录与 `/home/ubuntu/.rayagent/outputs` 由该用户写入。长命令约 5 秒返回 running。证据：代码核对；沙箱 `ShellService` 测试；2026-09-28 在 API 容器内跑检查脚本（用户 ubuntu，目录属主 ubuntu，内存与 swap 均为 2147483648 字节，NanoCpus 2000000000，PidsLimit 512，`SERVER_TIMEOUT_MINUTES=60`，超时计时处于活动）。同日 E4 容器的 HostConfig 与此一致 | 不是多租户隔离，没有网络出站过滤；工作目录不构成访问围栏；supervisord 主进程仍是 root；已有沙箱地址模式不套用限额。TTL 只确认计时按配置启动，没有等到容器真正销毁；多数 API 请求会把剩余时间再延长 3 分钟，所以检查时的剩余秒数可以大于 60 分钟 |

## 尚未具备

| 缺口 | 影响 |
|---|---|
| 并行工具调用 | 一次回复的多个调用全部执行但严格串行，请求层仍设置 `parallel_tool_calls=False`；互不依赖的动作不能并发 |
| 幂等键与请求去重 | 响应丢失后重试可能重复产生副作用 |
| 检查点与执行恢复 | 进程重启后不能从中断处继续执行，只能把遗留的 `running` 和等待审批标成 `interrupted` 后重新开始；等待提问的 `waiting` 可以续接。等待审批在同一事务里把挂起调用补为未执行。崩溃前已在沙箱中的进程不会被启动扫描终止 |
| 跨进程执行所有权 | 没有会话级认领或租约，多实例下的归属未定义 |
| 独立的目标验收 | 最终答复与计划清单都是模型的陈述；旧版的假完成守卫已随步骤结构删除，没有程序侧替代，也没有通用检查系统 |
| 按运行归集的变更集 | 项目具有运行前快照与整项目恢复，但没有按运行归集的 diff/变更集；不做 Git 或 worktree |
| 路径访问围栏 | 工作目录只解释相对路径，不限制沙箱内可读写的位置 |
| MCP 多轮交互与凭据 | 不支持 `input_required` 续接，不订阅工具列表变化，不支持完整 OAuth |
| A2A 多轮交互与产物落地 | 不支持 `input_required`/`auth_required` 续接，远程产物不会自动成为可下载附件 |

## 已知不一致

以下是代码核对中发现的、当前实现与配置或说明不吻合的地方。

**停止时正在执行的工具没有配对的 `called` 事件。** 停止取消执行协程，当前工具只留下 `calling` 事件（2026-09-28 评测 E4：1 次只有 calling）。会话投影在运行进入终态后把仍为 calling 的调用标成已取消。2026-09-29 在状态条为「执行工具」时停止 `sleep 45`，工具卡显示「已取消：运行被停止」，终态为「你停止了这次运行」。Shell 进程本身会被终止（2026-09-28 同次 E4 记录终止成功，停止后标记不再增长）。模型侧不受影响：下一次运行开始时该调用补为"执行中断，结果未知"。

**运行器启动后基础设施不可达时，会话可能停在 pending。** 2026-09-28 Docker 资源耗尽、API 容器暂时无法解析 Redis 地址时，一个新会话只保存了用户消息，状态停在 pending，页面一直显示思考中；清理资源后新会话正常。2026-09-29 W7 评测时 Docker 虚拟机里积压了 21 个动态沙箱（每个约 300 MiB，虚拟机共约 8 GiB），创建会话用了约 72 秒，评测客户端的请求超时，留下一个没有消息的 pending 会话，侧栏一直标「运行中」；清掉空闲沙箱后单独复跑同一任务 15 秒完成。该路径没有测试覆盖。

**开发库里若仍有 `context.op` 为旧值 `compact` 的事件，当前读取不会把它当成 `strip_reasoning`。** W2 曾为共用开发库保留这条兼容，总计划记为收口时删除。当前 `ContextOp` 只有 `append`、`strip_reasoning`、`replace`。新写入的事件不受影响。本次未清库、未改代码。

### 各包记录、后续条目尚未关闭

- 沙箱 TTL 到期后容器是否销毁。W0 与 W7.1/W7.3 的检查脚本只确认 `SERVER_TIMEOUT_MINUTES` 与超时计时已启动，多数 API 请求还会把剩余时间延长 3 分钟
