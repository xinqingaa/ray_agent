# 能力与边界

本文记录 RayAgent 当前实现到了什么程度：哪些能力已经可用，哪些只搭了骨架，哪些完全没有，以及每条结论依据什么证据。其他文档在介绍机制时不再逐句设防，边界统一在这里查。

核对日期 2026-09-16，基线为当时工作副本；运行观察的证据已归入[背景中的 2026-09-14 记录](background/README.md#能力评估的真实任务记录)。执行内核、工具调用、文件交付、重试与上下文清理相关条目于 2026-09-28 按 W1 单循环实现更新，运行证据为 [W1 评测报告](plan/evidence/w1-2026-09-28-9faa304.md)与同日真实 Web 走查截图（`plan/evidence/w1-2026-09-28-web-*.png`）。上下文治理（容量检查、自动压缩、结果整形）与 MCP 截断条目同日按 W2 更新，运行证据为 [W2 评测报告](plan/evidence/w2-2026-09-28-c0822dc.md)。运行与事件事实源、停止传播和启动扫描同日按 W3 更新，运行证据为 [W3 评测报告](plan/evidence/w3-2026-09-28-8511bdf.md)与手动重启观察（运行中刷新后为 interrupted，等待中回复可续接）。界面条目于 2026-09-29 按 W5 阶段二更新：会话页消费视图模型，工作台、开发者视图、会话列表与首页已重组；设置页仍是此前的分区。证据为同日 Playwright 走查截图（`plan/evidence/w5-2-2026-09-29-*.png`）。前端订阅、按序号去重与投影于 2026-09-28 按 W4 更新，观察脚本仍通过；浏览器里刷新不重复只在任务刚开始、仅有 2 条事件时核对过，运行中断网后的事件补齐没有观察到。沙箱配额、执行身份、Shell 初次返回与进程组终止同日按 W7.1、W7.3 更新。流式组装、文本增量通道、首字延迟、失败尝试与会话页的增量渲染、生成速度于 2026-09-29 按 W6 更新。浏览器走查条件见运行视图一行。二次开发计划不代表其余能力已改变；实现与验证完成后再更新本表。判断一项能力能否用于某个场景时，请同时看结论和证据类型。

## 证据类型

| 标记 | 含义 |
|---|---|
| 代码核对 | 读源码确认逻辑，未运行 |
| 本地测试 | 有测试用例覆盖该行为，使用替身而非真实模型或环境 |
| 运行观察 | 有带日期的实际运行记录 |
| 未验证 | 既没有测试覆盖，也没有运行记录 |

"代码里存在某个工具"不等于"这个工具在任务里组合使用时可靠"。下面的三态分级针对的是后者。

| A2A 远程委派 | 能力卡片读取、消息委派、Task 轮询、取消尝试 | 代码核对、本地测试、labs 可复现 |

## 已具备但较浅

这些能力能跑通主路径，但缺少让它们在压力下仍然成立的机制。

| 能力 | 当前做法 | 缺什么 |
|---|---|---|
| 计划清单 | 模型调用 `update_plan` 维护清单，页面展示进度 | 只记录不调度，不校验与实际执行是否一致；模型可能不写或不及时更新 |
| 上下文治理 | 每轮请求前按上次 `prompt_tokens` 加字符估算检查容量，四部分构成随 `turn(started)` 记录；超过水位时自动压缩：较早轮次交给独立摘要请求，用户原文重新注入，保留区与调用配对不拆开；压缩失败或仍放不下以 `context_limit` 失败；服务端超长拒绝时先压缩一次再重试。单条结果超过 8,000 字符时完整内容写入沙箱文件，模型收到首尾预览与路径。证据：代码核对、本地测试（ScriptedLLM 与临时 PostgreSQL）；2026-09-28 [W2 评测](plan/evidence/w2-2026-09-28-c0822dc.md) E7 在 `context_window` 调低到 24576 时压缩 2 次、约束与 12 个校验码全部保留；同日手动会话 `seq 1 6000` 的结果被整形，模型按路径读回末行 | 估算是字符系数近似，没有分词器，只在有 usage 后校准；摘要质量依赖模型，细节会丢失，只有用户原文保证逐字保留。压缩只在请求前或服务端拒绝后触发，单轮内一次返回的多个大结果不会被拆开，保留区本身过大时只能以 `context_limit` 失败。服务端超长拒绝的识别按错误信息关键字，只覆盖 OpenAI 兼容客户端，没有真实拒绝的运行记录。E7 只跑 1 次，默认 65536 窗口下的长任务压缩没有运行记录 |
| 重试与截断 | 只对模型请求的传输类错误与空回复重试，每次尝试计入单次运行的请求上限；输出被长度截断时丢弃并提示缩短，重试一次 | 可重试判定只覆盖 OpenAI 兼容客户端的错误类型；工具不重试，模型再次调用同一工具时没有幂等保护 |
| 超时 | 连接、发现、调用、请求各有独立超时 | 没有跨运行的任务总预算与 token 计费预算（上下文容量只按单次请求检查），超时后远程副作用状态未知 |
| 工具参数校验 | 参数 JSON 严格解析，按工具声明校验必填字段、顶层类型与枚举，失败回填模型 | 不校验嵌套结构与格式约束，不做 JSON 修复 |
| 可观测性 | 事件带会话内序号、运行 ID 与毫秒时间；每轮有成对的轮次事件（耗时、尝试次数、用量，流式时还有首字延迟）；失败的模型请求另有 `attempt` 事件。生成速度由页面计算：运行中按累计字符估算并标明估算，轮次结束后在有 `completion_tokens` 与 `ttft_ms` 且 `model_ms` 更大时用公式，并在有 `reasoning_tokens` 时从分子扣除 | 没有 trace/span。`attempts > 1` 时 `model_ms` 含失败尝试，速度偏小；推理 token 已从分子扣除，但首字之前的等待仍留在分母里 |
| 流式模型响应 | 默认按流式分片组装完整 message、`finish_reason` 与 usage，文本增量经 Redis 推给当前 SSE，不落库、无序号。会话页按 `(run_id, turn, attempt)` 把增量拼成时间线末尾的临时旁白，同一 attempt 的助手消息到达后替换它；更大 attempt、另一轮、该轮结束但没有对应助手消息、运行终态、刷新或重连时丢掉临时文本。推理分片进入最终消息，不推给页面、不计首字。流在结束原因前断开时重试，不执行工具、不进入模型历史。`turn(completed).ttft_ms` 是产出本次响应那次请求的首字延迟，非流式为空。`streaming` 与 `request_timeout` 只写在 `config.yaml`，设置页保存不会改它们。证据：代码核对、本地测试（伪造的模型流与 ScriptedLLM）、前端观察脚本（`ray_agent/ui` 下 `node scripts/check-event-observability.cjs`，2026-09-29 通过）。2026-09-29 对配置中的 `deepseek-flash` 做了一次流式请求：27 个分片里 24 个是推理分片（不进入增量回调），可见文本 1 片，`finish_reason=stop`，末片 usage 含 `prompt_tokens` 与 `reasoning_tokens`，`stream_options` 被接受 | 供应商不返回 usage 时，容量估算保留上一次的 `prompt_tokens`；从未收到过才全部按字符估算，页面速度也只标估算。`model_ms` 含失败尝试的耗时；公式已扣除 `reasoning_tokens`，但首字之前的等待仍在分母里，不要把结果当成可见文本的瞬时速度。增量通知丢失不补发，半截文本刷新后不在 |
| 跨进程控制 | 单进程内任务注册表、会话锁与协程管理 | 多实例时停止请求可能落到没有该任务的进程：运行会被写成 cancelled，但执行协程和已登记的 Shell 会话留在另一个进程（未验证） |
| 动作授权 | 系统提示要求敏感操作前确认 | 没有执行前的审批闸门，提示词是约定不是技术约束。界面已有审批卡和设置页工具策略分区的位置，接口与策略内容未接（W7.2） |
| 沙箱配额与执行身份 | 动态容器创建时设置内存 2048 MiB（swap 不超过该值）、2 CPU、512 个进程；存活时间由 `SANDBOX_TTL_MINUTES` 注入为沙箱读取的 `SERVER_TIMEOUT_MINUTES`。Supervisor 管理的服务进程以用户 ubuntu 运行，HOME 与工作目录为 `/home/ubuntu`，需要 root 时用免密 sudo。上传目录与 `/home/ubuntu/.rayagent/outputs` 由该用户写入。长命令约 5 秒返回 running。证据：代码核对；沙箱 `ShellService` 测试；2026-09-28 在 API 容器内跑检查脚本（用户 ubuntu，目录属主 ubuntu，内存与 swap 均为 2147483648 字节，NanoCpus 2000000000，PidsLimit 512，`SERVER_TIMEOUT_MINUTES=60`，超时计时处于活动）。同日 E4 容器的 HostConfig 与此一致 | 不是多租户隔离，没有网络出站过滤；工作目录不构成访问围栏；supervisord 主进程仍是 root；已有沙箱地址模式不套用限额。TTL 只确认计时按配置启动，没有等到容器真正销毁；多数 API 请求会把剩余时间再延长 3 分钟，所以检查时的剩余秒数可以大于 60 分钟 |
| 运行视图 | 会话页消费 `view`：状态条、计划条、时间线、输入框与上下文环；工作台跟随最新工具（终端、浏览器、文件）；开发者视图按轮显示上下文构成，并可读取重建请求。工具完成后用动词，不再显示「正在…」。等待回复的会话在侧栏是「等你回复」，不是加载图标。证据：代码核对；2026-09-29 在 `http://localhost:8088` 用 Playwright 走查真实模型（E2 上传 CSV 并下载 `summary.json`、E3 提问、E4 在执行工具时停止、多工具任务与计划条 3/3、暗色、约 390px 窄屏），截图 `plan/evidence/w5-2-2026-09-29-*.png`。同日补看 W6：长文生成中两帧文本变长且状态条为「速度（估算）」；停止后临时文本消失，时间线为「第 1 次请求已停止」，侧栏不再标「运行中」；生成中刷新后，刷新前的半截开头不在页面上；执行工具时断网 8 秒，恢复后事件序号 1–23 连续且不重复（断网前 9 条都在）；E3 回复后到达「已完成」并出现交付文件；工作台在「已固定查看」时点「回到最新」，文案变为「正在跟随最新操作」。开发者视图轮次行有首字延迟、尝试次数和速度。截图 `plan/evidence/w6-2026-09-29-*.png`。组件状态目录仍用夹具 | 没有做浏览器对比度自动检查。设置页保存与校验没有逐项操作。「停止中」文案没有单独截到。刷新不重复只覆盖任务开头的 2 条事件。API 重启后的中断文案未在浏览器里核对。生成中刷新并重连后，新到的文本片段会再出现在临时条目里，不会把刷新前已经看到的开头补回来。断网那一次，工作台终端在恢复事件后仍显示「网络连接失败」，没有再等它自己刷新 |
| 设置页 | 通用、模型提供商、MCP、远程 Agent 四个分区，带字段说明、草稿、保存结果和未保存离开提示；工具策略分区是占位。证据：代码核对；2026-09-28 浅色、暗色与约 390px 窄屏截图（`plan/evidence/w5-2026-09-28-settings-*.png`） | 四个分区的保存、校验和错误提示没有逐项操作。窄屏只保证分区可切换，没有单独的移动端布局 |

## 尚未具备

| 缺口 | 影响 |
|---|---|
| 并行工具调用 | 一次回复的多个调用全部执行但严格串行，请求层仍设置 `parallel_tool_calls=False`；互不依赖的动作不能并发 |
| 幂等键与请求去重 | 响应丢失后重试可能重复产生副作用 |
| 检查点与执行恢复 | 进程重启后不能从中断处继续执行，只能把遗留的 `running` 标成 `interrupted` 后重新开始；`waiting` 可以续接。续接时只补齐悬空调用的结果。崩溃前已在沙箱中的进程不会被启动扫描终止 |
| 跨进程执行所有权 | 没有会话级认领或租约，多实例下的归属未定义 |
| 独立的目标验收 | 最终答复与计划清单都是模型的陈述；旧版的假完成守卫已随步骤结构删除，没有程序侧替代，也没有通用检查系统 |
| 长期项目工作区 | 任务以会话为单位，没有跨会话的项目、基线或变更集模型 |
| 路径访问围栏 | 工作目录只解释相对路径，不限制沙箱内可读写的位置 |
| MCP 多轮交互与凭据 | 不支持 `input_required` 续接，不订阅工具列表变化，不支持完整 OAuth |
| A2A 多轮交互与产物落地 | 不支持 `input_required`/`auth_required` 续接，远程产物不会自动成为可下载附件 |

## 已知不一致

以下是代码核对中发现的、当前实现与配置或说明不吻合的地方。

**停止时正在执行的工具没有配对的 `called` 事件。** 停止取消执行协程，当前工具只留下 `calling` 事件（2026-09-28 评测 E4：1 次只有 calling）。会话投影在运行进入终态后把仍为 calling 的调用标成已取消。2026-09-29 在状态条为「执行工具」时停止 `sleep 45`，工具卡显示「已取消：运行被停止」，终态为「你停止了这次运行」。Shell 进程本身会被终止（2026-09-28 同次 E4 记录终止成功，停止后标记不再增长）。模型侧不受影响：下一次运行开始时该调用补为"执行中断，结果未知"。

**运行器启动后基础设施不可达时，会话可能停在 pending。** 2026-09-28 Docker 资源耗尽、API 容器暂时无法解析 Redis 地址时，一个新会话只保存了用户消息，状态停在 pending，页面一直显示思考中；清理资源后新会话正常。该路径没有测试覆盖。

## 未验证的范围

下列行为不应假定可用。条目本身没有完整验证；括号里写明已经覆盖的那一部分。

- 浏览器里运行中断开网络后，页面是否补齐期间新产生的事件（观察脚本覆盖去重与重连等待；2026-09-28 用 curl 核对过按序号补齐。2026-09-29 一次在任务已经结束后断网，50 条序号不丢不重，但没有新事件可补；另一次任务在进入工具阶段前就结束。运行中的断网补齐仍未观察到）
- 多 worker 部署下的并发竞争、重复提交与停止投递
- API 进程崩溃后沙箱里已启动进程的回收（启动扫描只改运行状态；`waiting` 续接已有手动观察）
- 沙箱 TTL 自动到期回收（检查脚本确认环境变量与超时计时已按配置启动，没有等到容器真正销毁）、容器异常退出后的清理
- 容器逃逸、多用户隔离、资源耗尽场景
- 沙箱公网出口、DNS 与受限网络条件
- 完整的浏览器端到端任务
