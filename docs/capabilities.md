# 能力与边界

本文记录 RayAgent 当前实现到了什么程度：哪些能力已经可用，哪些只搭了骨架，哪些完全没有，以及每条结论依据什么证据。其他文档在介绍机制时不再逐句设防，边界统一在这里查。

核对日期 2026-09-16，基线为当时工作副本；运行观察的证据已归入[背景中的 2026-09-14 记录](background/README.md#能力评估的真实任务记录)。执行内核、工具调用、文件交付、重试与上下文清理相关条目于 2026-09-28 按 W1 单循环实现更新，运行证据为 [W1 评测报告](plan/evidence/w1-2026-09-28-9faa304.md)与同日真实 Web 走查截图（`plan/evidence/w1-2026-09-28-web-*.png`）。运行与事件事实源、停止传播和启动扫描同日按 W3 更新，运行证据为 [W3 评测报告](plan/evidence/w3-2026-09-28-8511bdf.md)与手动重启观察（运行中刷新后为 interrupted，等待中回复可续接）。界面条目同日按 W5 阶段一与阶段三更新：运行视图组件只在开发模式目录页用夹具展示，会话页尚未替换；设置页已改为分区。二次开发计划不代表其余能力已改变；实现与验证完成后再更新本表。判断一项能力能否用于某个场景时，请同时看结论和证据类型。

## 证据类型

| 标记 | 含义 |
|---|---|
| 代码核对 | 读源码确认逻辑，未运行 |
| 本地测试 | 有测试用例覆盖该行为，使用替身而非真实模型或环境 |
| 运行观察 | 有带日期的实际运行记录 |
| 未验证 | 既没有测试覆盖，也没有运行记录 |

"代码里存在某个工具"不等于"这个工具在任务里组合使用时可靠"。下面的三态分级针对的是后者。

## 已具备

| 能力 | 说明 | 证据 |
|---|---|---|
| 单循环执行内核 | 一个循环、一份记忆；一次回复的多个调用按顺序执行、按 ID 配对结果；未知工具、非法参数、工具异常都回填为失败结果而不终止；提问续接与停止、失败后补齐悬空调用 | 代码核对、本地测试、2026-09-28 评测 E1–E3、E5、E6 通过与 Web 走查 |
| 内置工具集 | 文件读写查找、Shell 执行与进程管理、网页检索、浏览器操作 | 代码核对；文件与 Shell 有 2026-09-14 运行观察 |
| 沙箱执行环境 | 动态创建容器或连接已有地址，文件、终端、浏览器在同一环境内 | 代码核对、2026-09-14 运行观察 |
| 文件同步与附件交付 | 上传同步到沙箱；交付只经 `deliver_files`：逐个路径校验存在、上传并关联会话，部分失败时返回各路径原因 | 代码核对、本地测试、2026-09-28 评测 E2/E3 与 Web 走查（页面下载附件） |
| 事件流与历史回放 | 事件按会话内序号落在独立表，先提交再通知。计划、消息、工具（含毫秒耗时）、轮次与运行状态经 SSE 按序号补齐，刷新后可重看。用量在轮次完成事件上，不再单独发用量事件 | 代码核对、本地测试、2026-09-28 评测 E1–E6 |
| 状态分层与持久化 | 会话、运行、事件、记忆、文件元数据各有归属；`sessions.status` 是最新运行状态的副本 | 代码核对、本地测试 |
| MCP 工具接入 | 发现、别名路由、调用、错误分类、超时分层、结果截断 | 代码核对、本地测试、labs 可复现 |
| A2A 远程委派 | 能力卡片读取、消息委派、Task 轮询、取消尝试 | 代码核对、本地测试、labs 可复现 |
| 停止与中断 | 停止把运行置为 `cancelled` 并取消协程，再终止本次运行登记的 Shell 会话；API 重启把遗留的 `running` 置为 `interrupted`，`waiting` 可续接 | 代码核对、本地测试、2026-09-28 评测 E4（停止后标记不再增长）与手动重启观察 |

## 已具备但较浅

这些能力能跑通主路径，但缺少让它们在压力下仍然成立的机制。

| 能力 | 当前做法 | 缺什么 |
|---|---|---|
| 计划清单 | 模型调用 `update_plan` 维护清单，页面展示进度 | 只记录不调度，不校验与实际执行是否一致；模型可能不写或不及时更新 |
| 上下文清理 | 每次新用户消息开始运行时，`compact()` 按工具类型定点裁剪此前的浏览器正文、删除推理字段 | 一次运行内不清理，不按 token 预算触发，未命中的长结果仍会累积，裁掉的内容不可还原 |
| 重试与截断 | 只对模型请求的传输类错误与空回复重试，每次尝试计入单次运行的请求上限；输出被长度截断时丢弃并提示缩短，重试一次 | 可重试判定只覆盖 OpenAI 兼容客户端的错误类型；工具不重试，模型再次调用同一工具时没有幂等保护 |
| 超时 | 连接、发现、调用、请求各有独立超时 | 没有跨运行的任务总预算与 token 预算，超时后远程副作用状态未知 |
| 工具参数校验 | 参数 JSON 严格解析，按工具声明校验必填字段、顶层类型与枚举，失败回填模型 | 不校验嵌套结构与格式约束，不做 JSON 修复 |
| 可观测性 | 事件带会话内序号、运行 ID 与毫秒时间；每轮有成对的轮次事件（耗时、尝试次数、用量） | 没有 trace/span；首字延迟字段尚未写入（流式在 W6） |
| 跨进程控制 | 单进程内任务注册表、会话锁与协程管理 | 多实例时停止请求可能落到没有该任务的进程：运行会被写成 cancelled，但执行协程和已登记的 Shell 会话留在另一个进程（未验证） |
| 动作授权 | 系统提示要求敏感操作前确认 | 没有执行前的审批闸门，提示词是约定不是技术约束。界面已有审批卡和设置页工具策略分区的位置，接口与策略内容未接 |
| 运行视图组件 | 状态条、计划条、工具流、提问、审批、交付、压缩、失败尝试、终态和上下文环已实现，开发模式 `/dev/components` 用夹具列出 [W5 子计划](plan/w5-ux.md#组件与状态)要求的状态。证据：代码核对；2026-09-28 目录页亮色与暗色截图（`plan/evidence/w5-2026-09-28-catalog-*.png`） | 尚未接入会话页，工作台、开发者视图和首页未重组（W5 阶段二）。截图不是真实任务走查，也没有做浏览器对比度自动检查 |
| 设置页 | 通用、模型提供商、MCP、远程 Agent 四个分区，带字段说明、草稿、保存结果和未保存离开提示；工具策略分区是占位。证据：代码核对；2026-09-28 浅色、暗色与约 390px 窄屏截图（`plan/evidence/w5-2026-09-28-settings-*.png`） | 四个分区的保存、校验和错误提示没有逐项操作。窄屏只保证分区可切换，没有单独的移动端布局 |

## 尚未具备

| 缺口 | 影响 |
|---|---|
| 流式输出与增量 `tool_calls` 拼装 | 模型生成期间页面没有增量内容，首字延迟等于整次响应耗时 |
| 并行工具调用 | 一次回复的多个调用全部执行但严格串行，请求层仍设置 `parallel_tool_calls=False`；互不依赖的动作不能并发 |
| Context 预算 | `context_window` 只用于展示，没有基于预算的裁剪或拒绝 |
| 幂等键与请求去重 | 响应丢失后重试可能重复产生副作用 |
| 检查点与执行恢复 | 进程重启后不能从中断处继续执行，只能把遗留的 `running` 标成 `interrupted` 后重新开始；`waiting` 可以续接。续接时只补齐悬空调用的结果。崩溃前已在沙箱中的进程不会被启动扫描终止 |
| 跨进程执行所有权 | 没有会话级认领或租约，多实例下的归属未定义 |
| 独立的目标验收 | 最终答复与计划清单都是模型的陈述；旧版的假完成守卫已随步骤结构删除，没有程序侧替代，也没有通用检查系统 |
| 长期项目工作区 | 任务以会话为单位，没有跨会话的项目、基线或变更集模型 |
| 沙箱资源配额与权限策略 | 创建容器时未设 CPU/内存上限，工作目录只解释相对路径，不构成访问围栏 |
| MCP 多轮交互与凭据 | 不支持 `input_required` 续接，不订阅工具列表变化，不支持完整 OAuth |
| A2A 多轮交互与产物落地 | 不支持 `input_required`/`auth_required` 续接，远程产物不会自动成为可下载附件 |

## 已知不一致

以下是代码核对中发现的、当前实现与配置或说明不吻合的地方。

**沙箱存活时间的环境变量命名不一致。** API 在创建容器时注入 `SERVICE_TIMEOUT_MINUTES`，沙箱服务读取的是 `SERVER_TIMEOUT_MINUTES`。两侧默认值都是 60 分钟，所以默认行为一致，但修改 API 侧的 `sandbox_ttl_minutes` 不会改变沙箱的实际存活时间。

**沙箱服务的执行身份与镜像意图不一致。** 镜像创建了 `ubuntu` 用户并把工作目录放在 `/home/ubuntu`，但没有切换执行身份，服务以 root 运行。W1 起系统提示按实际的 root 身份描述，涉及权限的行为判断仍应以实际身份为准。

**停止时正在执行的工具没有配对的 `called` 事件。** 停止取消执行协程，当前工具只留下 `calling` 事件，页面上该工具记录停在执行中（2026-09-28 评测 E4：1 次只有 calling）。Shell 进程本身会被终止（同次 E4 记录终止成功，停止后标记不再增长）。模型侧不受影响：下一次运行开始时该调用补为"执行中断，结果未知"。

**运行器启动后基础设施不可达时，会话可能停在 pending。** 2026-09-28 Docker 资源耗尽、API 容器暂时无法解析 Redis 地址时，一个新会话只保存了用户消息，状态停在 pending，页面一直显示思考中；清理资源后新会话正常。该路径没有测试覆盖。

## 未验证的范围

下列行为不应假定可用。条目本身没有完整验证；括号里写明已经覆盖的那一部分。

- 浏览器里事件流断线后的自动重连（服务端按序号补齐有用例，需设置 `RAY_TEST_DATABASE_URI`；页面重连未经走查）
- 多 worker 部署下的并发竞争、重复提交与停止投递
- API 进程崩溃后沙箱里已启动进程的回收（启动扫描只改运行状态；`waiting` 续接已有手动观察）
- 沙箱 TTL 自动到期回收、容器异常退出后的清理、进程树回收
- 容器逃逸、多用户隔离、资源耗尽场景
- 沙箱公网出口、DNS 与受限网络条件
- 完整的浏览器端到端任务
- 接真实模型的 MCP / A2A 完整 Web 任务
- 大文件、并发文件操作、沙箱销毁后的历史附件下载
- 运行视图接入真实会话后的浏览器走查（含 E2、E3、E4、多工具任务、工作台跟随、开发者视图，以及窄屏与暗色）。当前只有组件状态目录的亮暗截图
- 设置页四个分区的保存、校验与错误提示逐项操作。当前只有外观截图
- 亮暗主题的浏览器对比度与可访问性自动检查

带日期的旧调研来源与证据见[背景说明](background/README.md)；后续范围、进度与验证见[二次开发总计划](plan/README.md)。判断当前能力时以源码及最新实际核对结果为准，不以计划目标覆盖本文。
