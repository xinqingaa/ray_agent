# 主产品 MCP/A2A 升级计划

本方案仅针对 `ray_agent/`。阶段状态与验收进度维护在 [PLAN](../PLAN.md#阶段-2升级-a2amcp)，本文维护实施范围和验收要求。版本依据核对日期：2026-09-08。

## 1. 目标与范围

升级后，用户能够在产品中配置 MCP 工具服务和 A2A 远程 Agent，通过现有任务界面真实调用，并查看准确的结果、错误与历史。

当前产品已包含两种接入：MCP 使用官方 SDK，A2A 使用手写 HTTP 客户端。阶段 1 的文件任务使用内置工具，外部 MCP/A2A 均未配置，因此它是内置能力回归基线，不是外部协议验证记录。

本次包含协议适配、必要的配置及展示调整、依赖同步、测试服务、测试和运行说明。主执行流程继续使用现有 Plan + ReAct。协议相关的过时实现可直接替换或删除，不以原类结构、旧函数签名或旧数据格式限制重构。

“旧事件”指重构前保存在数据库中的任务记录，例如计划、工具调用、工具结果和最终回复，不是旧版 MCP/A2A 协议。新实现只维护一套事件契约，实时流与历史读取均使用这套契约，不增加旧字段回退、双格式解析或旧 SDK 包装。未改变的事件格式自然仍可读取；已经改变的旧格式不承诺回放，也不作为验收条件。验收使用新建会话，必须验证重构后生成的记录能刷新和重新打开。

本次不以清空历史来规避问题，也不自动删除已有会话或文件。若现有数据会阻塞应用启动或新会话使用，单独明确一次性数据处理方案，而不是长期维护旧逻辑。

以下工作另行安排：labs 迁移、完整 OAuth 登录流程、MCP resources/prompts/sampling/elicitation/tasks 产品能力、A2A 推送通知及 gRPC 接入、跨进程远程任务恢复、完整多轮远程人工续接、框架替换。

直接开展适配，并用针对性测试暴露和验证旧实现中的问题。不单独搭建一套旧版外部服务进行完整验收。

## 2. 版本与适配方式

| 项目 | 当前基线 | 本次目标 |
|---|---|---|
| MCP SDK | 声明、锁文件、导出依赖及已检查容器均为 1.22.0 | `mcp==2.2.0`，通过锁文件固定 |
| MCP 协议 | 当前代码手动执行 initialize 握手 | 仅 2026-07-28，新版协议模式，不降级到旧握手 |
| A2A SDK | 产品未安装，使用 httpx 手写客户端 | 引入 `a2a-sdk==1.1.2`，通过锁文件固定 |
| A2A 协议 | 使用手写旧卡片及请求 | 以 1.0 JSON-RPC 验收，卡片解析和协议协商遵循官方 SDK |

依赖声明设置受控主版本范围，锁文件固定上表版本；不进行全量依赖升级。A2A GitHub 发布页已列出 1.1.3，但本次查询 PyPI 该版本返回 404，1.1.2 有未撤回的安装包，因此选择 1.1.2 作为可安装基准。实施前复核分发可用性；若目标失效或需要跨主版本变更，先更新方案说明，不静默换版。

MCP 使用官方 2.x Client，显式指定 `mode='2026-07-28'`，不使用自动回退旧 initialize 握手的模式。支持 stdio、Streamable HTTP，移除旧独立 SSE 传输的配置枚举、后端连接分支、前端类型和说明。此处删除的是 MCP 旧传输入口，产品向页面推送任务事件的 SSE 继续使用，两者没有依赖关系。验证真实请求按目标协议运行，不把“SDK 已升级”当作“新版协议已验证”。

A2A 使用官方 `A2ACardResolver` 和 `ClientFactory`：SDK 负责卡片解析、接口选择、版本协商和协议消息；项目只负责超时、任务状态与 `ToolResult` 转换。根据实施期间用户明确的范围修订，不再额外强制拒绝 SDK 能处理的旧卡片，也不自建兼容转换或手写协议请求。验收目标仍为真实 1.0 JSON-RPC 调用；SDK 自带的协商机制不等于本项目承诺完整旧协议验收。仅启用产品本次需要的 JSON-RPC 传输。

## 4. 执行批次

### 批次 A：MCP 升级与修复

1. 固定目标依赖并迁移 SDK 接口。处理 Python 字段命名变化、旧 `streamablehttp_client` 移除和 HTTP 客户端类型变化；MCP 的 `httpx2` 对象与其他服务使用的 `httpx` 对象不混用。只补充必要的直接依赖。
2. 明确新版 stdio 配置：省略 `env`、`args` 时分别采用空字典、空列表；显式非法类型给出校验错误，不添加历史配置兼容转换。验证进程启动失败和正常关闭；凭据及环境配置不写入示例或错误展示。
3. 使用目标新版协议路径；发现工具时读取全部分页，校验重复游标等异常。以完整映射保存“对模型暴露的工具名 → 服务器和原始工具名”，修复服务器名前缀重叠导致的误路由，并处理名称冲突与模型可接受的名称格式。
4. 正确保留文本、结构化结果及内容块的类型信息。非文本块保留可序列化的描述和引用，避免直接把大型二进制内容塞入模型上下文；本次不新增多模态渲染器。有效空结果与缺失或非法响应区分处理。
5. 工具执行错误映射为失败结果，保留可理解的原因；协议错误、传输错误和超时另行区分。已发送且结果不确定的有副作用调用不自动重放；发现和只读探测才允许有限重试。
6. 明确资源拥有者。初始化与清理在同一所属任务中执行，单个连接初始化失败立即回滚该连接；不以“全部初始化成功”为清理的前提。取消时有界清理，清理后缓存与包装层标记一致，支持重复清理和再次初始化。不得将跨 Task 的 cancel scope 异常当作无害警告吞掉。

**验收：** stdio、Streamable HTTP 均按目标新版协议发现并调用；旧 SSE 配置与旧协议被明确拒绝；错误、分页、路由与清理用例通过；API 可正常加载。

### 批次 B：A2A 升级与状态适配

1. 使用官方卡片解析器和客户端工厂选择 JSON-RPC 接口，协议协商遵循 SDK。对缺少受支持接口、非法卡片及必需但不支持的能力报错；不自建卡片字段转换或版本选择算法。
2. 接入新消息和 Part 类型，用 SDK/ProtoJSON 转换工具生成普通 JSON；不对 Protobuf 对象调用 Pydantic 方法，不给远程卡片追加产品私有属性。产品配置 id、enabled、连接状态独立维护。
3. 保持单次委派入口。优先请求在服务端等待结果；如返回进行中的 Task，在本次调用总时限内查询该 Task，保留 task/context 标识，不重新提交 query。轮询结束条件覆盖完成、失败、取消、拒绝、需要输入、需要认证和超时。
4. 使用下表映射结果。远程执行状态保存在工具结果中，不覆盖本地 SessionStatus。只有有效 Message 回复或已完成 Task 标记调用成功；这不保证远程回答本身的业务正确性。
5. 已获得远程 Task ID 时，本地取消进行有时限的远程取消尝试。记录成功、拒绝或结果未知，并继续本地清理；没有 Task ID 时不声称远程已取消。远程取消能力不延伸为跨进程恢复功能。

| 协议结果 | 产品结果 |
|---|---|
| 有效 Message | 返回文本、结构化数据或产物描述，本次调用成功 |
| Task completed | 提取消息与 artifacts，保留远程标识，本次调用成功 |
| Task submitted / working | 继续有界查询，不发布成功结果 |
| Task failed / rejected / canceled | 返回准确状态及原因，调用不成功 |
| Task input-required / auth-required | 返回待处理原因与远程标识，不标成功；本次不自动衔接产品 waiting 状态或创建完整续接 UI |
| JSON-RPC error、非法响应 | 返回协议错误，即使 HTTP 为 200 也不标成功 |
| 超时或连接中断 | 返回未取得最终结果及已知远程标识，不推断远程停止 |

**验收：** 1.0 服务可发现和调用，卡片兼容转换由官方 SDK 承担；Message、Task、错误及超时行为符合上表；资源正常释放。

### 批次 C：配置、展示与依赖整合

1. 以已保存配置为设置列表的来源，离线 A2A 服务不能从列表消失。分开表达 enabled 与连接状态；失败项保留禁用、删除入口。禁用服务默认不启动进程或网络探测，启用后再发现；现有可用工具缓存可作为上次发现信息展示。
2. 为协议连接、发现与调用设置可配置的时间限制。默认值为连接 10 秒、每服务发现总时限 15 秒、MCP 调用总时限 120 秒、A2A 委派总时限 600 秒、远程取消 5 秒；A2A 查询间隔从 1 秒退避至 5 秒。设置列表与执行初始化均并行发现，MCP/A2A 各有默认 20 秒整体预算，超出预算的项仍展示为未完成探测。调整默认值时记录实际依据。
3. 结果统一为可序列化内容，包含成功标记、内容、错误类别和必要的远程状态。后端、存储和 UI 同步使用新契约；空字符串、0、false 等有效值不能因为真假判断被丢弃。不为旧事件增加字段猜测和格式回退。
4. 修正 A2A 启停、删除方法误返回 MCPConfig 的应用层契约，并通过 SDK 类型获取卡片能力字段。核对设置请求与响应的前端类型。
5. 依赖声明、uv.lock、requirements.txt 一起提交，导出依赖与锁文件一致。产品保留 Python 3.12 基准，仅调整迁移所必需的关联依赖。镜像仍按现有 Dockerfile 安装来源构建，并核对最终容器中的真实版本。

MCP 的 HTTP 连接、写入和连接池等待使用连接超时；读取由调用总预算负责，避免两套读取超时竞争。调用超时后关闭该连接，不自动重新提交。

**验收：** 离线服务可管理，新配置按新规则校验，重构后新会话的实时结果与刷新后的历史一致；本地与镜像依赖一致；UI 构建及相关测试通过。

### 批次 D：产品端到端验收与文档

1. 在 API 测试目录提供确定性的 MCP/A2A 服务及必要的测试专用启动配置，不依赖 labs，不依赖模型 Key 即可完成协议测试。A2A 服务端所需 extras 只用于测试环境，不将产品改为 A2A 服务端。
2. 协议测试与连接检查不访问日常数据库或写入真实服务配置。需要数据库的 API 集成测试使用独立测试配置；检查现有 conftest 的应用导入与生命周期，避免收集纯协议用例时意外初始化外部资源。
3. 从实际 UI 分别发起本地 MCP 工具任务和 A2A 委派任务，使用现有可用模型验证规划到工具选择的完整链路。模型自述不作为成功证据，检查服务端收到的调用、工具结果、终态及产物。
4. 在新会话中重跑阶段 1 的 hello.txt 任务，检查写读内容、附件下载、刷新和重新打开该会话。运行已有受影响的后端测试与前端检查，观察页面 SSE 收尾和协议资源清理。不以重构前的历史格式回放作为验收要求。
5. 将可复制的运行命令、Docker 内外地址及卡片公布地址配置写入对应服务指南；本文只维护验收要求。测试配置退出后恢复原配置，不覆盖用户已有的服务配置。
6. 保存验收使用的版本、任务 id、关键日志与结果摘要，区分静态核对、自动测试和真实 UI 运行。迁移细节集中维护在本文，完成后将未来式计划整理为最终决策与验证依据；阶段完成状态只更新 PLAN。

**验收：** 新版外部 MCP/A2A 任务及原有内置工具任务均形成 UI 到结果和历史的完整闭环。

## 6. 可复现的验收操作与通过条件

验收由实现者执行并交付证据，用户不需要自行拼装测试环境。测试目录提供两个真实运行的本地协议服务：MCP 暴露加法、返回固定错误、延迟返回等工具；A2A 暴露固定回复、延迟完成并返回文本产物、失败及需要输入等测试场景。协议测试通过真实 HTTP 或 stdio 通信，不能全部用 mock 客户端代替。

### 6.1 用户能在页面复核的验收

| 编号 | 具体操作 | 通过条件与证据 |
|---|---|---|
| U1 MCP 真调用 | 新建任务：“使用验收 MCP 服务的 add 工具计算 17 + 25，返回工具结果。” | UI 工具记录显示参数 17、25 和结果 42；MCP 服务日志确认收到调用；任务正常结束。模型自行算出 42 不算通过 |
| U2 A2A 真委派 | 新建任务：“将字符串 ray-agent-a2a-check 委派给验收 Agent，返回它的回复。” | 对端真实收到该字符串并回复预设 `A2A_OK:ray-agent-a2a-check`；工具记录和页面结果一致；不能仅看到本地模型复述该字符串 |
| U3 A2A 任务与产物 | 新建任务要求验收 Agent 执行“延迟完成”场景 | 对端先 working 后 completed，工具在完成前不标成功；最终呈现预设文本产物 `A2A_ARTIFACT_OK`，保留相同 Task ID；对端只有一次任务提交 |

## 7. 交付与回退

保留阶段 1 的可运行版本和数据卷。回退时将代码、锁文件、导出依赖及镜像作为一组恢复；若实施涉及持久化结构变化，回退使用升级前备份或独立验证卷，而非要求旧程序读取新数据。主产品只维护新版配置和代码，不为回退保留运行时兼容分支。若实际修改必须迁移数据库或扩大到主循环、完整认证或任务恢复，先说明具体原因与新增范围，再调整计划。

主产品验收后，以最终依赖和协议边界另行制定 labs 统一方案。
