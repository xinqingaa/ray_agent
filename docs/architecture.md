# RayAgent 架构说明

本文说明组件如何协作、状态由谁持有，以及执行、数据库与文件之间的一致性边界。循环内部的决策与反馈见 [Harness 工程](harness.md)，实现入口见[代码地图](code-map.md#主执行路径)。

## 系统边界

![RayAgent 系统协作与数据归属：界面经 HTTP 与 SSE 进入本机核心，单循环调用模型，工具适配连接外部能力；执行环境中文件、Shell 与浏览器由本机端口提供；核心管理 SQLite 业务库、进程内通知与数据根文件](assets/system-data-map.svg)

*橙线表示调用，结果沿原调用返回；蓝线表示页面事件，绿线表示核心的数据访问。图省略内部读写和 skill 独立文件命名空间，后者见本文“全局 skill 资源”。*

- **界面** 运行在桌面宿主的 WebView 中，接收目标与控制请求，经 HTTP 与 SSE 消费核心事件并展示过程和成果；页面状态由执行事实派生。
- **桌面宿主** 拉起与回收核心进程，只连接协议版本一致的核心，把接口地址与本次实例令牌交给界面；保存文件、打开外部链接与退出确认由它完成。核心的每个 `/api` 请求都要出示实例令牌，WebView 直接加载的图片、PDF 与网页预览改用只放行单条资源路径的短期票据。
- **本机核心（Harness）** 受理消息、组织运行、调用模型与工具并保存记录。执行协程与任务注册表由当前核心进程持有；核心只监听回环地址，由桌面宿主经私有管道拉起，开发时用启动参数直接启动，启动方式见[桌面开发指南](../ray_agent/desktop/README.md)与 [API 开发指南](../ray_agent/api/README.md)。
- **执行环境** 提供文件、Shell 与浏览器。文件由核心经限根文件端口直接读写工作区文件夹与会话工作目录；Shell 在执行开关打开且 supervisor 可用时装配，浏览器在组件可用时装配，否则按能力声明关闭且相关工具不进入模型请求。
- **模型服务** 根据上下文生成文本与工具调用，动作由本地工具管线执行。
- **MCP / A2A 服务** 提供外部工具与远程 Agent，经客户端适配接入同一工具层。

核心不依赖 PostgreSQL、Redis、Nginx 或 Docker，也不向浏览器托管界面；原 Compose 部署已删除。

## 核心对象与身份

用户任务可以跨多次运行推进，不能用一次运行的终态代表整个目标已经达成。

- **工作区**：绑定一个本地文件夹的持久对象，有稳定身份、文件夹位置与可用状态；文件夹登记为可访问根，工作区会话在其中读写。独立对话没有工作区。
- **会话**：组织连续消息、运行和附件；创建时同事务登记一个会话工作目录根，工作区会话另带 `workspace_id`，归属创建后不变。
- **运行**：表示一次受理后持续推进的执行，有独立 ID；运行中补充和等待续接沿用该 ID。
- **持久输入**：已受理的用户消息与目标运行；进入模型历史时标记消费，所属运行结束后仍未消费的输入保持可见，由用户明确重新发起。
- **轮次**：组织一次模型决策及工具批次，可以包含失败后的多次请求尝试。
- **工具调用**：表示模型提出的一项动作，通过调用 ID 与结果配对。
- **后台任务**：持久的长操作，带代次与实例所有者，状态沿长操作契约。
- **写入租约与变更记录**：工作区文件夹当前的写入者，以及每次覆盖、新建或删除的前后版本，是写前备份与撤销的依据。
- **skill 与不可变版本**：全局目录和包版本，运行引用固定实际使用的材料。
- **计划与成果记录**：保留范围、进度、核验和交付事实，可以跨运行承接，不承担动作调度。

每个会话至多有一个活动运行。会话列表中的状态是最近运行状态的冗余投影，不代表进程内协程一定存在。

## API 分层

请求沿接口、应用、领域和基础设施之间的职责边界处理：

- **接口层**：映射 HTTP 请求、响应和 SSE，并组装依赖，将外部请求交给应用服务。请求、响应、错误与事件信封以核心的 Pydantic 契约为唯一来源，UI 与桌面宿主使用由它生成的类型；失败统一为带机器可读代码的结构化错误，生成与检查见[契约指南](../ray_agent/contracts/README.md)。
- **应用层**：协调会话、文件、配置、后台任务与执行资源，组织受理、事务和跨资源操作。
- **领域层**：定义运行模型、单循环、工具管线及外部能力抽象，维护执行规则和状态约束。
- **基础设施层**：实现 SQLite 仓库与写协调、内容对象与会话工作目录、模型调用、进程内通知、公开网页读取和协议访问。

依赖在接口入口组装；数据访问通过仓库与工作单元组织。分层表达职责，具体对象放在哪个目录仍以[代码地图](code-map.md)和调用关系为准。

## 一次任务的执行

以下说明跨模块协作顺序，循环内部的反馈路径见 [Harness 决策层](harness.md#决策层)。

1. **受理输入**：应用服务在一个写事务中保存用户消息、新建或续接运行，并写入一条待消费输入；请求带幂等身份时同事务登记受理结果，可按身份读回。执行在后台启动，受理成功不代表执行开始。
2. **准备资源**：运行器按能力声明组装工具，执行开关关闭、工具运行时缺失或浏览器组件不可用时，相应工具不提供；工作区会话按绑定登记文件夹为可访问根；附件从内容对象放入工作区文件夹或会话工作目录。
3. **装配运行**：skill 目录在消息受理事务中已冻结并登记持久版本引用；显式选择在业务决策前加载。新运行按平台、工作目录与能力生成系统提示并冻结模型、协议、参数与工具声明；等待续接读取原快照。MCP 服务与 A2A 卡片按需发现，发现结果随运行保存。
4. **进入循环**：领域循环从持久输入取出补充消息、检查容量并请求模型；模型适配将完整响应归一后交回循环，文本增量另走临时展示通道。
5. **执行与回填**：工具管线校验、授权并执行动作；结果先进入模型记忆，再与完成事件同事务落库。整批独立白名单读取可有界并发，其他批次保持串行。
6. **等待或结束**：运行器保存等待或终态，并在同一会话锁内核对是否还有未取用的输入。

确认计划时，受理事务验证来源运行、计划身份、事件版本与请求身份并绑定新运行；重复请求读回原受理结果，过期引用返回冲突，自然语言确认仍是普通消息。计划、范围、成果与核验按完整计划事件恢复，实际文件版本及交付事实由运行器补充。机制见 [Harness 计划清单](harness.md#计划清单)。

后台启动在登记任务前再次核对运行身份；停止撤销尚未登记的启动，已组装的任务不再执行。MCP/A2A 已发现的服务身份和实际声明随运行保存，等待续接按这些身份重新发现；声明变化保存为工具修订，不能据此保证远端能力始终不变。

## 结束路径与控制平面

### 状态迁移

`running` 与 `waiting` 是活动状态；其余状态为终态，进入后不再迁移。

| 目标状态 | 触发条件 | 保存的结果 |
|---|---|---|
| `completed` | 无工具调用，有限结束反馈已处理 | 最终答复、运行汇总与成果完整程度 |
| `waiting` | Agent 提问或调用需要审批 | 问题或审批请求、待处理调用与冻结配置 |
| `failed` | 模型请求、请求预算、容量治理、启动或运行器无法继续 | 失败原因及已有执行事实 |
| `cancelled` | 用户停止 | 取消原因、未结束轮次及后续收尾结果 |
| `interrupted` | 核心重启遗留执行或审批；运行记录与本进程协程失配 | 中断原因；旧审批同时失效，未消费输入保持可见 |

工具失败通常作为反馈交回循环，只有运行无法继续时才进入 `failed`。正常完成仍可能部分交付，业务正确性需要独立核验。

受理与结束通过会话锁协调。结束判断若发现已受理但未取用的补充消息，先将其交给同一运行继续，避免消息落入已经结束的运行。

### 等待与续接

等待保存状态后退出当前协程。回复到来时重建运行器，沿原运行 ID 继续；原调用栈不会恢复。

提问和审批都要保存待处理调用与冻结配置，但续接条件不同：

- **提问等待**：回复成为该提问调用的结果，同批后续调用补为未执行，再请求模型。核心重启后保持等待，可以重新组装运行器续接。
- **审批等待**：批准后将具体调用重新交给管线，只跳过再次询问，当前禁止策略仍生效；拒绝则回填拒绝结果。同批后续调用补为未执行。核心重启使旧审批失效，补齐未执行结果并中断运行。

等待审批期间先处理审批或停止，普通聊天不注入运行。重建还恢复请求预算、有限反馈、skill 绑定及浏览器资源记录，再核对实际环境；持久记录不证明旧进程或连接仍然存在。

### 调用配对与未知结果

进入下一次模型请求前，所有助手工具调用必须有配对结果：

- 正常执行：回填工具结果，失败也保留为结果。
- 停止或失败后重新执行：已发出执行开始事件的调用补为“执行中断，结果未知”；未开始的补为“未执行”。
- 提问或审批：按上表补齐；等待审批时停止或重启，在审批失效的同一事务中完成补齐。

“结果未知”保留了可能已有副作用的事实，不能按未执行自动重放。

### 停止传播与资源收尾

1. 先在数据库事务中保存取消终态并补齐未结束轮次。
2. 取消本次执行协程，有界等待其退出。
3. 对本次登记的 Shell 会话终止进程组；尝试取消 A2A 远程任务，将控制结果保存为收尾事件。失败不回改运行终态，也不保证远程任务已结束。
4. 尚未进入模型历史的补充消息保持已受理未消费，可明确重新发起。

停止不撤销已经产生的副作用。协程取消、进程终止与资源回收属于不同操作。超时与宽限见[运行参数与限额](limits.md)。

## 状态与持久化

### 信息寿命

信息按寿命分为三个范围：

- **请求装配期间**：Context 对象与编码后的模型请求只在装配过程中存在；已记录输入可以由快照与事件重建。
- **当前核心进程**：协程、任务注册表、会话锁、进程内通知订阅与局部状态随退出丢失，由下一次启动扫描处理遗留运行。
- **数据根中**：业务库、内容对象、会话工作目录与 skill 存储可以重新读取，但读取记录不等于恢复任意执行位置。

### 业务库与写协调

业务库是数据根中的一个 SQLite 文件，启用 WAL 与外键。写协调器独占一条写连接，业务写事务按进入顺序串行，以 `BEGIN IMMEDIATE` 开始；同一任务内嵌套写事务直接报错，不会自锁。读取使用只读连接池，在 WAL 下与写入并发。其他连接占用写锁时按 busy 等待，开始写事务仍忙碌只在业务代码执行前有界重试，超出后返回可重试的不可用错误。

取消不会打断进行中的数据库调用：调用交给驱动线程后总会做完，期间的取消（任务取消或客户端断开带来的取消范围）在之后第一个不访问数据库的等待点生效；在工作单元主体里生效则事务回滚，主体已经做完则照常提交。提交或回滚、归还连接与释放写入权在独立任务中完成，调用方被取消也会等它结束，被取消的事务不会遗留连接、读快照或写锁。流式接口每次补读用一个短的只读工作单元，读完即关，等待通知、sleep 与 yield 时不持有连接。

活动运行唯一由写事务内复核与条件唯一索引共同保证；每会话事件序号取自会话行的下一序号，与事件同事务分配，`(session_id, seq)` 是主键。数据根由操作系统级实例锁独占，第二个核心无法打开同一数据根。schema 由 Alembic 管理：启动时升级到程序的最新版本，版本号进入握手与状态；业务库版本超出程序可读范围时拒绝启动。表结构变更使用批量模式。

### 持久输入、受理与启动扫描

- **受理**：用户消息、运行状态与待消费输入同事务提交；带请求身份时，受理结果与内容摘要同事务登记，同身份同内容返回原结果，内容不同返回冲突，结果未知时按身份读回。
- **消费**：运行器从持久输入取用户消息；消息写入模型记忆后，记忆、那批上下文事件与输入的消费状态在同一事务提交。
- **启动扫描**：在开始受理前，把上次进程遗留的 `running` 运行置为 `interrupted`，等待审批的运行同样中断并使审批失效，等待提问的运行保持等待；未消费输入保持已受理可见，由重新发起接口交给新运行，不自动启动执行。
- **通知**：事件提交后经进程内通知唤醒订阅方，订阅方按序号补读；通知只是唤醒，丢失或失败由补读覆盖。

### 后台任务

后台任务在业务写事务中登记，状态沿长操作契约（`queued / running / succeeded / failed / cancelled`），带类型、范围、对象版本、幂等键、实例所有者、取消请求、进度、错误与代次。执行器领取任务时记录所有者；进度与结果写回同时核对代次与所有者，重试或重启接管后迟到的写回被拒绝。取消请求先记录，由处理函数在安全点确认。启动扫描把上一实例遗留的运行中任务按类型重新排队或标为可重试失败。当前登记的类型有数据清理、工作区删除、会话摘要、记忆提炼与文档索引。

### 记忆与上下文的责任边界

会话工作记忆、工作区长期记忆、请求输入和审计历史由不同部分维护：

- 领域循环维护会话工作记忆（messages），负责结果整形、容量检查及自动压缩；压缩组件生成摘要与替换消息。
- 工作区服务维护工作方式版本；记忆服务维护长期记忆条目、来源、变更与抑制；文档索引服务登记文件夹材料、经可取消 worker 解析并按工作区串行发布片段；检索服务按工作区范围维护全文索引（记忆、会话摘要与文件片段）。
- 新运行受理时，上下文装配按产品系统提示 → 工作方式 → 常驻记忆 → 有界初始召回 → 会话历史组织内容，并写入运行背景清单；活动运行与等待续接沿用冻结版本。运行器在每轮请求与重试前调用应用层核对来源有效性，撤回优先于冻结引用；清单与运行快照的修订可重复写回，提示词按生效轮次保留用于请求重建。
- 运行器把会话工作记忆的改动与随后落库的事件放在同一事务保存；运行正常结束后同事务登记摘要与提炼后台任务。开关关闭与旧任务失效在同一写事务提交，业务发布事务再次核对后台任务取消、代次与所有者；具体记忆、更正、撤回与摘要检索规则见 [Harness](harness.md#长期记忆怎样更正与撤回)。
- 事件仓库保留原始过程，压缩不删除既有事件；手动压缩将替换工作记忆与事件同事务提交。

选择范围、触发条件与信息保护统一见 [Harness 上下文与记忆治理](harness.md#上下文与记忆治理)与[工作区与长期记忆](plan/workspaces-and-memory.md)。本节只规定所有权与持久化边界，不复制压缩算法。

### 数据归属

| 数据 | 所属存储 | 保存目的 |
|---|---|---|
| 会话、运行、事件、模型记忆、计划事件与文件元数据 | 业务库 | 业务状态、历史、配置快照及来源 |
| 持久输入与受理记录 | 业务库 | 输入不丢失、不重复成为业务执行，请求结果可读回 |
| 后台任务、应用配置、skill 目录与运行引用 | 业务库 | 长操作状态，模型、Agent、工具策略、MCP 与 A2A 配置 |
| 事件与目录变更通知、模型文本增量 | 进程内通知 | 唤醒订阅方重读持久数据；增量只给当前连接，不补发 |
| 附件、交付文件与截图字节 | 数据根的内容对象 | 输入材料、交付文件及视觉资源 |
| 附件副本（独立对话）、超长工具结果、截图与临时文件 | 会话工作目录 | 本会话工具可用的工作文件，随会话删除回收 |
| 工作区、文件夹绑定与可用性 | 业务库 | 工作区状态与版本、文件夹位置、文件系统身份与可用状态 |
| 工作方式版本、记忆条目／来源／变更、会话摘要、运行背景清单、文档修订／片段与全文检索文档 | 业务库（含 FTS5） | 跨会话长期背景与可重建的全文索引；按工作区隔离；向量索引留给后续工作包 |
| 写入租约、变更记录与备份对象登记 | 业务库 | 工作区文件夹当前的写入者；每次覆盖、新建或删除的前后版本；写前备份的归属与哈希 |
| 写前备份与撤销前备份字节 | 数据根的工作区内容对象 | 归属工作区、同哈希在工作区内只存一份，随工作区删除的清理任务回收 |
| 工作区文件夹中的文件与身份标记 | 用户的文件夹 | 用户自己的文件；核心只写任务需要的内容与 `.rayagent` 标记，删除工作区不删除它们 |
| 页面派生状态与预览缓存 | 浏览器或核心临时资源 | 展示与阅读，不作为业务产物 |

模型地址与密钥只从用户配置文件读取，不写入业务库，界面只得到掩码与可用状态。资源 ID 只是引用，不能证明字节仍然存在；数据库记录可回放，文件是实际副作用，两者不能相互替代。

### 删除与业务清空

- **删除会话**：一个写事务删除会话及其运行、事件、输入、文件元数据与根登记，并登记清理任务；任务按清单回收会话工作目录与内容对象，可重复执行。正在执行的运行先取消。
- **删除工作区**：先等文件夹的写入租约结束（期限内仍有写入者则返回冲突），随后在同一事务删除其全部会话、解除文件夹登记并把工作区标为删除中，登记清理任务；之后取得租约会因工作区已不存在而被拒绝，不会产生无归属的备份；同一事务也删除其变更记录、备份对象登记、写入租约，以及工作方式、记忆、摘要、运行背景清单、文档索引与检索文档；任务回收会话文件与备份字节，尽力移除文件夹里本机的标记条目，最后删除工作区记录，从不删除文件夹与其中的用户文件。
- **清空业务数据**：存在运行中或等待中的对话、正在压缩上下文、已有未完成的清空，或有文件夹仍被写入租约占用时拒绝；受理事务删除全部会话与文件记录，同时删除全部工作区登记、变更记录、备份对象登记与写入租约，并登记清理任务；任务回收内容对象、会话工作目录与备份字节，尽力移除各文件夹里本机的标记条目，不删除任何文件夹或用户文件。失败按同一清单重试，不扩大范围。应用配置与全局 skill 库保留。

记录先删除、字节后回收：迟到的写回找不到记录即失败，回收失败留下可辨认的孤立字节，不会出现有记录却没有字节的文件。

### 构建身份与运行快照

冻结核心时产生构建清单，内容指纹覆盖显式源码、依赖清单及构建输入，排除凭据、可变运行配置和缓存；界面随同一个应用包分发，不单独记录构建身份。Git 提交仅辅助定位，不能区分同提交上的工作树修改；未知构建身份保持未知。

运行快照保存核心构建身份与实际提示，新运行使用当前提示，等待沿冻结提示，不重写历史请求；内容指纹不证明外部模型或运行配置正确。

## 事件与投影

### 提交与通知

持久事件是页面历史回放和运行过程审计的依据；外部动作是否发生仍需结合实际资源判断。

1. 运行账本在同一写事务中保存事件、相关运行计数与状态、会话状态，以及记忆和输入消费等附带更新。
2. 事务提交后发布新序号通知；通知失败不撤回提交，订阅方通过兜底查询补齐。
3. 带运行 ID 的写入在写事务内复核运行状态，终态后的迟到事件被丢弃，明确允许的收尾记录除外。

这个事务不包含模型请求、网络访问或文件复制，副作用与其数据库记录可能在不同时间可见。

### 记录与请求重建

运行快照固定实际提示、模型、协议、参数和工具声明。围绕这份快照保存以下过程记录：

- **轮次事件**：配对记录模型请求及工具批次，包含耗时、用量和结束原因；停止或中断时补齐未结束轮次。
- **尝试事件**：记录失败、重试与取消，不进入模型历史。
- **上下文事件**：记录追加消息、清理推理字段与压缩替换，用于重建输入，不重放动作。
- **审批事件**：记录待处理及批准、拒绝或失效结论，与对应运行状态迁移同事务保存。

请求重建由运行快照和此前上下文事件还原消息、工具定义、协议及图片引用。通信编码与图片字节在模型适配时装配；重建接口只读。压缩替换模型工作记忆，不改写原会话事件，手动压缩也不创建产品运行。

### 订阅、重连与临时增量

- **持久事件**：按会话序号补读；订阅建立后再查询一次，覆盖建立订阅时的空档。通知触发补查，无通知时兜底查询；SSE 以序号作为事件 ID，断线从最后序号继续。
- **文本增量**：不带持久序号，按运行、轮次、尝试拼成临时条目；完整消息到达后替换。重试、轮次结束、终态、刷新或重连会清除相应临时内容。
- **目录通知**：只传对象身份，列表重新读取；页面隐藏时断开，重新可见时核对。

接口投影省略工具原始大结果与上下文全文，保留展示预览和整形信息。预览从当次结果派生，不重新读取环境冒充历史画面；前端按调用身份合并开始和结果，消息只引用当时已交付的附件，不关联未来版本。详细接口与实现定位见[代码地图](code-map.md#事件观测与投影)，查询间隔见[运行参数与限额](limits.md)。

## 跨模块协作

- **公开网页读取**：在核心中直接完成，每跳固定公开地址、不带 Cookie 与认证，不需要执行环境。本机代理以 fake-IP 模式接管 DNS 时，先经 DNS-over-HTTPS 核对真实地址全为公开地址，再交由代理按域名转发。
- **文件**：文件工具、交付、附件放置与文件接口都经同一个限根文件端口访问两类可访问根（工作区文件夹与会话工作目录），位置一律是 `root_id` 加相对路径；工作区文件夹的写入统一经应用层写入口，规则见[执行环境与限制](#执行环境与限制)。
- **Shell 与浏览器**：Shell 由执行开关和基础工具运行时决定可用性，浏览器由受管组件决定；不可用工具不进入模型请求。组件安装由应用服务协调持久后台任务，数据根保存按代次隔离的文件，supervisor 回收安装 worker。
- **MCP 与 A2A**：经协议客户端进入本地工具管线，保留本地运行控制。
- **输入附件与交付**：上传保存为内容对象，发送时归属会话：工作区会话把附件复制进工作区文件夹根目录（同名不覆盖；文件名命中文件工具禁止规则的附件留在会话工作目录，模型才读得到），独立对话复制到会话工作目录；交付把可访问范围内的文件保存为新的内容对象并关联会话，记录来源根与相对路径，之后再改文件不改变已交付版本。普通工作文件不会自动成为下载附件。
- **文件预览**：由核心直接读取附件内容对象，不启动 Agent，临时解析资源与缓存由核心回收。

MCP 别名区分同名工具，超长外部结果保留完整内容再进入统一整形；外部交互限制见 [Harness 执行适配层](harness.md#执行适配层)。

## 执行环境与限制

- **执行能力**：文件访问可用；本机命令依赖执行开关与 supervisor，浏览器依赖组件安装状态，能力声明给出可恢复原因。
- **本机进程与运行时**：Shell 与组件 worker 经私有 IPC 交给 supervisor，浏览器驱动也按运行登记；核心失联时 supervisor 回收登记的子树，不靠旧 PID 接管。基础包以只读归档分发正常 CPython／Node，首次需要执行时校验归档和关键文件，在数据根原子展开，并实际核对解释器版本。工具 Python 加载自身库，不参与核心动态库重写；字节码与其他可写内容不会写回应用包。冻结核心仅通过专用 worker 入口启动自身子进程。工具 PATH 使用受管解释器及系统目录，移除核心密钥与冻结标记。显式终止与收尾都以整棵子树为准，不能由外壳已退出推断后代已结束。本机执行沿当前用户权限运行，Shell 不是文件限根沙箱，不支持主动脱离监管的后台服务。浏览器首次动作才创建实例，同工作区资料目录串行准入，下载先进入本次会话临时目录。
- **组件发布**：业务库保存受理身份、取消与代次；下载及校验写入独立暂存版本，发布在写事务核对所有者、代次和取消后原子切换收据。重启会接管未完成操作，已请求取消的操作保留取消结果，迟到 worker 不得切换当前版本。收据分别记录已发布版本、文件布局与兼容契约；目标更新期间，符合当前适配契约的旧版本保持可用，失败、取消或重启不切换指针。完整校验后才原子切换到目标版本；已发布目录保留，不破坏仍在使用它的进程。不兼容或文件不完整时给出更新原因。
- **文件访问范围**：一次运行可访问当前工作区文件夹（如有）与本会话工作目录，越界路径被拒绝。每次访问先核对根身份，再逐级不跟随链接地向下打开，符号链接、设备与管道不被跟随或读写；保留目录 `.rayagent` 不可读写也不列出；经 HTTP 上传同样遵守禁止规则，不能写入版本控制内部、保留目录或凭据文件名。工作区文件夹失联时该根不可用，会话照常运行，不在旧位置自动建目录。
- **工作区文件夹的绑定**：新建在默认位置下，打开已有文件夹需要宿主选择器产生的一次性授权，不接受界面提交的桌面路径；文件夹内的 `.rayagent/workspace.json` 记录本机条目，用于识别移动与复制，不能识别时按路径与文件系统身份绑定；同一个工作区不会同时绑定两个文件夹。重新定位把工作区改绑到宿主选中的另一个文件夹，不依赖标记。
- **写入保护**：工作区文件夹的所有写入（文件工具、上传、撤销）只经应用层写入口：按文件夹持久持有写入租约（每个工作区至多一个，同一运行重入，其他会话立即得到带持有者与原因的冲突，不排队；尚未执行且没有既有写入者的审批不占用），覆盖或删除前把原字节存为工作区内容对象，发布后记录变更；备份失败则不写入，磁盘不足时停止发布新版本且不删除已有版本。发布前核对目标版本并在发现外部改动时返回冲突；但覆盖发布不是原子的比较交换（尚未使用 macOS 的 `renamex_np` 做条件替换），最后一次核对与 rename 替换之间仍有很小的竞争窗口，窗口内的外部改动可能被覆盖。会话工作目录、只读、检索与记忆不取租约。停止运行时，租约在执行协程确认退出后释放；期限内无法确认则转为阻止状态并提供重试收尾，迟到的结果按租约身份核对，不会释放后来取得的租约。启动扫描释放旧核心实例中文件工具写入者遗留的租约，外部进程写入者的租约保留为阻止状态，只有确认其已结束才释放。Shell 启动前取得进程写入租约，等待时保留写入者，运行结束先回收子树再释放；旧实例或未知进程保持 blocked，可重试收尾，或由用户明确确认旧进程已结束后按所见租约身份释放。首次实际 Shell 启动前，沿文件端口的排除规则和扫描边界记录工作区与会话工作目录的文件大小、修改时间，保存在运行快照；同一核心内的等待续接沿用同一清单；观察归属到核心实例，跨实例续接把旧区间标为未知，不认领旧进程或补造连续观察。确认整棵子树退出后再扫描比较，生成可分页读取的区间摘要。扫描截断或失败时标明范围不完整，缺失的一端不被误判为新增或删除；结束未确认或崩溃时标为未知，不补造执行后状态。摘要可能含文件工具或外部并发修改，不能确定写入者，不能捕获区间外、元数据未变或创建后又删除的写入；没有字节备份，不提供任意脚本写入的撤销。
- **撤销本次修改**：按运行把同一文件的多次写入折叠为「运行前版本」与「运行最后写入版本」，并核对相邻写入是否首尾相接。只有当前版本仍是运行最后写入的版本且运行期间没有外部改动时才自动恢复；运行期间被外部改过的文件以「运行期间被外部修改」冲突提示，撤销会同时丢掉那些修改；之后被外部改动的文件返回冲突，用户看到当前版本后明确要求才覆盖，覆盖前同样先备份。覆盖时带回的当前版本用十进制字符串表示纳秒时间戳，界面原样回传后再转为整数核对。运行新建的文件只有仍等于运行写入的内容才会被移除，运行前已存在或与本运行无关的文件不会被删除。撤销经同一写入口并记为一次独立的操作，与运行一样出现在最近修改里，可整体撤回，因此撤销前的版本不会丢失；不回滚会话事件与记忆，运行仍在进行时不能撤销。
- **外部变更**：有订阅者的可用工作区文件夹由核心监视文件系统通知，并以有界的定期重扫兜底；变化按相对路径（或需要整体刷新）经 SSE 推送，文件夹被移动、删除或替换时标记不可用并推送，回到原处后恢复。应用自己的写入同样会触发通知；改绑后订阅切到新位置。
- **会话工作目录**：位于数据根，按会话分开；目录名是根的不透明身份，不由客户端提交的会话 ID 推导。独立对话把它作为工作目录；工作区会话里它只存放超长工具结果、截图与临时文件。
- **视觉分析图**：按模型能力与容量装配，历史保存引用；临时截图在终态且到期后回收，活动图受保护。
- **文件预览**：按类型分段读取或在有界子进程解析，临时副本与缓存独立回收。

配额统一见[运行参数与限额](limits.md)。页面终态、后台协程结束与资源回收应分别确认。

## 全局 skill 资源

skill 管理由应用服务协调，包解析在领域层，GitHub 获取、不可变文件与业务库访问由基础设施实现。设置和聊天安装共用服务；业务库持有目录、版本、导入与运行引用，数据根的 skill 存储持有完整包；文件先发布再短事务登记，不宣称跨资源原子性。删除会话释放引用，清空业务数据保留全局库；回收依据持久引用。

正文和参考文本直接从 skill 存储读取；把完整材料准备到执行环境需要本机执行端口，接入前该工具不提供。加载、审批、等待与压缩的行为见[skill 机制](skills.md)。
