## 1. 修复目标与范围

全量处理下列清单，不以“先做几个界面小修”代替收口。没有日期排期、工时估计或按时间划分的阶段。依赖关系只用于保证实现正确。

- 实施同时更新代码、接口/事件契约、设计说明、事实文档和验证证据。

归属沿用 W5（界面）、W9（命令/容量/计划）、W10（受理与恢复）、W11（项目/文件/记忆）；涉及执行完成反馈时联动 W1/W3/W4。不会新建另一套工作包编号。

## 3. 项目设置与项目记忆：重点重做

### 3.1 目标结构

项目页顶部直接提供“文件”“项目记忆”入口；项目菜单中保留“项目设置”，用于名称、归档等项目管理。现有文件/快照工作台保持职责，记忆不再藏在“快照 → 项目操作记录 → JSON”里。

“项目记忆”采用可阅读的独立内容区：桌面是工作区面板或独立视图，窄屏是具有完整高度和独立滚动区的视图。使用三个清晰分区，默认阅读，按需编辑。不要继续让 520px 弹窗同时承载两个长文本编辑器和全部解释。

| 分区 | 对用户的解释 | 默认展示 | 操作与边界 |
|---|---|---|---|
| 项目说明 | 你为本项目设置的长期目标、工作要求和交付偏好 | 全文阅读；为空时给填写提示 | 用户编辑；名称与说明可独立保存，不随笔记写入而冲突 |
| 项目笔记 | 你和 Agent 共同维护的结论、决策、待办和重要文件位置 | 全文、版本、最近修改来源与时间 | 编辑、比较冲突、查看历史、取回旧内容；整篇替换仍需版本校验 |
| 近期对话摘要 | 自动生成或手动改写的近期背景，不能替代完整历史 | 对话标题、摘要、来源、状态、截止范围；标明是否进入当前预览 | 打开原对话、改写、重新生成；没有摘要、生成中、失败、保留旧摘要分别表达 |

次级区域提供“用于下一次新运行的内容预览”以及“修改记录”。日常不用展示代次、seq、操作 ID 等实现字段；诊断细节按需展开。保留读屏可用信息。使用 UI 现有 DESIGN/token，不重置品牌与主题，不要求插图或技术示意图。

| F04 改进 | 20px 缩进、长名称和状态/大小并列，深层难定位 | 层级线、目录图标、合理缩进与选中高亮；详细路径/面包屑；深层允许横向滚动或层级导航，不只加缩进 | 至少 8 层目录、长中文名和相同 basename 可区分；390px 主操作与路径可用 |
| F05 改进 | 筛选器没有计数与路径搜索，大批材料定位困难 | 筛选显示真实计数，窄屏滚动或菜单；增加路径搜索、展开/折叠及跳转需确认项 | 搜索/筛选只改展示不改上传集合；返回全部保留确认状态；键盘可找到目标 |
| F06 确认 | 树对目录状态聚合有简化：混合已上传/已排除可仍显示“将上传”；部分预检问题不充分展示在节点 | 用明确状态模型区分可上传、需确认、复用、排除、阻塞、传输、已发布、失败/未知；目录聚合计数，不冒充单一文件状态 | 混合目录显示实际汇总；预检不可上传的节点有原因；失败与未知不显示完成 |
| F07 改进 | 详情仅显示路径/大小/原因，类型和可预览范围不足 | 增加类型/扩展名、浏览器 MIME（可为空）、大小和动作；安全预览文本/图片；不支持的文档明确说明，不假称可预览 | 大文件预览有上限；图片 URL 被释放；HTML/脚本不执行；可选敏感文件确认前不读取内容 |
| F08 改进 | 可选上传与同名覆盖是不同确认，容易混淆；复用/排除/失败总量不够直观 | 分开“允许纳入材料”和“覆盖项目同名文件”；底部显示纳入、排除、复用、需确认、失败总量 | 禁止项没有确认入口；筛选后仍能看见总确认数；覆盖必须指向具体路径 |
| F09 改进 | 完成/部分失败/取消后结果与按钮混杂，成功与失败可能只能读回才明确 | 单独结果区列成功、失败、未知、复用；重试失败项、读回、取消批次、完成按状态展示；阻塞错误保留 inline | 仅成功项可正常使用；失败项重试不重复发布；取消保留已发布文件并解释结果 |
| F10 核验 | 关闭/刷新后批次仍占用项目；本地 File 对象不能持久恢复；localStorage 写失败可能中断已受理流程 | 以服务器 operation_id 为事实源，持久化只做恢复索引；存储不可用时保持内存状态并提供入口；重新选源只补失败项 | 刷新/无本地索引仍发现活动批次；关闭不误称取消；重新选择正确文件，哈希一致才复用 |
| F11 核验 | 文件系统 picker 与 webkitdirectory 回退性能、安全提示及取消路径未完成完整真实验收 | 保留不同浏览器能力检测；说明回退先枚举材料的代价；真实选择、拖入、取消、权限拒绝各走一遍 | 原生选择与回退结果一致；权限拒绝可恢复；依赖目录排除、可选目录继续扫描符合规则 |
| F12 改进 | 已导入文件浏览和上传前预览的状态/类型/错误术语不一致 | 统一文件路径与类型表达；区分本地待上传内容和服务端项目内容；文件/整项目下载失败给读回入口 | 本地预览不被当成已入项目；上传后刷新能读到真实字节；下载禁用与服务端拒绝理由一致 |

进度设计必须同时调整传输封装、超时/取消、API 错误解码与导入状态模型；不能只增加一根按文件索引增长的“百分比条”。扫描结果总量与仅失败项重试的分母分别计算；已排除材料不计入上传字节。所有持久化未知结果仍先读回。

## 6. 后端一致性、文件生命周期与恢复

| 编号/判定 | 什么问题或需核验的链路 | 怎么修复/收口 | 验收条件 |
|---|---|---|---|
| B01 核验 | 附件上传→消息受理→副本关联→后台发布→快照→沙箱同步的跨层顺序 | 复核已有 stage/publish/readback 与受理事务；明确拒绝、受理后环境失败、DB 提交未知三种责任；补未覆盖组合 | 消息未提交无 pending 关联；受理后失败只终结原 run，不要求重发；未知发布不误删；同附件 id 复用 |
| B02 核验 | 同名不同附件、运行中追加附件、停止/重启时 pending 关联是否可恢复 | 复用唯一关联与规范化路径分配；展示 pending 原因及恢复方式，不让用户误以为附件丢失 | 不同 id 不互相覆盖；追加附件不绕过文件操作；启动只清孤儿，不删 accepted/ready |
| B03 核验 | `/workspace` 内交付与外部路径复制、项目补存失败的部分成功 | 保持会话附件先可下载；项目补存状态独立；同 run/call/path 幂等；补存用已存附件而非重跑模型/沙箱 | 项目补存失败时原下载可用；重试只有一份副本；快照恢复不改变历史下载字节；符号链接以实际路径判定 |
| B04 核验 | 首次/普通发送响应丢失、历史重复内容、附件顺序与模式的受理归因 | 复核 accepted seq/run 与提交前 seq；附件 id 和运行模式参与核对；失败读回不得清除 submission；保护有歧义消息 | 已接受响应丢失不重发；重复相同文本/附件、不同模式不错误归因；连接恢复可继续原运行 |
| B05 确认 | 普通新建项目无受理未知保护；导入创建只能让用户关闭后猜项目列表；创建会话响应丢失也没有唯一关联 | 为项目创建/首次创建会话定义有限作用域的创建标识与读回契约，原标识重试返回同对象；不扩展成全局请求平台 | 请求提交后丢响应再读回得到原对象，不多建项目/会话；重复名称仍允许不同真实创建；拒绝无残留登记 |
| B06 核验 | 运行快照超限允许跳过，上传覆盖/恢复却必须有保护，前后端可能误用相同“保护”状态 | 统一 ready/skipped/failed 及来源；跳过仅运行准入；UI 与模型均知道降级；缺保护的覆盖/恢复明确拒绝 | 运行超限可以按现有契约继续；覆盖/恢复超限不改文件；没有快照不提供恢复；后台写入错误不被当成超限跳过 |
| B07 核验 | 恢复中断、重复修复、回到恢复前、GC 失败与取消线程的状态收敛 | 复用固定 target/before 清单与磁盘最终校验；校验后才解占用；GC 待重试与恢复完成分开表达 | 路径集合/类型/哈希与目标一致；两种修复重复执行收敛；坏对象/清单不半恢复；IO 真结束前不能放行 |
| B08 核验 | 批次断线/上传取消与快照、归档、运行准入互斥 | 各入口使用统一 claim/owned/finish 与 operation_id；明确 stale operation 读回/核对入口 | 多请求间持续占用；另一批/运行/恢复收到明确 409；两个不同项目互不阻塞 |
| B09 核验 | 文件大小有过期标记，但浏览器下载/其他工具写文件和保留后台进程可能影响准确性 | 核对所有实际写入路径；保守标记活动期间未知；停止写入者后统一重算；展示测量时间/过期状态 | File/Shell/浏览器产生文件后不把旧大小当当前值；对未知写入不报精确值；读取页面不做无界重算 |
| B10 核验 | run 已终态但容器/线程仍可写，迟到启动与 settling 尚有组合竞态 | 保持 run 终态与文件占用独立；所有权按 run/operation 核对；停止、迟到创建、API 重启组合验证 | completed/cancelled 后旧写入者不影响新上传/恢复；waiting 合法容器保留；不清理其他项目/独立会话 |
| B11 改进 | 项目/操作异常各层返回字符串，前端难统一给修复动作；新记忆冲突还需要结构化全文 | 统一有限错误码、用户文案与 data：占用会话、操作类型/状态、修复动作、最新版本；原始诊断留日志 | UI 可按结构展示动作；非 JSON 网关错误不泄漏 HTML；422/409 不当网络未知重试 |
| B12 改进 | 新历史/记忆接口及已有列表容易拉取大量正文或 N+1 查询 | 定义分页、摘要元信息和按需全文；检查项目列表的逐项目 active 查询成本，必要时批量读取 | 大量项目/摘要/审计历史下查询与返回有边界；摘要全文不随所有导航轮询重复传输 |

B01/B03/B06/B07/B08/B10 已有专项测试。先比对当前变更与原测试覆盖，再补缺口；不将“有测试函数”写成“本轮测试通过”。文件安全继续沿用无跟随遍历、规范化路径、发布哈希与根目录不可替换，不放宽以解决 UX。

## 7. AI 逻辑与项目记忆质量

这些项同时包含代码问题与质量改进。不能用加强提示词替代事务、版本、预算或完成事实校验。

| 编号/判定 | 什么问题 | 怎么修复 | 验收条件 |
|---|---|---|---|
| A01 确认 | 摘要材料只取首条用户目标和各已完成运行最后一条 assistant；后续改目标、用户纠正、取消/失败时的重要结论不在材料 | 保留首目标，按确定顺序提取近期用户修订与完成结果；取消/失败只加入明确的“未完成/已确认部分”，不冒充成功；可用交付/笔记事件补事实 | 多次改目标、纠正数字、失败后完成、计划但未执行各有语义夹具；摘要不把目标、计划或失败动作写成完成 |
| A02 确认 | 每条材料有截断，但 finals 数量随运行无限增加；摘要请求缺统一总预算 | 材料构造有总字符/token 与条数预算，按近期优先/目标保留选择；截断记录；模型请求前检查容量和总期限 | 数百次运行的材料仍有界；不同窗口不会超请求预算；超限有明确结果且保留旧摘要 |
| A03 确认 | 手动摘要重新生成先将 source 改 auto，旧文本保留；生成失败会把旧手动文本标成自动 | 分离“当前文本来源”与“生成请求状态/代次”；成功提交才换文本来源；失败保留文本及来源；用代次使旧任务失效 | 手动文本→重生成→失败后仍标手动；重生成成功才标自动；手动编辑期间迟到结果丢弃 |
| A04 改进 | 自动摘要后台任务没有用户可理解的更新时间/陈旧标记，重复触发会消耗无效请求 | 用 source_seq/材料版本表达覆盖截止与是否有新材料；相同材料复用/合并进行中的任务；跟踪后台任务并沿用启动中断收敛 | 同材料不重复请求；新材料晚到不会被旧代次覆盖；重启生成中变可重试失败，不无限“正在生成” |
| A05 确认 | 注入摘要按最新对话活动排序，并允许保留的旧摘要进入；当前片段没有表达 generating/failed/覆盖落后 | 保留旧摘要可用，但带来源/截止/陈旧信息；按文本内容的实际覆盖排序或明确现行规则；总量裁剪保证条目标识完整，避免半条难归因 | 有新消息但旧摘要不会伪装最新结论；手动摘要不被自动覆盖；10 条/1500 总字符及截断标志与预览一致 |
| A06 改进 | 项目段直接拼接说明、笔记、摘要，三类内容的信任与优先级缺少清晰约定 | 区分用户说明（长期偏好）、当前用户目标、共同笔记（可错的背景）、模型摘要/外部材料（数据）；转义或结构化边界；要求冲突时核对材料，必要时提问 | 含伪造标签/“忽略指令”的笔记与摘要不会改变工具策略；当前用户纠正优先；中英文版本同语义 |
| A07 改进 | 笔记更新只有“可复用结论/决策/待办”提示；整体替换可能删旧结论、积累冗余、写入未确认推断 | 规定保留仍有效条目、更新已完成待办、去重、标明不确定事实与文件位置；冲突合并不用旧全文重试；不记录逐轮过程或实际凭据 | 用现有含笔记场景测两次连续更新、用户并发修改、接近上限；旧有效条目不丢，废弃项有明确处理 |
| A08 改进 | 笔记工具成功后新版本只靠返回值，system 仍是受理快照；模型可能继续用旧版本；失败易被最终答复掩盖 | 明确“本运行冻结背景，工具返回是当前写入结果”；返回新版本与可核对内容/范围；有限冲突恢复；写失败不声称已记住 | 同运行两次更新用前次返回版本；冲突恢复保留用户新改；计划模式拒写；最终答复与写入成功/失败一致 |
| A09 改进 | 多文件交付可能部分成功但顶层 success 仍 true；模型若只看成功易遗漏失败；项目补存失败与下载成功是两个维度 | 在工具返回中明确 complete/partial/failed 与下载/项目保存两种结果；提示只重试失败项，不重做整个任务；同步 UI 投影 | 一成功一失败必须表达部分交付；会话下载成功而项目失败显示独立状态；不声称全部保存 |
| A10 改进 | 无工具调用就 completed，文件任务未交付或计划未完成也可能结束；现有“提示必须交付”没有程序事实约束 | 添加限定范围的结束前一致性反馈：仅在明确文件产出要求/已有失败交付/已列计划未完成时核对事实，给模型有限补救机会；问答任务不强制工具；不能建立无限自循环或宣称通用正确性验证 | 文件要求未 deliver 时有明确缺口；部分交付仍部分；最多有限补救后给用户明确未完成结果；普通问答直接结束，停止始终可响应 |
| A11 改进 | 项目笔记与摘要生成辅助请求不计入 Agent run，用户难辨别记忆更新耗时/失败与主任务完成 | 项目记忆状态显示独立生成任务；保留辅助请求的模型、时长、错误与实际 usage（有则记录，缺则未知）；不混算现有运行指标 | 主 run 已完成但摘要生成中显示真实状态；失败不把主任务变失败；没有 usage 不伪造费用 |

A01 改变现有“只依据首目标与完成最终答复”的契约，需要同步 W11 子计划与产品说明；材料仍只来源于有明确语义的事件，不读取全部工具日志塞给摘要模型。A10 是本轮限定的完成一致性改进，不能扩张为独立目标验收平台；具体事件/失败出口先写入 W1/W3/W4，避免以改 run 终态名称掩盖任务缺口。

### 7.1 项目上下文不变式

- 受理时从一致事务视图冻结说明、笔记、摘要与版本；实际请求拼入 system，不污染基础对话记忆。
- waiting 回复/审批续接沿用同一运行冻结内容，不偷偷读取新说明覆盖历史。
- 新运行读取新内容；模型内的工具反馈可以提供新的笔记版本，但不倒改冻结快照。
- 实际请求、请求重建、配置快照、手动压缩估算都使用相同项目段构造与预算规则。
- 固定输入超限时，历史压缩不能解决；新运行/手动压缩按已有 context_limit 契约明确退出，不发无意义摘要请求。
- 项目记忆编辑不触碰文件；文件恢复不回滚记忆和对话历史。界面必须说明此边界。
