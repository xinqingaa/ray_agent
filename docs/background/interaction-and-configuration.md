# 用户交互与模型配置的演进

能力增加后，RayAgent 的入口逐渐混合了材料管理、成果阅读、技术检查与部署配置。后续优化主要重新确定每个入口回答什么问题，并把运行事实与当前可编辑内容分开。交互方案见 [用户交互与文件阅读](../plan/interface-and-preview.md)，接入方案见 [模型目录与端点](../plan/model-connections-and-selection.md)。

## 从入口增加转向职责统一

早期工作台承接终端、浏览器、文件、请求与记忆，侧栏和项目页又重复提供管理入口。项目设置同时编辑名称、跳转说明/笔记、归档与删除；“对话摘要与记忆预览”先打开的却只是摘要，用户要再找一层菜单才能看使用内容。容器标题还随开发者模式改变，削弱了归属感。

问题不只是图标不一致，而是入口名称、首次显示内容和返回路径不一致。最终项目主页承担稳定材料管理，对话侧承担阅读和当前工作；摘要成为主页稳定内容，设置只处理名称与生命周期，辅助视图保留清楚的返回路径。

主页稳定分为对话、文件、说明、笔记和摘要，标题栏与页签保持固定，当前内容区承担滚动。普通用户查看背景和成果，开发者模式额外查看实际输入快照、事件、请求和终端。开发者开关只控制观察入口，不改变权限、运行方式或记录范围。

## 从页面推断转向统一事实投影

早期页面同时维护发送过程流和补齐流，并从多个工具或步骤事件推断状态；重试还可能折叠之前失败的轮次。运行事实完善之后，界面改为一次提交与一条订阅分工，按序号补齐，用纯投影组织运行、轮次和调用。用户看到的“当前动作”、等待和终态因而有共同来源，不再由每个组件自行猜测。

容量入口也出现过把估算当实测、把压缩后的当前配置与旧窗口拼接的问题。后来统一命令可用性和容量来源，区分真实 usage、请求前估算、冻结项目背景和手动摘要结果。摘要后估算不一定减小，固定背景超限也无法靠压缩历史解决；入口需要解释实际原因，不能用一个圆环掩盖不同状态。

## 草稿、冲突与迟到响应属于交互契约

弹框关闭看似局部动作，实际涉及保存中的请求、未提交内容和原页面焦点。不同关闭入口各自处理，会造成 Escape 清空草稿、旧项目响应覆盖新项目、删除确认叠在设置上等问题。

方案统一取消、关闭、遮罩和 Escape 的离开保护；保存失败保持内容，版本冲突提供当前与最新状态，保存中不重复提交。设置、删除确认与占用导航作为一条状态链，返回时保留身份和焦点。辅助记忆视图切换也不能重新挂载后丢掉编辑内容。

“当前项目组合”与“本次运行快照”尤其不能混用。用户修改现在的笔记，只影响新运行；正在等待的任务仍使用冻结背景。技术预览需要标明实际归属，没有快照时不能将当前组合包装成已使用内容。

## 文件预览为何成为独立阅读能力

文件卡、工作台与项目文件曾各有查看路径，Excel 下载后才能看，HTML 又涉及脚本执行边界。统一查看器让查看文件不必创建任务或启动沙箱，普通阅读与开发者调试分工更明确。

不同文件格式不能假装具有同样还原能力。文本、表格、图片及 HTML 各自解析和展示，分页、大小限制、损坏、版本冲突与到期都有出口。下载原件保持原字节，解析结果用于阅读，不等于改写原文件。HTML 在隔离页面中运行自己的脚本，同时隔离应用接口与不必要的外部访问；不能把它当成完整浏览器沙箱。

## 首页和输入区为什么一起调整

独立首页的介绍与历史模块占据输入空间，历史本来已经由侧栏提供。图片粘贴、文件选择、草稿和发送却是共用组件，若只在首页增加能力，会产生跨页差异。因此简化首页，同时统一上传协调、缩略图预览、内容高度和聚焦时机。

上传请求属于发起时的草稿作用域；切页后晚到结果不能污染新草稿。部分失败保留成功材料，纯文本、混合粘贴和中文组合输入都沿原规则处理。输入高度根据内容重测，删除和发送后回缩，达到上限后内部滚动；返回首页可以继续输入，普通重渲染和弹框操作不抢焦点。

初版曾要求用户理解视觉能力并选择输入方式，用户随后要求简化。当前由后台自动组织：能力和预算允许时提供像素，否则作为文件材料并保存原因说明。输入区不再承担能力判断流程，但模型仍需知道哪些图片实际进入像素输入，不能把上传成功当作已经看图。

## 过程统计需要明确口径

时长、请求轮次、生成速度和本次用量帮助理解运行过程，会话累计用量是另一种口径。统计放在当前过程与终态记录旁，避免无关常驻数据干扰输入。生成速度不是精确费用，缓存输入是输入的子集，等待续接与新运行也不能随意相加成一次请求。

这类信息组织改变有价值，逐次间距、颜色和图标选择则不需要永久方案日志。相关实际浏览器、组件和仅构建修订在 [界面验证](../plan/evidence/interface-and-preview.md)中分开记录。

## 模型接入从猜域名转向明确目录

通过 URL 的官方域名推断模型厂商，在代理地址下会失效；全局默认连接又可能把 GPT 请求送到 DeepSeek 上游。思考快照若只按另一个系列的开关恢复，会混淆未发送与显式关闭。

2026-10-12 的简化方案把三件事分开：模型目录定义能力与请求规则，内部映射选择端点，环境提供 URL 和 Key。普通用户只选择模型与思考，维护者配置连接。前端消费后端目录，避免两份模型白名单；不建立渠道 CRUD、自动回退或辅助模型管理页面。

这个选择将接入复杂度留在维护边界，保持会话和运行快照稳定。非法 URL 只使所属端点不可用，显式清空 Key 不恢复旧值，其他可用模型仍能读取目录与估算容量。兼容端点可以主要通过配置增加，新增模型或协议仍需适配及验证。

接入检查使用定向替身与合成目录，未调用真实 GPT 上游或部署新服务。配置正确、参数编码正确和真实服务支持分别验证，不能由目录中的 capability 声明推导实际支持。条件见 [模型验证](../plan/evidence/tools-and-models.md)。
