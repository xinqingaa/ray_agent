# 用户交互与模型接入的设计取舍

材料管理、成果阅读、技术观察和部署连接各有使用目的。入口归属和状态来源明确，用户才能判断正在查看什么、修改何时生效，以及关闭后返回哪里。交互契约见 [UI 设计说明](../../ray_agent/ui/DESIGN.md)，模型机制见 [Harness](../harness.md#模型选择与请求分工)。

## 为什么管理、阅读与技术观察分开

同一内容在侧栏、设置和工作台重复管理，会使入口名称、默认内容和返回路径不一致。工作区页与文件夹面板承担稳定材料管理，对话侧承担当前工作与阅读，设置处理名称与生命周期。

原始事件、请求和运行快照供技术观察，普通阅读不需要这些字段。开发者开关只控制展示，不能改变权限或执行事实。

## 为什么界面消费统一事实投影

组件各自根据工具或步骤推断状态，会在重试、重连与多轮任务中产生矛盾。提交负责受理，订阅负责按序号补齐，视图投影统一组织运行、轮次与调用。

容量也需要共同来源。实际 usage、请求前估算和压缩后估算各有含义，不能拼接不同窗口或把估算增大称为释放空间。

## 为什么草稿与迟到响应需要作用域

关闭弹框、切换页面和保存请求可能同时发生。没有对象身份与离开保护，旧响应就可能覆盖新对象，上传结果可能进入另一份草稿。独立首页、各工作区首页与具体会话各有一份草稿，创建会话的请求标识随作用域保存，互不覆盖。

因此保存失败保留内容，版本冲突提供最新状态，切换与关闭处理未保存内容。辅助视图保留返回路径与焦点；当前背景和冻结运行输入也分别展示，避免把编辑误认为已经改变执行条件。

## 为什么预览与输入是共用能力

文件卡、工作台和工作区文件夹里的文件都需要阅读材料，共用查看器避免为阅读启动任务或沙箱。不同格式按实际解析能力展示，下载保持原字节，HTML 隔离预览不等同于完整浏览器沙箱。

独立首页、工作区首页与会话共用输入，使草稿、图片、粘贴和聚焦保持一致。图片是否进入像素输入由后台按能力与容量组织，用户无需选择协议模式，但模型必须获得真实原因，上传成功不能冒充看过图片。

## 为什么模型能力与端点配置分开

代理域名不能可靠说明模型能力，统一默认连接也可能将请求送错上游。能力与编码规则由后端目录定义，模型到端点由内部映射选择，地址与密钥由环境提供。

用户选择模型与思考，部署维护者处理连接；前端无需再维护能力白名单或渠道管理。非法端点影响所属模型，已知映射缺失明确失败，不自动转发到其他服务。

这个边界使会话选择与运行快照可解释，但目录声明和编码正确仍不能证明实际上游支持，需要按[模型通信检查](../../ray_agent/api/README.md#responses-模型通信)验证。
