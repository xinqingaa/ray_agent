# 运行事实与控制的演进

页面请求、后台协程、模型轮次和沙箱进程各有寿命。把它们都叫“运行中”，会使刷新、停止和重启后的状态无法解释。RayAgent 的演进先分离事实，再补控制传播和可靠受理，最后核对实际运行版本。完整设计见 [生命周期、事件与可靠性方案](../plan/runtime-and-control.md)。

## 停止暴露了不同寿命

旧会话状态兼任执行结果，页面结束与实际进程是否停止没有明确对应。两项历史观察暴露了不同问题：

| 条件与观察 | 判断 | 边界 |
|---|---|---|
| 基线停止后标记文件继续增长 | 取消 Python 协程不会自动终止 OS 进程 | 需要控制传播，不是只改页面状态 |
| macOS 临时目录直接调用 ShellService，sleep 6 约 6.02 秒返回 completed，未按预期约 5 秒返回 running | 线索指向直接等待输出读取器 | 未经过 Docker/HTTP，不能推广到所有环境 |

改造因此把会话、运行和请求轮次分开：会话保存连续历史，每次运行有自己的身份与终态，每次模型尝试有自己的开始、结束和用量。取消、中断、失败和正常完成分别记录，避免通过同一个 completed 掩盖原因。

停止需要先保存取消事实，再取消调度并终止本次登记的 Shell 进程组。已有文件副作用保留，容器寿命另行管理。独立对话保留环境便于续用；项目共享目录可能有未登记后台写入者，终态还需确认环境静止，见 [项目保护背景](projects-and-artifacts.md)。容器继续存在本身不构成泄漏证据。

## 回放事实与恢复执行不是同一件事

早期事件记录可以让页面回看，但模型记忆变化、运行配置和工具调用身份并不完整。只保存界面内容，无法解释模型为什么做出某个选择；只保存进程内对象，又无法跨重启读取。

后来选择以 PostgreSQL 保存运行、事件和上下文变化：业务状态与事件同事务提交，事件按会话序号排序，Redis 只通知出现新序号。断线或通知丢失时从数据库补查。运行配置冻结系统提示、模型规则与工具集合，使已经记录的请求可以重建。界面投影可以省略原始大结果，但不能改变执行事实。

这套记录提供审计、回放与有限续接，不能让未知副作用自动重放。数据库事务不包括 Shell 写文件、外部提交和上传；连接丢失后可能无法确认动作是否发生。通用检查点、跨 worker 认领与副作用对账是另一类工程，不能由“事件完整”推导已实现。

## 等待为什么退出协程

提问或审批可能等待很久。如果仅把执行协程挂在那里，重启就丢失待处理调用及其上下文。因此等待信息持久化后退出协程，回复到来时重新装配运行器，并补齐协议上的悬空结果。

提问回复可以作为同一运行中那次提问的结果；提问之后未执行的调用不能在恢复时盲目重放。审批只授权一次具体调用，批准后执行一次，拒绝回填拒绝事实。API 重启后旧审批环境失效，提问等待则可以继续。持久记录和环境有效性必须同时考虑。

后续请求预算也沿这个边界恢复：审批续接保持计数，真实新用户消息按当前契约重新计数。内部纠正消息不能冒充新输入获得额外预算。

## 流式展示为什么不等于流式执行

整包模型返回便于解析，但生成期间用户看不到内容。增加流式后，需要同时保留可见响应与完整响应：文本增量用于即时展示，工具调用参数必须组装完整并检查结束原因后才能执行。

增量不带持久序号，是可能丢失的临时展示；完整消息、调用与用量作为事件保存，刷新按事实源重建。半截工具参数不执行，输出长度截断按有界恢复处理。模型的首段到达时间、完整模型耗时、工具时间和任务墙钟各有口径，不能相互替代。

## 可靠受理来自客户端与后台边界

同步等待沙箱和外部发现会使首次发送看起来长时间未受理；客户端超时后再发，可能产生重复任务。改造将受理与准备拆开：短事务保存输入和运行，返回可读回的身份，后台再准备环境。

需要的不是按钮多禁用一会儿，而是服务端按请求身份、会话锁与当前运行核对准入。响应丢失时读取受理结果，晚到准备结果必须仍属于当前运行；取消后不能把旧容器重新挂回。项目操作也必须共用准入协调，不能依赖前端 disabled。

结构化计划确认在这条路径上继续扩展：按钮携带具体计划版本，同事务绑定新运行，立即显示准备执行。手动输入确认文字仍是普通消息，不用关键词猜测授权。计划本身的后续变化见 [长任务背景](plans-and-delivery.md)。

## 健康服务为什么仍要核对身份

对真实服务的评估发现，健康 API 与工作区有五个提示或工具说明文件不同。后续又发现旧会话的新运行可能继续使用历史 system。服务可访问、镜像构建成功，都不足以证明新任务使用预期代码和提示。

于是为 API/UI 分别生成构建清单，以实际构建输入的内容指纹定位；运行快照保存实际提示和配置。新运行采用当前系统提示，等待续接沿自己的冻结快照，历史请求不回写。Git SHA 用于定位，不能独自标识同一提交之上的工作树修改。

凭据、可变环境与外部模型不在源码指纹的保证范围内。部署仍要保留配置并分别读回 API/UI 身份，不能以任一端健康代替两端匹配。服务健康与版本匹配需要分别判断。
