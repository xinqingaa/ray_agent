# 文件夹工作区与写入保护的设计取舍

工作区让 Agent 直接读写用户磁盘上的文件夹。材料原位保存、用户随时可以用别的程序改动，带来托管副本时代没有的几类问题：文件夹会被移动、复制或消失，路径不能直接作为身份；用户文件没有平台快照兜底；多个对话和外部程序可能同时写。本文说明这些问题如何决定当前机制，行为与接口见[产品说明](../product.md#工作区)和[架构说明](../architecture.md#执行环境与限制)，实现入口见[代码地图](../code-map.md#文件与交付)。

## 为什么直接读写原位文件，而不是上传副本

[托管项目](projects-and-artifacts.md)保存平台副本，用户材料要经过选择、预检与上传，成果要下载才回到用户手里，本地修改也不会回流。让 Agent 直接读写原位文件省掉了这条链路，代价是失去平台快照：任何写入都作用于用户自己的文件，因此保护必须落在每次写入上（写前备份、版本核对、撤销），而不能依赖一份可整体恢复的副本。

## 为什么用标记加文件系统身份识别文件夹

路径在移动、改名、外接盘重新挂载后都会变，不能作为工作区身份。核心同时记录规范路径与文件系统身份（设备与 inode），并在文件夹里写一个只含身份的 `.rayagent/workspace.json`：只保存本机安装身份与工作区的对应，不含名称、对话或其他内容，因此复制到别处的标记不会泄露工作区内容。

标记使“用户在 Finder 里移动了文件夹”可以被认回；复制出的文件夹也带着同一个标记，两个文件夹不能共用一个工作区，所以必须让用户选择作为新工作区或改绑到副本。标记写不了（只读文件夹、权限）时退回路径加文件系统身份，并要求用户手动重新定位，不为了认回而放宽限根检查。外接盘重新挂载会改变设备号，身份核对需要容忍这类变化而不误判为另一个文件夹。重新定位不依赖标记，因而在标记不可用时仍可恢复。

## 为什么文件夹只经宿主选择器授权

界面运行在 WebView 中，页面脚本持有实例令牌，如果核心接受界面提交的桌面路径，任何页面内容都能把工作区指向任意目录。文件夹授权因此拆成两步：宿主在系统选择器里取得用户的选择，带每次启动随机生成的宿主密钥向核心登记，得到一次性、短期的凭证；界面只能拿着凭证请求打开或重新定位。宿主密钥不进环境变量，也不交给界面，实例令牌不能代替它。“在 Finder 中显示”同理：宿主向核心解析位置，界面只传根身份与相对路径。

## 为什么限根 IO 使用目录描述符

先检查路径字符串再打开文件，检查与使用之间可以被符号链接替换。核心按登记的根身份核对根，再从根的描述符起逐段以不跟随链接的方式向下打开，符号链接、设备与管道不被读写；遍历按相对路径逐层打开，不让描述符占用随目录深度增长，也就不依赖提高进程的描述符上限。

禁止规则（保留目录、版本控制内部、凭据与数据库文件）在 macOS 上必须比较折叠后的名字：文件系统可能忽略大小写，也可能把不同的 Unicode 写法视为同一名字，只做字面比较会被等价写法绕过。

## 为什么写入租约覆盖整个文件夹且不排队

不同对话可以并行思考与读取，但写入同一个文件夹时没有可靠的合并方式。以整个工作区文件夹为单位持有租约，第二个写入者立刻得到占用者与原因，而不是排队等待，用户可以决定先停哪个对话。审批等待期间不占用租约，避免等待用户的运行阻塞别人。

停止时先阻断后续动作、确认写入者退出，才释放租约；无法确认时转为阻止状态而不是假定已经静止，迟到的结果按租约身份核对，不能释放后来者的租约。外部进程写入者尚未接入，其租约保留阻止状态，需要用户确认的释放入口随本机执行一并设计。

## 为什么用写前备份与版本核对，而不是整体回滚

外部编辑器不会遵守租约，跨进程也没有原子的比较交换：核心能做的是在发布前核对版本、发现改动就报冲突，并把被覆盖的原字节先保存下来；最后一次核对与替换之间的窗口只能缩小，不能消除。

撤销因此逐文件核对当前版本，而不是回到某个快照。同一运行对同一文件的多次写入折叠为运行前与运行最后写入两个版本，相邻写入首尾不相接说明运行期间有外部改动，这类文件不自动恢复；运行之后被改动的文件默认不覆盖，用户看到当前内容后明确要求才覆盖，覆盖前同样备份。运行新建的文件只有仍等于运行写入的内容才移除，运行前已存在的文件从不被删。撤销本身经同一写入口并记为独立操作，所以可以撤回，撤销前的内容不会因此丢失。

## 为什么外部变更用通知加定期重扫

文件系统通知可能丢失、合并或在文件夹被移动后失效，不能作为唯一依据。核心用监视通知获得及时性，再用有界的定期重扫兜底，并核对文件夹是否仍在原处；订阅者队列写满时合并为一次整体刷新，而不是丢变化。界面合并短时间内的通知，只刷新受影响的目录，正在预览的文件被改动时提示重新载入，不替换用户正在读的内容。应用自己的写入同样触发通知，使文件树与预览走同一条路径。

## 为什么删除工作区不删用户文件

文件夹属于用户，应用只拥有其中的 `.rayagent` 标记条目。删除通过持久清理任务回收会话、备份与登记，等待文件夹的写入租约结束，之后拒绝再取得租约，避免产生没有归属的备份；标记只尽力移除，失败后再打开该文件夹按新工作区处理。这样“删除”的含义始终是应用不再管理，而不是清理用户的目录。

## 遗留的边界

覆盖发布尚未使用 macOS 的原子条件替换，保留上述很小的竞争窗口；外部进程写入者的租约没有用户确认释放入口；非 macOS 平台只有端口与分支，没有验证。这些边界在对应的机制说明和服务指南中标注，不在此重复。
