# 托管项目与数据保护的设计取舍

多段对话共享材料，需要分别管理长期文件、运行环境、版本和背景。仅保留目录不能保证文件可恢复，详细机制见[项目执行与文件保护](../architecture.md#托管项目执行与文件保护)。

## 为什么保存平台副本

直接接入宿主机路径或 Git 会要求用户理解工作区与权限。上传副本、平台托管和下载成果适用于通用材料任务，代价是没有本地实时回写。

平台文件、沙箱环境和附件各有寿命。API 阅读无需沙箱存活，项目保存也不保证进程、浏览器登录或服务状态持续；文件恢复不会撤回已交付的附件。

## 为什么快照需要独立对象与发布清单

Agent 可以改写输入，只保存最终结果不足以保护原材料。运行或覆盖前保护现状，为恢复提供稳定版本。

文件复制成功不等于可恢复：对象和清单需要完整发布，登记失败要能识别，回收要核对引用。恢复替换根目录还可能使挂载指向旧对象，因此选择在原根目录内应用并保护恢复前材料。

符号链接、特殊文件和属主差异也影响保护边界。统一的无跟随访问与实际内容哈希避免仅凭路径、大小或页面成功提示判断版本有效。

## 为什么恢复先确认旧写入者静止

旧进程可以在恢复后再次覆盖共享目录，运行终态也不证明全部后台写入已经停止。因此运行、上传、恢复和环境收尾共用占用边界，无法确认静止时保留阻止标记。

恢复自身可能部分失败，持久修复状态让重启后仍能阻止冲突写入，并允许只读查看、重试目标或回到恢复前。保护超限与 IO 损坏需要不同出口，不能统一当作可忽略失败。

## 为什么上传需要预检和结果读回

目录上传包含排除、冲突、敏感材料与总量判断，浏览器预检便于确认，服务端仍需核对实际路径和字节。目录名相同不代表用途相同，排除规则需要结合材料条件。

网络断开时文件可能已经发布。按操作身份读回、同内容复用和完整临时对象发布，避免把响应丢失误当未执行后再次覆盖。

## 为什么项目背景可编辑而运行输入冻结

全部历史自动进入新对话会增加重复内容并削弱来源。说明、版本化笔记和有来源摘要分别承担固定要求、长期结论与其他对话概况。

用户需要纠正背景，活动运行则需要稳定执行条件，因此新运行冻结选定材料。版本比较和摘要代次防止迟到结果覆盖编辑；当前内容与实际快照分开展示，编辑不追溯改变等待中的输入。摘要仍然有损，不能替代文件版本事实或检索系统。

## 为什么删除使用持久清单

归档不回收全部资源，只删除数据库行也可能遗留文件或误删共享附件。固定清理清单、关闭写入准入，再依次回收资源，可以保留失败位置和重试范围。

这类协调不构成数据库、容器与对象存储的跨资源原子事务。附件与项目副本也需分别记录，具体取舍见[成果交付](plans-and-delivery.md#为什么分项交付与业务正确分别判断)。
