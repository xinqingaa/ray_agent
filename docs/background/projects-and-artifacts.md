# 托管项目、记忆与数据保护的演进

跨对话工作需要材料和背景持续存在，但保留一个目录并不足以保护成果。项目设计逐步分开了用户文件、运行环境、文件版本和对话记忆的寿命，并把恢复、上传、运行与删除纳入同一协调边界。完整设计见 [项目、文件与记忆方案](../plan/projects-and-data.md)。

## 从本地代码工作区转向通用材料容器

早期讨论过宿主机路径、Git 身份及工作区接入。定位调整明确 RayAgent 是门槛更低的通用 Agent 应用，日常用户不应先理解 Git 或授予宿主机目录权限。于是选择上传副本、平台托管、下载结果，以项目组织材料和多段对话。

上传的材料与本地原件是两份副本；项目长期目录与运行沙箱不同。API 可以在沙箱不存活时读取平台文件，沙箱仅挂载工作目录，快照不可见。这个选择保留了通用材料处理，代价是没有本地实时回写、完整代码工作区或按运行归集的变更集。

因此“项目保存”不能含混地承诺全部状态延续。长期文件和背景持续存在，浏览器登录、进程与服务状态未必持续；对话附件另有存储寿命，文件恢复也不会撤回已下载的结果。

## 可恢复文件先要有稳定副本

Agent 会改写上传材料，单独保存最终结果不能保护输入。运行前快照和覆盖上传前保护使用户可以回到较早文件状态；恢复前再保存当前材料，避免修复失败后无路可退。

完整复制并直接替换目录的简单做法又有风险：文件发布和数据库登记可能分开失败，链接可能越界，快照回收可能删掉仍被引用的对象，替换根目录还可能使既有挂载指向错误位置。方案于是采用清单与内容对象，先完整发布再登记可用，恢复固定目标与保护材料，保留根目录身份。

所有遍历都需要一致处理普通文件、目录、链接和特殊项。符号链接保存链接文字而不跟随，读取与父目录核对防止 API 穿过项目链接访问卷外文件；哈希不能只依赖长度和 mtime。容器属主不同也必须处理，否则 API 保存的文件在沙箱里无法修改。这些细节属于文件保护契约，不能由页面“恢复成功”替代。

## 恢复为什么必须先处理旧写入者

如果旧沙箱进程继续写共享目录，恢复当时成功的字节会很快再次被覆盖。运行终态不等于共享文件静止，取消登记的 Shell 也不覆盖全部后台进程和浏览器副作用。

项目因此统一协调运行、上传、恢复与环境收尾。终态后先停止项目环境并确认旧写入者静止，再释放占用；等待回复或审批保持占用和环境。无法确认时保留失败与重试入口，不能为了让下一任务启动而乐观释放。

恢复本身也可能在多个 IO 阶段失败。持久标记使 API 重启后知道项目需要修复，阻止继续写入而允许只读查看；用户可以重试目标恢复或回到恢复前。快照保护超限和文件操作损坏是不同原因，处理出口不能混用。

历史故障注入、HTTP 中进程退出、真实 Docker 写入者停止与浏览器修复分别检验这些边界。首次探针失败与模拟方法修正有记录；最后一次正常截图不能概括所有异常路径都通过。

## 上传从文件接口变成发布事务

目录上传要决定扫描哪些材料、如何处理排除项、冲突和总量。前端预检便于说明，服务端仍需复核实际路径、字节、哈希和当前冲突，不能信任浏览器声明。

目录名称相同不代表是依赖，例如普通资料目录也可能叫 build。排除规则结合清单条件，由 API 下发一份规则；未扫描项不伪造大小。确认之后发生规则或冲突变化需要重新核对，敏感文件提醒也不能绕过路径与总量限制。

网络响应丢失时，服务器可能已经发布文件。于是上传状态可以按身份读回，同内容复用，临时对象和未完整发布对象不进入可用列表。超时或断连不能自动重传覆盖；这与工具调用的未知结果问题相同。

## 透明记忆为何比隐式累积更合适

只让历史留在当前对话，不能支持项目中新建对话。把所有历史自动塞进新请求，又会重复当前会话并让背景失去来源。项目选择说明、版本化笔记和有来源摘要：说明表达固定要求，笔记沉淀结论，摘要帮助理解其他对话做过什么。

新运行冻结选定背景，等待续接使用同一版本；修改笔记采用版本比较，摘要记录截止位置和生成代次，避免迟到自动结果覆盖用户编辑。摘要仍有信息损失和容量成本，不等于检索系统，也不能替代计划和文件版本事实。

后续界面发现“当前内容”和“本次运行实际使用内容”被混在入口里。最终将摘要放回稳定内容分区，技术预览归开发者入口，并标明快照归属。用户能修正现在的背景，不意味着已经修改等待运行的冻结输入。

## 删除补齐了更长的资源寿命

归档只是隐藏和禁用新工作，不能回收全部数据。后续永久删除和业务清空需要处理项目文件、快照、共享附件、沙箱、迟到回调和失败重试；只删除数据库行可能遗留资源，也可能误删其他对象引用的附件。

最终采用固定清理清单与准入协调，资源处理完成后再删除业务记录，保留失败阶段及重试，配置不随业务清空删除。这没有提供跨所有后端的原子删除；真实 COS 和多实例链路仍有验证空白。

交付副本与附件各自记录结果，一项失败只补该项；通用长任务成果设计另见 [交付背景](plans-and-delivery.md)。
