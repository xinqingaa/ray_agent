# 工具观察与执行效率的演进

2026-10-08 的审查从“为什么浏览器每次都截图”开始，扩展到正文质量、工具反馈、模型往返和资源准备。结论是需要改善动作与观察的契约：简单删掉截图，既不能消除全部开销，也可能让用户失去结果。完整设计见 [浏览器观察与视觉资源方案](../plan/browser-and-visual-resources.md)。

## 自动截图原本供谁使用

当时内置浏览器工具完成后，只要没有被策略拒绝，就尝试截图并上传。导航、读正文、读日志、执行只读脚本和部分失败都会进入分支；截图与面板是否打开、任务是否需要视觉判断无关。

顺序是工具结果先写模型记忆，再由运行器补图，图片引用保存给前端。模型收到的是工具 JSON 文本，没有收到像素，因此过程预览不能证明模型检查过排版或图表。历史纯读网页任务确实产生三个不同截图引用，但没有比较像素，不能声称三张完全相同。

每次补图还包括 PNG 编码、CDP 传输、文件写入或 COS 上传、元数据提交，串行等待发生在完成事件持久化前。工具 duration 当时已计算，不含这部分；墙钟差额不能直接当作截图耗时，也不能套用视觉模型图片 token 价格。

默认视口图又不一定覆盖页面下半部分，缩到侧面板后文字更小；动作结束也不等于 SPA、图片和目标状态已稳定。改成每次整页长截图只会改变范围，不能解决时机、目的和输入链路。

## 删除截图为何还要同步修改展示

旧 SSE 的浏览器展示内容主要来自截图字段，没有直接投影工具原始结果。前端虽有无图展示分支，标准事件却缺正文和日志。因此不能只删补图：动作结果、URL、文本观察和错误需要从同一次结果派生给模型与 UI，实时和历史回放采用同一契约。

这也发现了文件和 Shell 展示补读：为了预览再次读取环境，可能拖延循环，甚至把后来的内容当成当时结果。最终优先复用已有结果，有界补充不得改写历史事实。工具动作成功但观察失败时，界面和模型应看到两个状态，不能为了补观察重放提交动作。

## 浏览器效率还受到哪些契约影响

| 调研时的问题 | 对执行的影响 | 后来采用的方向 |
|---|---|---|
| 正文将父节点和后代 outerHTML 重复拼接，通用落盘前已截断 | 输入冗余、长页内容不可恢复，可能诱发重复读取 | 源头去重并保留范围，统一结果整形 |
| 导航主要返回元素，点击等主要返回成功标记 | 每个动作后要再发一轮观察 | 允许同次返回所需文本、元素或状态 |
| 元素编号重用、自动跟随标签页 | 引用可能指向其他节点或页面 | 绑定标签页和真实 DOM 节点，失效后重新观察 |
| 参数不足也可能返回成功，输入失败后回退再输入 | 无动作却显示成功，或出现部分重复输入 | 严格动作参数和输入语义，不盲目重放 |
| 控制台补丁只在脚本执行时注入 | 空日志不足以排除页面错误 | 可靠采集错误、警告和页面异常 |
| 提示允许多调用，适配参数却限制生成数量 | 程序能执行批量，不代表模型实际可生成批量 | 按模型能力编码，依赖动作失败后停止后续写动作 |
| 所有网页都用渲染浏览器，全量外部能力提前准备 | 文本取数和短任务也承担准备成本 | 公开正文用轻量读取，交互/登录/JS 用浏览器，能力按需发现 |

这些是当时源码可达路径及影响推断，不意味着每一项都在用户任务中复现。模型批量生成和程序并发执行是两个开关；同页写动作应保持顺序，独立白名单读取才适合有界并发。项目文件保护则需要自己的准备顺序。

## 外部方案提供的是分工参考

原调研阅读了 Playwright MCP、Chrome DevTools MCP、Codex/Cursor 浏览器资料和 Anthropic 工具契约。结构化观察与显式截图可以分别提供，轻量 fetch 与渲染交互也可以分工；视觉 Agent 的截图必须真正进入模型输入。

这些是 2026-10-08 查阅公开资料形成的分析快照，没有平台间同任务性能实测。RayAgent 使用自研 DOM/Markdown 与元素列表，不能直接称为某外部工具的可访问性树，也无需为借鉴分工迁移框架。

## 视觉输入与永久交付怎样拆开

视觉分析需要模型能力、实际图像字节、编码尺寸、像素预算与请求重建一起接通。只返回下载 URL 能留证，不能证明模型看图。显式截图因此分别支持分析与交付：临时分析图按运行归属和期限回收，永久附件沿交付规则保存，历史保留元数据及到期状态。

模型不支持视觉或图像不符合当前输入限制时，保留文件材料并说明原因，不猜图、不自动切换模型。用户上传图片后来沿同一能力边界接入，交互过程见 [配置与输入背景](interaction-and-configuration.md)。

2026-10-11 的实际任务又发现用修改 body 宽度或强制 grid 单列代替窄屏验证。这不能证明 CSS 媒体查询生效，于是增加指定标签页的真实 viewport，记录原值、运行归属及恢复。它仍不等于触屏、软键盘或真实移动设备。

## 优化结果怎样解释

受控页面、节点替换、审批续接、观察失败、实际视口、临时图到期和随机像素标记分别验证不同边界。并发三读取的受控等待减少了；表单的后测墙钟却没有比前测更快，冷暖与缓存条件也不同。因此保留“契约改善”和具体观察，不宣称所有任务统一提速。

完整条件见 [工具、视觉与模型验证](../plan/evidence/tools-and-models.md)。当时未覆盖任意网页、真实 COS 回收与默认大窗口视觉压力，优化不能被描述成通用浏览器认证。
