# 工具观察与执行效率的设计取舍

浏览器动作、观察、模型输入与界面展示有不同目的。将它们固定绑定，会增加等待，也容易让展示结果被误认为模型依据。详细契约见[浏览器与视觉资源](../harness.md#浏览器动作与视觉资源)。

## 为什么截图是显式动作

自动为每个动作截图，会将像素编码、传输和存储成本附加到纯文本任务。截图范围也不一定覆盖目标状态，页面加载完成不证明业务已经完成。

截图是否供模型分析，与是否作为附件交付是两个选择。分析需要真实字节、编码、模型能力与容量共同成立，返回下载 URL 或展示图片不能证明模型看过像素。

## 为什么模型与界面复用同次结果

为了展示再次读取文件、终端或页面，可能增加等待，还可能把变化后的内容当作动作当时的结果。因此动作、URL、观察和错误从同次结果派生，历史展示不通过重读环境补造。

动作成功但观察失败时，两个事实必须同时保留。恢复观察只读取状态，不能诱导重新点击、输入或提交。

## 为什么节点身份与正文范围属于契约

父子正文重复拼接会增加输入，源头裁剪又可能使长尾无法读回。提取需先减少重复并说明范围，结果整形只能保存已经取得的内容。

元素编号重用或自动切换标签页可能让旧引用指向其他目标，因此引用绑定页面与真实节点，失效后重新观察。输入部分生效后再换路径重试，也可能重复提交，不能由异常统一推断动作未发生。

## 为什么按任务选择读取方式与并发

无需登录的公开正文可以轻量读取，登录、动态状态和交互需要渲染浏览器。浏览器无需承担所有取数任务，轻量读取也不能承诺还原任意页面。

模型能生成多个调用，不代表这些调用可以并发执行。同页写动作依赖页面状态，保持顺序；只有独立白名单读取适合有界并发。项目文件保护还有独立的准备顺序，不能为提速省略。

## 为什么视觉资源和真实视口各有所有权

临时分析图与正式交付附件具有不同寿命，分别保存归属和引用，才能在回收分析字节时保留历史解释及交付文件。

修改业务 CSS 会改变被测对象，不能代替真实视口检查。视口变更因此保存页面原值与运行归属，并在收尾时尝试恢复；它仍不能模拟触屏、软键盘或设备性能。

契约减少重复往返，不代表所有任务都会统一提速。性能比较需要相同模型、输入、缓存和资源条件，墙钟差额不能直接归为截图或模型成本。
