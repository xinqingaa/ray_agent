# 桌面日常使用验收待办

环境为 macOS Apple Silicon。上一轮使用独立验收数据根、公开资料及 DeepSeek Flash。本轮使用主工程现有的桌面实例、gpt-6.1-sol 及「验收资料」中的中文样本。下列条目来自实际运行，后续统一处理。

## 交付任务误把文件写到系统桌面

- **复现**　在启用本机执行的网页工作区，要求交付单文件 HTML 到「本次成果」，并说明“我在桌面哪里能打开”。任务会话「SFPL 中文数字协助活动筛选页」运行完成。
- **实际**　成果区正常出现 HTML，模型同时用 Shell 将同一文件复制到系统桌面。三处的文件哈希一致。用户原意是找 RayAgent 桌面界面中的入口。
- **预期**　回复说明成果卡片、预览和下载入口。系统桌面等工作区外位置的写入需要明确目标。
- **影响**　一次普通的交付入口询问产生额外用户文件。现行 Shell 运行于本机用户权限，按现有执行边界分析，此条是交付行为和目的地确认问题。
- **证据**　运行 `a66a2fdd-0f54-4e5b-a504-3f6a43995bba`。时间线在交付工具之前有实际复制操作，末尾回复将系统桌面路径当作主要打开方式。

## HTML 从成果打开后，页面内导出日历被拦截

- **复现**　在单文件活动页成果卡点击「在浏览器中打开」，Chrome 成功载入。隐藏取消场次、选择有效场次，再点击页面提供的「导出所选日历」。
- **实际**　隔离页脚本可筛选。在同一预览接口的控制复测中，Chrome 未发出下载事件，控制台报告沙箱缺少下载许可。RayAgent 自己的 HTML 文件下载正常且与原件逐字节一致。同一份原件从独立回环静态入口运行时，下载的 ICS 包含正确的旧金山时区和时段。
- **预期**　用户能顺利取走导出的日历，或者预览入口明确告知限制，并给出可行的原件打开路径。处理时维持预览隔离边界。
- **影响**　预览看起来可操作，核心交互到最后一步才失败。
- **证据**　Chrome 复测收到 HTTP 200；响应的 HTML 沙箱策略禁止脚本联网，且没有下载许可。筛选 12 月 8 日显示 2 条，取消的其中 1 条不能选择。独立副本的导出事件为 2026-12-08 10:00–12:00，`America/Los_Angeles`。

## 应用内缺少项目运行预览和重新打开入口

- **复现**　生成可交互的网页，查看成果卡、右侧「成果」和「文件夹」，尝试找到应用内的运行页面。
- **实际**　HTML 成果有「查看」「在浏览器中打开」和「下载」入口。桌面操作实际把页面交给系统 Chrome。内置浏览器属于任务工具。当前文件预览的隔离策略禁止 fetch/XHR，无法借此加载带 API 的应用。
- **预期**　在工作区中明确提供生成网页的运行、查看、重开和导出路径。静态多文件工程和依赖本机服务的工程要能说明各自的启动方式、运行状态与可移交文件。
- **影响**　用户拿到源码或 ZIP 后仍需知道怎样启动和验证。对于服务型作品，打开入口和生命周期需要额外解释。
- **证据**　桌面单文件预览实测，当前机制见[文件预览](../product.md#文件预览)。此条是验收发现的产品缺口。
- **主工程复现**　网页工作区的「下周排班移动网页」完成 Vue 与 Python 换班版，交付试用入口、源码和前端构建包。运行期间本机试用地址返回 HTTP 200。任务完成后端口停止监听，从成果卡打开试用入口、点「打开本机换班页」，Chrome 显示 `ERR_CONNECTION_REFUSED`。最终答复仍称服务已启动，用户必须解压再按说明启动才能用。源码包独立复测通过，两个 ZIP 内的前端一致，临时副本换班、停止、重启后读回成功。会话 `c9f6e925-0f45-4da7-9f53-c66d3377daaa`，该次运行 `5a6a35df`。

## 工作区写入互斥时，任务连续重试并要求用户终止另一会话

- **复现**　在办公工作区分别启动场地申请交付和中文扫描件转表，两条都需要本机 Shell。扫描件会话先持有工作区写入租约。
- **实际**　场地任务多次收到相同占用提示，连续重试 16 次后进入等待，并要求用户关闭扫描件会话。咨询工作区发生过同类占用，压力咨询会话探测 PDF 读取时也收到占用反馈。
- **预期**　保留互斥保护。对稳定占用识别并停止盲重试，说明占用来源和恢复路径，优先让仍可完成的步骤继续。
- **影响**　重复模型与工具调用消耗时间和额度，还可能误导用户停止另一条有价值的任务。
- **证据**　核心直连复测中，场地任务 `282b917c-f6e3-4e6f-a0a6-e122a48af4f8` 的第 172、174 号事件为第 16 次探测及占用反馈，第 179 号事件请求用户关闭另一会话。后来回到原桌面对话续跑交付。
- **主工程复现**　咨询工作区的主管沟通会话读取看板期间占用 Shell 写入租约。面试会话第 85、100 号事件两次尝试写入工作区内的提纲并被拒绝，后来写入会话目录，通过成果附件成功交付。用户可下载；工作区内没有自动落盘的副本。面试会话 `36c202e6-c2ca-47c7-b5fb-f74668dfab76`。本轮下载该附件到咨询目录，方便复核。

## 传统 Word 原件缺少清晰的应用内阅读路径

- **复现**　打开带有南沙区公开申报材料的办公工作区，展开含三份 `.doc` 的目录，查看文件行与知识索引。
- **实际**　传统 `.doc` 可以列入文件夹，但没有可检索标记。核心实际读取这些原件时依靠本机格式转换。点击自查表后右侧显示「暂不支持预览」，面板有「在 Finder 中显示」。标准 DOCX 原件在同一工作区可进入全文索引。
- **预期**　对常见历史文档提供明确的可阅读或转换路径。格式属于能力缺口时，保留原文件并就地提示原因与外部打开方式。
- **影响**　真实申报仍可能收到旧 Word 文件。用户难以在应用中判断该附件是等待索引，还是需要另存或转换。


## 生成的 Excel 在预览里看不到汇总值

- **复现**　从南沙盖章扫描件生成 Excel，随后在 RayAgent 的电子表格预览读取「类别汇总」页。
- **实际**　生成文件的明细 22 项复核正确，公式也在。公式缺少保存的计算结果，预览接口在名单小计两列返回 SUM 公式和未缓存标记。用外部表格引擎重算副本后得到 22 项、1,630,100 元。
- **预期**　交付可编辑工作簿前检查关键汇总值。对于需要外部重算的文件，交付回复给出能立即核对金额的入口或清晰提示。
- **影响**　用户点进刚生成的文件无法直接看见本次任务的关键数字。现行 Excel 预览机制详见[文件预览](../product.md#文件预览)。

## 验收工具无法直接连接未打包的开发窗口

- **条件**　主工程通过开发命令启动未打包的 macOS RayAgent，桌面进程及其核心正在运行。本轮要求从这个窗口发起任务。
- **实际**　桌面自动化工具只识别独立安装的 RayAgent 应用。按运行中的可执行文件绝对路径和进程名连接都返回 `Invalid app`，还未进入应用界面。已确认 `docs/todo/验收资料` 的输入文件齐全。
- **影响**　此项属于验收工具的连接限制。本轮由用户授权后用 AppleScript 按进程号接入现有窗口，完成三个工作区的验收。

## 任务停止后看不到当前进度，也缺少继续入口

- **来源**　用户发现。几轮真实任务中，手动停止或运行被动中断后，执行过程收起，用户需要再发一条「继续」才能往下做。
- **定位**　时间线对完成、停止、失败和中断统一应用结束后的默认折叠。手动停止有文字提示，但没有「继续任务」按钮。部分失败提供「重试」，会重新发送该次运行的原指令。验收中，报销任务停止后发送「继续」，在同一对话内启动新运行并做完。
- **预期**　停止或中断后直接展示停在哪、原因和已经生成的成果，提供「继续任务」入口。继续时沿用当前对话、计划和已有成果，先核对结果未确认的步骤，避免重复写入或提交。

## 工作区知识检索框连续输入会丢字

- **来源**　用户发现。检索时键盘输入和框内文字对不上。
- **定位**　工作区「知识」检索框把页面地址中的查询参数直接作为输入值，每次按键都通过导航更新。用项目相同的前端依赖做了最小复现，在导航更新尚未生效时连续输入 `a`、`b`，最终只剩 `b`。改用输入框自己的状态接收按键后，同样的操作保留了 `ab`。
- **预期**　输入框及时保留文字和光标位置，再按需同步检索词和页面地址。修复后在 macOS 桌面端验证连续输入、中文输入法选词和回车上屏。顶栏「搜索对话」使用另一套输入组件，本次复现覆盖工作区「知识」。

## 运行组件说明没有讲清装前装后的能力

- **来源**　用户发现。没安装文字识别时，支持视觉的模型仍能识图。没安装语义检索时，仍能搜到工作区材料。设置页没有把这些路径讲清楚。
- **定位**　自动化浏览器提供本机浏览器操作，与联网搜索、公开网页正文读取及通过系统浏览器打开成果分别工作。文字识别组件在本机把扫描页和图片文字加入工作区索引，模型直接看随消息发来的图片取决于模型视觉能力。全文检索一直在本机可用，安装语义检索后，工作区文件建完语义索引才会加入按含义匹配的结果。
- **预期**　设置页说明每个组件额外提供什么能力，未安装时哪些入口仍可用。在知识页区分全文检索、语义索引构建中及语义检索已就绪。

## 顶部切换栏与工作台的选中动画不一致

- **来源**　用户发现。截图圈出了顶部的「对话／背景／知识」和右侧工作台的「文件夹／成果／查看／修改」。
- **实际**　顶部切换时选中底块直接换到目标项，缺少滑动。右侧工作台切换时，新选项的文字已出现，滑块还在移动。
- **定位**　顶部是路由链接，按当前页面给链接直接切换背景，只有文字做过渡。右侧用 `SegmentedControl`，滑块根据选中按钮的位置和尺寸更新，文字则独立展开和淡入。现有检查覆盖滑块的最终位置和尺寸，桌面端过渡时序仍待验证。
- **预期**　两处的选中态切换观感一致。右侧标签和滑块同步，切换过程中避免新标签已经出现、底块还明显停在旧项。验收时在桌面端用鼠标和键盘来回切换，并确认系统开启减少动态效果时选中态直接到位。

## 运行组件安装进度和操作入口需要重新设计

- **来源**　用户发现。运行组件的下载进度应改成水波纹动效，安装和卸载需要易辨认的 SVG 图标，卸载须二次确认。
- **现状**　运行组件页用细进度条显示下载字节数。安装、更新或重试主要是文字按钮，目前没有组件卸载入口及卸载接口。
- **进度设计**　从安装图标的位置进入进度态，在同一位置显示有边界的水波填充。已知总量时，填充高度随实际下载比例推进，旁边保留百分比或字节数。等待、总量未知、校验、完成和失败分别显示清楚的阶段，校验时保留「正在校验」。系统开启减少动态效果时，仍可从静态填充和数字看进度。
- **图标与卸载**　绘制同一套线描 SVG。安装用向下箭头落入托盘，卸载用带减号的组件盒，悬浮、键盘聚焦和读屏均能取得操作名称。点卸载图标后先在确认框列出组件名、卸载影响和保留的内容，再提供明确的「确认卸载」。卸载涉及组件资源及能力状态，需要一起验证占用提示、卸载失败、重新安装和各项能力的回退。

## 工作方式的入口文字过多

- **来源**　用户发现。空态和标题栏都铺了文字，设置工作方式、模板、版本历史希望用 SVG 图标。
- **预期**　把设置或编辑、模板、版本历史做成一组对齐的线描 SVG 操作，空态保留一句能说明用途的短提示。各图标提供悬浮提示和可访问名称。编辑态的保存、取消和「下一次运行生效」仍清楚可见。

## 记忆列表的抓手、行内操作和新增入口不好用

- **来源**　用户发现。悬浮时左侧出现抓手，却无法按条目排序，行内图标没有居中。「添加记忆」入口和正文区域也需要一起整理。
- **定位**　当前拖放只在钉住与其余分组间改变钉住状态，组内拖动不会改变顺序。抓手的外形让人以为可以重排。抓手和行末操作各自定位，多行正文和来源信息展开时需要核对整行对齐。
- **预期**　若抓手用于排序，支持可见的插入位置及保存后的顺序恢复，并提供键盘操作。若保留跨组钉住，交互要明确体现钉住状态变化。重新对齐抓手、正文起始位置和行末图标，悬浮或聚焦时动作可见且不挤动文字。「添加记忆」入口与编辑区一起设计，表单集中展示正文、类型、保存和取消。

## 按需召回区域分割线多，记忆条目难扫读

- **来源**　用户发现。按需召回的多层分割让标题、分组和正文挤在一起。
- **预期**　在折叠标题上集中呈现展开状态和条目数，展开后用间距和简短分组标题建立层级，减少重复分割线。正文优先阅读，来源、类型和行内操作靠同一条对齐线组织，展开来源时保持行的阅读顺序。

## 索引页的范围设置和运行操作堆在一起

- **来源**　用户发现。截图圈出了「内容类型」「Agent 产出」「后台索引」和「重新扫描」所在区域，要求重新排版。
- **定位**　内容类型是多选，Agent 产出策略是单选，两处现在用了相同的筛选按钮样式。后台索引打开时固定写「后台索引中」，即使上方显示处理数为零，也容易看成正在执行。
- **预期**　把「哪些文件进入索引」和「现在怎样运行索引」做成主次清楚的两组。内容类型保留可独立开启的表达，Agent 产出明确是手动或自动二选一。分清后台开关已开启、正在处理和已暂停，把「重新扫描」放在运行状态旁边，范围统计和文件列表连续可读。
