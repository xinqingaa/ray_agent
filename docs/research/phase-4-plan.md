## 2. 合并调研后的结论

此次整合实际覆盖 5 篇正文，不含目录 README：工作区调研、课程评审、能力评估、Codex 比较、改造复审。原分散稿撤出 research，证据的日期、基线和更正集中保存在背景说明；本文承担唯一可执行路线。

### 2.1 保留、改变和不做

| 类别 | 决策 |
|---|---|
| 保留 | Python、自研 Harness、现有分层、Web UI、PostgreSQL、Redis 传输、Docker 沙箱、MCP/A2A、浏览器和文件交付 |
| 改变主循环 | 开放任务改为单 Agent 工具反馈循环；计划改为 `update_plan` 工具，不再强制另一个 Planner 逐步调度 |
| 改变记忆职责 | 持久事实、模型工作上下文、摘要分开；保留数据库，不迁移为 JSON 文件型主存储 |
| 改变运行契约 | 独立运行与调用身份，准确终态、预算、取消、等待/授权及中断处理 |
| 改变交互与交付 | 模型流式、完整工具调用集合、事件补齐、具体产物检查 |
| 暂不做 | 长期项目工作区、跨会话自动记忆、向量库、worktree 并发、多 Agent 团队、插件市场、框架迁移、跨实例自动接管、通用 exactly-once |
| 运行范围 | 单执行 worker、受管理的沙箱环境；已有沙箱模式保留但必须明确资源归属；不宣称生产多租户隔离 |

移除独立 Planner 是设计选择，不是“所有双循环都不合理”。若未来业务确实要求固定阶段或独立验收节点，可以另设业务流程。本阶段不产品化两套执行策略，也不新增自动选策略的路由模型。

### 2.2 差距与严重程度

| 差距 | 旧方案事实 | 目标与优先级 | 工作包 |
|---|---|---|---|
| 强制计划交接 | 两份 Agent 记忆、步骤 JSON、步骤后规划及最终总结 | 中：减少非必要交接，计划与调度分开 | P2 |
| 上下文无主动预算 | 全量追加，成功步骤后定点删浏览器结果 | 高：每次请求前控制容量，长轮次内可压缩 | P4 |
| 记录与上下文混合 | 会话 JSONB 中保存可变消息与事件 | 高在职责、低在介质：原始事实和模型视图分开 | P1、P4 |
| 终态不准确 | 停止也算完成，预算主要是单次上限 | 高：运行级状态、总预算及原因 | P1–P3 |
| 副作用重试 | 基类异常固定重试，缺少统一未知状态 | 高：区分可重试和结果未知，禁止盲目重放 | P3、P6 |
| 取消不完整 | 协程停止不代表 OS 进程结束；A2A 有取消尝试 | 高：取消所有权、句柄及确认 | P3 |
| 授权与隔离 | 提示词确认，缺少统一执行前策略 | 高：策略检查与真实隔离同时存在 | P3 |
| 部分流式 | 业务 SSE，模型整包响应 | 中高：文本 delta、工具完整性与完成状态分开 | P5 |
| 事件与历史 | 先 Redis 后数据库，运行关联不足 | 高：持久完成事实、稳定序号、补齐去重 | P1、P5 |
| 多工具响应 | 请求关闭并行，响应还只截取首条 | 中：先不丢调用、按 ID 配对顺序执行；并行后置 | P2、P5 |
| 中途输入与恢复 | 与旧计划/记忆回滚耦合；历史不等于恢复 | 中高：明确输入生效点、等待续接、重启中断 | P1–P3、P6 |
| 成果判断 | 假完成守卫和总结不能证明交付成功 | 高：具体产物验证、运行状态与验证结论分开 | P6 |
| 长期工作区 | 会话可多轮，没有独立项目寿命 | 条件性：明确后置，不妨碍本阶段完成 | 不纳入 |

校准结论：单循环不等于整个系统只有一个循环；JSONL rollout 不等于长期记忆，Codex 同时使用 SQLite；写入队列不承诺任意故障零丢失；worktree 不提供记忆或 OS 权限隔离；会话 resume 不保证远端副作用恰好一次。本计划采用其职责分工，不复刻全部产品。

不设置固定“12 个任务 × 3 次”或 20% 收益门槛。架构选择依据需求；行为回归必须做。只有宣称成功率或成本的量化改善时，才另做同模型、同预算、多次尝试的比较并报告波动。

## 3. 目标契约：先确定什么，再写代码

以下是目标契约，尚未实现。P1 将其细化为迁移、接口和测试；命名可在该工作包内调整，职责与保证不得静默删减。

### 3.1 状态与数据

| 对象 | 目标职责与持久化 | 不承担的职责 |
|---|---|---|
| Session | 多轮对话、附件关系、运行列表与展示摘要；兼容旧会话读取 | 不把会话状态当唯一执行事实 |
| Run | 本轮目标、配置/策略版本、预算累计、状态、结束原因、恢复关系 | 不保存可跨重启复活的协程 |
| ToolCall | call ID、执行尝试、参数引用、结果引用、副作用类别、取消确认 | 不把超时自动当作未执行 |
| 持久记录/事件 | 按 session/run/item/seq 关联；数据库保存完成事实，Redis 传输通知 | 不让 UI delta 成为权威事实 |
| ContextSnapshot | 模型消息投影、摘要、来源范围、版本和 token 估算 | 不覆盖原始事实，不共享不同会话历史 |
| PendingInteraction | 提问或授权类型、作用域、待处理调用、恢复关联 | 不把用户普通回复自动解释为所有操作授权 |
| Artifact/Verification | 可下载的产物版本、来源运行、验证方式和结论 | 不把模型宣称当验证通过 |

数据库采取增量迁移：保留旧 session/files 数据，新增运行、调用、按序记录及上下文快照所需结构；不得把全部新数据继续写回单个无限增长的 session JSONB。完成记录与相应数据库状态尽可能同事务提交。文件系统和远程工具仍在事务外，需要对账，不能称为全链路事务。

Run 状态至少区分 queued、running、waiting_input、waiting_approval、completed、failed、cancelled、interrupted；预算耗尽以明确结束原因表达，不伪装成功。等待回复继续同一运行并记录新的执行 attempt；已终止运行的显式续接创建有来源关系的新运行，保留旧终态。新运行重新分配预算必须在界面中明确，等待续接不能重置已用预算。

运行完成与成果验证分开：验证结果至少区分通过、失败、未检查/需人工检查。计划全部打勾不自动使验证通过；验证失败不在 UI 展示为目标成功。

### 3.2 输入、授权和副作用

- 同会话最多一个活动运行；等待态同样占有该会话。用数据库原子约束/状态迁移限制重复创建，不只靠进程内字典。部署明确限制为单执行 worker，禁止冒充多实例所有权方案。
- 客户端请求 ID 去重，返回同一次已创建的执行。运行中补充输入有持久 ID，在当前工具集合结束的安全边界消费；停止走独立控制路径。变更目标不能静默扩大既有授权。
- 提问回复与工具调用按 ID 正确配对；审批绑定调用及参数摘要、资源范围和策略版本。拒绝、过期、参数改变后授权均有明确处理。重启不自动重放审批中的写操作。
- 工具分为可安全重试、需幂等保护、结果未知需核对等类别；策略为未知的外部工具采用保守规则，不能完全信任工具自行声明的只读标签。普通 Shell 不靠命令字符串黑名单证明安全。
- 先保存调用意图，再执行，再保存结果。进程崩溃造成结果未知时，查询可确认的进程/文件/远程任务；无法确认则说明并等待显式处理，不能据一条意图记录自动补执行。
- 最小安全范围是无敏感宿主挂载、明确工作根与执行身份、CPU/内存/进程限制及配置化网络策略。浏览器、MCP/A2A 外部写入也需经过策略入口。完整租户、组织权限系统后置。

### 3.3 模型、预算和事件

- 保留当前模型供应商适配路线，不强制换 Responses API。完整消费工具调用集合并保持 ID 配对，首版串行执行；模型不调用工具时仍检查待输入、等待、预算、运行错误和交付条件。
- 单轮模型调用次数、总耗时和 token 预算跨工具循环、重试、摘要累计。活动执行时间与等待用户时间分开记录；token 未提供时标未知并采用保守估算，不能记零。供应商缺少精确计数时不声称精确费用硬上限。
- 模型请求前 Context 预算包括系统指令、工具 schema、历史与输出预留；摘要保留目标、授权约束、待办、关键结果和错误，调用/结果保持成对。超大输出外存并提供可读取引用，明确清理寿命。
- 模型文本 delta 供增量展示；完整工具参数通过校验后才执行；模型响应未正常结束时，不把半截参数作为调用依据。已执行调用不能因模型流重试而重复执行。
- 持久完成记录采用稳定 ID 和单调序号，先持久化再通知；通知丢失可从数据库补齐。连接断开不自动取消执行。delta 可以暂态，重连后以完整 item 与当前运行快照收敛，不重复追加已存在内容。

### P1：基线、运行/存储契约与兼容基础

依赖 P0。先重跑相关服务指南规定的旧基线检查，保存实际环境、模型配置及失败信息；保留旧版 Git 提交、历史会话与附件读取样本，不保存实际凭据。

旧会话默认可查看、可下载既有附件；不自动拼接 Planner/ReAct 两份记忆继续。续接入口明确“基于旧记录开始新版运行”，仅选择目标、经确认摘要与可用附件，保留来源。旧 sandbox ID 先验证可用性，不能直接当存活环境。

影响：API 会话/任务应用服务、领域模型与仓库、ORM/UoW、Alembic、接口类型、UI 历史与状态映射；入口见[改造代码映射](../code-map.md#第四阶段改造入口)。docs 更新状态归属、兼容与边界；课程 08、09、10 先明确新契约与当前进度，尚未交付能力不写成已实现。

验收：空库升级、旧库升级、旧历史及附件读取、重复请求与并发创建、状态/完成记录事务失败。使用专用数据库验证，不只用内存替身。此包不自动改生产数据库。

### P2：单循环与计划工具

依赖 P1。用一个自研执行循环消费工具反馈，新增计划更新工具；去掉运行时独立 Planner、强制 Step JSON 和独立总结交接。正常内容输出与工具结果、交付附件分开建模。计划面板显示清单，不再要求前端从步骤调度事件推断运行终态。

整理中英文提示词：保留必要工具使用约束，移除与旧双循环、强制通知工具及固定环境描述冲突的规则；进度输出可使用内容事件。先完整支持同轮多调用的顺序执行，校验重复 call ID、缺失工具、错误参数及每个调用对应的结果。

运行中消息在安全边界消费；提问和回复持久化配对，等待续接重建上下文，不回滚任意一条消息。总次数/时间预算在此生效，token 预算在 P4 完整接入。

影响：Flow/Agent/提示词/工具注册、Runner、依赖装配、计划和消息事件、UI 计划面板；docs 核心循环与分层；课程 02、03、04、06、07。旧流程测试转为新不变量测试；原双循环案例归 background/Git，不长期保留产品双模式。

验收：纯回答不强制规划；真实工具反馈可多轮推进；计划不控制步骤指针；完整多调用回填；提问后同运行续接；新输入、无进展、迭代耗尽及错误出口正确。包含真实模型小规模任务，不设固定数量或收益门槛。

### P3：工具策略、取消与沙箱资源

依赖 P2。分发前统一参数校验、策略决策和授权；等待审批与普通提问使用不同记录及 UI。按调用/参数/范围绑定授权，拒绝反馈可回到模型，批准不突破沙箱硬限制。

贯通运行取消→调用取消→Shell 进程组/远端取消→确认记录；区分任务前台子进程和显式后台服务。修复或验证 Shell 输出读取器阻塞导致无法按时返回句柄的问题；终止超时使用有界升级，不误杀其他运行资源。浏览器取消报告已发出动作与不可撤销副作用。

动态和已有沙箱用显式 ownership 决定销毁权；修正 TTL 配置名称；核对执行身份、资源配额、允许目录与网络。API 需要 Docker 权限不意味着沙箱应获得宿主 Docker socket。纯文本任务和文件任务按实际需要准备浏览器，避免固定依赖所有资源。

影响：工具分发和策略、Runner/任务适配、沙箱 HTTP 契约及 Shell/文件服务、Docker/配置、浏览器、MCP/A2A、UI 授权和停止状态。课程 03、08、11、13、14、15；docs 资源归属、控制边界及服务指南。

验收：审批拒绝/过期/参数变化、目录和符号链接边界、受控网络策略、真实进程树取消、忽略 TERM 的进程、外部容器不被误删、TTL 和配额；MCP/A2A 保留协议测试，远端取消无法确认时 UI 如实报告。前端按钮变化不能代替进程验证。

### P4：上下文预算与记忆分工

依赖 P3。实现请求前 Context 构建、估算与实际 usage 校准；长结果按大小外存、保留引用和摘要；按 token 水位在轮次内压缩，保留目标、用户约束、授权和调用配对。原始消息、摘要版本和来源范围独立，摘要调用计入预算。

预算不足时先选择/压缩，再确认能否请求；无法缩减或摘要失败有明确停止原因，不能无限重试。缺失外存引用返回可解释错误，不假装内容仍在。原始内容保存遵守访问控制、保留与脱敏，禁止把模型原始请求和凭据无差别写调试日志。

影响：Memory/Context、模型接口及 usage、存储仓库/文件存储、预算配置、UI 用量展示。课程 05 主更新，02、08、09、10、16 联动；docs 状态与记忆职责、能力与边界。

验收：同一长轮次触发压缩、中文及工具 schema 计数、超大单结果、摘要失真与失败、调用配对、使用量缺失、预算跨重试累计、重建后约束仍在。记录压缩前后容量及所需事实是否保留，不只比较 token 数。

### P5：端到端流式与事件一致性

依赖 P4。模型适配返回增量及完成对象；按调用 ID/index 拼装多个工具参数，完整校验后分发。处理空片段、混合文本与调用、UTF-8、异常中断、finish reason、usage 延后到达及重试。供应商不支持流式时走明确兼容路径，不假装流式；并行执行仍不在本包。

API→SSE→UI 统一 run/item/call 身份；完成结果先保存，通知可重放。实现游标补齐、重复事件去重、订阅与历史之间的竞态处理；重连以完整记录收敛临时文本。修复现有 SSE CRLF 分片及 EOF 观察脚本暴露的边界，旧限制不能继续算“通过”。

影响：模型抽象/适配、事件、仓库、Redis 通知、路由/schema、Nginx 超时/缓冲、前端解析/hooks/消息与工具组件；课程 02、10 主更新，06、09 联动；docs 产品与观测说明、API/UI 指南。

验收：确定性分片夹具、同轮多调用、断流不执行半截参数、完成消息不重复、刷新/断线补齐、数据库失败和通知失败窗口；浏览器中真实流式任务与停止。首个事件、首个有意义文本、首 token 和总耗时分别统计，不能混用。

### P6：中断对账与成果交付

依赖 P5。启动时识别遗留活动运行为 interrupted；扫描处于执行中但没有结果的调用，记录确认/未知；安全读取可重试，外部写入不得盲目重放。用户显式续接产生新运行，继承已确认事实，预算和来源可见。

把成果验证落到文件内容、附件版本与下载、工具实际执行结果、测试退出码等可判定对象；开放报告质量可人工评价。交付失败、部分交付、验证失败与模型总结分开显示。保持既有文件串行替换和旧附件可下载语义，不重新引入已修复问题。

影响：启动/运行协调、记录仓库、文件同步/存储、校验器及 UI 产物和终态；课程 09、12、16 主更新，06 联动；docs 产品、恢复边界及运行指南。

验收：动作前、动作后结果未保存、结果保存后通知丢失三个故障窗口；真实 API 重启、重复提交、附件上传失败/下载、进程或远端结果无法确认。成果检查器本身必须有反例，不能只测正常文件。

### P7：新版课程与全部图文整合

依赖 P1–P6 相关实现与证据。各包已局部同步；本包检查 16 章跨章用语、示例、导航、能力表述与配图一致性。课程直接以新版机制为主线；旧方案只随需要链接 background，不在每章留一套旧正文。

优先完成机制章节 02–05、07–10、11–16，再用真实端到端任务重写 06，最后校准 01、目录、README 和项目总览。每个章节都区分教学简化与实际实现，并使用当次验证条件。旧 PNG 取证不能标为新版界面。

验收：下述文档/配图矩阵全部有处理结论；正式 SVG 完成结构检查、渲染和目视检查；链接有效；无“当前双循环”“模型非流式”等过期当前事实；不删除仍合理的通用比较。

### P8：综合验收、兼容回归与结项

依赖 P7。按服务指南运行全套受影响测试、UI lint/build、专用数据库迁移检查、沙箱真实进程与协议测试，再做真实 Web 文件/浏览器/外部工具任务及故障场景。验证部署与本地依赖一致；清理测试资源，保留脱敏的验证摘要。

检查旧历史、附件、升级回退；删除未使用旧运行路径与临时开关，保留作者许可。确认 docs/lessons/界面承诺与通过证据一致，将尚未验证范围写入能力与边界。只有进度证据完整才结项，不以计划打勾代替结果。

| 文档与图 | 链接、当前能力与证据一致、全部图处理、中文版标题/导航 | 静态核对＋实际渲染目视 |

每次证据至少记录：工作包/验收项、代码提交与未提交变更、环境与模型版本、输入和初始条件、预期、实际结果、产物引用、未覆盖范围。凭据与敏感原始轨迹不进入仓库。行为测试不固定模型必须按某一种工具顺序完成；不要把有效替代轨迹判失败。

## 9. 执行纪律、风险与停止边界

- 后续实施按包建立可审查变更，每包完成代码、对应回归与局部图文后再推进；进度中的“完成”必须有证据。不要求每次常规修改都另写规格文档，复杂契约直接在本文对应节落实。
- 范围漂移时先更新本计划及受影响验收项，不以“Codex 有这个功能”为新增需求依据。工作区、自动记忆、分布式和多 Agent 不得夹带进来。
- 主要风险是迁移损坏历史、取消误伤资源、工具重放、摘要丢约束、流式半截调用、UI 误报成功以及教材提前宣称新能力；分别由 P1、P3、P4、P5、P6、P7 验收覆盖。
- 已实现但未验证必须单独标注；外部模型、Docker 或数据库条件不足时记录阻塞，不用 mock 通过替代真实检查，也不把整个阶段标完成。
- 不给出无基线的工期承诺。先完成 P1 的基线与迁移范围核对，再按实际变更量评估后续耗时；以验收包而非代码行数/课时衡量进度。

阶段完成后的最大变化：RayAgent 从以步骤调度和消息堆积为中心，升级为有明确运行契约、有预算上下文、可追溯工具动作和可核对交付的 Harness。是否提高成功率或降低成本，按实际测量表述，不预先保证。
