## 2. 合并调研后的结论

此次整合实际覆盖 5 篇正文，不含目录 README：工作区调研、课程评审、能力评估、Codex 比较、改造复审。原分散稿撤出 research，证据的日期、基线和更正集中保存在背景说明；本文承担唯一可执行路线。

### 2.1 保留、改变和不做

| 类别 | 决策 |
|---|---|
| 保留 | Python、自研 Harness、现有分层、Web UI、PostgreSQL、Redis 传输、Docker 沙箱、MCP/A2A、浏览器和文件交付 |
| 改变主循环 | 开放任务改为单 Agent 工具反馈循环；计划改为 `update_plan` 工具，不再强制另一个 Planner 逐步调度 |
| 改变记忆职责 | 持久事实、模型工作上下文、摘要分开；保留数据库，不迁移为 JSON 文件型主存储 |
| 改变运行契约 | 独立运行与调用身份，准确终态、预算、取消、等待/授权及中断处理 |
| 改变交互与交付 | 模型流式、完整工具调用集合、事件补齐、具体产物检查 |
| 暂不做 | 长期项目工作区、跨会话自动记忆、向量库、worktree 并发、多 Agent 团队、插件市场、框架迁移、跨实例自动接管、通用 exactly-once、运行中人工接管协议、后台服务跨运行转交 |
| 运行范围 | 单执行 worker、受管理的沙箱环境；已有沙箱模式保留但必须明确资源归属；不宣称生产多租户隔离 |

移除独立 Planner 是设计选择，不是“所有双循环都不合理”。若未来业务确实要求固定阶段或独立验收节点，可以另设业务流程。本阶段不产品化两套执行策略，也不新增自动选策略的路由模型。

### 2.2 差距与严重程度

| 差距 | 旧方案事实 | 目标与优先级 | 工作包 |
|---|---|---|---|
| 强制计划交接 | 两份 Agent 记忆、步骤 JSON、步骤后规划及最终总结 | 中：减少非必要交接，计划与调度分开 | P2 |
| 上下文无主动预算 | 全量追加，成功步骤后定点删浏览器结果 | 高：每次请求前控制容量，长轮次内可压缩 | P4 |
| 记录与上下文混合 | 会话 JSONB 中保存可变消息与事件 | 高在职责、低在介质：原始事实和模型视图分开 | P1、P4 |
| 终态不准确 | 停止也算完成，预算主要是单次上限 | 高：运行级状态、总预算及原因 | P1–P3 |
| 副作用重试 | 基类异常固定重试，缺少统一未知状态 | 高：区分可重试和结果未知，禁止盲目重放 | P3、P6 |
| 取消不完整 | 协程停止不代表 OS 进程结束；A2A 有取消尝试 | 高：取消所有权、句柄及确认 | P3 |
| 授权与隔离 | 提示词确认，缺少统一执行前策略 | 高：策略检查与真实隔离同时存在 | P3 |
| 部分流式 | 业务 SSE，模型整包响应 | 中高：文本 delta、工具完整性与完成状态分开 | P5 |
| 事件与历史 | 先 Redis 后数据库，运行关联不足 | 高：持久完成事实、稳定序号、补齐去重 | P1、P2、P5 |
| 多工具响应 | 请求关闭并行，响应还只截取首条 | 中：先不丢调用、按 ID 配对顺序执行；并行后置 | P2、P5 |
| 中途输入与恢复 | 与旧计划/记忆回滚耦合；历史不等于恢复 | 中高：明确输入生效点、等待续接、重启中断 | P1–P3、P6 |
| 成果判断 | 假完成守卫和总结不能证明交付成功 | 高：具体产物验证、运行状态与验证结论分开 | P6 |
| 长期工作区 | 会话可多轮，没有独立项目寿命 | 条件性：明确后置，不妨碍本阶段完成 | 不纳入 |

校准结论：单循环不等于整个系统只有一个循环；JSONL rollout 不等于长期记忆，Codex 同时使用 SQLite；写入队列不承诺任意故障零丢失；worktree 不提供记忆或 OS 权限隔离；会话 resume 不保证远端副作用恰好一次。本计划采用其职责分工，不复刻全部产品。

不设置固定“12 个任务 × 3 次”或 20% 收益门槛。架构选择依据需求；行为回归必须做。只有宣称成功率或成本的量化改善时，才另做同模型、同预算、多次尝试的比较并报告波动。

## 3. 目标契约：先确定什么，再写代码

以下是目标契约，尚未实现。P1 将其细化为版本化记录、接口规格与仓库契约测试；P2/P3a 等行为产生包负责端到端验收，P1 不宣称真实执行器已支持这些状态。命名可在该工作包内调整，职责与保证不得静默删减。

### 3.1 状态与数据

| 对象 | 目标职责与持久化 | 不承担的职责 |
|---|---|---|
| Session | 多轮对话、附件关系、运行列表与展示摘要；兼容旧会话读取 | 不把会话状态当唯一执行事实 |
| Run | 本轮目标、配置/策略版本、预算累计、状态、结束原因、恢复关系 | 不保存可跨重启复活的协程 |
| ToolCall | call ID、执行尝试、参数引用、结果引用、副作用类别、取消确认 | 不把超时自动当作未执行 |
| 持久记录/事件 | 按 session/run/item/seq 关联；数据库保存完成事实，Redis 传输通知 | 不让 UI delta 成为权威事实 |
| ContextSnapshot | 模型消息投影、摘要、来源范围、版本和 token 估算 | 不覆盖原始事实，不共享不同会话历史 |
| PendingInteraction | 提问或授权类型、作用域、待处理调用、恢复关联 | 不把用户普通回复自动解释为所有操作授权 |
| Artifact/Verification | 可下载的产物版本、来源运行、验证方式和结论 | 不把模型宣称当验证通过 |

数据库采取增量迁移：保留旧 session/files 数据，新增运行、调用、按序记录及上下文快照所需结构；不得把全部新数据继续写回单个无限增长的 session JSONB。完成记录与相应数据库状态必须同事务提交；提交失败不得发布完成通知或推进执行位置。文件系统和远程工具仍在事务外，需要对账，不能称为全链路事务。

Run 状态至少区分 queued、running、waiting_input、waiting_approval、completed、failed、cancelled、interrupted。queued 只表示准入成功、已持久接收但执行尚未启动，不是等待资源的调度队列；预算耗尽以明确结束原因表达，不伪装成功。等待回复继续同一运行并记录新的执行 attempt；已终止运行的显式续接创建有来源关系的新运行，保留旧终态。新运行重新分配预算必须在界面中明确，等待续接不能重置已用预算。

启动协调必须在接受新运行或回复之前完成，不能将所有活动运行统一改为 interrupted。

| 重启前状态 | 启动后的处理 | 回复与预算 |
|---|---|---|
| queued | 首版标为 interrupted，原因为启动前中断，不自动执行积压任务 | 用户显式续接创建新 Run，保留来源 |
| running | 标为 interrupted，缺少结果的调用待对账，相关环境隔离 | 不自动重放，处理未知结果后才允许续接 |
| waiting_input | 保留原状态、交互记录及调用集合位置 | 按交互 ID 回复后继续原 Run、增加 attempt，累计预算不重置 |
| waiting_approval | 保留原状态；旧批准不得在重启后自动触发写操作 | 重新检查参数、资源与策略版本，必要时重新审批；继续原 Run |
| completed / failed / cancelled / interrupted | 保留原终态与来源 | 显式续接创建新 Run |

等待态表示调用集合已持久暂停，不存在未登记的前台执行。恢复前检查环境及引用；环境丢失或被隔离时保留等待并展示阻塞原因，允许取消。需要重建环境时使旧授权失效并重新核对事实，不静默换环境执行。重复回复与回复/取消竞态使用原子状态迁移处理，迟到回复不得重新激活终态。

运行完成与成果验证分开：验证结果至少区分通过、失败、未检查/需人工检查。计划全部打勾不自动使验证通过；验证失败不在 UI 展示为目标成功。

### 3.2 输入、授权和副作用

- 同会话最多一个活动运行；等待态同样占有该会话。用数据库原子约束/状态迁移限制重复创建，不只靠进程内字典。部署明确限制为单执行 worker，禁止冒充多实例所有权方案。
- 客户端请求 ID 去重，返回同一次已创建的执行。运行中补充输入有持久 ID，通常在当前工具集合结束消费；提问或审批形成的持久暂停边界也可处理补充输入，并按下述规则作废过时调用；停止走独立控制路径。变更目标不能静默扩大既有授权。
- 提问回复与工具调用按 ID 正确配对；审批绑定调用及参数摘要、资源范围和策略版本。拒绝、过期、参数改变后授权均有明确处理。重启不自动重放审批中的写操作。
- 完整模型响应中的调用集合先整体保存，再顺序执行；逐调用保存位置、状态、结果和 attempt。已完成动作不得因续接重放，缺失工具或错误参数产生对应 call ID 的失败结果，不静默丢弃。
- 集合中遇到提问或审批立即暂停后续调用。回复按交互 ID 配对；拒绝审批、目标改变或参数/资源失效时，当前调用保存拒绝/作废结果，后续未执行调用显式作废并补齐对应结果，再交回模型重新决策。纯澄清且目标未变时可重新校验后继续，授权仍逐调用检查。取消时保存未执行状态，续接投影补齐配对但不伪造执行结果；下一次模型请求不得包含缺少结果的调用集合。
- 工具分为可安全重试、需幂等保护、结果未知需核对等类别；策略为未知的外部工具采用保守规则，不能完全信任工具自行声明的只读标签。普通 Shell 不靠命令字符串黑名单证明安全。
- 先保存调用意图，再执行，再保存结果。进程崩溃造成结果未知时，查询可确认的进程/文件/远程任务；无法确认则说明并等待显式处理，不能据一条意图记录自动补执行。
- 环境使用权与销毁权分别记录。首版对已有共享沙箱实行环境级单运行占用，覆盖文件、Shell 与浏览器上下文；单 worker 内的异步任务也不能绕过。等待态保留占用，前台调用全部结束或取消确认、且没有遗留写入者后才释放。
- cancelled/interrupted 不证明资源已停止。取消无法确认的环境标为隔离并禁止自动复用，对账确认安全后才释放；远端任务仍可能写入的资源范围同样记录阻塞，不能仅更换本地沙箱就判安全。本阶段不支持后台服务跨运行转交；运行启动的进程必须登记并归该运行所有，结束时清理，无法确认停止则隔离。沙箱自身浏览器等基础服务归环境所有，不按运行进程误杀。
- 最小安全范围是无敏感宿主挂载、明确工作根与执行身份、CPU/内存/进程限制及配置化网络策略。浏览器、MCP/A2A 外部写入也需经过策略入口。完整租户、组织权限系统后置。

### 3.3 模型、预算和事件

- 保留当前模型供应商适配路线，不强制换 Responses API。完整消费工具调用集合并保持 ID 配对，首版串行执行；模型不调用工具时仍检查待输入、等待、预算、运行错误和交付条件。
- 单轮模型调用次数、总耗时和 token 预算跨工具循环、重试、摘要累计。活动执行时间与等待用户时间分开记录；token 未提供时标未知并采用保守估算，不能记零。供应商缺少精确计数时不声称精确费用硬上限。
- 模型请求前 Context 预算包括系统指令、工具 schema、历史与输出预留；摘要保留目标、授权约束、待办、关键结果和错误，调用/结果保持成对。超大输出外存并提供可读取引用，明确清理寿命。
- 新版会话的普通新 Run 继承同会话前序已确认消息、结果及可用附件引用，使用有效快照及其覆盖序号之后的增量构建历史，不能只读当前 Run。快照标明来源范围、覆盖序号和版本，压缩替换原子发布；失效时从持久记录重建，避免重复或遗漏。跨会话不自动继承，旧会话转换遵循第 5 节：P1 定义 legacy 契约，P2 实现确认入口，P8 演练升级。
- 系统约束、当前目标及用户约束记录、待处理交互、策略和授权状态从权威记录重新注入；摘要仅辅助理解，不能授予权限或覆盖这些记录。历史授权不因上下文继承而自动沿用。P2 实现跨 Run 历史投影与请求前容量保护，放不下时明确停止，不任意截断调用配对；P4 增加主动压缩、外存和快照，使长任务能够继续。
- 外存结果使用受会话访问约束的不可变引用与内容版本，提供模型可调用的分段读取工具，限制单次返回大小；读取结果同样经过 Context 预算，禁止全量反复回灌。P4 明确保留期限、引用失效及会话删除后的清理，不能仅提供不可读取的摘要链接。
- 模型文本 delta 供增量展示；完整工具参数通过校验后才执行；模型响应未正常结束时，不把半截参数作为调用依据。已执行调用不能因模型流重试而重复执行。
- P1 定义身份及游标契约，P2 一次接通持久记录、非增量 SSE、历史与 UI；P5 只扩展模型 delta，不再次更换权威身份。持久完成记录采用稳定 ID 和单调序号，先持久化再通知；通知丢失可从数据库补齐。连接断开不自动取消执行。delta 可以暂态，重连后以完整 item 与当前运行快照收敛，不重复追加已存在内容。请求重传按 request ID 去重，运行与内容按 run/item ID 投影；相同文本不能推断为同一运行。显式重试/续接保留原终态、动作和来源，不删除失败轨迹。

### 3.4 现有产品链路的最小闭环

以下补充归入已有工作包，不增加工作包或独立平台。交互必须让用户知道当前发生了什么、是否需要处理以及可采取的下一步；目标仍是文件、浏览器和外部工具任务。

| 环节 | 本阶段必须明确的行为 | 工作包 |
|---|---|---|
| 正式交付入口 | P2 删除总结阶段时，同步提供显式交付工具，接收待交付文件及说明；校验路径后保存不可变存储副本，成功后绑定消息附件，失败则将错误回填模型并显示给用户。不从自然语言猜路径，也不等到 P6 才恢复附件功能。P6 的验证绑定实际交付版本与具体检查要求，文件存在不等于内容正确 | P2、P6 |
| 输入资料准备 | 区分已上传、已准备可读、准备失败；用户本次提交的附件默认都是所需输入，同名附件不能静默覆盖。准备失败时暂停进入模型执行，允许重试准备、取消，或由用户明确排除失败附件后继续；排除和缺失信息进入持久记录及模型上下文 | P2 |
| 浏览器控制边界 | 本阶段新版入口只提供只读画面，不开放运行中人工接管；提示词不得再要求用户接管。服务端禁止用户输入转发，不能只靠前端 viewOnly；做不到安全只读时关闭交互 VNC 入口并保留截图预览。需要人工登录/交互的任务明确报告暂不支持，不伪装继续 | P2、P3a |
| 环境占用与阻塞退出 | P3a 实现环境准入：先按 request ID 查询去重记录，再检查会话/环境占用，准入事务同时认领环境并创建 queued Run；竞争失败返回冲突且不创建 Run，不新增调度队列。相同 request ID 已创建时返回原 Run；准备失败则结束该 Run 并清理资源。P6 提供核对/放弃续接；未知资源不因放弃而释放，重建需先确认旧资源停止 | P3a、P6 |
| 会话删除 | P1 定义删除与创建互斥契约；P2–P5 的新版测试入口暂不开放删除。P6 统一实现第 5 节删除顺序及失败重试，并联验所有资源与引用；不拆成各包分别宣称删除已完成，不新增回收站 | P1、P6 |
| 内容信任与任务验收 | 网页、文件和外部工具结果保留来源，经过摘要也不能变成用户指令或授权；以反例验证该边界，不宣称彻底解决提示注入。真实任务除了机制通过，还要核对目标与交付质量；不新增通用评测平台 | P4、P8 |

输入准备失败使用持久交互记录区分原因，P1 定义记录、P2 接入行为；无需为后置的人工接管预建状态机。重建环境或删除数据都不能被普通模型输出隐式触发。

## 4. 工作包、技术依赖与切换门槛

工作包编号是职责标识，不代表必须按编号串行。技术依赖如下；单人实施可选择串行，但不得把选择的日程当作技术前置。

| 包 | 技术前置 | 包结束时可证明的行为 | 是否切换现用版本 |
|---|---|---|---|
| P0 计划与背景 | 无 | 范围、背景、证据入口一致 | 否 |
| P1 契约与迁移基础 | P0 | 真实数据库上的记录、约束、升级/回退及旧数据读取 | 否；不接管旧执行器 |
| P2 非流式新版纵向链路 | P1 | 单循环、真实提问续接、基本交付、容量保护、持久事件到 UI 闭环 | 否；专用测试部署 |
| P3a 执行控制 | P2 | 审批、环境准入、取消与未知隔离 | 否；专用测试部署 |
| P3b 环境硬限制 | P3a | 受支持环境的权限/配额/网络与按需准备 | 否；专用测试部署 |
| P4 Context 压缩 | P2 | 长任务预算、压缩、快照及外存读取 | 否；不依赖 P3b |
| P5 模型增量 | P2 | delta 展示、分片完整性及与持久 item 收敛 | 否；不依赖 P4 |
| P6 对账与交付收口 | P3a、P4 | 未知结果处理、版本验证、删除全链路 | 否；不依赖模型 delta |
| P7 课程图文整合 | 局部随对应包；最终汇合 P1–P6，含 P3b | 全课程与最终实现一致 | 否 |
| P8 综合验收与发布 | P1–P7 全部完成 | 新旧数据升级演练、真实任务与故障回归、一次性发布切换 | 达标后才允许 |

**包完成不等于对现有用户发布。** P1–P7 在开发分支和专用测试部署递增验证，新版部署使用独立测试数据；现用版本保持旧基线。P8 才执行第 5 节的停机升级与 UI/API 同步切换，不产品化双执行模式。真实外部写操作只在 P3a 相应控制验收后测试，P2 使用每会话独立的临时沙箱及受控协议夹具，不支持共享环境；未知资源由测试操作者核对清理，不冒充已实现环境准入。

### P0：计划与背景整理

交付统一计划、独立进度、旧方案背景、PLAN 软链接和维护入口。验收唯一来源、引用和范围一致；计划编制不授权产品实施。

### P1：基线、契约与迁移基础

重跑旧基线，保留旧会话/附件样本，并冻结第 8 节必需任务场景。定义 Run、Call、持久事件、交互和环境记录的身份/版本/状态迁移及 UI schema；Context 快照、验证和删除所需关系先定接口，具体算法由后续包实现。

使用增量迁移、仓库与 UoW 建立数据库约束，验证 request ID 去重、状态与完成记录同事务、单活动运行、删除/创建互斥。可以人工构造等待/审批/未知记录测试迁移和启动扫描的规则函数，但必须标为契约测试，不计为真实等待、审批、占用或重启续接通过。P2 才把启动协调接入应用生命周期，P3a 才产生审批和实际占用。

本包同时实现可配置的显式迁移入口：新版部署启动只检查 schema 版本，不再无条件执行 upgrade head；版本不匹配拒绝启动。升级命令与备份/回退步骤写入服务指南，在专用库演练，禁止自动操作现用数据库。

验收：空库/旧库增量升级、旧历史/附件读取、事务回滚和并发约束、构造记录的状态迁移、schema 不匹配拒绝启动、备份恢复及兼容读取。不得把未来行为的 fixture 通过写成运行证据。文档更新存储契约与迁移指南，保留当前执行事实。

### P2：非流式单循环与前后端纵向链路

依赖 P1。在新版测试部署中一次接通 Run 创建、执行器、数据库事件、非增量 SSE、历史读取和前端状态。去掉独立 Planner/Step JSON/总结交接，新增计划工具、显式交付工具与输入准备路径；保留所有调用并按 ID 顺序回填。

P2 必须满足以下硬规则，全部通过才可结项：

- 纯回答不强制规划；每个调用得到真实结果、失败结果或明确未执行结果，重复/缺失 call ID 不进入分发；同集合遇到提问持久暂停，回复或变更目标后按第 3 节处理，不重放前序动作。工具异常首版保守地不自动重试可能有副作用的调用，保存未知结果并停止；P3a 才按分类开放安全重试。
- 接入真实启动协调：queued/running 重启后中断，不自动恢复副作用；实际提问产生的 waiting_input 重启后继续同一 Run，重复回复及回复/取消竞态不产生第二次执行。审批与实际环境占用不在本包冒领验收。
- 总调用次数、活动时间及请求容量保护先落地，重试计入预算。每次请求估算系统/schema/历史并预留输出空间；超限停止为 failed 并给出 context_limit/budget_exhausted 等明确原因。P4 前允许长任务受控停止，禁止超限硬发或静默丢历史。非流式适配在 P2 即保留 finish reason；截断/异常结束不得执行工具或记为正常完成。
- 移除 Step 守卫时保留“不能以口头声称代替动作”的不变量：显式交付必须有存储副本和可下载附件；交付失败未修复则不能成功收口。可恢复工具错误可反馈模型继续，致命错误/预算耗尽为 failed，取消为 cancelled，崩溃为 interrupted；等待不是终态。无工具的正常回答可 completed，但不自动声称成果验证通过。
- 完成记录和运行状态提交成功后才通知；基础重连按持久游标补齐。UI 同步支持新版状态、同文本独立运行、失败轨迹与续接来源；不等待 P5 才改事件身份。停止显示“取消已请求/资源待确认”，不把协程结束描述为 OS 进程停止。
- 新版暂不开放会话删除、交互 VNC 或未知资源的自动复用；提示词和界面明确这些测试阶段边界。P3a/P6 再补齐控制和处置。

验收：真实数据库与浏览器完成纯回答、文件上传/生成/交付、提问重启续接、同轮多调用、交付失败和输入准备失败/重试/排除、同名附件、短跨 Run 对话、超限拒绝及各终态反例。事件通知失败后刷新不丢已提交内容；模型使用固定夹具和受控真实任务。局部更新 docs、课程 02–04、06–10、12 及受影响图，均描述非流式新版测试基线。

### P3：工具策略与环境控制

P3 为汇总包，P3a、P3b 分别验收，二者完成才结项。

#### P3a：审批、取消与资源准入

依赖 P2。统一工具分发前的参数/策略检查，审批绑定调用、参数及资源；实际产生 waiting_approval 并接通回复、拒绝、过期与重启后的重新校验。实现第 3.4 节环境准入和占用、调用句柄及资源隔离。

贯通运行取消→调用取消→进程组/远端取消→确认记录；修复 Shell 句柄迟迟不返回的问题，有界升级终止。登记运行创建的进程，运行结束时清理，无法确认则隔离；保留环境基础服务。不新增后台服务跨运行转交或运行中人工接管协议。新版画面只读由服务端保证；无法保证时关闭交互入口。

验收：真实审批的集合中间拒绝/过期/参数变化、审批中重启和迟到回复；进程树取消、忽略 TERM、远端取消未知；两会话争用同一环境、重复请求不重复认领、准备失败清理、等待保留占用、取消未知后拒绝复用、基础服务不误杀、已有容器不误删、只读画面不能注入用户输入。P6 前隔离资源仅展示阻塞，不宣称已有自动对账。同步控制/环境 docs 与课程 03、08、11、13–15。

#### P3b：受支持环境的硬限制

依赖 P3a，可与 P4/P5/P6 独立推进。修正 TTL 配置，落实容器身份、CPU/内存/进程配额、工作根与出站边界；纯文本/文件任务按需准备浏览器。仅支持服务指南中明确可执行与可验证的配置，不建设通用安全平台。

文件服务检查路径与符号链接；Shell 由挂载/权限及身份约束可写范围，exec_dir 不是围栏。网络限制必须覆盖实际出口，代理变量不等于强制策略。API 内的 MCP/A2A 单独核对允许对端、网络和 stdio 启动身份，不冒充受沙箱边界保护；已有环境缺少必要条件时拒绝相关能力。API 的 Docker 权限不得透传到沙箱。

验收：文件/Shell 越界反例、沙箱/浏览器与 API 协议出口反例、stdio 权限、TTL/配额、已有环境不合格时拒绝、文本任务无需浏览器及协议回归。课程 11、13–15 随本包更新；本包不阻塞其他章节的局部更新，但最终阶段结项必须通过。

### P4：上下文预算、压缩与外存

依赖 P2 的模型接口、预算账本和历史投影，不依赖审批或完整环境强化。在 P2 的超限停止之前增加选择/压缩：按水位触发，快照原子发布，按覆盖序号加增量重建；系统、用户约束与授权仍来自权威记录。摘要失败或仍放不下时保留 P2 的明确停止出口。

长结果外存并提供受会话约束的分段读取；读取与摘要均计预算，缺 usage 用保守估算并标未知。定义保留寿命、引用过期与无引用副本清理接口，P6 联验删除。保留外部内容来源，不通过摘要提升权限；不承诺通用提示注入防御。

验收：长轮次连续压缩、中文/schema 计数、超大结果分段再读、摘要失真/失败、快照提交失败、跨 Run 重建、约束保留、来源不升级、预算跨重试与摘要累计、引用过期。与 P5 汇合时复验流式 usage；与 P3a 汇合时复验真实审批记录，汇合测试列入 P8。更新课程 05 及 02、08–10、12、16 相关部分。

### P5：模型增量与临时内容收敛

依赖 P2 已稳定的 run/item/call/event ID、持久游标与 UI 投影，不依赖 P4。仅把模型适配扩展为增量及完成对象，按 call ID/index 组装参数，正常结束且校验完整才分发；断流不执行半截调用，重试不重复已执行动作。

delta 使用同一 item 身份及临时分片位置，允许丢弃，完成 item 替换临时内容。重连沿用 P2 持久事件补齐，P5 不另建完成事实、主键或游标。非流式供应商保留 P2 路径。

验收：多调用分片、混合文本/调用、UTF-8/CRLF/EOF、finish reason、延后 usage、断流/重试、刷新后完整 item 不重复、停止时不误报完成。真实浏览器观察首事件/首文本/首 token/总耗时；没有 delta 的供应商不伪装流式。更新课程 02、10 及相关图，不重做基础身份迁移。

### P6：未知结果对账、成果验证与删除收口

依赖 P3a 的真实调用/资源记录及 P4 的外存引用，不依赖 P5 delta。沿既有启动协调核对进程/文件/远端任务；无法确认则保留未知与隔离，允许重新核对或放弃续接，但放弃不证明安全。确认后才释放资源；已终止 Run 显式续接新 Run，等待态不被一律中断。环境重建只在旧资源停止确认后进行。

P2 已能交付附件，本包增加具体检查器、版本绑定与结果展示。文件存在、下载可用、内容符合指定规则、测试退出码分别记录；验证后文件改变需生成新版本重新检查，开放质量允许人工评判。

本包是会话删除全链路的唯一验收负责人，按第 5 节实现并测试冻结入口、资源处置、事务删除、存储清理与失败重试；不以各包的单点测试替代。

验收：动作前、动作后结果未存、结果已存通知丢失三个窗口；API 重启、未知结果无法确认/确认后放行、放弃后仍隔离、重建条件不满足拒绝；附件部分失败、下载和版本变化、验证反例；删除的并发创建、未清理资源拒删、数据库失败、存储清理失败重试、其他会话引用保留。同步课程 06、09、12、16 与产品/恢复说明。

### P7：随包更新与最终课程整合

局部更新依赖各自机制交付，不等待 P3b 或所有代码完成。每个包结束时，其改变的当前事实、正文与图必须一起更新；暂不能重绘的旧实现图撤出当前段落并链接历史基线，不能让新正文引用旧流程图。基线说明区分新版测试部署与尚未升级的现用版本。

最终汇合 P1–P6（含 P3b）后，核对 16 章、目录、README、docs 与全部配图；先机制章节，再用新版真实任务收口 06，最后校准 01 和导航。P7 不是首次更新，旧 PNG 不充当新版证据。验收链接、当前事实、教学简化标注、正式 SVG 的结构/渲染/目视以及全清单处理结论。

### P8：综合回归、升级演练与发布

依赖 P1–P7 完成。按第 8 节冻结的案例和通过线进行服务检查、真实 Web 任务、故障及 P3a/P4/P5 汇合回归；按第 5 节在旧数据副本演练停机升级、失败回退及旧等待入口。

### 5.1 身份、版本与旧数据

P1 定义新版 schema，P2 首次接通即使用数据库生成的稳定 event ID 与会话内单调 seq；API 返回带版本的持久游标（会话与 seq），历史与 SSE 共用同一完成 item。Redis Stream ID 只作内部通知位置，不作为新版 API 身份。旧事件仅由 legacy 投影读取，其旧游标不能送入新版订阅；遇到旧游标明确返回重新取历史的响应，UI 按版本重建视图。P5 不修改这套身份。

旧记录不补造 Run、取消或 token 事实，旧 completed 保留“旧版结束、原因未区分”的含义。旧 WAITING/RUNNING 不套用新版同 Run 续接：升级停机时终止旧执行资格、记录升级中断说明并保留原历史；用户从旧会话确认目标、摘要与可用附件后新建有来源的新版 Run。旧 sandbox ID 只作待核对引用，资源未确认安全不得认领。

### 5.2 一次性发布切换

P1–P7 是开发与专用测试包，P2 不替换现用版本。P1 将新版启动自动 migrate 改为 schema 检查，真正迁移由发布流程显式执行。

1. 停止新任务与回复入口，停止旧 worker；核对旧活动任务、等待会话及外部进程。无法确认的资源列为隔离，禁止新版本复用。
2. 备份数据库与附件存储并记录版本；在副本完成增量迁移、旧历史/下载/旧等待入口和回退演练。
3. 停机执行已验证迁移，同步发布 API/UI。启动先检查 schema，再协调新版遗留状态；旧任务不被当作新版 Run 扫描。
4. UI 同时切换新版状态、身份、订阅与 legacy 读取；检查文件交付、提问续接、停止和刷新后历史，再开放入口。
5. 失败则停止新写入并保留现场。已有新版写入不得用旧程序直接解释；使用验证过的兼容读取或备份恢复，明确恢复点之后的数据处置。不得宣称 downgrade 无损，也不让旧、新 worker 同时操作同一会话。

P1 验证迁移机制；P8 验证上述完整手续并记录实际发布结果。备份范围、恢复命令与条件维护在应用/API 指南。

### 5.3 删除的完整顺序（P6 负责）

删除先在数据库将会话标为删除处理中，与创建 Run 使用同一互斥条件；这是数据生命周期标记，不是新增 Run 状态。若仍有活动运行、未知调用或资源未释放，拒绝删除并恢复入口标记，给出取消/核对路径；不得先删事实再寻找资源。

资源确认安全后，在事务内记录待清理的无引用存储对象并删除会话关联记录；提交失败回滚，保留所有副本。提交成功后执行幂等存储清理，失败保留清理记录供重试，重试前复查存活引用；共享副本不得删除。UI 区分拒绝删除、会话已删除但副本清理待重试、清理完成。无需新增后台治理平台，清理重试入口及操作记录即可。

## 8. 验证矩阵与验收证据

验收分三层：P1 的记录/仓库契约、P2–P6 各自产生行为的集成验收、P8 的跨包与升级发布验收。人工构造状态只证明第一层，不能冒充第二层；测试部署通过不能冒充现用版本升级成功。

P1 在进度证据中冻结必需案例的输入、初始状态、预期产物、允许的人工介入与失败条件。以下覆盖必须全部保留，可用组合任务覆盖，不以固定次数估算统计收益：

| 必需场景 | 通过线 | 首次闭环／最终复验 |
|---|---|---|
| 纯回答与短跨 Run 对话 | 不强制工具/规划，后续回答正确利用指定前序事实，无重复运行 | P2／P8 |
| 文件与输入资料 | 上传输入可读；按要求生成/修改文件，下载字节与声明版本一致；缺资料或交付失败不可假成功 | P2／P6、P8 |
| 提问与审批 | 正确等待，重启和重复回复后只执行一次；拒绝不执行被拒动作 | P2 提问、P3a 审批／P8 |
| 浏览器查证 | 从预先指定的可访问页面取得待核对事实并给出可核对来源，不用模型臆测代替；不要求人工接管 | P3a／P8 |
| 外部工具 | MCP 与 A2A 各覆盖已支持的发现/调用/结果及失败路径，结果与受控对端一致 | P3a／P8 |
| 长任务与流式 | 指定长输入实际触发压缩后仍保留所需事实；分片/重连不漏调用或重复完成；超限有明确失败出口 | P4、P5／P8 |
| 故障与升级 | 三个副作用窗口不盲目重放，未知事实可见；旧历史/附件可读，旧等待只经确认转为新 Run；删除失败可重试且不误删共享副本 | P6／P8 |

全部确定性必需检查必须通过；真实场景必须有满足预先约定条件的运行与产物证据，记录所有尝试及失败，不能只保留成功一次。失败须说明原因、修复或验证外部条件后复验；不能以通过其他案例抵消，也不宣称一次成功证明成功率。若必需场景无法支持，需用户明确同意范围变更后同步计划与验收，不能仅改能力文案结项。耗时/用量/人工介入如实记录，缺 usage 标未知，未预设量化收益门槛。

## 9. 执行纪律、风险与停止边界

- 后续实施按包建立可审查变更，每包完成对应契约或行为验收与局部图文后再推进其依赖包；进度中的“完成”必须有证据。不要求每次常规修改都另写规格文档，复杂契约直接在本文对应节落实。
- 范围漂移时先更新本计划及受影响验收项，不以“Codex 有这个功能”为新增需求依据。工作区、自动记忆、分布式和多 Agent 不得夹带进来。新增发现先判断能否用现有工作包的交互、失败出口或验收补齐；商业化差距不作为阶段 4 的结项条件。
- 主要风险是迁移损坏历史、取消误伤资源、工具重放、摘要丢约束、流式半截调用、UI 误报成功以及教材提前宣称新能力；分别由 P1、P3、P4、P5、P6、P7 验收覆盖。
- 已实现但未验证必须单独标注；外部模型、Docker 或数据库条件不足时记录阻塞，不用 mock 通过替代真实检查，也不把整个阶段标完成。
- 不给出无基线的工期承诺。先完成 P1 的基线与迁移范围核对，再按实际变更量评估后续耗时；以验收包而非代码行数/课时衡量进度。

阶段完成后的最大变化：RayAgent 从以步骤调度和消息堆积为中心，升级为有明确运行契约、有预算上下文、可追溯工具动作和可核对交付的 Harness。是否提高成功率或降低成本，按实际测量表述，不预先保证。
