## 2. 选择依据及事实边界

### 2.1 现有实现与设计选择

| 已静态核对的实现事实 | 新设计与理由 | 工作包 |
|---|---|---|
| 独立 Planner 与执行 Agent 各有记忆，步骤后规划并最终总结 | 单循环工具反馈；`update_plan` 只维护展示清单，不调度步骤 | P2a |
| Memory 全量追加；局部 compact 改写浏览器工具消息 | 持久事实、请求投影、摘要快照分开；请求前容量检查 | P1、P2a、P4 |
| 停止写 completed，任务注册在进程内 | Run 独立状态；取消与中断保留原因，重启不自动补执行 | P1、P2a、P3a |
| 工具异常统一重试；协议超时也可能返回失败对象而不抛异常 | 按执行确定性分类结果；未知副作用不自动重试 | P2a、P3a |
| 模型整包响应、丢弃 finish reason，调用集合只保留第一条 | 保留完整响应与调用集合，先串行执行，再增加模型 delta | P2a、P5 |
| 事件先写 Redis 后写数据库，UI 有旧状态及内容推断 | 数据库身份与完成记录权威，SSE/历史统一投影 | P1、P2a、P2b |
| 提问续接依赖旧计划与消息回滚；总结负责附件交付 | 显式交互和调用状态续接，交付改成工具 | P2a、P6 |
| A2A 已有远端取消尝试；取消协程仍不能证明 OS/远端任务停止 | 复用协议取消能力，补持久结果、Shell 句柄和进程组收尾 | P3a |

现有路径和测试集中在[代码地图的第四阶段入口](../code-map.md#第四阶段改造入口)。单循环是开放任务的设计选择，不证明所有双循环都不合理；不维护两套执行策略。历史文件 ID 替换、未知工具 raise 等已修问题不再作为待办。

请求中的 `parallel_tool_calls` 只影响模型产出约束，不提供执行调度。本阶段保存模型实际返回的所有调用，按返回数组顺序执行，以 call ID 配对；默认继续关闭并行提示，不要求为多调用验收打开该参数。保留现有非标准 `tool_use` 兼容层，但只在显式配置的兼容路径启用，完整响应校验后归一化并一次性保存 ID。标准路径缺失/重复 ID 拒绝分发；兼容路径生成的 ID 在持久化后不得重建。项目使用自研循环与 OpenAI 兼容适配，没有 Claude Agent SDK 编排可供依赖。

采用的启发是职责分开：计划工具不负责步骤调度；运行循环还要处理输入、容量与结束条件；模型历史需满足调用配对契约。单循环不等于系统只有一个循环。JSONL 不等于长期记忆或零丢失事务，worktree 不等于权限隔离，resume 不等于远端副作用恰好一次。

本计划的摘要、数据库事务、交付工具与 Web 恢复规则是 RayAgent 自己的取舍，不声称等同 Codex。尤其“请求中的调用必须配对”不意味着压缩后必须保留全部旧调用；允许用摘要整体替换已结束片段，原始记录不改。

## 3. 唯一执行契约

### 3.1 新数据与运行状态

| 对象 | 最小职责 |
|---|---|
| Session | 对话、运行列表、附件关系与展示摘要；不再承担唯一运行状态 |
| Run | 目标、配置/策略快照、状态/原因、累计预算、取消请求、来源 Run |
| ToolCall | 所属模型响应、稳定 call ID、参数、执行位置、结果确定性与引用、取消句柄 |
| 持久记录/item | 原始消息与调用完成事实、会话内 seq；完成记录与对应数据库状态同事务 |
| PendingInteraction | 提问/审批类型、交互 ID、绑定调用、状态及回复；输入准备失败另标原因 |
| ContextSnapshot | 摘要/请求投影、覆盖序号、来源与版本；不是原始历史或授权来源 |
| Artifact | 不可变交付副本、来源 Run/Call、文件摘要及具体检查结论 |

使用独立表保存运行、调用与按序记录，不继续堆入单个 session JSONB。外部副作用不在数据库事务内：先保存调用意图，再执行，再保存结果；提交失败不得发布完成通知或推进到下一调用。

保留 queued、running、waiting_input、waiting_approval、completed、failed、cancelled、interrupted 八态。queued 仅覆盖“已持久接收、执行器未启动”的短窗口，不是任务调度队列。数据库约束保证同会话一个活动 Run（含两类等待），request ID 重传返回原 Run；相同 ID 携带不同请求体返回冲突。不同请求竞争同会话返回 409，不创建第二个活动 Run。

| 重启前状态 | 启动处理 | 后续入口 |
|---|---|---|
| queued | interrupted，原因是执行前中断；待执行调用记未执行 | 用户显式创建有来源的新 Run |
| running | interrupted；已有执行意图但无结果的调用保守记 unknown，即使实际可能尚未发出；仅未进入执行意图阶段的 pending 调用记未执行 | 不自动重放；处理相关未停止资源后显式新 Run |
| waiting_input | 保留交互与暂停位置，检查环境和输入引用 | 按交互 ID 回复继续同一 Run；新增 attempt，预算不重置 |
| waiting_approval | interrupted；关闭交互、旧审批失效，未执行调用作废 | 确认目标后显式新 Run，不能沿用旧批准 |
| completed / failed / cancelled / interrupted | 保留原终态、动作和原因 | 显式续接创建新 Run，不修改旧终态 |

启动扫描必须在接收任务/回复前完成。等待态只允许在前台调用已结束且暂停记录提交后写入；环境丢失时保留等待并提示阻塞，允许取消后显式重建/续接，不静默换环境执行。正常完成、停止、回复及启动扫描都使用原子状态迁移；终态不可被迟到回复或完成回调覆盖。

运行结束与目标验证分开：completed 表示循环正常结束，检查结论为通过/失败/未检查或需人工检查。计划全勾选或模型说“已完成”不构成验证通过。文件交付有失败且未修复时不得 completed；未提供文件的任务不能显示“文件已交付”。不建设通用目标理解裁判，开放质量由用户判断，冻结案例另有明确判据。

### 3.2 单循环、提问与审批

首版不支持运行中 steer：普通新消息在 running/queued 时返回 409；等待时只接收绑定交互 ID 的回复或停止。目标改变通过取消后新 Run 表达。通知不是完成条件；默认工具集不再暴露仅用于刷进度的 `message_notify_user`，过程由工具/计划事件与模型文本展示。

完整模型响应先归一化、校验并整体保存，再顺序分发调用；正常完成信号缺失、截断或半截参数均不能执行。缺失工具和错误参数得到对应 call ID 的确定失败结果；重复/缺失身份按第 2 节拒绝整个集合。计划工具更新清单及事件，不调度步骤。交付工具和提问工具直接加入同一循环。

提问调用保存为 awaiting_reply，后续调用暂存 pending，Run 转 waiting_input 并退出协程。此时尚未构造下一次模型请求，**不提前伪造提问结果或把 pending 标成已执行**。回复与交互关闭同事务提交：将回复写为提问调用结果，将该集合的后续 pending 调用标 skipped 并补“未执行：交互后重新决策”的结果；继续原 Run 请求模型，不沿用暂停前的后续动作。前序已完成调用不重放。

审批由工具分发前的策略触发，不额外伪造模型调用。批准只绑定当前调用的参数、目标环境和策略版本；恢复时一致才执行该调用，否则标未执行。拒绝/过期直接形成对应未执行结果。无论批准、拒绝或失效，本集合的其余 pending 调用都作废并补结果，再交回模型决策；重启按 3.1 中断审批。重复回复幂等，回复与取消竞争只允许一个迁移生效。

取消或中断的新 Run 历史投影保留已有调用事实；对未执行、拒绝、取消及 unknown 补可辨识的结果说明，不能伪造成功。下一请求不能包含悬空调用。显式续接不是从头重跑原工具数组；模型收到已完成与未知动作的记录后重新决策，涉及未知副作用的重试仍须单独处理。

以下为控制关系的简化伪代码，不是现有实现；事务、取消传播与协议细节以相应条款为准：

```python
async def execute(run):
    while run.is_active:
        await check_cancel_and_run_budget(run)
        context = await project_confirmed_history(run)
        context = await fit_request(context)  # P2a 拒绝超限；P4 可压缩
        response = await sample(context)  # 重试也记账；异常结束不分发
        calls = await validate_and_record_response(response)
        if not calls:
            await finish_if_allowed(run, response)  # 与取消原子竞争
            return
        for call in calls:
            await check_cancel_and_run_budget(run)
            if call.is_question or needs_approval(call):
                await persist_wait(run, call, remaining=calls.after(call))
                return  # 回复后补结果、作废后续，再启动本循环
            await persist_intent(call)
            result = await invoke_once(call)
            await persist_result_and_position(call, result)
            if result.is_unknown:
                await fail_with_unknown(run, call)
                return
```

### 3.3 结果分类、取消与支持环境

结果确定性与工具副作用类别分开定义。结果至少包括 succeeded、failed（确定失败）、not_executed（拒绝/作废/取消前未分发）、unknown（可能已执行）；普通业务失败可回填模型继续，unknown 保存后结束为 failed/execution_unknown。协议适配必须把超时/断连失败对象也映射到 unknown，不能只看是否抛异常或 success=false。

P2a 所有工具只尝试一次；`llm_max_retries` 只控制模型请求，默认最多额外重试 2 次，并关闭或纳入 SDK 内部重试，使预算可核对。P3a 才为代码配置白名单中的安全只读调用开放 `tool_max_retries_safe`（默认 0 次额外重试）。未知副作用没有自动重试开关；工具自报只读或 Shell 命令字符串不能证明安全。幂等写重试协议不在首版范围。

停止先持久记录请求 ID/时间并原子转 cancelled，再取消模型/工具协程；P3a 贯通沙箱进程组 TERM→有界等待→KILL，以及已有 A2A 取消尝试，保存 requested/confirmed/unknown 结果。停止与调用登记通过同一运行协调边界竞争：取消先发生则不分发，调用先登记则进入取消/结果核对范围，不能只在长请求返回后检查 Run 状态。P2a 只能验证逻辑取消，页面不能写“进程已停”。终态后的清理结果可继续更新，不改变原终态。

首版只支持**单执行 worker、每会话独占的动态受管理容器**，不接入跨会话共享/任意已有沙箱。运行启动的进程绑定 Run/Call；Shell 句柄在等待输出前可取得，API 丢响应后仍可按调用标识查询/取消。正常、失败、取消结束都清理该 Run 的进程；环境浏览器等基础服务不在此清理范围内。等待前不得遗留运行写入者；本阶段不支持把后台服务带入等待或下一 Run。

无法确认本地进程已停时，只将该会话环境标记不可复用，不建立通用隔离平台。P6 提供人工核对、终止自有容器/重建和放弃续接入口；重建必须先确认旧容器停止，说明未交付工作文件会丢失。远端结果未知显示任务 ID/状态和人工核对方式；“我要重跑”不等于“旧任务已停止”。在确认前不允许自动重试该动作；对同一外部目标的再次写入须显式确认处置，不声称可以自动识别任意外部资源冲突。

P3a 只验证一种文档化配置：无敏感宿主挂载、不向沙箱透传 Docker 控制权限、明确执行身份与工作根、基本 CPU/内存/进程配额及 TTL；文件路径检查含符号链接，Shell 依靠容器挂载和身份边界。公网访问允许但如实说明边界，不建设通用出站过滤。MCP/A2A 仅连接受信任且显式配置的对端，stdio 命令由操作者配置，不能由模型注入；API 协议进程不冒充在沙箱内。纯回答不依赖浏览器启动，浏览器按需准备。

策略采用少量固定 allow/ask/deny 规则：工作根内文件操作和受管理容器内普通执行按预授权范围允许；外部写操作或未知类别默认逐调用审批，禁用的工具不分发。无需自动分析任意 Shell 语义。Web 画面首版为截图/只读预览；服务端不提供交互 VNC 输入通道，提示词不要求用户人工接管。需要登录交互时明确报告不支持。

### 3.4 两类预算与上下文投影

- **运行预算**：Run 累计模型请求数、活动耗时和 `max_total_tokens`；涵盖模型重试、摘要及工具循环。等待用户不计活动耗时，续同 Run 不重置累计量，新 Run 分配新预算并显示来源。达到任一运行上限以 failed/budget_exhausted 结束；执行中的模型/工具请求须受剩余活动时间约束，到期走取消与资源收尾。
- **请求容量**：每次请求估算系统指令、工具 schema、历史与当前输入的总量，再加输出预留及安全余量，与 `context_window` 比较。不设置四段独立硬配额，但不省略任何组成部分。P2a 放不下则 failed/context_limit；P4 在请求前按水位压缩，再检查，仍放不下则停止。
- 请求前同时检查剩余运行额度是否足以容纳本次估算输入和允许输出，限制输出上限；调用后按 usage 结算。无精确 usage 的请求标未知并保守估算，不能记零或宣称精确费用硬上限。摘要同样占窗口和运行预算；留不出摘要额度时受控停止，压缩不会返还累计消耗。
- 新 Run 继承同会话已确认历史和可用附件引用；快照覆盖 seq 加之后的增量，失效时从原始记录重建。快照发布原子化，提交失败不推进覆盖序号；正在等待的调用集合不被摘要拆开。已结束片段可整段替换成摘要，剩余调用/结果保持配对，不要求永久将全部工具正文发给模型。
- 系统规则、当前目标、用户约束、交互和审批状态从权威记录注入，不由摘要授予权限。摘要保留目标、关键结果、错误与待办；外部网页/文件/工具内容保留来源，不能提升成用户指令。用户约束首版保留真实消息及来源，不建设模型自动维护的权限账本。
- P4 在工具适配层截断前保存受支持的长文本/JSON原始结果，再返回有界预览与不可变引用；模型可用分段读取工具获取后部内容，读取也经容量控制。不能把已经被 MCP/A2A 裁掉的字符串冒充完整外存。二进制/媒体保留现有显式省略边界，不在本阶段扩展媒体能力。
- 长结果设单结果/会话存储字节上限，超出保留可用部分并标明截断范围，不能无限积累 Shell 内存输出。引用寿命随会话，清理时删除；失效返回明确错误，不重复全量回灌。P6 联验清理，具体默认限额在 P1 配置契约、P4 实测后定值。

### 3.5 事件与模型增量

P1 定义 run/item/call ID、会话内单调 seq 和游标。P2a 落数据库完成事实及按 seq 查询 API；P2b 接通持久记录→SSE/历史→UI；P5 只加模型 delta。原 Redis SSE 路径不能直接充当数据库补齐功能，P2a 不借旧 UI 宣称新版通过。

完成 item 与状态同事务提交，Redis 只发通知；通知失败不回滚已经完成的事实，也不重放动作。SSE 按数据库 seq 追赶，订阅与历史交界不得留窗口；即使连接未断且终态通知丢失，也须通过有界检查发现新记录。断线不取消运行，重连按游标补齐，过期/非法游标明确要求重取历史，无旧游标兼容层。

P5 按 response/item/attempt 与 call index 组装分片，再确定 call ID；正常结束且完整校验后才执行整个集合。delta 可暂态，完成 item 替换临时内容。断流/取消时关闭或丢弃该 attempt 的临时 item，重试使用可区分的 attempt，不把半截文本拼到新答案上；终态刷新后不保留虚假的“仍在生成”。usage 可延后到达，但不得再次执行调用或把半截响应视为完成。保留非流式供应商路径，不强制换 Responses API。

### 3.6 输入、交付与基本清理

附件准备使用独立文件 ID/路径避免同名覆盖；全部本次附件默认必需。准备失败不进入模型，保存 waiting_input（原因 input_preparation），允许重试或明确排除失败附件后继续同 Run；排除事实进入上下文。该交互不伪造 tool_call。P1 定义，P2a 实现。

`deliver_artifact` 接收路径和说明，校验后保存不可变存储副本、绑定当前 Run 和下载附件，错误回填模型；删除总结阶段时同时接入，不从自然语言猜路径。每次重新交付产生独立副本/摘要，检查绑定实际下载字节；只做存在/下载、指定内容规则、测试退出码等具体检查或人工结论，不做通用验证框架。

P6 保留个人会话基本删除：活动 Run/待回复或资源未处理时返回冲突，先取消/核对；清理开始后拒绝新 Run。每会话独立目录，不做跨会话共享存储引用；跨会话使用文件必须复制。先清理该会话容器与独占文件，再删除数据库记录，失败保留会话及清理中标记供同一操作重试。允许失败清理已移除部分文件，界面明确不可继续任务；不承诺跨数据库/文件系统原子删除、回收站或后台清理队列。P2a–P5 暂不开放新版删除入口。

<a id="p2a"></a>
### P2a：后端单循环

- **P2a.1**：删除独立 Planner/Step JSON/总结调度，接入计划、提问和交付工具；保存完整调用集合、结果和执行位置，保留 finish reason 与错误分类，协议超时/断连返回对象也映射为 unknown。工具只执行一次，固定响应夹具覆盖非标准兼容路径、缺失/重复 ID、未知工具/参数失败。
- **P2a.2**：接入 Run 创建、启动扫描、提问/输入准备等待、按 ID 回复及历史投影；实现逻辑取消与终态竞态。验证等待中重启续同 Run、回复幂等、普通运行中输入 409、后续调用作废及已完成动作不重放。
- **P2a.3**：落实运行预算及请求容量保护，配置 SDK 重试归属；短跨 Run 历史可用，超限停止原因准确。工具/模型超时及 unknown 不伪装 completed。
- **P2a.4**：接入附件准备、同名隔离、失败重试/排除、正式交付；完成记录与状态同事务；提供按 seq 查询历史的 API。

### P2b：事件与界面

- **P2b.1**：将持久事件接 SSE/历史/游标，UI 按 run/item ID 投影；覆盖连接未断时通知丢失、历史→订阅交界、断线/重传/刷新与重复完成事件。
- **P2b.2**：新版页面支持文件下载、计划、提问/回复、预算和终态、续接来源；失败轨迹不删除，同文本不同 Run 不合并。逻辑取消显示资源待确认；只读截图入口和删除禁用一致。

<a id="p3a"></a>
### P3a：最小执行控制

- **P3a.1**：按第 3.2/3.3 节实现固定策略、逐调用审批和安全重试白名单，沿用 P2a 的结果分类。验证拒绝/过期、回复取消竞争、审批中重启转 interrupted、旧批准无效，以及真实协议返回 unknown 时不重试。
- **P3a.2**：Shell 按 Run/Call 登记进程和句柄，取消传播及 TERM/KILL 有界收尾，持久记录 A2A 取消结果。真实进程验证子进程、忽略 TERM、句柄响应丢失、正常结束清理、基础服务不误杀；未知时禁止复用该会话容器。
- **P3a.3**：验证一种动态容器配置的执行身份、挂载/路径、基本配额、TTL 及按需浏览器；拒绝共享/已有环境配置，只读预览由服务端保证。对现有浏览器、MCP/A2A 各做最小接入及失败回归，不扩展鉴权/网络治理。

将原 P3b 必要小修合入本包，不单列环境加固平台。同步课程 03/08/11/13，14/15 仅更新接入及控制相关段。状态见[进度](phase-4-progress.md#checkpoints)。

## 8. 冻结案例与验收证据

以下八条是核心案例，不是成功率统计样本。P1 只补实际入口、受控路径/配置和数据生成器，不再从零决定通过线；夹具可约束调用序列以检验状态机，真实模型允许有效替代轨迹。每包先验自己产生的行为，P8 才复验整合后的真实 Web 链路。

| 案例 | 输入与初始条件 | 预期/禁止现象 | 首验与证据 |
|---|---|---|---|
| C1 纯回答与跨 Run | 空会话“记住本会话校验词是青松”；完成后问“校验词是什么” | 两个 Run，后者答青松；不强制计划/工具；同 request ID 重传不新建，不按文本去重 | P2a API/数据库，P2b/P8 真实 Web |
| C2 文件交付 | 上传 `input.txt` 内容 alpha，要求改成 beta 并交付；另测同名两附件、准备失败、上传副本失败 | 输入可读且不覆盖；下载对应副本字节为 beta；失败不宣称交付成功，排除附件须显式 | P2a 存储/固定响应，P6 检查反例，P8 真实模型及下载 |
| C3 提问重启 | 夹具先写一次标记，再返回 ask 与后续写调用；等待后重启 API，再按交互 ID 回复 | 同 Run 增 attempt，前序写一次；后续原调用 skipped，再请求模型；重复回复无第二次执行，缺环境不静默重建 | P2a 真实数据库/进程重启，P2b/P8 页面 |
| C4 多调用与审批 | 完整响应含两个可观测调用和计划更新；变体含重复 ID、未知工具、集合中审批拒绝/过期、审批中重启 | 全集合保存并顺序配对；错误结果明确；拒绝不执行；审批重启为 interrupted，迟到批准无效；工具只执行许可的动作 | P2a 确定性，P3a 真实交互，P8 汇合 |
| C5 停止与中断 | 启动受管理的长 sleep 及子进程后停止；变体忽略 TERM、调用分发后 API 崩溃、A2A 取消超时 | cancelled 与 interrupted 区分；已登记进程组确认结束，故障时准确 unknown 且不可复用；无自动重放；停止/完成竞争终态唯一 | P2a 逻辑，P3a 临时真实进程/协议夹具，P6/P8 人工路径 |
| C6 两类预算 | 夹具分别构造“累计额度足够但请求大于窗口”“窗口足够但额度不足”；另测重试/等待/活动超时 | 分别 context_limit/budget_exhausted；拒绝超限请求；不截断调用配对；等待不重置账本，活动超时触发收尾 | P2a 确定性，P4/P5/P8 汇合 |
| C7 压缩与再读 | 有前序标记“青松”的长历史；MCP/A2A 文本/JSON 返回尾部标记位于 16,000 字符之后且在存储限额内；限制窗口触发连续两次压缩 | 原始记录不改、快照覆盖不重复；分段工具能读到尾部；真实模型保留指定事实；摘要失败/预算不足/引用失效有明确出口 | P4 真实适配夹具+模型观察，P8 汇合 |
| C8 历史与增量 | 已连接页面时丢弃一次完成通知；另测历史订阅交界、断流重试、取消、刷新 | 已提交事实最终可见；item 不重复，临时 attempt 被关闭；半截调用不执行，断线不取消运行 | P2b 持久事件与浏览器，P5 分片，P8 汇合 |

已有能力回归保持小而具体：浏览器访问受控页面提取固定事实及来源；MCP add 返回精确结果，A2A 夹具回复与远端失败各一条。P3a 首验、P8 复验，均通过真实产品工具入口；不强制公网商业站点、真实第三方写操作或新增协议交互。至少文件、提问、浏览器查证和外部调用有代表性真实模型经 Web 的演示证据；固定模型夹具不替代这些观察，也不据一次成功声称稳定成功率。

确定性补充检查限于保留的实际契约：空库初始化/版本不符、事务回滚/同会话竞争、动作前意图已存但未分发、动作后结果未存、结果已存通知丢失、快照提交失败、审批回复与取消竞争、交付部分失败、终止会话清理失败重试。三种副作用窗口只要求不盲目重放和如实记录，不要求系统自动判断任意远端动作是否成功。

P1 的构造状态只证明契约；P2a–P6 必须由真实执行路径产生相应状态；P8 使用整合后的新数据环境。所有确定性必需检查必须通过，真实案例记录每次尝试、失败原因和修复/环境校正后的复验，不以别的案例成功抵消。若确需缩范围，更新计划与验收并说明原因，不把已支持能力静默变成加分项。

每条证据至少记录：包/案例、代码提交及未提交变更、环境与模型配置、输入/初始条件、预期与实际、产物/日志引用、未覆盖范围。课程 06 截图或替代证据归 P6，P7 验证图文，P8 核对最终运行依据；不把临时渲染 PNG 当真实界面证据。
