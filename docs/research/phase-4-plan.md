## 2. 合并调研后的结论

### 2.1 保留、改变和不做

| 类别 | 决策 |
|---|---|
| 保留 | Python、自研 Harness、现有分层、Web UI、PostgreSQL、Redis 传输、Docker 沙箱、MCP/A2A、浏览器和文件交付 |
| 改变主循环 | 开放任务改为单 Agent 工具反馈循环；计划改为 `update_plan` 工具，不再强制另一个 Planner 逐步调度 |
| 改变记忆职责 | 持久事实、模型工作上下文、摘要分开；保留数据库，不迁移为 JSON 文件型主存储 |
| 改变运行契约 | 独立运行与调用身份，准确终态、预算、取消、等待/授权及中断处理 |
| 改变交互与交付 | 模型流式、完整工具调用集合、事件补齐、具体产物检查 |
| 暂不做 | 长期项目工作区、跨会话自动记忆、向量库、worktree 并发、多 Agent 团队、插件市场、框架迁移、跨实例自动接管、通用 exactly-once |
| 运行范围 | 单执行 worker、受管理的沙箱环境；已有沙箱模式保留但必须明确资源归属；不宣称生产多租户隔离 |

移除独立 Planner 是设计选择，不是“所有双循环都不合理”。若未来业务确实要求固定阶段或独立验收节点，可以另设业务流程。本阶段不产品化两套执行策略，也不新增自动选策略的路由模型。

| 差距 | 旧方案事实 | 目标与优先级 | 工作包 |

## 3. 目标契约：先确定什么，再写代码

以下是目标契约，尚未实现。P1 将其细化为迁移、接口和测试；命名可在该工作包内调整，职责与保证不得静默删减。

### 3.1 状态与数据

| 对象 | 目标职责与持久化 | 不承担的职责 |
|---|---|---|
| Session | 多轮对话、附件关系、运行列表与展示摘要；兼容旧会话读取 | 不把会话状态当唯一执行事实 |
| Run | 本轮目标、配置/策略版本、预算累计、状态、结束原因、恢复关系 | 不保存可跨重启复活的协程 |
| ToolCall | call ID、执行尝试、参数引用、结果引用、副作用类别、取消确认 | 不把超时自动当作未执行 |
| 持久记录/事件 | 按 session/run/item/seq 关联；数据库保存完成事实，Redis 传输通知 | 不让 UI delta 成为权威事实 |
| ContextSnapshot | 模型消息投影、摘要、来源范围、版本和 token 估算 | 不覆盖原始事实，不共享不同会话历史 |
| PendingInteraction | 提问或授权类型、作用域、待处理调用、恢复关联 | 不把用户普通回复自动解释为所有操作授权 |
| Artifact/Verification | 可下载的产物版本、来源运行、验证方式和结论 | 不把模型宣称当验证通过 |

数据库采取增量迁移：保留旧 session/files 数据，新增运行、调用、按序记录及上下文快照所需结构；不得把全部新数据继续写回单个无限增长的 session JSONB。完成记录与相应数据库状态必须同事务提交；提交失败不得发布完成通知或推进执行位置。文件系统和远程工具仍在事务外，需要对账，不能称为全链路事务。

Run 状态至少区分 queued、running、waiting_input、waiting_approval、completed、failed、cancelled、interrupted；预算耗尽以明确结束原因表达，不伪装成功。等待回复继续同一运行并记录新的执行 attempt；已终止运行的显式续接创建有来源关系的新运行，保留旧终态。新运行重新分配预算必须在界面中明确，等待续接不能重置已用预算。

启动协调必须在接受新运行或回复之前完成，不能将所有活动运行统一改为 interrupted。

| 重启前状态 | 启动后的处理 | 回复与预算 |
|---|---|---|
| queued | 首版标为 interrupted，原因为启动前中断，不自动执行积压任务 | 用户显式续接创建新 Run，保留来源 |
| running | 标为 interrupted，缺少结果的调用待对账，相关环境隔离 | 不自动重放，处理未知结果后才允许续接 |
| waiting_input | 保留原状态、交互记录及调用集合位置 | 按交互 ID 回复后继续原 Run、增加 attempt，累计预算不重置 |
| waiting_approval | 保留原状态；旧批准不得在重启后自动触发写操作 | 重新检查参数、资源与策略版本，必要时重新审批；继续原 Run |
| completed / failed / cancelled / interrupted | 保留原终态与来源 | 显式续接创建新 Run |

等待态表示调用集合已持久暂停，不存在未登记的前台执行。恢复前检查环境及引用；环境丢失或被隔离时保留等待并展示阻塞原因，允许取消。需要重建环境时使旧授权失效并重新核对事实，不静默换环境执行。重复回复与回复/取消竞态使用原子状态迁移处理，迟到回复不得重新激活终态。

运行完成与成果验证分开：验证结果至少区分通过、失败、未检查/需人工检查。计划全部打勾不自动使验证通过；验证失败不在 UI 展示为目标成功。

### 3.2 输入、授权和副作用

- 同会话最多一个活动运行；等待态同样占有该会话。用数据库原子约束/状态迁移限制重复创建，不只靠进程内字典。部署明确限制为单执行 worker，禁止冒充多实例所有权方案。
- 客户端请求 ID 去重，返回同一次已创建的执行。运行中补充输入有持久 ID，通常在当前工具集合结束消费；提问或审批形成的持久暂停边界也可处理补充输入，并按下述规则作废过时调用；停止走独立控制路径。变更目标不能静默扩大既有授权。
- 提问回复与工具调用按 ID 正确配对；审批绑定调用及参数摘要、资源范围和策略版本。拒绝、过期、参数改变后授权均有明确处理。重启不自动重放审批中的写操作。
- 完整模型响应中的调用集合先整体保存，再顺序执行；逐调用保存位置、状态、结果和 attempt。已完成动作不得因续接重放，缺失工具或错误参数产生对应 call ID 的失败结果，不静默丢弃。
- 集合中遇到提问或审批立即暂停后续调用。回复按交互 ID 配对；拒绝审批、目标改变或参数/资源失效时，当前调用保存拒绝/作废结果，后续未执行调用显式作废并补齐对应结果，再交回模型重新决策。纯澄清且目标未变时可重新校验后继续，授权仍逐调用检查。取消时保存未执行状态，续接投影补齐配对但不伪造执行结果；下一次模型请求不得包含缺少结果的调用集合。
- 工具分为可安全重试、需幂等保护、结果未知需核对等类别；策略为未知的外部工具采用保守规则，不能完全信任工具自行声明的只读标签。普通 Shell 不靠命令字符串黑名单证明安全。
- 先保存调用意图，再执行，再保存结果。进程崩溃造成结果未知时，查询可确认的进程/文件/远程任务；无法确认则说明并等待显式处理，不能据一条意图记录自动补执行。
- 环境使用权与销毁权分别记录。首版对已有共享沙箱实行环境级单运行占用，覆盖文件、Shell 与浏览器上下文；单 worker 内的异步任务也不能绕过。等待态保留占用，前台调用全部结束或取消确认、且没有遗留写入者后才释放。
- cancelled/interrupted 不证明资源已停止。取消无法确认的环境标为隔离并禁止自动复用，对账确认安全后才释放；远端任务仍可能写入的资源范围同样记录阻塞，不能仅更换本地沙箱就判安全。显式后台服务必须登记服务身份、资源范围与寿命，核对冲突后才转交会话管理；未转交则仍由原运行负责，不因运行结束自动放行冲突资源。
- 最小安全范围是无敏感宿主挂载、明确工作根与执行身份、CPU/内存/进程限制及配置化网络策略。浏览器、MCP/A2A 外部写入也需经过策略入口。完整租户、组织权限系统后置。

### 3.3 模型、预算和事件

- 保留当前模型供应商适配路线，不强制换 Responses API。完整消费工具调用集合并保持 ID 配对，首版串行执行；模型不调用工具时仍检查待输入、等待、预算、运行错误和交付条件。
- 单轮模型调用次数、总耗时和 token 预算跨工具循环、重试、摘要累计。活动执行时间与等待用户时间分开记录；token 未提供时标未知并采用保守估算，不能记零。供应商缺少精确计数时不声称精确费用硬上限。
- 模型请求前 Context 预算包括系统指令、工具 schema、历史与输出预留；摘要保留目标、授权约束、待办、关键结果和错误，调用/结果保持成对。超大输出外存并提供可读取引用，明确清理寿命。
- 新版会话的普通新 Run 继承同会话前序已确认消息、结果及可用附件引用，使用有效快照及其覆盖序号之后的增量构建历史，不能只读当前 Run。快照标明来源范围、覆盖序号和版本，压缩替换原子发布；失效时从持久记录重建，避免重复或遗漏。跨会话不自动继承，旧会话转换仍走 P1 确认入口。
- 系统约束、当前目标及用户约束记录、待处理交互、策略和授权状态从权威记录重新注入；摘要仅辅助理解，不能授予权限或覆盖这些记录。历史授权不因上下文继承而自动沿用。P2 先实现不压缩的正确历史投影，P4 再加入预算和快照。
- 外存结果使用受会话访问约束的不可变引用与内容版本，提供模型可调用的分段读取工具，限制单次返回大小；读取结果同样经过 Context 预算，禁止全量反复回灌。P4 明确保留期限、引用失效及会话删除后的清理，不能仅提供不可读取的摘要链接。
- 模型文本 delta 供增量展示；完整工具参数通过校验后才执行；模型响应未正常结束时，不把半截参数作为调用依据。已执行调用不能因模型流重试而重复执行。
- 持久完成记录采用稳定 ID 和单调序号，先持久化再通知；通知丢失可从数据库补齐。连接断开不自动取消执行。delta 可以暂态，重连后以完整 item 与当前运行快照收敛，不重复追加已存在内容。请求重传按 request ID 去重，运行与内容按 run/item ID 投影；相同文本不能推断为同一运行。显式重试/续接保留原终态、动作和来源，不删除失败轨迹。

### 3.4 现有产品链路的最小闭环

以下补充归入已有工作包，不增加工作包或独立平台。交互必须让用户知道当前发生了什么、是否需要处理以及可采取的下一步；目标仍是文件、浏览器和外部工具任务。

| 环节 | 本阶段必须明确的行为 | 工作包 |
|---|---|---|
| 正式交付入口 | P2 删除总结阶段时，同步提供显式交付工具，接收待交付文件及说明；校验路径后保存不可变存储副本，成功后绑定消息附件，失败则将错误回填模型并显示给用户。不从自然语言猜路径，也不等到 P6 才恢复附件功能。P6 的验证绑定实际交付版本与具体检查要求，文件存在不等于内容正确 | P2、P6 |
| 输入资料准备 | 区分已上传、已准备可读、准备失败；用户本次提交的附件默认都是所需输入，同名附件不能静默覆盖。准备失败时暂停进入模型执行，允许重试准备、取消，或由用户明确排除失败附件后继续；排除和缺失信息进入持久记录及模型上下文 | P2 |
| 浏览器人工接管 | 默认 VNC 只读；显式接管需在当前动作结束并持久暂停后授予写控制，同时暂停 Agent 工具分发。交还后重新观察页面，作废旧元素引用并重新校验相关授权。断线或重启不能自动交还 Agent，也不能留下未受控的可写连接；控制边界由服务端执行，不能只靠前端 viewOnly | P3a |
| 环境占用与阻塞退出 | 共享环境已占用时首版直接拒绝新的执行请求并展示原因，不新增调度队列。界面区分等待用户与资源阻塞；原任务可回复或取消，未知结果可发起重新核对或放弃续接。放弃不等于确认安全，未知资源仍保持隔离。重建仅限受管理环境在旧资源停止确认后进行，已有外部环境由操作者处理；不提供无证据强制放行 | P3a、P6 |
| 会话删除 | 存在活动 Run、待对账调用、未释放环境或受管理后台服务时拒绝删除，并指向取消/核对/停止服务路径。删除与新运行创建互斥；符合条件后才删除关联记录。附件与外存引用按存活引用清理，不删除其他会话仍引用的副本；本阶段不新增回收站或数据治理平台 | P1、P3a、P4、P6 |
| 内容信任与任务验收 | 网页、文件和外部工具结果保留来源，经过摘要也不能变成用户指令或授权；以反例验证该边界，不宣称彻底解决提示注入。真实任务除了机制通过，还要核对目标与交付质量；不新增通用评测平台 | P4、P8 |

人工接管及输入准备失败使用持久交互记录区分原因，不新增与 Run 并行的第二套运行状态机。P1 定义所需记录，P2/P3a 接入具体交互。重建环境或删除数据都不能被普通模型输出隐式触发。

## 4. 执行顺序与工作包

核心依赖链：**P0 → P1 → P2 → P3a → P4 → P5 → P6**。P3 分为执行控制基础 P3a 和环境强化 P3b；P3b 依赖 P3a，可与 P4–P6 独立推进，不阻塞 Context 开发。**P7 汇合 P1–P6（包含 P3a、P3b），再进入 P8**；P3 主包须两个子包均验收才完成。依赖稳定后，局部说明和图的核对可随包推进；无需等所有代码完成才开始写文档。P7 是全课程整合验收，不是首次同步。

每包遵循：核对当前入口与基线 → 明确契约/失败出口 → 小步实现与迁移 → 确定性验证 → 必要真实集成 → 更新当前 docs 和受影响课程/图 → 记录进度证据。不能以删除旧测试代替验证新语义。

### P0：计划与背景整理（本轮）

交付：统一本文、独立进度、旧方案背景、PLAN 软链接；整合并移除五篇分散稿；修复引用；调整阶段与课程维护约定。正文与现有图片暂不改写为未来能力。

验收：唯一执行计划、唯一进度来源、软链接有效、旧稿引用已迁移、实际源码未改变。当前会话到此为止，不自动进入 P1 实施。

### P1：基线、运行/存储契约与兼容基础

依赖 P0。先重跑相关服务指南规定的旧基线检查，保存实际环境、模型配置及失败信息；保留旧版 Git 提交、历史会话与附件读取样本，不保存实际凭据。

实现 Run、调用身份、版本化事件/消息记录与必要仓库、迁移；数据库持久事实作为新运行的读取依据。加入请求去重与单会话活动运行约束。旧事件通过兼容投影读取，不补造历史缺失的运行、取消和 token 信息。实现第 3 节的最小启动协调、持久等待、环境占用/隔离记录与原子状态迁移；P2 切换默认循环前必须验证基础，不能等到 P6 才处理重启。

旧会话默认可查看、可下载既有附件；不自动拼接 Planner/ReAct 两份记忆继续。续接入口明确“基于旧记录开始新版运行”，仅选择目标、经确认摘要与可用附件，保留来源。旧 sandbox ID 先验证可用性，不能直接当存活环境。

影响：API 会话/任务应用服务、领域模型与仓库、ORM/UoW、Alembic、接口类型、UI 历史与状态映射；入口见[改造代码映射](../code-map.md#第四阶段改造入口)。docs 更新状态归属、兼容与边界；课程 08、09、10 先明确新契约与当前进度，尚未交付能力不写成已实现。

验收：空库升级、旧库升级、旧历史及附件读取、重复请求与并发创建、状态/完成记录事务失败；queued/running 重启迁移、等待和审批记录重启保留、重复回复及回复/取消竞态。使用专用数据库验证，不只用内存替身。增加删除与新运行创建竞态、活动/待对账会话拒删的仓库契约测试；具体资源清理由 P3a/P6 联验。此包不自动改生产数据库。

### P2：单循环与计划工具

依赖 P1。用一个自研执行循环消费工具反馈，新增计划更新工具；去掉运行时独立 Planner、强制 Step JSON 和独立总结交接。正常内容输出与工具结果、交付附件分开建模；落实第 3.4 节的显式交付工具与输入资料准备状态，保留原文件任务的端到端交付能力。计划面板显示清单，不再要求前端从步骤调度事件推断运行终态。

整理中英文提示词：保留必要工具使用约束，移除与旧双循环、强制通知工具及固定环境描述冲突的规则；进度输出可使用内容事件。按第 3 节实现调用集合整体持久化、顺序执行及持久暂停，校验重复 call ID、缺失工具、错误参数及每个调用对应的结果。

运行中消息在安全边界消费；提问和回复持久化配对，等待续接重建上下文，不回滚任意一条消息。先实现同会话跨 Run 的不压缩历史投影；总次数/时间预算在此生效，token 预算在 P4 完整接入。

影响：Flow/Agent/提示词/工具注册、Runner、依赖装配、计划和消息事件、UI 计划面板；docs 核心循环与分层；课程 02、03、04、06、07、12。旧流程测试转为新不变量测试；原双循环案例归 background/Git，不长期保留产品双模式。

验收：纯回答不强制规划；真实工具反馈可多轮推进；计划不控制步骤指针；完整多调用回填；提问后同运行续接；新输入、无进展、迭代耗尽及错误出口正确。增加“读文件→提问→写文件”、等待时变更目标/取消、重复回复、等待中真实 API 重启后继续同 Run 且不重放前序动作，以及普通跨 Run 历史继承的验收；审批组合由 P3a 补齐。覆盖删除总结阶段后的文件交付、上传失败回填、输入附件准备失败/重试/明确排除及同名附件不覆盖。包含真实模型小规模任务，不设固定数量或收益门槛。

### P3：工具策略、取消与沙箱资源

#### P3a：执行控制与环境占用基础

依赖 P2。分发前统一参数校验、策略决策和授权；等待审批与普通提问使用不同记录及 UI。按调用/参数/范围绑定授权，拒绝或失效按第 3 节结束剩余调用集合并回到模型，批准不突破沙箱硬限制。

贯通运行取消→调用取消→Shell 进程组/远端取消→确认记录；修复 Shell 输出读取器阻塞导致无法按时返回句柄的问题，终止超时使用有界升级。浏览器取消报告已发出动作与不可撤销副作用。落实环境级占用、等待保留、未知隔离和后台服务登记/转交；动态和已有沙箱用显式 ownership 决定销毁权。落实第 3.4 节的人工接管、资源占用拒绝与取消/阻塞入口，提供停止受管理后台服务的操作，接入会话删除前资源检查。

影响：工具策略、Runner/任务适配、沙箱 HTTP/Shell 句柄、浏览器、MCP/A2A、UI 授权/停止/阻塞展示；课程 03、08、11、13–15 与 docs 控制边界同步更新。

验收：集合中间审批拒绝/过期/参数变化、审批中重启与迟到回复；真实进程树取消、忽略 TERM、远端无法确认；两个会话竞争已有沙箱、取消未知后立即续接被阻止、等待占用、后台服务转交冲突、外部容器不被误删。补充人工接管互斥、交还重新观察/授权失效、接管断线和重启、共享环境拒绝提示、活动资源阻止删除。前端按钮变化不能代替进程验证。

#### P3b：环境硬限制与按需准备

依赖 P3a。修正 TTL 配置名称，落实执行身份、配额、允许目录与网络；纯文本和文件任务按实际需要准备资源，避免固定依赖浏览器。API 需要 Docker 权限不意味着沙箱应获得宿主 Docker socket。

| 执行面 | 最低控制位置与支持条件 |
|---|---|
| 文件与 Shell | 文件服务检查允许根及符号链接；Shell 由容器挂载/权限与执行身份约束可写工作根，允许必需的只读运行时路径及声明的临时目录，不能把 exec_dir 当权限边界 |
| 沙箱与浏览器 | 容器设置 CPU/内存/进程限制、禁止敏感宿主挂载；出站限制在实际网络出口执行，代理环境变量不等于强制策略；浏览器采用同一边界 |
| API 内 MCP/A2A | 调用前策略覆盖远端写入；HTTP 对端采用允许地址与 API 出站控制，stdio 子进程采用明确命令、环境与独立受限执行身份；不声称受沙箱网络隔离保护 |
| 已有沙箱 | 提供可核对的身份、挂载、配额与网络配置；可达不等于边界合格，缺少必要条件时禁用受影响执行能力并说明原因 |

影响：Docker/配置、沙箱文件服务、协议进程与网络、资源装配及服务指南；课程 11、13–15 和相关图按实际验证更新。实施前在服务指南确定具体机制、支持配置与检查入口；未强化的开发环境不得被描述为已满足目标边界。

验收：目录/符号链接越界、Shell 绕过文件工具直接写入、沙箱/浏览器及 API 协议路径访问禁止目标的反例、stdio 权限、TTL/配额、已有环境缺条件时拒绝执行、纯文本任务无需浏览器。保留 MCP/A2A 协议回归。P3b 是 P7/P8 汇合和阶段结项的硬门槛，不因 P4 完成而豁免。

### P4：上下文预算与记忆分工

依赖 P3a 的稳定调用/策略接口，不等待 P3b。实现请求前 Context 构建、估算与实际 usage 校准；长结果按大小外存、保留引用和摘要；按 token 水位在轮次内压缩，保留目标、用户约束、授权和调用配对。按第 3 节实现快照加增量重建、权威约束注入和外存分段读取。原始消息、摘要版本和来源范围独立，摘要调用计入预算。

预算不足时先选择/压缩，再确认能否请求；无法缩减或摘要失败有明确停止原因，不能无限重试。缺失外存引用返回可解释错误，不假装内容仍在。原始内容保存遵守访问控制、保留与脱敏，禁止把模型原始请求和凭据无差别写调试日志。保留外部内容来源，摘要不得将其提升为用户指令或授权；清理外存引用时核对其他存活引用。

影响：Memory/Context、模型接口及 usage、存储仓库/文件存储、预算配置、UI 用量展示。课程 05 主更新，02、08、09、10、16 联动；docs 状态与记忆职责、能力与边界。

验收：同一长轮次触发压缩、中文及工具 schema 计数、超大单结果、摘要失真与失败、调用配对、使用量缺失、预算跨重试累计、重建后约束仍在；跨 Run 对话、连续压缩、快照发布失败、摘要遗漏/篡改授权约束、外存再读取与引用过期、恶意网页/工具结果经摘要后不改变授权、删除时共享引用保留。记录压缩前后容量及所需事实是否保留，不只比较 token 数。

### P5：端到端流式与事件一致性

依赖 P4。模型适配返回增量及完成对象；按调用 ID/index 拼装多个工具参数，完整校验后分发。处理空片段、混合文本与调用、UTF-8、异常中断、finish reason、usage 延后到达及重试。供应商不支持流式时走明确兼容路径，不假装流式；并行执行仍不在本包。

API→SSE→UI 统一 run/item/call 身份；完成结果先保存，通知可重放。实现游标补齐、重复事件去重、订阅与历史之间的竞态处理；重连以完整记录收敛临时文本。修复现有 SSE CRLF 分片及 EOF 观察脚本暴露的边界，旧限制不能继续算“通过”。新版投影移除按用户文本/附件相等折叠运行及重试时裁掉失败输出的逻辑；旧记录使用独立兼容投影，不补造身份。

影响：模型抽象/适配、事件、仓库、Redis 通知、路由/schema、Nginx 超时/缓冲、前端解析/hooks/消息与工具组件；课程 02、10 主更新，06、09 联动；docs 产品与观测说明、API/UI 指南。

验收：确定性分片夹具、同轮多调用、断流不执行半截参数、完成消息不重复、刷新/断线补齐、数据库失败和通知失败窗口；浏览器中真实流式任务与停止；同文本两次独立运行、同 request ID 重传、失败后显式续接与刷新后完整历史一致。首个事件、首个有意义文本、首 token 和总耗时分别统计，不能混用。

### P6：中断对账与成果交付

依赖 P5。在 P1 启动协调和 P3a 环境隔离基础上对账；遵守第 3 节逐状态规则并保留等待态。扫描处于执行中但没有结果的调用，记录确认/未知；安全读取可重试，外部写入不得盲目重放。已终止 Run 的显式续接产生新运行，继承已确认事实，预算和来源可见；对账确认安全才释放环境占用/隔离，无法确认则保留阻塞。落实第 3.4 节的重新核对、放弃续接和受管理环境重建路径；放弃后仍保留未知事实，不自动释放隔离。

把成果验证落到文件内容、附件版本与下载、工具实际执行结果、测试退出码等可判定对象；检查结论绑定具体要求、验证方法和实际交付版本，验证后文件变化必须生成新版本并重新检查；文件存在或测试退出码不能单独证明整个目标达成。开放报告质量可人工评价。交付失败、部分交付、验证失败与模型总结分开显示。保持既有文件串行替换和旧附件可下载语义，不重新引入已修复问题。

影响：启动/运行协调、记录仓库、文件同步/存储、校验器及 UI 产物和终态；课程 09、12、16 主更新，06 联动；docs 产品、恢复边界及运行指南。

验收：动作前、动作后结果未保存、结果保存后通知丢失三个故障窗口；真实 API 重启、重复提交、附件上传失败/下载、进程或远端结果无法确认。成果检查器本身必须有反例，不能只测正常文件；覆盖验证后文件变化、核对后解除隔离、无法确认时放弃但不释放、重建条件不满足时拒绝，以及删除被阻止/安全清理两条路径。

## 5. 代码修改影响与兼容策略

精确现有路径集中在[代码地图的第四阶段入口](../code-map.md#第四阶段改造入口)，未来文件标为拟新增，不把计划路径当已存在实现。本计划按职责说明修改，不建立第二份路径清单。

| 代码面 | 必须变更 | 必须同时核对 |
|---|---|---|
| API 路由/应用协调 | 请求去重、运行/等待/授权/停止/续接、订阅游标 | 前端 types、错误响应、旧 session 读取 |
| 领域执行 | 单循环、计划工具、执行策略、预算、Context、结果验证 | 提示词两种语言、工具 schema、正常与异常终态 |
| 数据库/仓库 | 增量表、约束、序号、事务、来源版本、摘要与原始记录 | Alembic、UoW、旧 JSONB 与附件、删除保留策略 |
| 模型适配 | 结构化增量、完整调用集合、usage、错误分类 | 供应商兼容、缺少 usage、Chat Completions 兼容路径 |
| 任务/消息传输 | 单 worker 所有权、取消、持久结果后通知 | 重启识别、Redis 重连、UI 补齐；不自动增加分布式调度 |
| 工具与环境 | 策略入口、调用句柄、进程组、超时/取消、资源归属 | 文件、Shell、浏览器、MCP/A2A 均不可绕过 |
| UI | 运行状态、计划清单、流式文本、授权、用量与成果 | 历史/实时使用同一投影，旧事件容错，断线不误显示完成 |
| 构建部署 | 必要配置、数据库迁移、沙箱身份/配额、代理设置 | 环境模板和镜像来源；不为重构顺带升级所有依赖 |
| tests/labs/scripts | 新契约测试、旧观察预期更新、跨服务故障验证 | 不把故意复现旧缺陷的 LIMITATION 输出当新功能通过 |

迁移采用先增量后切换：P1 建兼容层、新表与最小启动协调，P2 验证重启/等待契约后切换默认循环，P5 切换新版事件投影，P8 清理临时分支。旧库不破坏性回填，旧记录不被伪造成新完整轨迹。切换前停止接收新运行并处理/停止活动旧任务，不做运行中热迁移。

回退边界：保留数据备份与迁移前版本；代码回退不能解释新版记录时，应禁用新写入并保留数据，回到备份或使用兼容读取，而不是假设 Alembic downgrade 可以无损转换。P1 必须在临时库明确测试并记录具体回退方式。

## 9. 执行纪律、风险与停止边界

- 后续实施按包建立可审查变更，每包完成代码、对应回归与局部图文后再推进；进度中的“完成”必须有证据。不要求每次常规修改都另写规格文档，复杂契约直接在本文对应节落实。
- 范围漂移时先更新本计划及受影响验收项，不以“Codex 有这个功能”为新增需求依据。工作区、自动记忆、分布式和多 Agent 不得夹带进来。新增发现先判断能否用现有工作包的交互、失败出口或验收补齐；商业化差距不作为阶段 4 的结项条件。
- 主要风险是迁移损坏历史、取消误伤资源、工具重放、摘要丢约束、流式半截调用、UI 误报成功以及教材提前宣称新能力；分别由 P1、P3、P4、P5、P6、P7 验收覆盖。
- 已实现但未验证必须单独标注；外部模型、Docker 或数据库条件不足时记录阻塞，不用 mock 通过替代真实检查，也不把整个阶段标完成。
- 不给出无基线的工期承诺。先完成 P1 的基线与迁移范围核对，再按实际变更量评估后续耗时；以验收包而非代码行数/课时衡量进度。

阶段完成后的最大变化：RayAgent 从以步骤调度和消息堆积为中心，升级为有明确运行契约、有预算上下文、可追溯工具动作和可核对交付的 Harness。是否提高成功率或降低成本，按实际测量表述，不预先保证。
