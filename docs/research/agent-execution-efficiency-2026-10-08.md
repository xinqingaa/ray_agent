## 1. 背景与结论

用户观察到同类任务在 RayAgent 中耗时较长、消耗较多，结果质量却未相应提高。同日[截图机制调研](browser-screenshot-policy-2026-10-08.md)已经确认：内置浏览器每次调用完成后补截图，图片只用于前端展示，没有进入模型视觉判断。本次将检查范围扩展到工具选择、观察内容、模型往返、执行反馈和计时。

最值得优先修复的是：正文提取重复且提前丢失长内容；浏览器操作和观察契约过粗；模型批量调用能力与请求参数不一致；展示补全同步阻塞执行且耗时未单列。它们分别影响信息质量、决策轮数和等待时间。仅取消截图，无法一并解决这些问题。

推荐保留现有自研单循环、Playwright/CDP、工具管线、统一结果落盘、上下文压缩和事件事实源。第一批集中改善现有浏览器链路，第二批增加轻量网页读取，视觉输入作为完整的独立能力处理。无需迁移 Agent 框架、引入多 Agent 或建设新的调度平台。

本文的判断分三种：**源码事实**说明实际分支与契约；**既有运行观察**引用带版本的历史记录；**影响推断和方案建议**说明可能收益及待验证条件。静态确认一个缺陷，不等于已经测得它占总耗时的比例。

### 2.2 一个小任务提供的证据

[W9–W11 标准评测原始数据](../plan/evidence/w9-w11-eval-2026-10-02-89aa642.json)中，E5 要求用浏览器打开受控页面，读取校验码并直接回答。基线为 `89aa642`，模型为 `deepseek-reasoner`，每任务一次，属于历史功能验收。

| 项目 | 记录值 | 解释 |
| --- | --- | --- |
| 结果 | 正确读回 `QX-7319-LM` | 该次任务成功 |
| 客户端任务墙钟 | 12.6 秒 | 从提交到观察到结束的任务口径 |
| 模型调用 | 4 次 | 导航、读取、脚本读取、最终回答分别占一轮 |
| 工具调用 | navigate → view → console_exec | 存在连续获取同一页面信息的轨迹；没有完整请求正文，不能断言第三次读取毫无必要 |
| 模型耗时之和 | 3,319 ms | 来自四条 `turn(completed).model_ms` |
| 工具耗时之和 | 606 ms | 579 + 12 + 15 ms；不含运行器补图等阶段 |
| 累计输入 / 输出 | 18,323 / 242 tokens | 输入是各次请求累计，不是最后一轮上下文大小 |
| 缓存命中输入 | 17,280 tokens，约 94.3% | 不能将全部输入当作未缓存价格计费 |

客户端墙钟减去上述模型与工具计时约为 8.7 秒。这只能称为**尚未分项归因的差额**，其中可能含准备环境、整形、截图上传、持久化、通知与客户端观察延迟，不能直接当作截图耗时，也不能承诺删截图便可省去这些时间。E1 是两轮纯回答任务，0 次工具调用，墙钟 8.1 秒、模型耗时合计 1,636 ms；这也提示需要关注浏览器之外的准备与协调开销。

另一份[界面验收原始记录](../plan/evidence/w9-w11-acceptance-2026-10-02.json)的 `external_ui.browser`，是不同会话、不同页面：4 次模型请求、3 次浏览器调用，分别保存了三个截图引用，第三次执行 `document.body.innerText`。这支持“纯读取也生成多张图片”的结论。该记录的工具耗时是 434、20、18 ms，不能与上述 E5 的数字混用。

### 2.3 已有机制应继续使用

当前已有多工具结果配对、超长结果落盘并按行读回、请求前容量检查、自动压缩、真实 usage/缓存/推理 tokens 解析、失败尝试记录和请求重建。模型配置已有思考档位与运行快照。完成前也已有针对文件交付与计划条目的**最多一次一致性反馈**，因此“完全没有完成检查”已不符合当前源码；该反馈仍不验证网页业务目标。

本轮不建议重做这些基础机制，也不因任务慢就一律降模型档位、提高上下文窗口或降低压缩水位。模型强弱、思考档位与工具质量应分别评估。

## 3. 主流工具的公开做法

以下比较的是可核实的公开能力和文档建议，不代表已掌握各产品的内部提示词，也不是性能排名。Claude Browser Use / Computer Use 是 API 工具契约，不能直接当作 Claude Code 或 Claude 消费产品的完整内部实现。

| 来源 | 已确认做法 | 对 RayAgent 的启示 |
| --- | --- | --- |
| Codex 浏览器文档 [S1] | 可操作网页、检查渲染状态、截图并验证结果，强调具体页面和目标状态；未公开“一切动作后都截图”的统一规则 | 将观察与明确的完成条件联系起来，不能从演示画面推断所有内部截图策略 |
| Cursor Browser [S2] | 日志写文件，由 Agent 选择性搜索；提供行数与预览；截图以图像形式被 Agent 读取 | 全量数据留在环境中，模型取必要部分；视觉反馈应实际进入判断链路 |
| Claude Browser Use [S3] | 页面结构与截图并存；建议先读树、按子树和交互元素缩小范围；无需每次调用后截图，批次末可返回一次观察 | 动作与观察可组合，文本、结构、图像按任务选择 |
| Claude Computer Use [S4] | 截图是模型输入；可将点击、输入、截图放在一轮返回并顺序执行；需要控制截图历史 | 视觉交互需要反馈，但反馈频率以决策需要为准 |
| OpenAI 函数调用 [S5] | `parallel_tool_calls=false` 保证模型一轮输出零个或一个工具调用 | “模型生成多个调用”与“程序并发执行多个调用”是不同开关 |

S3 还明确区分：找资料、读已知页面可用更轻的 web search / web fetch；网页交互或 JavaScript 渲染内容使用 browser use；整个桌面操作使用 computer use。RayAgent 可借鉴这种分工，而不必接入上述专有工具协议。

## 4. 发现的问题及其影响

### F1：正文重复提取，并在通用落盘之前截断

**源码事实。** 正文脚本遍历 `body *`，筛选与视口相交的元素，再把每个元素的 `outerHTML` 全部拼接。父元素已经包含后代，后代又被追加。例如可见的 `<div><p>校验码 A</p></div>`，父 div 和子 p 都会贡献这段文字。与视口相交的容器还可能夹带位于视口外或隐藏后代的 HTML，因此“仅视口正文”也不是严格保证。脚本不直接处理 body 自身的裸文本节点。

转换 Markdown 后，无论是否经过可选 LLM 整理，输入范围都先限为 50,000 字符；此处没有保留超出部分，也没有明确的提取截断标记。后续 `ResultShaper` 能保存的只是已经截过的工具结果，不能恢复此前丢失的正文。

**影响推断。** 重复会占据上下文和预览首尾位置，长页可能遗漏关键段落，诱发滚动、再次读页或 JS 补读。遍历全部元素并逐项读取布局/样式也有工作量。本次未测复杂网页的耗时和重复倍率。

**优先级：首批。** 先修源头提取，再讨论更频繁压缩。

### F2：自动截图不参与决策，却阻塞执行与展示

**源码事实。** `called` 且未被策略/用户/计划模式拒绝的内置 browser 事件会补截图，读取、日志和部分执行失败也进入该分支。模型结果已先写入记忆，补图只写到前端字段。截图与上传在运行器中串行等待，异常只记日志，没有这一整段独立的总预算。

**影响。** 这是明确的额外工作。默认视口图、未统一等待目标状态和面板缩放又使这些图片未必能回答用户关心的问题。更完整的触发、存储和显示背景沿用[截图调研](browser-screenshot-policy-2026-10-08.md)，本文不重复维护。

**优先级：首批。** 取消全量补图时必须同时补齐文本结果展示。

### F3：模型批量生成被请求参数限制，批次失败语义也不完整

**源码事实。** 提示词允许多个调用，循环也保存并顺序执行完整列表；但模型适配器对所有有工具的请求统一发送 `parallel_tool_calls=False`。按 S5 的 OpenAI 语义，它限制生成数量，并非仅要求执行器串行。第三方兼容接口是否遵循、忽略或拒绝该字段，需要分别确认，不能由注释推定。

循环遇普通工具失败仍继续本轮后续调用，只在提问和等待审批等分支离开批次。因此直接放开模型批量生成还可能让“点击失败后继续输入”等依赖链出错。

**影响推断。** 执行器具备批量能力，并不证明实际模型能够充分使用。若每个小动作都需新一轮判断，延迟和累计输入会增加。E5 的四轮记录本身不能证明该字段就是唯一原因。

**优先级：首批检查契约，随第二批启用。** 能力适配、失败中止、调用配对与审批续接一起处理，不做同页动作的无条件并发。

### F4：页面读取缺少用途与范围选择，普通取数容易绕路

**源码事实。** `browser_navigate` 只返回交互元素；`browser_view` 没有参数，返回正文与元素列表；click、input、scroll 等主要返回成功标记。默认工具集没有独立的网页正文抓取工具。系统规则要求 URL 用浏览器打开，事实核对走搜索后浏览器。

**影响推断。** 导航后读正文需要额外调用；只需一个值或提交状态时也容易拿到整块页面材料。搜索 → 原文核对是合理要求，但原文核对不必永远依赖渲染浏览器。用户明确要求使用浏览器时，则仍应尊重。

**优先级：首批优化现有观察；第二批增加轻量抓取。**

### F5：元素定位与输入语义存在明确缺口

**源码事实。** 每次观察从零编号，并向节点写 `data-manus-id`；没有清除全部旧标记，也没有给调用携带页面/观察版本。旧节点移出视口后仍可能保留标记，新观察又将同一编号给另一个节点；查询只取该选择器的首个匹配。页面选择还会自动跟随第一个 context 的最后一个 tab。

click 的参数都可选，无 index 且坐标不完整时可以不执行任何点击便返回成功。input 类似，还可能只执行 Enter。坐标输入直接打字，和工具描述的“覆盖”不一致；元素输入先清空再逐字输入，异常后回退点击再输入，若前一操作已部分生效，存在追加或重复输入的可能。索引分支缺少非负约束。

**影响推断。** 模型会收到不足以证明动作发生的成功结果；动态页面上的失效引用、错误 tab 和输入重复可能引起返工。这些是静态可达路径，未在用户会话中复现，不能声称已经导致某次误操作。

**优先级：首批修参数与输入；第二批补引用和 tab 契约。**

### F6：控制台观察不能可靠解释页面失败

**源码事实。** 只有执行 `browser_console_exec` 前才注入日志补丁；注入会清空 `window.console.logs`，再包裹一次 `console.log`。重复注入会叠加包裹。`browser_console_view` 只读取这个数组，未初始化时返回空；它没有自动覆盖此前日志、`console.error`、`console.warn` 和 `pageerror`。

**影响推断。** “没有日志”不等于页面没有报错。缺少可靠诊断信号，可能引导 Agent 再次点按钮、反复截图或执行试探性脚本。

**优先级：第二批，与操作后状态确认一起处理。**

### F7：展示结果不完整，展示补全又重复访问执行环境

**源码事实。** `ToolSSEEvent.content` 来自 `tool_content`，不直接投影 `function_result`。浏览器展示结构只有 screenshot。前端虽然能解析 `content.outcome.success` 并显示错误，标准浏览器事件却没有这些字段，执行失败可能无法呈现为失败状态。

同一运行器还会为 Shell 调用再次读取控制台；为带 filepath 的文件调用再次读取文件，不沿用原始读取范围。结果先写入模型记忆，再等待这些补全及事件持久化，循环才继续。因此，隐藏补全开销不只存在于浏览器。

**优先级：首批处理浏览器契约；文件与 Shell 仅做复用已有结果及有界预览。** 不用一次大规模 UI 重做解决这个问题。

### F8：当前指标不足以归因整体低效

**源码事实。** 工具管线首先注册 `_record_duration`，后面才执行结果整形、交付事件等后处理；运行器展示补全更晚。轮次 `tools_ms` 累加前述 duration，不能代表工具执行到用户可见完成的全部时间。准备环境和发现外部工具也在主模型循环之前。

**影响。** 已有 `model_ms`、`ttft_ms`、usage 和墙钟可以复用，但差额不能直接命名为截图或数据库成本。缓存统计已经存在，无需重新建设一套 token 记账。

**优先级：首批加少量分段计时，不引入新的可观测平台。**

### F9：纯回答也准备沙箱与外部工具，全量 schema 进入请求

**源码事实。** 运行器进入循环前等待沙箱服务就绪，并依次初始化 MCP、A2A。各自管理器内部已有并发发现及预算，不能称为每个服务都串行连接。每轮请求调用 `pipeline.schemas()` 提供全部已发现工具。项目任务还需要既有文件保护与占用流程。

需要纠正一种易混淆的说法：`get_browser()` 当前只构造 `PlaywrightBrowser`，CDP 连接在首次浏览器调用中初始化；它没有在每次纯回答前主动连接 CDP。但沙箱服务组包含 Chrome，准备完整沙箱的成本仍存在。浏览器适配器允许注入 LLM 整理正文，当前 Docker 组装并未传入该 LLM，不能把它算作实际额外模型请求。

**影响推断。** 冷启动和大量外部工具可能拖慢短任务；具体占比待分段计时确认。高缓存命中也表明不应为了缩短 schema 就每轮任意重排或改写前缀。

**优先级：后置。** 先测量，再决定是否需要资源惰性准备、工具目录按需展开。

### F10：视觉任务与业务完成判断仍存在能力缺口

**源码事实。** 浏览器图片没有进入模型请求，工具结果统一序列化为 JSON 文本。模型目录已有 `vision` 字段，但这不等于端到端图像输入已接通。现有结束反馈只核对部分交付和计划状态，没有网页业务目标验证器。

**影响。** 仅增加截图下载 URL 可以完成留证，无法保证模型看图；仅增加“再检查一遍”的提示也可能增加轮次而不增加证据。

**优先级：视觉能力单独形成完整交付；普通网页先提供可靠文本/状态读回。**

## 5. 推荐的技术方案

以下字段、接口和默认值都是候选设计，不是当前已实现能力。优先沿已有服务边界扩展，不引入第二套执行循环。

### 5.1 让执行结果、用户展示和视觉输入各有明确契约

浏览器工具生成一个结构化的观察结果，由同一次结果投影给模型与 UI，避免运行器再次操作页面以补齐展示。建议包含：

| 字段组 | 内容与用途 |
| --- | --- |
| 动作 | `action_success`、明确的 `error_code/message`；表示动作是否执行成功 |
| 页面 | `tab_id`、`url`、`title`、`observed_at`、`observation_id` |
| 观察 | 按需 `text`、`elements` 或目标状态；`observation_status` 区分成功、失败、未请求 |
| 范围 | `scope`、`truncated`、`total_chars`、`full_output_path`，避免把局部结果当整页 |
| 证据 | 可选 screenshot 元数据和文件引用；记录捕获状态，不用它覆盖动作结果 |

浏览器展示结构扩展为 `outcome`、受限 `content`、页面信息和可选 `screenshot`，利用前端已有 `content.outcome` 错误解析。普通完成事件显示文本、URL 和动作状态，显式截图才显示图。观察失败时显示“动作已执行，结果观察失败”，不让模型为了补观察重放提交动作。

事件落库与 SSE 使用同一投影；旧的仅含 screenshot 的事件继续可读。历史画面保持调用当时的文件引用，不用当前页补拍替代。参数校验失败或拒绝不再访问浏览器补内容。

Shell 与文件预览先复用 `raw_result` 中已有的数据。写入等确需额外读取的预览，限制行数/字节和等待时间；后续可改成用户展开时读取，但当前内容必须标注为“当前文件”，不能冒充历史快照。首批不建设异步预览队列。

### 5.2 改造正文与交互元素的观察方式

保留 Playwright，实现两个互补的读取路径：

1. **正文路径。** 以明确根节点提取一次：优先正文容器 `main/article`，否则 body；克隆后移除 script/style 等非正文，保留标题、列表、表格和链接语义，再由已有 `markdownify` 转换。需要严格视口文本时按文本节点遍历、检查可见性，每个节点只取一次，避免拼接所有祖先的 outerHTML。将视口与文档范围显式区分。
2. **交互路径。** 只在需要操作时返回可交互节点，补充 role、可访问名称或明确 label、当前值、disabled/checked/expanded 等状态。使用 Playwright locator 的 role/label 定位能力与有界 DOM 提取；不要把自研元素列表直接命名为完整可访问性树。

调整现有 `browser_view`，允许 `mode=text|interactive|both`、`scope=document|viewport|element`、可选目标引用与输出限制。保留无参调用的兼容行为；导航允许 `observe` 参数，纯阅读可在导航后同一次调用返回正文，表单任务返回元素。动作也可在关键步骤请求一次有界观察，普通输入无需每次返回整页。

输出先形成去重、可读的内容，再进入统一整形。删除静默 50k 截断；设置独立的提取资源上限，达到上限时明确 `incomplete` 和缩小范围的方法。上限内的完整文本保存一次，模型通过现有文件读取或搜索定位，禁止将超上限的部分宣称为已经落盘可恢复。

不默认调用第二个 LLM 摘要网页。HTML 转换与结构筛选先采用确定性代码，保留原文来源，减少额外等待和摘要丢失。

### 5.3 修正动作目标、引用与结果验证

- **目标校验。** index 与完整坐标二选一；缺目标、坐标只有一项、负索引和冲突目标均返回明确错误。顶层 schema 之外由工具校验组合关系，不能只写 `oneOf` 却让现有轻量校验器忽略。
- **稳定引用。** 给 tab 和文档导航维护标识，用带观察代次的引用替代裸整数。运行内保存引用到节点/locator 的映射，导航、关页和节点替换后失效；不复用指向别的节点的旧编号。重新观察清理旧标记；解析必须验证唯一性、连接状态和所属 tab。不能让旧引用悄悄命中另一个元素。
- **页面选择。** 绑定明确 tab，打开新页时返回新 tab 信息，再由后续调用选择；不依靠“最后一个 tab”隐式切换。先提供必要的选择和状态，不扩展复杂浏览器管理界面。
- **输入。** 使用 `locator.fill(text)` 实现覆盖；确需键盘事件的控件由明确输入模式处理。部分输入失败后先读回值，再决定修复，不盲目再次 type。坐标路径明确替换/追加语义，无法确认输入目标则返回失败。
- **等待。** 使用 Playwright 的动作可执行性检查，加可选目标条件，例如元素可见、文本出现、URL 变化或字段值读回。设置单次总超时，避免固定 sleep 或无限等待“网络完全空闲”。动作已执行与业务验证结果分别记录。
- **验证。** 提交后读回成功消息、记录编号或页面状态；视觉问题再截图。只为用户目标选一个有解释力的成功条件，不重复获取多个等价信号。

### 5.4 用正确的批次语义减少模型往返

把“是否支持一轮多个工具调用”纳入供应商/模型适配能力。遵循该参数语义的已验证服务允许模型生成多调用；不支持的服务省略或按其官方契约设置。未知接口保持保守配置，不根据 OpenAI 文档推定 DeepSeek 的实际行为，也不因报参数错误就盲目重发副作用动作。

执行层首批仍按顺序处理。优先把无需中途判断的已知动作放在一批，例如填写几个已确认字段，最后读回一次结果；需要先取得元素引用的下一步保留到观察之后。

放开批次前补齐失败规则：对包含浏览器写动作的批次采用保守的失败停止策略，某次失败或拒绝后，剩余调用逐个补“未执行，前序失败，需重新决策”的结果和事件；纯独立读取批次可继续。所有 call ID 必须配对；提问、审批挂起、批准后的续接、用户停止都遵守同一规则。这样无需引入依赖图调度器，代价是部分无关后续动作也会延期，文档和指标应如实说明。

同页 click/input/scroll 不并发。跨页面资料抓取或独立文件读取的受限并发，等串行语义稳定、计时证明有价值后再做，不能与启用模型批次混为一项。

### 5.5 增加轻量网页正文工具

第二批新增 `web_fetch`，定位为**公开 HTTP(S) 文本材料获取**。保留搜索引擎用于发现来源，保留浏览器用于登录、交互、JavaScript 渲染和用户明确要求的浏览器任务。

建议采用沙箱内 `httpx` 流式抓取，复用现有沙箱 HTTP 服务与身份边界；API 侧用已有 BeautifulSoup/markdownify 做正文根节点选择与转换，不直接给 API 主机增加一个任意地址抓取入口。沙箱新增依赖需更新自己的锁文件和容器安装来源，不能因为 API 已有 httpx 就假定沙箱也有。

结果返回原 URL、最终 URL、状态码、标题、获取时间、提取方式、受限正文和完整文本引用。限定协议、重定向次数、解压后字节数、总超时及支持的 MIME；默认抓公开网页，内部地址和重定向目标受明确策略约束。浏览器 Cookie 与用户凭据不自动复制到抓取器。

解析不到正文、返回登录页或依赖渲染时，返回有原因的 `requires_browser`，由循环选择现有浏览器。一次失败不要让 fetch 和 browser 无限互相回退。原始页面中的指令仍按外部资料处理，不作为用户授权。

第一版复用现有依赖，不先增加向量库、自动爬虫或 LLM 网页摘要服务。如果真实材料证明正文容器启发式不足，再评估专门正文提取库。

### 5.6 截图留证与模型视觉能力分开完成

**首批显式截图工具。** 新增 `browser_screenshot`，参数包含 purpose、tab、视口/整页/元素范围。复用 `page.screenshot`、locator 截图和既有文件存储；记录实际像素尺寸、页面 URL、捕获时间、文件大小及关联调用。页面达到目标状态后才调用；全页图设尺寸/字节上限，超限建议分区，不无限生成长图。

截图是被明确请求的工具结果，捕获与存储设置总预算并分别计时。截图失败明确反馈，不覆盖此前动作成功。留证文件登记到可追踪的会话/运行归属，首批按普通交付文件显式保留、不自动过期，并限制每次运行的截图数量和累计字节，超过限额明确返回原因。生成上限不能替代存储回收；当前删除会话不清理截图的边界继续明示。历史自动截图不批量清理。临时视觉图的保留期和按引用回收在视觉阶段补齐，扩展存储删除能力时只处理已登记归属的新产物，过期后历史事件显示“图片已过期”，不能假装仍可预览。

**视觉阶段。** 扩展工具结果和消息装配，使图像引用经模型适配器变成真实多模态内容；数据库存稳定文件引用、内容哈希和尺寸，二进制留在文件存储。不要把 base64 当 JSON 文本送入模型，也不能把应用内部下载 URL 当作供应商可访问的图片。

逐模型检查 `vision` 及供应商支持的消息格式，默认不自动切换模型。非视觉模型仍可为用户生成截图，但必须反馈“仅留证，未做图像判断”。视觉模型可以接收受控尺寸的图片；字符估算不能计量图像，需要补充对应图像容量估算。请求重建要包含图片清单、哈希和实际输入规格，不能破坏现有可追溯性。

只在当前视觉任务需要时输入图片；旧图在完整轮次边界压缩为观察结论和引用，具体裁剪策略服从供应商推理历史与缓存约束，不每轮随意删除历史。用具体观察结论证明模型看到了指定图像，不能以“接口接受图片”代替视觉任务验收。网络、能力和压缩契约未闭合前，不将截图工具宣传为视觉验收。

### 5.7 可靠日志和有边界的进展控制

用 Playwright `page.on('console')`、`page.on('pageerror')` 在页面建立时捕获日志，保存到按 tab 隔离的有界缓冲；记录级别、时间和序号。`console_view` 支持 level、since 和条数上限，不再通过反复包裹页面 console 实现。需要长期查看的日志沿现有结果落盘路径保存，输出说明最早可用序号及丢弃情况。

提示词改为说明何时选文本、结构、截图，何时观察以及何时停止；中英文版本同步。达到目标并有直接证据后结束；失败先诊断，不原样重放副作用操作。不要用中文关键词判断截图意图，也不增加一个默认运行的“评审 Agent”。

保留现有完成前最多一次反馈。若真实轨迹中仍有明显原样重复，可增加很轻的提示：同一目标、相同参数、相同观察连续数次时提醒换方法；不因合法轮询或页面尚未加载就强制终止。首次优化不建设通用语义进展评分器。

### 5.8 补齐计时，再决定后续资源优化

沿现有事件与开发者视图增加少量字段：准备环境、协议发现、工具执行、结果整形、观察/截图、上传、展示补全、事件持久化。使用单调时钟计算耗时，墙钟只用于用户时间和关联；异常、取消与超时同样记录。持久化本身的耗时在后续汇总或日志中记账，不能要求事件在提交前就精确记录自己的提交耗时。

保留历史 `duration_ms` 的口径，新分段字段可缺省，旧记录显示“未采集”。截图工具的总耗时包含其捕获/存储子阶段，汇总时不得重复相加。准备与收尾不塞进模型耗时；人工等待与实际执行分开。首批不追求每毫秒都精确归因，也不为此部署 OpenTelemetry 后台或新的数据库。

直接使用现有输入、缓存、输出、推理用量，记录供应商未返回的空值；没有价格表时不展示推测金额。不把缓存命中率、工具数量和 tokens 单独作为质量排名。

如计时证明短任务主要卡在准备环境，再评估惰性沙箱：无附件纯回答先运行模型，第一次资源工具或大结果落盘前创建沙箱；项目占用、保护快照与旧写入者处理仍保留在原有正确边界。MCP/A2A 可先考虑独立发现并行；工具较多时再设计目录发现与按需 schema 展开，保持请求快照/重建及授权一致。此项影响生命周期较大，后置，不以关键词分类提前猜用户是否需要沙箱。

## 7. 克制的验证方案

### 本轮已做

源码静态核对、历史 JSON 读取与简单加总、官方资料核对。文档交付前检查相对链接和改动范围。没有新产品运行证据，没有测得优化收益。

### 批准实施后建议做

先选三个固定任务，在改动前后各跑一次：纯回答、网页取数、多字段填写后读回结果。控制同模型、思考档位、输入、页面和冷热环境条件，记录质量、总时间、模型轮数、用量及新增分段计时。存在网络波动或失败才补一次针对性复核，不循环跑全套评测。视觉阶段再增加一个关键状态截图判断任务。

自动检查仅覆盖实际改变的关键契约，并尽量合并到现有夹具：

1. 一个受控页面覆盖嵌套正文不重复、长文尾部可读、范围选择和目标状态等待。
2. 同一交互夹具覆盖无目标拒绝、过期引用/新 tab、覆盖输入，以及批次失败后后续未执行且调用配对完整。
3. 事件/前端夹具覆盖文本成功、业务失败、截图失败、旧截图回放；取消或存储失败不掩盖已执行动作。
4. 新增 fetch 时检查限制与渲染回退；新增图像输入时检查真实消息结构、能力不支持和容量边界。未实施的阶段不提前铺设其测试体系。

成功标准以业务目标和信息正确为前提。纯文本任务零自动截图属于确定性验收；小型取数任务以“读取结果足以回答、没有无理由重复读取”为目标，不强制规定任何模型都必须恰好两轮。一次观察不外推成功率，也不承诺固定节省比例。

生产构建、类型和服务检查采用所属指南入口，只运行受影响部分。无必要不重跑全套历史 E1–E7、全部故障注入或完整视觉审计。
