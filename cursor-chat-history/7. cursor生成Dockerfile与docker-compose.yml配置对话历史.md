## 核心架构

```
浏览器 → :8088 → Nginx
                    ├── /       → manus-ui:3000   (Next.js)
                    └── /api/   → manus-api:8000  (FastAPI)
                                    ├── PostgreSQL (manus-postgres:5432)
                                    ├── Redis      (manus-redis:6379)
                                    └── Sandbox    (manus-sandbox:5901/8080/9222)
```

- 仅 Nginx 的 **8088** 端口对外暴露，其他服务均在内部网络 `manus-network` 中通信
- API 的 `/api/` 路径已配置 WebSocket 升级支持（VNC 远程桌面）和 SSE 流式传输（`proxy_buffering off`）
- 前端 API 调用：开发环境默认 `http://localhost:8000/api`，生产环境使用 `/api`（由 Nginx 反向代理）

```bash
# 1. 编辑 .env 填入 COS 密钥和 LLM API Key
# 2. 一键启动
docker compose up -d --build
# 3. 访问 http://your-server-ip:8088
```

**根本原因**：`refresh()` 从 API 加载了历史事件后，`startEmptyStream()` 调用 `chat(sessionId, {})` 没有传递 `event_id`，导致后端从头返回所有事件，`appendEvent` 直接追加造成重复。

3. **`startEmptyStream()` 传递 `event_id`**（第 87 行）- 调用 `chat` 时将 `lastEventIdRef.current` 作为 `event_id` 传递，后端的 `output_stream.get(start_id=latest_event_id)` 就只返回该 ID 之后的新事件

4. **`appendEvent` 自动更新 `lastEventIdRef`**（第 47-48 行）- 每次收到新事件都更新游标，确保后续重连也不会重复
