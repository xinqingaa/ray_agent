# 独立核验与质量批判

跳出“写完就觉得没问题”的盲区，专职承担**交付前把关**。若需要补充外部事实或检索原文档，应回到取证规则，不在本流程重复猜测。

## 轻 / 重档位判断

- **IF 文本答复、轻量整理或普通问答 → 走轻档（默认）**：
  - 交付前逐条对照用户原话检查：核心问题是否答全、硬篇幅/受众/语言限制是否满足、假设或待确认处是否就近标明。
- **IF 交付 `.xlsx`、`.pptx`、`.docx`、`.pdf`、`.html` 文件或可执行网页/脚本 → 走重档**：
  1. 先调用 `prepare_skill_resources(name="verification-critique")` 获取本包稳定快照根路径；
  2. 用随包 Python 运行 `<root_path>/scripts/verify_office.py <交付文件路径>`，并将结果核验挂入工具 `verification` 或在关键交付前读取核对 JSON（`passed` 为 `true` 才算结构检查通过）；
  3. 对 `.pdf` 额外调用 `read_document` 抽读全文或首末关键页，确认中文文本可完整提取、无乱码方块或缺字；
  4. 对 `.xlsx` 若脚本提示存在未缓存公式值，必须用 Python 代码独立核算核心汇总数值，在最终答复中附上可核对汇总表并说明应用内表格预览不重算公式。

## 交付前核对清单

1. **要求覆盖**：用户指定的格式、文件名、工作表/页数、剔除项、禁止联网等约束是否全部兑现。
2. **数值与口径**：汇总值、增长率、占比是否通过代码计算，是否与明细行总和一致。
3. **诚实标注**：尚未取得一手依据的推定/占位内容，是否在主视图紧邻位置标明「待确认」或占位标记。
4. **可用路径**：文件成果已通过 `deliver_files` 交付（网页类同时调用 `register_preview`），不把未执行或失败的命令写成已完成。

## 反模式红线

- **禁止把“脚本跑完无报错”等同于内容正确**：文件生成成功不代表公式结果对了、PDF 没有乱码或网页按钮真能点。
- **禁止跳过文本提取验证交付 PDF**：不得仅靠渲染截图判断 PDF 没问题。
- **禁止隐瞒警告**：`verify_office.py` 报出的 `warnings` 或 `issues` 若未修复，必须在答复中如实说明真实缺口。
