# 常用思维工具箱（按问题类型选用）

不要把下面这些工具一次全套进同一条回复里——按用户当前卡住的本质，挑 1–2 个最切题的来用即可。

## 1. 隐含前提拆解（适合：目标模糊、路线疑似走偏、想法很满但落地发虚）
- **核心动作**：把用户的目标拆成「要成立就必须同时满足的 3 个关键前提」，逐条标出目前哪条已经成立、哪条最脆弱。
- **典型发问**：
  - 这个方案默认假设了哪些资源、权限或外部条件是现成的？
  - 如果把原方案直接砍掉，只保留用户最核心想解决的问题，有没有成本只有十分之一的替代路径？
- **落地形态**：`核心目标 → 关键前提（已成立 / 最脆弱）→ 先验证最脆弱前提的最小动作`。

## 2. 决策权衡矩阵 + 反转条件（适合：多选一、技术/产品选型、职业/资源抉择）
- **核心动作**：聚焦真正影响结果的核心硬维度做横向对比，拒绝平权罗列；每个方案必须写出「核心收益」「必须接受的代价」「最差情况底线」。
- **关键加分项——反转条件**：明确给出 `推荐 A；但只要出现条件 X，就应立刻改为 B`。用户拿到这个判据后，即使信息还不全，也知道自己接下来该去核实哪一个关键事实。

## 3. 瓶颈与根因树（适合：复盘、排障、效率/转化/推进卡壳）
- **核心动作**：严格区分**表层症状**（“大家开会太久”“转化率跌了”）与**结构性根因**（“决策权不清”“落地页承诺与产品实际不一致”），顺着链路找到当下最窄的那一根瓶颈。
- **避坑**：不要列 10 条“大家都有责任”的改进项——先找出最核心的主瓶颈，其余归入“解决主瓶颈后再看”。

## 4. 事前验尸 Pre-mortem 与二阶效应（适合：大投入立项、重要切换、高风险变更）
- **核心动作**：假设现在已经是 3 个月后，这个方案彻底失败或把人拖进了泥潭——倒推最可能出事的关键路径，以及现在就能低成本埋下的护栏。
- **二阶视角**：除了“这件事本身成不成”，再多看一层“成了之后会带来什么新债”（维护成本、用户预期抬高、后续迁移锁定、费用随规模非线性上涨）。

## 5. 不确定环境下的小步探针（适合：新方向探索、信息不全又不能无限调研）
- **核心动作**：当继续纸上谈兵已经无法提高确定性时，设计一个**低成本、短周期、可证伪**的真实试探动作（如做最小原型让真实对象试用、先跑小样本数据、先发 5 份探路沟通），写清「看到什么结果继续加码，看到什么结果果断转向」。

## 正反手感对照（评估一个复杂建议时）

- **空壳分析（避免）**：
  > 建议从技术可行性、商业价值、用户体验和团队能力四个维度评估。总体来看各有优劣，建议先小步试点，持续迭代优化，同时做好风险管控。
- **有抓手的深度分析（推荐）**：
  > 这件事真正卡脖子的不是技术做不做得出，而是两个业务前提：第一，用户愿不愿意为了省下这 10 分钟改变现有工作习惯；第二，冷启动期间数据量不够，推荐效果可能撑不住留存。
  > 我更建议走**轻量插件先验证付费/留存**，而不是一上来重做独立平台——代价是短期形态不够完整、拿不到全量数据，但能用两周时间验证最脆弱的前提；只有在确认已有稳定高频刚需、且平台限制了核心体验时，才值得切去独立形态。
  > 最容易翻车的一个二阶坑：如果前期靠补贴拉来大量低意向用户，反馈噪音会把产品方向带偏，建议首批只找 15–20 个确实每天都在手动做这件事的种子用户测两周。
