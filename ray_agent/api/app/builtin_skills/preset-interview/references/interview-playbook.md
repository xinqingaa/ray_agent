# 面试追问树、复盘评分卡与改写对照

## 一、按岗位方向的深挖追问链（模拟面试官用）

不要机械照搬顺序，顺着薄弱点或亮眼点逐层深挖即可：

### 1. 研发 / 架构 / 算法岗
- **背景与边界**：这个需求的峰值量级/延迟约束是多少？你个人独立负责的边界在哪，哪些是团队既有底座？
- **关键取舍**：为什么选方案 A 而不是更简单的方案 B？当时评估过哪些代价或一致性/吞吐折中？
- **异常与压测**：上线后有没有遇到过最难排查的故障、抖动或边界 case？当时怎么定位、怎么止血、事后怎么防复发？
- **演进与迁移**：如果现在流量再翻 10 倍，或者让你重新设计一次，当前架构第一个撑不住的点在哪？

### 2. 产品 / 运营 / 商业分析岗
- **问题定义**：你怎么判断这是真痛点而不是伪需求？有没有反面数据或用户访谈证伪过你的初版判断？
- **推动与取舍**：研发排期紧或跨部门利益打架时，你砍掉了什么功能、保住了什么核心指标？怎么说服反对方的？
- **归因与复盘**：指标涨了之后，怎么剥离自然流量/大盘季节性/补贴因素，证明是你的策略带来了净增量？
- **反问迁移**：如果换到我们公司当前这个业务阶段，这套打法哪一块可以直接搬，哪一块一定会水土不服？

### 3. 技术管理 / 团队负责人（TL / Manager）
- **用人与拆解**：项目延期且核心骨干状态不对时，你具体怎么介入既保住交付又不把人管死？
- **向上与跨界**：老板目标不合理或资源砍半时，你如何重排优先级、向上对齐预期？
- **复盘反思**：带团队做过最让你后悔的一次决策是什么，后来建立了什么机制？

## 二、模拟结束后的结构化复盘模板

退出面试官角色后，按以下脉络给出真正能帮用户下一场翻盘的复盘：
1. **面试官视角总评**：当前表现处于什么水位（强推荐 / 边缘可过 / 暂不通过）及核心原因。
2. **值得保留的亮点**（具体到哪一轮哪句话加了分，告诉他正式面试一定要稳住这些点）。
3. **最致命的关键失分点**（直说面试官听到时的真实疑虑，如“只讲流程不讲取舍，会让人怀疑只是执行者”）。
4. **逐题精修建议**：每道关键题给出 `原回答问题 → 考察本质 → 升级回答骨架（30–90 秒口述结构）`。
