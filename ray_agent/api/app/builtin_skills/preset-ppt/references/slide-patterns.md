# 幻灯片差异化版式库与 HTML 演示稿工程要点

不要把一整套演示稿做成 10 页一模一样的“标题 + 3 个圆角卡片”。按每页的信息性质交替选用以下版式，建立清晰的观看节奏：

## 一、8 种高频页面版式

1. **封面页（Cover）**
   - 结构：清晰大标题（直指主题）+ 一行价值副标题 + 底部汇报人/日期元信息；可用深色主底或高留白素白底定下整套基调，一处简洁几何线条或色块呼应主题即可，不堆花哨装饰图。
2. **结论总览页（Executive Summary）**
   - 结构：顶部大号结论句（Action Title）+ 中部 2–4 个核心数字指标卡（大字号 `tabular-nums` + 一句业务含义）+ 底部 1 条总建议横幅。
3. **双栏对比页（Comparison / Before-After）**
   - 结构：左右非对称或对称双栏（现状痛点 vs 目标方案、方案 A vs 方案 B），用细竖线或底色深浅拉开主次，突出主推栏，把关键取舍用清晰对比标签点透。
4. **结构化对比表页（Matrix / Table）**
   - 结构：3–5 维横向决策表（维度 × 方案），主推列用极淡强调底色高亮，单元格写清关键指标与判断，避免堆砌无层次长段。
5. **数据图表 + 洞察页（Data & Takeaways）**
   - 结构：左 60% 清晰内联 SVG 图表（柱状/横向条形/折线/构成条，数值直接标在图上），右 40% 放 2–3 条“所以怎么办”的业务洞察，形成「看图 → 得结论」的视线动线。
6. **流程与里程碑页（Timeline / Roadmap）**
   - 结构：横向 3–5 步演进轴，每步写清「阶段目标 + 关键产出 + 验收/转向判据」，只在真正有先后顺序时使用步骤编号。
7. **焦点深挖页（Deep Dive / 2-Part Narrative）**
   - 结构：左 35% 放核心论点大字引用或关键问题，右 65% 用层次清晰的结构化论据支撑，适合讲清一个复杂判断。
8. **收尾与行动请求页（Closing / Next Steps）**
   - 结构：不要只写空洞的“谢谢观看”！左/上部重申最关键的决策结论，右/下部列清需要现场拍板或会后立刻启动的核心行动项。

## 二、自包含 HTML 演示稿关键工程规范

- **画布比例与防溢出**：每张 `.slide` 固定 16:9 舞台比例（如 `aspect-ratio: 16 / 9; max-width: 1120px; width: 100%;`），合理使用 `clamp()` 控制字号，内边距留足（`44px–56px`），确保正文永不贴边或顶出卡片；窄屏下优雅降级为纵向阅读流，无横向滚动条。
- **翻页交互**：
  - 绑定 `ArrowRight` / `PageDown` / `Space` 下一页、`ArrowLeft` / `PageUp` 上一页、`Home` / `End` 首末页；
  - 底部提供清爽不遮挡正文的翻页控制条：上一页、下一页、`当前页 / 总页数`、轻量进度条及可选“总览/打印”提示。
- **打印与导出 PDF（`@media print`）**：
  - 设置 `@page { size: A4 landscape; margin: 10mm; }`；
  - 打印态下隐藏翻页控制条，把所有 `.slide` 改为 `display: flex`（或 `block`）逐页展开，每页加 `break-after: page; page-break-after: always;`（末页 `break-after: auto`），确保直接打印成 PDF 即得完整演示稿。

## 三、做完前快速剔除 3 个常见瑕疵
1. 有没有哪一页出现密密麻麻无层级的纯文本墙？（按受众与阅读场景拆页，或转化为对比表/图示。）
2. 有没有连续 3 页长得几乎一模一样？（把中间一页换成双栏、表格或左图右文。）
3. 缺失的数据是不是都显式标了「占位 / 待确认」，且没有外链失效的图片或字体？
