# DeepSearch 深研实战手册

执行中大型调研、行业/岗位行情、竞品选型或多文档对账时参考本手册，按任务需要灵活取用。

## 一、按任务类型的拆词矩阵

### 1. 行业 / 岗位行情与前景调研（如面试备考、转行评估、赛道调研）
至少覆盖 4 个互补检索面：
1. **需求侧真实口径**：目标岗位近期招聘 JD 核心技能词、硬门槛变化、头部/腰部公司用人偏好（加年份词，如 `2026` / `2025`）；
2. **供给与面试风向**：近期真实面经、高频考察点、淘汰重灾区、从“八股”转向“业务场景/工程落地”的具体信号；
3. **商业基本面**：该领域头部公司近两季财报/融资/业务收缩或扩张动向，判断是增量红利期还是存量内卷期；
4. **反方与替代风险**：从业者真实吐槽、天花板、自动化/AI 替代压力与隐性淘汰机制。

### 2. 技术方案 / 产品 / 供应商选型
1. **官方一手文档与定价页**：核心能力边界、计费口径、限流/配额、最新变更日志（Changelog）；
2. **第三方实测与对比**：独立 Benchmark、迁移案例、生产环境稳定性评估；
3. **GitHub Issues / 社区踩坑**：搜索 `"<产品名> limitations" OR "migration issues" OR "pricing gotchas"`，专门挖官方宣传页不会写的坑；
4. **退出成本与替代品**：数据导出、协议兼容性与备选方案。

### 3. 政策 / 规则 / 定价细则核查
1. 优先锁定发布主体官网（政府门户、监管机构、厂商正式文档），核对**生效日期、适用地区/对象、例外条款与旧版废止状态**；
2. 遇到新闻解读或自媒体总结，务必反查原文编号或公告全文确认没有断章取义。

### 4. 多份本地文档交叉核对
先建一张隐式台账再下结论：
- 每份文档记录：`文件名 | 成文/更新日期 | 适用范围/版本 | 核心口径与关键数值`；
- 专门核查三类高频雷区：**同名不同义**（如“营收”含不含税/渠道返点）、**时间窗错位**（自然月 vs 滚动 30 天）、**局部更新漏改汇总页**。

## 二、遇到冲突数据怎么写才专业

不要写成“有的说 A，有的说 B，不太确定”。改成清晰的口径对照：

| 争议点 | 来源 A（时间与口径） | 来源 B（时间与口径） | 差异原因与采信建议 |
|---|---|---|---|
| 具体指标或条款 | 数值 + 来源 + 日期 + 口径 | 数值 + 来源 + 日期 + 口径 | 说明是时间更新、样本范围还是定义差异；明确当前任务建议按哪一口径采用 |

## 三、调研报告的“高价值组织方式”

调研结果发给用户时，避免堆砌一长串原始摘录，优先按阅读效率组织：
1. **核心结论先给透**（开篇正面讲清核心判断、依据方向与把握程度，篇幅随问题复杂度自然展开）；
2. **关键证据与结构化对比**（用对比表或分主题要点承载一手事实，每条紧邻来源与时间）；
3. **推演洞察与反方风险**（把查到的零散事实串成对用户有用的判断，明确标为「基于以上事实的推断」）；
4. **信息盲区与可继续深挖点**（诚实指出哪些数据没有公开一手来源，及下一步怎么核实）。

## 四、检索卡壳时的破局技巧

- **中文结果全是营销号/搬运站**：换英文专业术语、加 `site:` 限定官方/文档/GitHub/学术域，或搜具体版本号与报错/参数原词；
- **`web_fetch` 返回 `requires_browser` 或空壳 JS 页**：先找同一信息的静态替代一手源（如官方 GitHub README、PDF 公告、文档站纯文本页），确需交互渲染且浏览器可用时再切浏览器；
- **查了 3 轮仍找不到可靠定量数据**：果断停止空转，诚实向用户交代“已查过哪些一手渠道、目前公开口径缺失哪块、现有条件下能确定的边界是什么”。
