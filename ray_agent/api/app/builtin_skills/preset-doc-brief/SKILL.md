# 文档与会议提炼工作流

快速读透长文档、会议记录或多份散乱材料，按受众输出结构严谨、依据可追溯、不超篇幅的提炼结果。

## 轻 / 重与子模式切换

根据用户材料和要求选择对应子模式（不清晰时默认用「决策速览」出初版）：
1. **决策速览（默认）**：适合给负责人看。结构为 `① 一句话核心结论 → ② 关键依据（3–5 条带数据/出处）→ ③ 主要风险、分歧与待确认项 → ④ 建议下一步`。
2. **执行拆解**：适合会后推进。结构为 `已对齐结论 / 未决问题 / 行动项表（事项 | 负责人 | 截止时间 | 依赖或待确认）`。
3. **多文档对比**：适合政策/方案/报价/纪要对照。先用表格逐项对比各文件口径，再单列「一致项」「冲突点与各自原文出处」「缺失盲区」。

## 操作规范

1. **完整读原文**：对 PDF、DOCX、`.doc`、XLSX、PPTX 优先调用 `read_document` 分段通读；工作区会话配合 `knowledge_search`/`knowledge_read` 找回关联纪要与背景，保留 `[出处](#rayagent-source-片段ID)`。
2. **缺背景低摩擦处理**：会议记录缺少负责人、截止时间或背景口径时，**不要连环反问**，先基于已有材料产出初版，在对应单元格或要点紧邻处标明 `[待确认：缺负责人]` 等标记。
3. **硬约束优先**：若用户指定字数/页数上限（如“一页以内”“300 字发群里”“不要技术术语”），必须先满足硬约束，再保留最高价值结论。

## 反模式红线

- **禁止为了显得全面把原文复述一遍**：删掉客套寒暄、重复讨论过程，只保留决策、依据、分歧和行动项。
- **禁止补造材料里没有的因果、完成度或负责人**：没写谁负责就标「待确认」，不能替用户指派。
- **禁止把「待确认」只藏在文末备注**：必须紧邻展示在主视图对应表格或条款旁。
- **禁止超出用户明确指定的篇幅或受众语域限制**。
