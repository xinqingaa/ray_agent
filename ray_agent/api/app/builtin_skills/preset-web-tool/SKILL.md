# 网页工具与单文件前端构建

目标是交付**单个自包含 HTML 文件**（除非用户要求拆分），一打开就有清晰的美感、顺手的交互和完整可靠的业务逻辑。代码规模与视觉细节完全服从真实体验和需求复杂程度，不做人为的行数或功能压缩。

## 设计与工程工艺原则

- **主画布聚焦高频操作，维护表单收进弹窗或抽屉**：把用户高频观看和直接操作的核心工作区（如排班表、看板、计算画布、预览区）放在首屏主角位；人数增减、规则配置、模板设置、导入导出等低频设定，收进顶部工具栏触发的 Modal 或侧边 Drawer 中，避免把长串配置表单直接堆在页面上方把主体挤出首屏。
- **矩阵与表格单元拒绝“满屏原生 `<select>` 墙”**：密集单元格内优先渲染干净的视觉标签（色块、图标、胶囊徽章、简洁文字），点击或悬停时再唤起轻量气泡菜单、快捷切换环或内联弹层进行修改，既提升扫描效率又显著拉开工业级界面质感。
- **禁用粗陋的系统原生弹窗**：严禁使用 `window.alert()`、`window.confirm()` 和 `window.prompt()`，统一用美观的页面内 Toast 提示与二次确认对话框承接反馈和危险操作。
- **业务逻辑与汇总统计必须全口径自洽**：涉及筛选、日历/跨月、统计看板、汇总计数或冲突检查时，确保统计逻辑覆盖完整数据集（例如全月全部日期、全部成员或已筛选视图与全局汇总明确区分），状态变更后所有派生计算同步刷新，补全空状态、边界保护与 `localStorage` 本地持久化。
- **视觉与交互细节**：注意恰当留白、层次对比、清晰状态色与深浅和谐，常用操作支持合理快捷方式（如 Esc 关闭弹层、快捷键撤销/重置确认），桌面与窄屏下都保持布局稳固、不溢出折行混乱。

## 高效交付与防空转规则

- 构思完整页面架构、状态模型、样式系统与核心交互后再一次性用 `write_file` 落盘，减少反复零碎改写。
- 若当前运行环境未提供终端命令或浏览器工具，**写完文件确认核心逻辑无遗漏后，直接依次或同批完成 `register_preview`、`deliver_files` 与 `update_plan` 并给出清晰说明，切勿为了“自查”分段多次 `read_file` 重读自己刚刚写入的完整 HTML**。
- 若具备命令行或浏览器验证条件，再按 `verification-critique` 核验关键交互与统计边界后交付。
