# 信息呈现与视觉设计

把结论做成真正好读、好用的交付物。本规范专用于向用户交付的产物（网页、HTML 演示稿、长报告、表格呈现），与开发规范彼此独立。

## 轻 / 重档位判断

- **IF 纯对话答复、短摘要或轻量列表 → 走轻档（默认）**：
  - 结论先行，层级不超过 3 级；并列数据用短表或紧凑要点，段落控制 3–4 行内，不堆装饰符号。
- **IF 制作互动网页、HTML 演示稿（PPT）或长篇可视化报告 → 走重档**：
  - 动工前读取包内 `references/visual-checklist.md`（通过 `read_skill_resource`），确定内容类型、主色调与字体栈后再编写代码。

## 核心视觉原则

1. **克制高级感，拒绝廉价 AI 模板味**：
   - 浅色阅读/办公类产物首选干净中性底色（如 `#FAFAF9` / `#FFFFFF`）+ 极克制单个强调色，不默认使用紫蓝渐变、霓虹发光或玻璃拟态卡片堆砌；
   - 中文排版优先原生字体栈：无衬线 `'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif`，衬线 `'Songti SC', 'Noto Serif SC', serif`，等宽 `'SF Mono', Menlo, monospace`。
2. **信息层级与留白**：
   - 严格控制一屏/一页只讲 1 个核心观点，留白占视觉呼吸感至少 25%；
   - 字号拉开清晰阶梯（主标题 / 节标题 / 正文 / 辅助元信息），关键数字与结论加粗或单独卡片承载，辅助说明降灰降字号。
3. **自适应与可用性**：
   - 网页与 HTML 演示稿必须兼容窄屏与宽屏，无横向溢出、无文字裁切；交互控件（按钮、筛选器、翻页）具备清晰可见焦点态与真实可用行为。

## 反模式红线

- **禁止紫蓝渐变大背景 + 满屏半透明毛玻璃**：除非用户明确指定暗黑赛博/霓虹主题，否则禁用大面积渐变背景和过度阴影。
- **禁止每页/每段强行凑 3–4 个等宽图标小卡片**：结构形式必须服务真实信息（对比用表、流程用时间线、结论用核心指标卡）。
- **禁止假数据撑画面**：真实数据不足时显式标注「占位 / 待确认」，不能为了排版好看编造营收、百分比或用户评价。
