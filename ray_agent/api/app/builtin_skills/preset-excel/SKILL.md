# 整合与清洗 Excel 工作流

先盘点真实数据结构与口径冲突，再做清洗合并与公式生成，最后用独立代码核算关键汇总值并诚实说明预览边界。

## 阶段流

1. **盘点原表与口径确认**：
   - 用 `read_document`（按 `sheet` 读取）或随包 Python 探查所有输入表的工作表名、表头列名、空值/重复键、日期与金额格式；
   - **IF 发现多表字段命名不同、合并主键不明或同一指标存在口径冲突**：用 1–2 个简明选择题向用户确认合并键与优先口径；若结构明确则直接给出默认合并方案并动手。
2. **清洗整合与公式生成**：
   - 临时脚本与中间依赖装在会话 `scratch` 目录（不要污染工作区文件夹）；
   - 优先保留原始明细表、新增清洗后明细表与汇总分析表；汇总列写入标准 Excel 公式（如 `SUM`、`SUMIFS`、`AVERAGE`、`COUNTIF`），设置清晰表头、数字格式与自适应列宽；
   - 若用户要求局部调整已有交付表格，先读取原文件在原基础上修订并另存清晰新版本，不丢失原有工作表。
3. **独立核算与核验（必做）**：
   - 用 Python 代码独立计算一遍汇总表中的所有关键合计数、均值与分组统计（不依赖 Excel 公式重算缓存）；
   - 运行 `verification-critique` 的 `scripts/verify_office.py <输出.xlsx>` 检查工作簿结构与未缓存公式计数；
   - 调用 `deliver_files` 交付 `.xlsx`。

## 交付答复规范与反模式红线

- **必须在答复中给出「代码核算后的关键汇总表」**，同时诚实提醒用户：应用内表格预览不会重算未缓存的公式单元格（若需在 Excel 中触发全量公式计算，下载后用 Excel/WPS 打开即可）。
- **禁止心算或直接抄估算值**：所有合计、占比、同比增长必须由脚本算出。
- **禁止静默丢行或硬覆盖口径冲突**：去重数量、被剔除的异常行、缺失匹配键的行必须在「清洗日志 / 处理说明」中列出。
- **禁止把临时脚本或虚拟环境留在工作区交付目录**。
