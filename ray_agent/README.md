# RayAgent 运行指南

本文说明桌面应用的模型连接、数据位置、运行检查与排查。产品能力见[项目首页](../README.md)，执行与数据流见[架构说明](../docs/architecture.md)。构建与开发命令在[桌面开发指南](desktop/README.md)。

## 适用范围

RayAgent 是单机桌面应用：Tauri 宿主随包带上冻结的 Python 核心，核心只在本机回环地址监听，界面经实例令牌访问。运行不需要 Docker、PostgreSQL、Redis 或 Nginx，也不向浏览器提供访问入口。原 Compose 部署已经删除，旧数据不迁移。

当前构建目标为 Apple Silicon Mac 内部包（本机 ad-hoc 签名，不公证），首个交付仍在实施中，不作为对外交付物。应用面向可信的本机使用者，没有账户或多用户权限。工作区已接入文件夹读写、工作方式、记忆、检索、Skill 与本机执行适配；组件安装入口、持久安装操作与随包工具运行时已有实现，语义检索与首个交付仍有未闭环项，见[收尾清单](../docs/plan/first-delivery-remaining.md)。独立对话不写入工作区记忆与索引，本机执行默认关闭。模型连接见下文；内部包构建与签名核对见[桌面开发指南](desktop/README.md#构建内部包apple-silicon)。

## 模型连接

在「设置 → 模型提供商」添加连接，填入接口地址、协议和 API Key，选择目录模型或声明自定义模型。可以先读取上游模型列表或测试连接，确认后保存。已有密钥以掩码显示。文件被其他程序改过时，重新读取后再编辑。

核心从用户配置文件读取地址与密钥，默认位置为 `~/.config/rayagent/config.toml`，环境变量 `RAYAGENT_CONFIG` 可另指路径。「打开配置文件」可用系统编辑器手动改动。默认权限见[配置示例](api/config.example.toml)。逐模型采样参数与 Agent、工具策略、MCP、A2A 设置保存在业务库。连接的生效与续接规则见[模型连接](../docs/model-usage.md#模型连接如何生效)。

## 数据位置

应用数据根为 `~/Library/Application Support/com.rayagent.desktop/core/`，其中有业务库、内容对象、会话工作目录与 skill 存储，布局见 [API 开发指南](api/README.md#数据根)。开发构建使用同目录下的 `dev-core/`，两者互不影响；环境变量 `RAYAGENT_CORE_DATA_DIR` 可另指数据根。

同一数据根同时只允许一个核心。备份或迁移时先退出应用，再整体复制数据根；只复制业务库会让附件、交付文件和 skill 包缺失。

覆盖安装新内部包前先退出旧应用。新核心若发现业务库 schema 低于本程序，会先用 SQLite 备份接口在数据根 `upgrades/` 写下升级前副本，再迁移并完成启动扫描后才受理；旧二进制打不开更新的 schema。回退旧版时需同时恢复该副本。完整备份／恢复界面与自动更新在后续正式发布阶段。

## 启动、关闭与退出

打开应用后宿主拉起核心，界面在核心就绪前显示启动状态；核心失败、意外退出或版本与应用不匹配时，界面显示原因、核心日志尾部与“重新启动核心”。

关闭主窗口只隐藏窗口，核心与正在执行的任务继续，从程序坞重新打开。退出用菜单或 Cmd+Q：没有活动任务时直接退出；有任务在执行或等待时先确认，确认后核心停止受理新工作、结束活动运行后退出。从程序坞菜单退出、注销或关机时系统直接结束应用，不会先确认，正在执行的任务记为中断。系统终止信号走同一条停止流程。各等待期限见[运行参数与限额](../docs/limits.md#桌面宿主与核心进程)。

## 运行检查

1. 打开应用，确认界面进入首页而不是核心错误页。
2. 在设置页“模型提供商”确认配置文件已找到，要用的模型显示为可用且有密钥掩码。
3. 新建对话，发送一条不需要文件或命令的任务，确认流式回复、计划与最终结果正常。
4. 切换会话与设置页，退出后重新打开，确认会话历史、未发送的文字和已上传附件仍在。用失效的草稿附件检查恢复反馈和移除后继续发送。
   - 模型连接使用临时 TOML 走查。添加、测试和保存连接，使自定义模型可在会话选择。编辑页打开时在外部保存配置，确认界面提示冲突。
   - 用量切换预设、自定义和提供商，查看日历、时段、时间柱下钻和用途。和对话中的费用核对，关闭偏好后对话中不再显示费用。
   - 在内部包使用未设置语音偏好的数据根，首次点麦克风查看两种方式的说明。下载本机模型后断开外网，使用本机录音、转写并编辑回填文字，核对该笔时长与零费用。使用已配置的 DeepSeek 在同一入口录音，核对估算费用。另可通过拒绝麦克风权限或失效连接检查就地提示和重试。
5. 工作区（需要宿主窗口，浏览器里打开文件夹入口是禁用的）：
   - 首页“新建工作区”，确认默认位置下出现同名文件夹，进入后在工作区里发起对话，左侧只列这个工作区的对话，独立侧栏看不到它们；工作区首页与独立首页的未发送草稿互不影响。
   - “打开文件夹”选一个已有文件夹，确认出现扫描摘要；再选一次同一个文件夹，提示已是工作区而不是新建；取消选择不产生任何提示。
   - 复制一个已打开的工作区文件夹再打开副本，确认出现冲突对话框，两个选项的后果说明清楚。
   - 附件与落点：在工作区从回形针选择样例文件，分别选择进入消息草稿和复制到指定目录。用 Finder 拖一个文件进主纸面，再检查两个落点和悬停目录。独立对话检查单落点。选择横图和竖图，检查草稿、已发送缩略图和放大预览的完整性。
   - 使用 PDF 与 DOCX 检查两个落点。从消息发送的附件应能被模型使用。复制到工作区的文档应在索引发布后可搜到，原件定位到对应页或段落。用其中一条结果引用到新任务。
   - 在输入区选择 Skill 并附上图片，确认发送后的消息与运行使用了所选材料。用测试核心让已受理的计划在执行中失败，检查失败提示能打开该次运行的清单。
   - 文件夹面板：展开子目录、预览文本与图片、添加同名文件时提示另存名称，会话里的“本次成果”可预览交付版本。
   - 工作台切换：在工作区会话里让模型执行一次带工具的任务，点时间线上的工具卡片，确认右侧面板切到“查看/工作台”并选中该工具，切回“文件夹”后展开状态与预览仍在；窄屏下同样在抽屉里切换。
   - 分栏连续性：在宽窗口拖动右侧分隔条并停住，确认边界随指针移动、松手后宽度不再变化、文件夹内容没有被选中。打开与收起右侧后分别在同一工作区切换两条对话，确认开合与宽度保留，并在读取期间观察对话区和右侧的边界位置。
   - 外部变更：保持工作区页打开，在 Finder 里新建、改名、删除文件夹里的文件，确认文件树稍后只刷新相关目录并保留展开；正在预览的文件被改动时出现“重新载入”；把文件夹移走时不可用横幅立即出现，移回后恢复；离开工作区页后改动不再触发刷新，回来后内容是最新的。
   - 脚本文件变化：让模型实际执行写文件的脚本，运行后从“查看文件变化”核对观察到的路径；同时改文件时不把所有变化归属给脚本。截断或中断时应显示范围不完整或状态未知；观察列表不提供撤销。
   - 撤销本次修改：让模型在工作区里新建并修改几个文件，运行结束后确认时间线末尾出现“撤销本次修改”，运行进行中不出现；打开后默认勾选可撤销的文件，可展开查看差异；先手动改其中一个文件再打开，确认它显示冲突、默认不勾，只有“仍要覆盖”才会覆盖；提交后逐项显示结果，对话内容不变，文件夹面板出现“最近修改”并可从那里撤销；归档后没有入口。
   - 写入占用：打开两个对话，让其中一个正在写文件时在另一个或文件夹面板里添加文件，确认提示是哪个对话占用并可跳转；停止写入后若显示“重试收尾”，点后应解除占用。
   - 在 Finder 中改名或移走工作区文件夹，回到应用点“重新检查”，确认出现不可用横幅，对话仍可发送，面板暂停；改回后恢复，或点“重新定位”选择新位置，确认横幅消失、文件树换成新位置的内容、之后在新位置里改文件仍会刷新；取消选择没有提示。分别选择已是另一个工作区的文件夹、含有另一个工作区标记的副本、应用数据目录与对话运行中重试，确认各有明确说明。
   - 在面板标题栏点“在 Finder 中显示”：选中子目录或文件、预览文件、什么都不选（显示文件夹本身）三种情况下 Finder 都定位到对应位置；浏览器里打开时没有这个按钮。
   - 独立对话侧栏只列独立对话，工作区里发起的对话不出现在其中；工作区侧栏只列该工作区的对话。含中文名的图片、PDF、网页在文件夹面板里能预览。
   - 归档后确认对话只读、不能添加文件，取消归档后恢复；删除确认框写明文件夹不受影响，受理后窗口顶部显示清理进度，磁盘上的文件夹原样保留。
   - 在「背景 → 工作方式」编辑正文、查看历史并恢复旧正文，再从新对话检查「本次参考」记录的版本。候选表单打开后，通过测试核心更新目标条目。检查旧版本确认被拒绝，重新审阅后可确认现有版本。在「背景 → 记忆」展开按需召回，检查来源深链可自动展开并定位。检查钉住、撤销和来源跳转，重启后核对状态。另一个工作区和独立对话应与本工作区的记忆隔离。
   - 在「知识」用同一词切换全部、文件、记忆和会话摘要，检查结果行、预览、过渡和来源跳转。检索 Markdown、带文字层的多页 PDF、含表格或图片的 DOCX 和带空行的多工作表 XLSX，检查块、页和实际单元格坐标。打开 PDF 命中页与 DOCX 命中块，翻页或放大后能返回检索。用测试材料引用到新任务，发送后检查「本次参考」原位展开、角标顺序与正文一致、摘录直接可读，点击文件名在右侧定位到引用位置。检查「运行详情」反复开合时回复位置及布局稳定。外部更新文件后检查历史片段，删除或排除后检查不可读反馈。
   - 在「知识 → 索引」检查大目录范围预检、暂停后已有材料可查、恢复后待处理项继续、重扫、排除和重新纳入。用可重建的解析失败检查行内原因和重试。窄窗口、共享界面移动视口、深浅主题、键盘焦点和减少动态效果按[原型验收规则](../docs/plan/prototype-ui.md#验收方式)检查。
   - 用含文字层和扫描页的同一 PDF 验证先查到文字层，从文件行安装文字识别，返回原索引位置，待补录后查到扫描页并打开对应页码。用只靠语义匹配的检索词检查安装语义组件、工作区重建、停留在当前查询时的结果刷新和来源引用。退出后重开确认已发布版本仍可读，删除样例文件后确认检索和来源入口反映撤回。
6. 打开“设置 → 运行组件”，分别检查未安装、安装进度、取消、错误与重试；安装过程中关闭设置再打开，状态应保留。断网失败后恢复网络，重试沿同一操作；退出并重新打开应用后能读回原操作。浏览器可用后完成网页短任务，确认下载在本次会话目录，不串用其他工作区资料；停止任务后不留浏览器进程。启用独立对话执行或工作区本机执行，分别执行 Python 与 Node 短脚本，确认使用随包解释器。
7. 有任务执行时按 Cmd+Q，确认先出现退出确认；退出后没有残留核心进程：

   ```bash
   pgrep -fl rayagent-core || echo "no core left"
   ```

8. 任务完成通知与偏好：按[桌面开发指南的检查](desktop/README.md#检查)走查通知、点击打开会话与偏好开关。

## 排查入口

| 现象 | 优先检查 |
|---|---|
| 显示“核心未能启动” | 错误页中的日志尾部；数据根是否被另一个核心占用；业务库版本是否高于应用 |
| 显示“核心版本与应用不匹配” | 宿主与随包核心来自不同构建，重新构建应用 |
| 模型不可选或发送前提示未配置 | 设置页列出的配置文件路径、提供商原因与密钥掩码 |
| 模型调用失败 | 上游地址、密钥、模型 id 与所配协议、工具调用支持 |
| 外部链接或下载没有反应 | 外部链接只放行 http、https 与 mailto；下载需要核心处于就绪状态 |

从终端启动内部包时可直接看到 `[core]` 与 `[host]` 前缀的日志，命令见[桌面开发指南](desktop/README.md#构建内部包apple-silicon)。

## 开发入口

仓库根目录运行 `./dev.sh` 会安装界面与宿主依赖并启动开发构建，说明见[桌面开发指南](desktop/README.md#开发运行)。各服务使用独立的依赖和运行环境：

- [桌面宿主](desktop/README.md)：Tauri 宿主、核心拉起与退出、内部包构建。
- [API](api/README.md)：核心、业务库迁移、后端分层与测试。
- [UI](ui/README.md)：Vite 与 React 共享界面、请求封装与检查脚本。
- [契约](contracts/README.md)：由核心 Pydantic 模型生成的 OpenAPI、JSON Schema 与 TypeScript 类型。

默认可调数值集中在[运行参数与限额](../docs/limits.md)。
