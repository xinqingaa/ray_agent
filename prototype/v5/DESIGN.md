# RayAgent V5 设计说明

本文记录 V5 原型的设计思路、视觉语言和组件规则，作为桌面界面升级的设计依据。它描述的是原型中的拟议交互，不代表 `ray_agent/ui` 已经实现；落地时以产品契约（[UI 设计说明](../../ray_agent/ui/DESIGN.md)、[产品说明](../../docs/product.md)）为准，冲突处见文末的「落地时要改的现有约定」。

## 这一版要解决什么

V1–V4 一直在回答「功能放在哪」：背景放第几个 tab、Skill 放左下角还是设置里。信息结构反复挪动，视觉语言却始终是 V1 那一套，结果是：

- **层级靠线条撑起来**。顶栏底线、tab 底线、列表分隔线、侧栏边框叠在一起，每一层都差不多重，没有主角。
- **新能力被做成了页面**。记忆、检索、Skill 各占一页，像设置表单，看不出它们在为当前任务服务。它们真正有价值的时刻，是「这次任务用了什么、还缺什么、要不要记住」。
- **动效没有被设计**。切换、展开、拖拽都是瞬时的，用户看不出界面发生了什么变化。

V5 换了一个顺序：先定一个原则和一套规则，再把每个页面放进去。

## 一个原则

> **界面安静地承托任务；需要人做决定的地方才站出来。**

从这句话推出五条可检验的判断：

1. **层级用明度，不用线条。** 能用背景明暗和留白区分的，就不画分割线。
2. **卡片只给两类东西：需要你处理的，和可以拿走的。** 审批、Agent 建议、记忆冲突、交付文件、正在安装的组件是卡片；过程、记忆列表、文件树、搜索结果都是平铺的行。
3. **能力回到发生的地方。** 记忆在回复下方回流（「记住了 2 条」），检索结果以引用角标出现在正文里，Skill 以整段名称出现在输入框开头。独立页面只负责全局管理。
4. **动效回应操作。** 弹性、磁吸、拖拽、重排都由用户的动作触发，用来说明「什么变了、去了哪」。持续动画只留给正在执行的那一步。
5. **一个状态只在一个地方说。** 运行状态在时间线，等待原因在审批卡，索引进度在知识页；顶栏和标题不重复播报。

## 空间结构

```
┌──┬────────────┬──────────────────────────────────────────────┐
│＋│ 列表        │ 透明顶栏：面包屑      [◉ 对话][≡][▥]        ⌕ ▥ │
│  │（落在画布上）│┌───────────────────────────┐┌───────────────┐│
│◉ │ 工作区       ││                           ││ [▣ 文件夹][…] ││
│▢ │  ▸ 季度复盘  ││  纸面：对话 / 背景 / 知识    ││  右侧面板      ││
│──│    整理竞品表 ││                           ││  （同一纸面层） ││
│✦ │    写纪要    ││                           ││               ││
│▣ │  ▸ 课程笔记  ││   ┌ 计划条 ───────────┐   ││               ││
│  │             ││   └ 输入框 ───────────┘   ││               ││
│☾ │             │└───────────────────────────┘└───────────────┘│
│⚙ │             │                                              │
└──┴────────────┴──────────────────────────────────────────────┘
 轨道  列表              主区（画布上的一到两张纸面）
```

| 区域 | 角色 | 规则 |
|---|---|---|
| 轨道 | 全局去哪儿 | 通高，最亮的一条；新建固定在顶部，设置固定在底部；中间按「对话与工作区 / Skill 与组件」分两组 |
| 列表 | 当前范围里有什么 | 没有底色，文字直接落在画布上；可收起，窄窗口变为抽屉；没有列表的页面（组件）整列让出 |
| 顶栏 | 我在哪、看哪一面 | 透明，没有背景和分割线；左面包屑，中间视图图标组，右侧全局动作 |
| 纸面 | 正在做的事 | 唯一明显的"面"，比画布亮一档，大圆角；内容居中限宽 |
| 右侧面板 | 手边的材料 | 与主纸面同层，并排而不嵌套；可拖宽、可收起，窄窗口变为浮层 |

**为什么是三栏而不是两栏。** 轨道回答"去哪"，列表回答"有什么"，两者混在一列里（V1–V4 的做法）会让工作区、独立对话、资源入口挤成一长串。拆开以后，列表可以完全专注当前范围，也可以整列收起而不丢全局导航。

## 视觉语言

### 色彩

画布带一点色温的浅灰，纸面只比画布亮一档，强调色是低饱和的暮蓝。刻意避开纯白 + 高饱和品牌色的组合：Agent 任务经常一跑就是很久，界面要耐看。

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| canvas | `#ecebe7` | `#1a1c1f` | 画布：轨道之外、纸面之下 |
| sheet | `#fbfbf9` | `#23262a` | 纸面、浮层底色 |
| sheet-2 | `#f4f4f1` | `#2a2d32` | 纸面内的次级底面：用户消息、选中行、计划条 |
| rail | `#fdfdfc` | `#26292d` | 轨道，整条最亮 |
| ink / ink-2 / ink-3 | `#1f2328` / `#555b63` / `#8b9097` | `#e8e8e4` / `#a9adb3` / `#7c8187` | 正文 / 说明 / 更弱信息 |
| dark | `#24282d` | `#e8e8e4` | 轨道当前项、主按钮、提示、勾选；深色主题里反转为浅色 |
| accent | `#4d679c` | `#8ea6d6` | 唯一强调：当前交互、引用、运行中、焦点 |
| wait / ok / bad | `#9a6a1c` / `#3f7656` / `#ad4a3d` | 提亮版本 | 等待、成功、失败；永远与对应浅底成对使用 |

规则：

- **强调色只有一个。** 暮蓝只出现在"此刻相关"的东西上：运行中的点、引用角标、选中的滑块、焦点环。新建按钮用它，是因为它是唯一永远可用的主动作。
- **主按钮用深色，不用强调色。** 「批准这一次」「接受」「采用新的」是黑底白字，和强调色分开，避免"蓝色到处都是"。
- **状态色成对。** 文字色 + 同色浅底（`wait` + `wait-soft`），状态同时有文字含义，不只靠颜色。
- **文件类型色只区分类型。** PDF 玫瑰、表格绿、文档蓝、图片紫、文本石板灰，用浅底 + 类型缩写的字标表达，不传达状态。
- **工作区用色相区分。** 每个工作区一个色相，标记是按色相着色的小文件夹（展开时为打开的文件夹），不用首字。

### 字体与字号

| 用途 | 字号 | 说明 |
|---|---|---|
| 界面文字 | 13px | 列表、按钮、标签、说明 |
| 阅读正文 | 14.5px | 回复、用户消息、记忆、工作方式；随「阅读字号」缩放 |
| 回复首段 | 15.5px / 500 | 结论先行，用字号和字重拉开，不用颜色 |
| 页面标题 | 22px / 650 | 背景、Skill、运行组件等页面 |
| 小标签 | 11–12px | 来源、版本、状态 |

字体使用系统栈（SF Pro / 苹方），等宽用 SF Mono。桌面应用里系统字体最稳，中文和西文的度量也一致。数字（用时、轮次、计数、大小）使用等宽数字，命令、路径与版本号使用等宽字体。

### 形状与层次

| 层 | 表达 |
|---|---|
| 画布 | 没有阴影 |
| 纸面 | 18px 圆角；1px 极淡描边 + 很轻的下方投影，几乎看不出来，只为在深浅相近时托住边缘 |
| 浮层 | 14–22px 圆角；明显的投影。提示、引用、模型菜单、斜杠菜单、计划清单、对话框、拖拽中的条目 |
| 卡片 | 14–16px 圆角；描边 + 轻投影。需要处理的卡片描边带状态色（审批带等待色，失败组件带失败色） |
| 行 | 8–12px 圆角；无底色，悬停浅底，选中半透明白 |

圆角随层级变大：行最小，纸面和对话框最大。避免所有东西同一个圆角造成的"卡片模板感"。

### 图标

统一的线描图标，24 栅格、1.75 线宽、圆角端点。重复的行内动作（预览、在 Finder 中显示、钉住、撤回）用图标并带悬停提示和可访问名称；主要动作与不可逆动作（批准、接受、清空）写清文字。

## 导航与切换

### 竖向图标轨道

- 当前项是深色圆角块。块是**一个独立元素**，切换时沿轨道弹性滑到新位置，而不是旧的消失、新的出现，用户能看到"从这里到那里"。
- 悬停约 0.25 秒后，提示向右出现并带轻微位移；轨道上的提示比其他地方出现得快，因为图标没有文字。
- 图标组之间用很淡的短分割线，这是全局唯一保留的分割线之一，因为它分隔的是不同性质的入口。
- 有待处理事项时，图标右上角一个等待色小点（例如工作区有待确认的记忆冲突）。

### 透明顶栏与图标组

- 顶栏没有背景，文字直接落在画布上。
- 入口多、空间有限时用**图标组**：选中项展开文字，其余只留图标。切换时选中块的宽度用弹性曲线变化，文字淡入。工作区的「对话 / 背景 / 知识」、右侧面板的「文件夹 / 成果 / 查看 / 修改」、知识页的「检索 / 索引」都用同一个组件。
- 图标组可以带计数（背景的待处理数量），计数跟在图标后，用等待色。
- 在画布上，选中项是半透明白；在纸面上，选中项是纸面色压在次级底面上。

### 列表

- 工作区行：色相文件夹 + 名称 + 状态（找不到文件夹 / 已归档）。点击进入工作区首页并展开；再点收起。展开有弹性高度动画，子项左侧一条淡竖线表示归属。
- 会话行：名称 + 时间；运行中显示呼吸的强调色点，等回复显示等待色点，替换时间。
- Skill 页时，列表变成来源筛选（全部 / 工作区 / 用户目录 / 额外目录 / 应用安装 / 内置），需要处理的同名冲突单独成组。

### 右侧面板

- 与主纸面并排，是同一层的另一张纸，不是抽屉压在主区上（宽窗口）。
- 左缘可拖动调整宽度，悬停时出现一根短把手。
- 点对话里的步骤，面板切到「查看」并显示那一步的结果；点引用或文件，面板显示预览并高亮对应段落。

## 动效

| 曲线 | 用途 |
|---|---|
| 弹性 `cubic-bezier(.34, 1.45, .55, 1)` | 位置与尺寸变化：轨道指示块、图标组宽度、展开收起、拖柄、计划清单弹出、条目重排 |
| 缓出 `cubic-bezier(.22, .8, .3, 1)` | 透明度与颜色：淡入淡出、悬停底色 |

| 时长 | 用途 |
|---|---|
| 160ms | 悬停、颜色 |
| 300ms | 淡入、小位移 |
| 460ms | 弹性位移与尺寸 |

具体的手法：

- **弹性展开**：执行过程、本次参考、工作区子项、撤销差异，用高度从 0 到内容高度的弹性过渡，不跳。
- **磁吸**：主要按钮（新建、发送、批准、接受）在指针靠近时轻微跟随，最多几个像素。拖拽时，条目进入可放置区域会被吸向落点并回正。
- **拖拽**：记忆拖到「钉住」、文件拖进对话区。拖起时原位置变淡，幽灵块略微倾斜跟随；进入落点后落点展开空位、描边变实。
- **重排（FLIP）**：钉住、撤回、筛选、排除目录导致的列表变化，条目从旧位置弹性移动到新位置，新出现的条目淡入。用户能看到"那一条去哪了"。
- **离场**：接受建议、处理冲突、撤回记忆时，卡片或行先轻微上移淡出，其余内容再补位。
- **持续动画只有一处**：正在执行的那一步（状态点呼吸 + 文字微光），以及安装和索引中的转圈。其他地方不用持续动画表达"运行中"。
- **减少动态效果**：系统开启后，所有过渡与动画缩短到几乎为零，磁吸关闭。

## 核心流程

### 对话

- **过程**：运行中展开，逐步出现，当前步有微光；完成后收成一行「执行过程 · 6 步 · 1 分 42 秒」。最终回复、交付与提问始终可见。
- **审批**：全页唯一带等待色描边的卡片，写清"要做什么、在哪里做、会产生什么"，命令原文用等宽块。批准后继续执行。
- **回复**：首段是结论，用字号和字重拉开；数字后面跟引用角标。表格用细描边容器，表头浅底。
- **引用**：角标悬停或点击弹出原文片段（高亮命中词），可打开原文（右侧预览并闪一下对应段落）或引用到输入。
- **交付**：可以拿走的文件用卡片，整张可点，次级动作（预览、在 Finder 中显示）是同级图标。
- **回复下方的一行**：本次参考 · 记住了 N 条 · N 条待你确认 · 撤销修改 · 统计。统计靠右，只有图标加数值，含义在悬停提示里。
- **本次参考**：按装配顺序分三列：工作方式版本 → 常驻记忆 → 检索命中。用户能一眼看出 Agent 这次带上了什么。

### 输入

- **输入框**是纸面上的一张浮起的卡，聚焦时描边染上强调色并加一圈浅色光晕。
- **计划条**贴在输入框上方，一行显示「阶段 2/4」、进度、当前阶段与当前子步骤。点开后清单从计划条向上弹出，**盖在时间线上而不挤压阅读区**；子步骤轻缩进，已完成打勾变弱，当前项转动（等批准时不转）。
- **斜杠菜单**：分「操作」与「Skill」两组，Skill 始终标出来源，压缩项带上下文圆环。一次展开期间高度固定，过滤只换内容；鼠标只改高亮不滚动，方向键越界时才最小滚动。选中的 Skill 以整段名称放在输入框开头。
- **模型菜单**：上半部分按厂商分组的模型行（名称 + 上下文窗口，输出上限在提示里），下半部分是思考：标题行 + 胶囊轨道滑块。换模型、开关思考、改用默认档都不改变菜单高度，提示写在标题行右侧。关闭时才提交一次。
- **上传**：拖入文件时整个对话区出现两个落点：「随这条消息发给 Agent」或「只加入文件夹」（可选目录）。附件依次显示上传中 → 解析中 → 建立索引 → 可检索，让用户知道材料什么时候能被检索到。

### 工作区背景

背景页回答一个问题：**这个工作区里开始新任务时，Agent 会先带上什么。** 页头三个数字：工作方式版本、常驻记忆占用、待处理数量。

- **工作方式**像一段文档一样直接阅读，编辑时原地变成可编辑区。版本历史是对话框：左侧版本列表，右侧与当前版本的差异；恢复会另存为新版本，不删除历史。
- **Agent 建议**只标出变化的片段（删除标红、新增标绿），三个动作：接受、改一下再接受（原地变为可编辑文字）、忽略。
- **记忆冲突**并排显示「已保存」和「新发现」，二选一。
- **常驻排序**与核心规则一致：钉住的排在最前，其余按约束 → 偏好 → 决定 → 事实、再按最近使用排序，前 12 条每次带上。第 12 条下方一条虚线分界，之后的条目只在检索时召回。**排序本身就是说明**，不需要额外解释"常驻"是什么。
- **拖拽钉住**：从「其余」拖到「钉住」，落点吸附，其他条目弹性重排，分界线随之移动，用户直接看到"谁被挤出了常驻"。

### 知识

知识页分「检索」和「索引」两面，右上角一直显示能力可用性：全文 / 语义 / 文字识别，未安装的给出安装入口。

- **检索**：大搜索框 + 范围（全部 / 文件 / 记忆 / 会话摘要）+ 结果列表 + 右侧原文预览。没有结果时说明"目前只有全文匹配"，提示语义检索能带来什么，而不是只说"无结果"。结果可以引用到新任务。
- **索引**：顶部四个计数（可检索 / 处理中 / 待文字识别 / 失败）和一条按文件着色的分段条，下面写清范围与规模。可以暂停后台索引、重新扫描、全部重试；目录可以排除（说明文件本身不受影响）和重新纳入。每个文件的状态在固定的一列，动作在另一列：失败可重试，缺组件的直接给"安装文字识别"。

### Skill

- 一行一个 Skill：名称、描述、来源、版本；右侧两个开关：「每次带上」（进入每次运行的目录）和启用（能在 `/` 里选择）。停用时「每次带上」一起关闭并置灰。
- 同名冲突是页顶的一张卡，两份并排，点哪份就以哪份为同名时的默认。
- 详情是宽对话框：左侧包文件树，右侧内容，可在渲染与源码之间切换。底部说明这一类 Skill 的边界（外部目录只读、内置可停用不可删除、应用安装的可编辑）。
- 添加：GitHub / 本地文件 / 直接编写三种方式共用一个对话框。GitHub 获取后先展示包内容再安装。

### 运行组件与设置

- **运行组件**：每个组件一张卡，写清"装了能做什么"和"不装会怎样"。安装中显示下载量与阶段，可以取消；失败显示原因与重试。
- **设置**是覆盖应用的弹层，底层页面保持不动。左侧分区，右侧内容；修改后底部浮出深色保存条，未保存时不能关闭（保存条会抖一下提醒）。模型提供商只读展示配置文件与各上游状态；危险操作放在数据管理的危险区，需要输入确认短语，取消默认聚焦。

### 撤销本次修改

逐个文件列出：可直接撤销的默认勾选；已是运行前状态的不可选；运行之后又被改动的标为冲突，用等待色底，默认不选，勾「仍要覆盖」才能选；二进制与大文件只说明大小；有差异的可以展开。提交后每项显示结果，底部提示这次撤销也记在「最近修改」里，可以撤回。标题下方始终写明"只恢复文件内容，不改变对话和记忆"。

## 文案

- 用动作和结果说话："要在文件夹里运行一条命令""已钉住，下次运行排在最前"。
- 不可用状态给简短原因和下一步："原位置找不到这个文件夹，对话仍可继续，文件工具暂停　[重新定位]"。
- 不在正常操作里解释原理。需要解释规则时，让界面本身成为说明（常驻分界线、本次参考的三列顺序）。
- 撤销类提示一律带"撤销"按钮，停留时间比普通提示长。

## 可访问性与窄窗口

- 所有图标按钮都有可访问名称；开关用 `role="switch"`，滑块用 `role="slider"` 并支持方向键；对话框聚焦容器、Esc 关闭并把焦点还给入口，点遮罩不关闭。
- 焦点环用强调色，任何组件都不去掉焦点样式。
- 桌面最小宽度是 960。1180 以下右侧面板变为浮层并默认收起；1100 以下列表变为抽屉，在列表里导航或点列表以外时收起，统计只保留前两项。
- 深色主题不是简单反色：画布最暗，纸面亮一档，深色块反转为浅色（主按钮、轨道当前项），状态浅底改为同色低透明度。

## 落地时要改的现有约定

V5 与 [UI 设计说明](../../ray_agent/ui/DESIGN.md) 的大部分交互契约一致（计划展示、斜杠菜单、模型菜单、撤销、设置弹层、文件预览）。以下几处是有意的改变，实施前需要确认并更新正式文档：

| 现有约定 | V5 的做法 |
|---|---|
| 侧栏只列对话，顶部是「对话」标题与新对话按钮 | 竖向图标轨道 + 可收起的上下文列表；新建固定在轨道顶部 |
| 工作方式与记忆是顶栏打开的弹层 | 工作区的「背景」视图，有完整页面 |
| 文件夹面板底部只有索引汇总 | 知识页的「索引」面，补齐范围、暂停、排除与重试（对应收尾清单 F11） |
| 运行组件与 Skill 是设置里的分区 | 轨道上的一级入口；设置里保留跳转 |
| 浅色是近白中性纸面 + 钴蓝 `signal` | 带色温的浅灰画布 + 暮蓝 `accent`；主按钮改用深色 |
| 会话的“聊天／日志”分段 | V5 未覆盖开发者视图，沿用现有分段 |

token 映射建议：`--background` → canvas，`--card` → sheet，`--muted` → sheet-2，`--sidebar` → rail，`--signal` → accent，状态色与浅底沿用现有 `state-*` 的成对结构，只调整取值。

## 还没有决定的

- 视图图标组放在顶栏中间还是紧跟面包屑：中间更对称，紧跟面包屑在窄窗口里更稳。
- 「每次带上」与启用是否合并成一个三态控件（停用 / 可选择 / 每次带上），减少一行两个开关。
- 开发者视图（日志、终端、上下文环、请求原文）在新的视觉语言里怎么表达，V5 没有覆盖。
