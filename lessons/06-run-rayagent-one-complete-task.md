# 从 Agent Loop 到完整 Harness

沿 hello.txt 任务核对：信息谁准备、控制谁推进、工具结果回给谁、产物落在哪里？

## 叙述方向

本章仍为待写骨架。以一条真实任务为主线，追清已学机制之间的交接；职责地图由第一章建立，这里不重新列举 Harness 的组成。

1. 明确任务和观察依据：创建 hello.txt、写入 hello、读取并总结，说明要核对的实际结果。
2. 请求进入执行：谁接收消息，谁准备任务和本次模型输入，谁启动推进。
3. 行动产生后续决策：沿实际写入、工具结果回传和后续调用，核对信息交给谁、控制由谁推进。计划步骤和调用次数以实际运行记录为准。
4. 执行成为可见、可交付的结果：区分工具结果、页面事件和最终文件，追清沙箱文件、同步存储与用户访问的联系。
5. 确认观察边界：核对本次文件任务的结果，不以一次成功证明取消、恢复或长期记忆等能力。

每次交接交代来源、接收方、传递内容及可核对的依据。配图按任务过程或交接组织，不再画职责总图；不把页面显示的每条记录都视为模型发起的独立操作。

## 材料与范围

主要载体是 RayAgent 的共同文件任务。材料与实现入口见 [素材索引](map.md#shared-product-observation)，运行条件见 [应用指南](../ray_agent/README.md)。详细安装步骤留在运行指南。

本章深度来自追清交接：展示本次 Context 如何准备，不重复第五章的信息选择策略；辨认 Planner 与执行器，不展开第七章的两层状态转换；说明状态、事件和文件去向，不替代第八至十二章的控制、存储与环境机制；核对本次结果，不展开第十六章的任务验证方法。
