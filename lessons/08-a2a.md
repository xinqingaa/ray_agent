# A2A agents and product integration

Status: stub
Area: Protocols
Prerequisites: [07](07-mcp.md) 中的「协议工具进入产品工具层」；[03](03-react-loop.md)

## 1. Learning objectives and prerequisites

- 能说明 A2A 1.0 如何用 Agent Card 发现对端，再用 JSON-RPC 发消息。
- 能对比 SDK 客户端与手写 `httpx` 客户端各自暴露的协议细节。
- 能说明产品用官方解析器/工厂，以及单次委派遇到进行中 Task 时的查询策略。
- 前置：基线无需 Key。入口：[A2A 实验](../labs/a2a/README.md)。`2-2 code/` 不进基线。

## 2. Essential concepts and a runnable example

| 档位 | 脚本（`labs/a2a/`） |
|---|---|
| Required | `main.py`（先起，`:9999`）、`agent_executor.py`、`client.py`、`httpx_a2a.py` |
| Optional | `A2A_LAB_MODE=deepseek` 及 `LLM_*`（非阶段 2 验收） |
| Out of scope | `labs/foundations/2-2 code/weather/`、`2-2 code/ui/` |

已验证期望：两个客户端都发送 `ray-agent-lab`，收到 `A2A_LAB_OK:ray-agent-lab`。

lab 只覆盖非流式 Message 回复，不含任务轮询、远程取消、认证、推送通知。这些若存在，在产品侧单独讲。

## 3. Product code entry points and the execution path

| 主题 | 入口 |
|---|---|
| 官方卡片与客户端 | `ray_agent/api/app/infrastructure/protocols/a2a.py` |
| 工具端口 | `domain/services/tools/a2a.py` |
| 设置页 | `manus-settings.tsx`；`components/tool-use/a2a-tool.tsx` |
| 夹具 | 与 MCP 同一套 `run-protocol-fixtures.sh` |

产品：单次委派收到进行中的 Task 后只查询同一 Task，不重发原 query。远程状态留在工具结果里，不替代本地 `SessionStatus`。需要输入或认证时返回未完成原因，本次不自动把主流程打成 waiting 续接。

## 4. Design rationale, limitations, and relevant failure behavior

- 实验目录里的**服务端**示例不能直接套成产品职责；产品是客户端。
- A2A 另有 `cancel_timeout`；配置根节点有 `discovery_budget`。
- 历史天气 Agent / 旧 UI 依赖旧 SDK 或缺失模块，只作「为何排除」的说明，不写运行步骤。
